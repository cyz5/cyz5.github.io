
## 1. 学习目标

### 理解

- 解释临界区保护的目标：让共享状态更新满足原子性、一致性与可见性要求。
- 区分**任务间互斥**、**任务与 ISR 间互斥**、**多核并发保护**这三类问题。
- 说明关中断、调度器挂起、互斥锁、原子操作和自旋锁各自能保护什么、不能保护什么。

### 掌握

- 根据共享数据的访问上下文选择合适的保护机制。
- 正确配对临界区进入与退出，并保证所有错误路径都能退出。
- 使用 FreeRTOS 的任务版与 ISR 版同步 API，避免在 ISR 中使用不允许的操作。
- 测量临界区最长时长、最大中断屏蔽时间和锁等待时间。

### 精通

- 分析优先级反转、锁顺序死锁、嵌套临界区、编译器重排和缓存一致性问题。
- 结合目标端口源码判断临界区实际屏蔽哪些中断。
- 设计有上界的共享状态更新协议，评估其对最坏响应时间的影响。

### 能够设计

- 为单核 MCU、多核 SoC 和 DMA 共享数据分别制定保护策略。
- 给关键锁定义所有权、锁顺序、最大持有时间与超时恢复规则。
- 建立可审计、可测量的临界区与互斥锁规范。

## 2. 前置要求

### 知识要求

- 任务调度、抢占、优先级与中断嵌套。
- Cortex-M 异常优先级与 BASEPRI/PRIMASK 基础。
- 队列、信号量、互斥锁和任务通知。
- C 语言 `volatile`、原子访问、编译器内存模型基础。
- 若涉及多核：了解缓存一致性、内存屏障和跨核同步。

### 技能要求

- 能查阅目标 RTOS 端口的临界区实现。
- 能阅读反汇编，确认临界区宏最终生成了什么指令。
- 能用逻辑分析仪、DWT 或 trace 测量临界区与锁等待时长。
- 能编写并发测试，覆盖抢占、中断嵌套和超时错误路径。

## 3. 技术概述

**临界区**是访问共享状态时必须满足特定并发约束的一段代码。它的本质不是“把代码包起来”，而是建立正确的同步关系，使并发执行者不能观察到不一致的中间状态。

常见保护机制：

- **关中断或屏蔽部分中断**：阻止特定中断打断当前代码，适合极短的任务/ISR 共享状态保护；会增加中断延迟。
- **调度器挂起**：禁止任务切换，不等于禁止中断，不能保护任务与 ISR 共享的数据。
- **互斥锁**：保护任务间共享资源，通常支持优先级继承；不适用于 ISR。
- **二值/计数信号量、队列、任务通知**：用于事件同步或数据传递，通常比自行设计共享标志更安全。
- **原子操作**：对单个变量或有限状态转换提供原子性；不自动保护多个变量构成的不变量。
- **自旋锁/跨核锁**：用于多核间互斥，持锁时不能阻塞；单核上通常没有必要。

临界区策略必须先回答：

1. 共享数据有哪些并发访问者？
2. 这些访问者运行在任务、ISR、DMA 还是其他核心？
3. 需要保护的是单次读写，还是多个字段构成的整体不变量？
4. 最大允许屏蔽中断或等待锁的时间是多少？

## 4. 核心特性横向对比

|机制|任务间|任务与 ISR|ISR 与 ISR|多核|主要代价|
|---|---|---|---|---|---|
|调度器挂起|是，禁止任务切换|否|否|通常否|任务响应延迟|
|全局关中断|是，单核上可阻止 ISR 抢占|是|是|否，通常只影响本核|所有相关中断延迟|
|BASEPRI/优先级屏蔽|是，单核上保护被屏蔽优先级范围|是，针对可屏蔽范围|部分|否，通常只影响本核|被屏蔽中断延迟|
|互斥锁|是|不允许 ISR 阻塞获取|不适用|依内核实现|阻塞、优先级反转、死锁|
|原子操作|有限场景|有限场景|有限场景|有硬件原子支持时|复杂不变量仍需组合保护|
|自旋锁|不适合单核任务阻塞场景|取决于架构|取决于架构|是|忙等、持锁时延|

表中是机制的一般边界；实际能力由 RTOS、CPU 架构和端口实现决定。特别是 FreeRTOS 临界区宏可能使用 PRIMASK、BASEPRI 或其他端口机制，不能假设所有中断都被屏蔽。

## 5. 底层原理与功能特性深度解析

### 5.1 临界区究竟保护什么

假设一个环形缓冲区由生产者更新写索引，由消费者更新读索引。正确性依赖的不只是某个变量“不会被同时写”，还包括：

- 数据写入必须先于写索引发布。
- 消费者不能在数据尚未完整写入时观察到新索引。
- 索引读写宽度与对齐需满足目标处理器的原子访问条件。
- 若访问者位于多个核心或 DMA，需额外考虑缓存与内存屏障。

因此，`volatile` 只能约束部分编译器优化，不能提供互斥、复合原子性或通用内存顺序保证。

### 5.2 Cortex-M 上的关中断与优先级屏蔽

常见 Cortex-M 实现涉及：

- **PRIMASK**：屏蔽可配置优先级的普通中断，NMI 和 HardFault 等不可屏蔽异常不受其通常意义上的屏蔽。
- **BASEPRI**：屏蔽某个优先级阈值及其以下的中断；具体优先级编码与分组配置有关。
- **FAULTMASK**：屏蔽范围更广，通常不应用于一般 RTOS 临界区。

在 FreeRTOS Cortex-M 端口中，`taskENTER_CRITICAL()` 的实现可能通过 BASEPRI 屏蔽低于内核允许阈值的中断，使更高优先级、不会调用内核 API 的中断仍可运行。必须检查目标端口，例如 `portmacro.h` 和中断优先级配置。

如果某个高优先级 ISR 调用 FreeRTOS API，却未被临界区屏蔽，内核数据结构可能被并发修改。FreeRTOS 通过 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 等配置约束哪些 ISR 可以调用内核 API。

### 5.3 任务临界区与 ISR 临界区

任务上下文中可按端口使用任务临界区宏：

```
static volatile uint32_t shared_count;

void update_shared_count(void)
{
    taskENTER_CRITICAL();
    shared_count++;
    taskEXIT_CRITICAL();
}
```

在 ISR 中不能盲目使用任务版宏。FreeRTOS 对部分 Cortex-M 端口提供 ISR 专用的进入/退出宏，并要求保存和恢复中断屏蔽状态：

```
void peripheral_isr(void)
{
    UBaseType_t saved_mask;

    saved_mask = taskENTER_CRITICAL_FROM_ISR();

    shared_count++;

    taskEXIT_CRITICAL_FROM_ISR(saved_mask);
}
```

该代码只适用于确实提供这些宏且其端口语义匹配的配置。优先选择队列、通知等 ISR-safe API，避免手写共享变量协议。进入与退出必须配对，并保留原屏蔽状态；不能在 ISR 中用一个简单的“开中断”操作覆盖外层已有屏蔽状态。

### 5.4 调度器挂起不等于临界区

```
vTaskSuspendAll();

/* 其他任务不会切换，但中断仍可运行。 */
update_task_shared_structure();

xTaskResumeAll();
```

调度器挂起适合短暂防止任务切换、且被保护结构只会被任务访问的特定场景。它不能防止 ISR 修改共享数据，也不能用于长时间执行。若期间发生 ISR 导致更高优先级任务就绪，切换会在恢复调度后进行。

### 5.5 互斥锁与优先级继承

互斥锁用于任务间资源互斥。优先级反转示例：

```
低优先级任务 L 获得锁
高优先级任务 H 请求锁并阻塞
中优先级任务 M 持续运行
L 无法运行释放锁，H 长时间等待
```

支持优先级继承的互斥锁可暂时提升 L 的优先级，降低反转时长。但它不能消除死锁，也不能让 ISR 安全地等待锁。

```
static SemaphoreHandle_t bus_mutex;

bool bus_transfer(const uint8_t *tx,
                  uint8_t *rx,
                  size_t length,
                  TickType_t timeout)
{
    if (xSemaphoreTake(bus_mutex, timeout) != pdPASS) {
        return false;
    }

    bool ok = bus_transfer_locked(tx, rx, length);

    xSemaphoreGive(bus_mutex);
    return ok;
}
```

生产实现还应保证所有错误路径都会释放锁；若底层传输可能永久等待，应使用硬件超时或中断驱动方案，不能无限持锁。

### 5.6 原子操作与内存屏障

原子操作适合保护单个状态量或无锁协议中的明确步骤：

```
#include <stdatomic.h>

static atomic_uint event_flags;

void publish_event(unsigned int bits)
{
    atomic_fetch_or_explicit(&event_flags,
                             bits,
                             memory_order_release);
}

unsigned int consume_events(void)
{
    return atomic_exchange_explicit(&event_flags,
                                    0U,
                                    memory_order_acquire);
}
```

注意：

- C11 原子是否 lock-free 取决于编译器和目标架构。
- 原子操作不一定适用于所有 MCU 编译器或 RTOS 配置。
- `release/acquire` 管理内存可见性，但不自动保护复杂对象生命周期。
- ISR 中使用原子操作前需确认该类型操作在目标平台上可用于 ISR，且不会调用隐藏锁库。

### 5.7 多字段一致性与快照

若读写双方需要一致读取多个字段，单独保护字段通常不够。可用短临界区复制快照，再在临界区外处理：

```
typedef struct {
    uint32_t sequence;
    int32_t temperature_milli_c;
    uint32_t status;
} sensor_snapshot_t;

static sensor_snapshot_t g_sensor;

bool sensor_get_snapshot(sensor_snapshot_t *out)
{
    if (out == NULL) {
        return false;
    }

    taskENTER_CRITICAL();
    *out = g_sensor;
    taskEXIT_CRITICAL();

    return true;
}
```

关键是临界区只包含固定长度复制，不在其中做格式化、浮点计算、I/O 或日志。若 ISR 也访问该结构，需确认任务临界区确实屏蔽对应 ISR；否则需使用端口定义的适用保护机制。

## 6. 性能量化分析

### 6.1 任务响应时间影响

关中断或屏蔽中断会增加被屏蔽中断的最坏响应延迟。粗略上界可写为：

Lirq,max≥Tmask,max+Thigher priority interferenceLirq,max​≥Tmask,max​+Thigher priority interference​

`T_mask,max` 是相关中断被屏蔽的最长连续时间。若屏蔽期间存在多个高于屏蔽阈值的中断，还要把这些中断的干扰计入分析。

任务锁等待时间近似为：

Twait=Towner remaining+Thigher priority interference+TqueueingTwait​=Towner remaining​+Thigher priority interference​+Tqueueing​

锁持有时间无界时，任务响应时间也无法给出可靠上界。

### 6.2 CPU 开销估算示例

假设某个临界区在目标板实测为 120 CPU cycles，CPU 频率为 120 MHz：

Tcritical=120120 MHz=1 μsTcritical​=120MHz120​=1 μs

如果每秒进入 20,000 次，其纯执行时间占比为：

U=20,000×1 μs=2%U=20,000×1 μs=2%

这是计算示例，不是指定平台实测值。实际临界区耗时受编译器、总线等待、Flash/SRAM 位置、嵌套中断和插桩影响。

### 6.3 需要报告的指标

- 临界区最大时长，而非只报平均值。
- 每个中断优先级的最长屏蔽时间。
- 互斥锁最大等待时间与最大持有时间。
- 锁超时、重试、优先级继承发生次数。
- 临界区调用频率与累计 CPU 时间。
- ISR 延迟分布和最坏响应时间。

测量方法可用 DWT `CYCCNT`、GPIO 翻转、ETM/RTOS trace。使用 GPIO 测量时，记录 GPIO 操作本身的固定开销；调试插桩也可能改变临界区长度。

## 7. 应用场景选型指南

```
共享状态由谁访问？
├─ 仅单任务：通常不需要并发保护
├─ 多个任务
│  ├─ 访问的是长期资源：互斥锁
│  ├─ 传递数据/事件：队列、通知、事件组
│  └─ 极短共享状态更新：短临界区或原子操作
├─ 任务与 ISR
│  ├─ 可用事件传递：ISR-safe 队列/通知，优先选择
│  └─ 只能共享小型状态：端口适用的短 IRQ 临界区/原子协议
└─ 多核或 DMA
   ├─ 多核：跨核锁/原子协议 + 内存序与缓存一致性
   └─ DMA：缓存维护、DMA 所有权协议，CPU 临界区通常不够
```

|场景|推荐方案|理由|
|---|---|---|
|任务间共享 I²C/SPI 总线|互斥锁，限制持锁时间|资源独占且可能等待外设|
|ISR 通知任务有新数据|队列或任务通知的 ISR-safe API|避免自建竞态与复杂共享状态|
|任务更新几个计数器|原子操作或短任务临界区|代码小且执行时间可界定|
|ISR 与任务共享小型标志|端口适用的中断屏蔽或原子协议|需明确 ISR 优先级与可见性|
|多字段配置更新|短临界区复制快照，或双缓冲协议|保持数据整体一致|
|DMA 与 CPU 共享缓冲区|所有权状态机 + cache clean/invalidate|关中断不能阻止 DMA 访问|

## 8. 工程最佳实践

### 设计原则

- 先确定并发访问者，再选择保护机制。
- 优先使用内核同步原语表达事件和资源所有权。
- 关中断临界区只保护固定、极短的状态更新。
- 互斥锁持有期间避免等待另一个资源、执行慢速 I/O 或调用未知回调。
- 为多个锁定义全局获取顺序，避免循环等待。
- 若 ISR 访问共享数据，确认保护机制覆盖该 ISR 优先级。
- 多核和 DMA 场景单独设计一致性方案，不能照搬单核关中断经验。
- 不在临界区内调用不可重入函数、阻塞 API 或复杂日志。

### 选型决策矩阵

|访问形态|首选|需要核查|
|---|---|---|
|任务间共享资源|互斥锁|优先级继承、超时、锁顺序|
|ISR 唤醒任务|ISR-safe 队列/通知|中断优先级限制|
|单变量状态|原子操作|是否 lock-free、ISR 可用性|
|短小多字段更新|临界区保护快照|屏蔽范围、最大时长|
|多核共享|跨核锁或原子协议|缓存一致性、内存屏障|
|DMA 缓冲|所有权协议和缓存维护|cache line 对齐、DMA 可见性|

### 工业级编码规范

- 临界区进入与退出必须在同一函数或清晰的作用域管理中配对。
- 任何可能提前返回的代码都必须保证释放锁/退出临界区。
- 为每把锁记录保护对象、持有者、锁顺序和最大持有时长。
- 禁止在任务临界区中等待；禁止在 ISR 中获取可能阻塞的互斥锁。
- 通过断言检测非法嵌套、递归获取和锁顺序违规。
- 对关键路径保留最大时长的 trace 统计，按版本回归。

## 9. 常见错误与避坑指南

### 错误一：用 `volatile` 代替互斥

```
static volatile uint32_t counter;

void increment(void)
{
    counter++; /* 不是原子读-改-写 */
}
```

**根因：** `counter++` 包含读、加、写多个步骤；任务切换或 ISR 插入时可能丢失更新。`volatile` 不提供互斥和内存顺序保证。

**正确实现：**

```
static uint32_t counter;

void increment(void)
{
    taskENTER_CRITICAL();
    counter++;
    taskEXIT_CRITICAL();
}
```

若使用 C11 原子，需确认目标编译器和 ISR 上下文支持情况。

**风险影响：** 计数丢失、状态机条件错误、现场问题随负载变化而出现。

### 错误二：用调度器挂起保护 ISR 共享数据

```
vTaskSuspendAll();
shared_value = new_value;
xTaskResumeAll();
```

**根因：** 调度器挂起只限制任务切换，ISR 仍可能抢占并访问 `shared_value`。

**正确实现：** 使用适用于该 ISR 优先级的临界区或原子协议；若数据本质上是事件，改用 ISR-safe 队列或通知。

**风险影响：** ISR 读取到部分更新状态，或更新被覆盖。

### 错误三：临界区内执行慢速操作

```
taskENTER_CRITICAL();
flash_write_page(data, length);
taskEXIT_CRITICAL();
```

**根因：** Flash 操作可能耗时数毫秒，且期间中断响应被延迟。

**正确实现：** 在临界区内仅复制必要状态或切换缓冲区所有权；在临界区外执行 Flash 操作。若要避免数据变更，使用双缓冲或版本号协议。

**风险影响：** 丢失高优先级中断、通信 FIFO 溢出和控制期限违约。

### 错误四：在 ISR 中获取互斥锁

```
void SPI_IRQHandler(void)
{
    xSemaphoreTake(spi_mutex, portMAX_DELAY); /* 错误 */
}
```

**根因：** ISR 不能阻塞等待；互斥锁的优先级继承也依赖任务调度语义。

**正确实现：** ISR 只确认硬件状态并使用 ISR-safe API 通知任务，由任务取得互斥锁并处理资源。

**风险影响：** 系统死锁、断言失败或内核状态损坏。

### 错误五：错误处理路径未释放锁

```
xSemaphoreTake(mutex, portMAX_DELAY);

if (!device_ready()) {
    return false; /* 错误：未释放 mutex */
}

xSemaphoreGive(mutex);
```

**根因：** 提前返回跳过了解锁。

**正确实现：**

```
bool operation(void)
{
    bool result = false;

    if (xSemaphoreTake(mutex, timeout) != pdPASS) {
        return false;
    }

    if (device_ready()) {
        result = perform_operation();
    }

    xSemaphoreGive(mutex);
    return result;
}
```

**风险影响：** 后续所有使用者阻塞，形成系统级死锁。

### 错误六：认为关本核中断能保护多核共享数据

```
disable_local_interrupts();
shared_state = new_state;
enable_local_interrupts();
```

**根因：** 本地中断屏蔽不会阻止另一个 CPU 核访问同一内存，也不会自动提供跨核缓存一致性。

**正确实现：** 使用平台支持的跨核锁或原子协议，并按架构要求执行内存屏障与缓存维护。

**风险影响：** 多核数据竞争、缓存陈旧读、偶发状态破坏。

## 10. 多机制组合使用方案

### 组合架构：ISR 发布数据，任务串行处理资源

```
外设 ISR
  ├─ 读取/确认最少硬件状态
  ├─ 写入固定环形缓冲区或取得 DMA 描述符
  └─ 用 ISR-safe 通知唤醒工作任务

工作任务
  ├─ 阻塞等待通知
  ├─ 取得总线/设备互斥锁
  ├─ 在短时间内更新共享配置
  ├─ 释放锁
  └─ 在临界区外完成慢速处理
```

示意代码：

```
typedef struct {
    uint16_t length;
    uint16_t buffer_index;
    uint32_t sequence;
} rx_descriptor_t;

static QueueHandle_t rx_queue;
static SemaphoreHandle_t device_mutex;

void DMA_IRQHandler(void)
{
    BaseType_t woken = pdFALSE;
    rx_descriptor_t desc;

    dma_ack_interrupt();
    desc.length = dma_get_completed_length();
    desc.buffer_index = dma_get_completed_buffer_index();
    desc.sequence = dma_get_sequence();

    /* ISR-safe 队列发送；队列容量和满队列策略必须事先定义。 */
    if (xQueueSendFromISR(rx_queue, &desc, &woken) != pdPASS) {
        record_rx_queue_overrun_from_isr();
    }

    portYIELD_FROM_ISR(woken);
}

static void rx_worker(void *arg)
{
    (void)arg;
    rx_descriptor_t desc;

    for (;;) {
        if (xQueueReceive(rx_queue, &desc, portMAX_DELAY) != pdPASS) {
            continue;
        }

        if (xSemaphoreTake(device_mutex,
                           pdMS_TO_TICKS(20)) != pdPASS) {
            record_device_lock_timeout();
            continue;
        }

        update_device_state_bounded(&desc);

        xSemaphoreGive(device_mutex);

        /* 大块解析和日志不放在锁或临界区内。 */
        process_received_buffer(desc.buffer_index, desc.length);
    }
}
```

设计要点：

- ISR 和任务之间以描述符传递所有权，不共享未保护的可变结构。
- 队列满时必须定义丢弃、背压或故障策略；不能静默覆盖仍在处理的数据。
- 若 DMA 缓冲区位于缓存区域，按 MCU 手册执行 cache invalidate/clean，并确保缓冲区与 cache line 对齐。
- 互斥锁只保护设备状态更新，不包住解析、日志或等待。
- `record_rx_queue_overrun_from_isr()` 必须确实适用于 ISR 上下文，或仅设置经验证的原子/端口安全标志。

## 11. 工业级实际案例分析

### 案例一：多任务共享 SPI 总线

**需求：** 传感器、Flash 与显示任务共享 SPI 控制器，操作过程中需要统一配置片选、模式和速率。

**架构设计：**

- 使用互斥锁保护总线资源。
- 锁持有期间完成有限、可超时的传输。
- DMA 完成中断只通知发起任务或驱动任务，不获取互斥锁。
- 对所有总线操作设定超时和错误恢复路径。

**设计要点：**

- 若传输时间过长，采用驱动任务集中管理 SPI 请求，避免多个任务长时间持锁。
- 禁止持有 SPI 锁时调用需要另一个锁的未知回调。
- 对锁持有时长建立最大值监控。

### 案例二：高频控制 ISR 与任务共享状态

**需求：** 高频采样 ISR 更新测量值，控制任务读取一组一致的测量数据。

**架构设计：**

- ISR 将一帧测量写入备用缓冲。
- 完成后以短原子状态切换发布缓冲索引。
- 控制任务读取稳定缓冲，或在短临界区内复制快照。
- 在多核或带缓存系统上增加内存屏障与缓存处理。

**设计要点：**

- 不要只分别读取多个 `volatile` 字段，否则控制任务可能读到跨帧混合数据。
- 若采用双缓冲，必须定义生产者追上消费者时的行为。
- 以实际优先级配置确认临界区是否屏蔽该 ISR。

### 案例三：共享配置的在线更新

**需求：** 管理任务更新控制参数，控制任务周期读取全部参数，不能读到半更新配置。

**架构设计：**

- 管理任务先在私有临时结构中校验配置。
- 使用短临界区交换活动配置指针，或使用双缓冲发布新配置。
- 控制任务在一个周期内固定使用同一配置版本。
- 对配置版本号和切换时间做 trace。

**设计要点：**

- 不要在临界区中逐项解析和校验配置。
- 若交换指针后旧配置会被释放，必须保证所有读者不再使用旧对象；可以使用静态双缓冲、引用计数或明确的周期边界回收协议。
- 指针原子交换不等同于对象生命周期安全。

## 12. 高频问题深度答疑

### Q1：临界区越短越好吗？

通常是，但短并不等于正确。首先要覆盖完整的不变量更新，其次要确保保护机制覆盖全部并发访问者。过早缩短可能把关键步骤拆开，导致读者观察到中间状态。目标是**完整且有上界**。

### Q2：单核 MCU 上 `taskENTER_CRITICAL()` 能保护任务与 ISR 吗？

取决于端口屏蔽哪些中断，以及该 ISR 的优先级是否落入屏蔽范围。某些 Cortex-M 端口使用 BASEPRI，允许更高优先级 ISR 继续运行。必须核对端口和 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 等配置。

### Q3：互斥锁是否能用于 ISR？

通常不能。ISR 不能阻塞，互斥锁的所有权和优先级继承机制以任务调度语义为基础。ISR 应使用 ISR-safe 队列、信号量或任务通知。

### Q4：关中断和互斥锁哪个更快？

取决于架构、端口和竞争情况。关中断通常路径短，但扩大了中断延迟；互斥锁可能发生阻塞和调度开销，但不会全局延迟所有中断。选择应基于访问者类型和实时性约束，而非只比较指令数量。

### Q5：为什么互斥锁解决不了死锁？

优先级继承只缓解部分优先级反转，不会打破循环等待。若任务 A 持有锁 1 等锁 2，任务 B 持有锁 2 等锁 1，二者仍会死锁。通过全局锁顺序、超时和资源集中管理预防。

### Q6：原子变量能否替代所有临界区？

不能。原子变量可保证特定读写或原子操作，但不能自动保护多个字段构成的不变量、复杂对象生命周期或外设资源。还需确认原子实现是否 lock-free，以及在 ISR 中是否安全。

### Q7：DMA 访问共享缓冲区时，关中断够不够？

不够。DMA 不受 CPU 中断屏蔽控制，仍会独立读写内存。需要缓冲区所有权协议；带 D-cache 的 MCU 还需按平台要求进行 cache clean/invalidate 和内存屏障。

## 13. 课程核心总结

- 临界区设计从并发访问者和共享不变量开始，而不是从宏开始。
- 调度器挂起只阻止任务切换，不能保护任务与 ISR 共享状态。
- 互斥锁用于任务间资源互斥，不能在 ISR 中阻塞获取。
- 关中断范围越大，中断响应上界越差；必须量化最长屏蔽时间。
- `volatile` 不是互斥或原子操作；原子操作也不自动保护复杂对象。
- 多核和 DMA 场景需要跨核同步、缓存维护与所有权协议。
- **工程目标不是“没有并发”，而是让共享状态更新正确、可证明且有时间上界。**

## 14. 快速参考速查表

### 场景选型表

|场景|机制|
|---|---|
|任务间独占访问总线或设备|互斥锁|
|ISR 向任务传递事件|ISR-safe 队列/通知/信号量|
|单个共享计数器或标志|确认 lock-free 后使用原子操作，或短临界区|
|任务与 ISR 共享小型状态|符合 ISR 优先级约束的临界区/原子协议|
|多核共享|跨核锁或原子协议 + 内存顺序保证|
|DMA 与 CPU 共享内存|所有权协议 + 缓存维护|
|多字段快照|短临界区复制、双缓冲或版本化协议|

### 特性对比表

|机制|阻止任务切换|阻止 ISR|支持阻塞|优先级继承|
|---|---|---|---|---|

|IRQ 临界区|视端口而定|屏蔽范围内|否|否|

## 16. 实践与进阶路径

### 梯度实战任务

1. 用两个任务并发更新共享计数器，对比无保护、短临界区和原子操作的结果。
2. 在 ISR 与任务之间共享状态，分别用任务通知和短临界区实现，验证中断优先级约束。
3. 为共享 SPI 驱动加入互斥锁、获取超时和锁持有时间统计。
4. 构造两把锁的反向获取场景，观察死锁，再用全局锁顺序修复。
5. 对 DMA 缓冲区加入所有权状态机，并在带 D-cache 的目标板验证缓存一致性。
6. 使用 DWT 或 GPIO 测量最大临界区时长和 ISR 延迟，纳入回归测试。

### 性能测试方法

- 固定 CPU 频率、编译选项、内存位置和中断负载。
- 分别测量无竞争与高竞争下的锁等待时间。
- 报告最大值、高分位数和调用频率，不只报告平均值。
- 对临界区同时测量代码执行时间和被屏蔽中断的端到端响应延迟。
- 在发布构建中验证插桩关闭后的实际开销，并记录目标端口与配置版本。

### 进阶方向

- 阅读 FreeRTOS 对应端口的临界区宏、BASEPRI/PRIMASK 操作和中断优先级校验。
- 深入研究 C11 原子内存序、编译器屏障与 ARM DMB/DSB/ISB 的适用边界。
- 学习固定优先级系统中的优先级反转分析与优先级继承协议。
- 研究多核 RTOS 自旋锁、缓存一致性和跨核中断。
- 学习 lock-free 数据结构的 ABA、对象回收与内存序问题。
