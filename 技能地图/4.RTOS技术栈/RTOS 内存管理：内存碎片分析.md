
## 1. 学习目标

### 理解

- 理解内部碎片、外部碎片、空闲容量和最大连续可分配块的区别。
- 理解分配尺寸、对象生命周期、申请释放顺序如何共同导致碎片。
- 理解堆统计、碎片率和分配失败分别能说明什么、不能说明什么。

### 掌握

- 掌握从分配器空闲链表、内存池和运行日志中计算碎片指标。
- 掌握在目标板上构造长期分配释放压力测试，观察碎片随时间的变化。
- 掌握根据分配尺寸分布和生命周期选择 `heap_4`、固定池或分级池。

### 精通

- 能够区分堆耗尽、外部碎片、内部浪费、内存泄漏和最大块不足等故障。
- 能够定位碎片产生模块、分配尺寸和持有时间，并推导造成失败的分配序列。
- 能够设计按生命周期分区、固定池、分级池和通用堆的组合内存架构。

### 能够设计

- 能建立产品级碎片监控指标、阈值、告警和长期稳定性测试。
- 能为动态内存制定容量上限、分配失败策略和碎片恢复策略。
- 能把碎片测试、堆水位和最大可分配块纳入持续集成及发布门禁。

## 2. 前置要求

### 知识要求

- 熟悉 RTOS 堆实现，如 FreeRTOS `heap_1`～`heap_5`。
- 熟悉内存块头、对齐、首次适配、空闲块合并和固定块池。
- 熟悉 C 指针生命周期、动态分配和释放。
- 理解任务并发、临界区以及动态对象创建销毁。

### 技能要求

- 能查看目标工程实际使用的 `heap_n.c` 和配置。
- 能通过 map 文件、调试器或分配器接口统计堆容量。
- 能在压力测试中记录分配尺寸、释放顺序、失败和延迟。
- 能根据目标分配器实现扩展或获取最大连续空闲块指标。

## 3. 技术概述

### 核心定义

内存碎片是可用内存因分割、对齐或分配粒度等原因，无法有效满足后续申请的现象。RTOS 堆中主要关注两类：

- **内部碎片**：已分配块的实际占用大于用户请求。
- **外部碎片**：空闲内存被分割成多个不连续块，虽然空闲总量足够，但最大连续块不足以满足申请。

### 内部碎片

假设请求 100 字节，分配器实际占用 128 字节：

```
内部浪费 = 128 - 100 = 28 字节
内部碎片率 = 28 / 128 ≈ 21.9%
```

来源包括：

- 块头部。
- 对齐填充。
- 最小分配粒度。
- 固定池的块尺寸大于对象实际尺寸。
- 对象尺寸被分级池向上取整。

### 外部碎片

假设空闲块分别为 256、128、64 字节：

```
总空闲量 = 448 字节
最大空闲块 = 256 字节
```

若申请 300 字节，申请会失败，尽管总空闲量大于 300 字节。这是外部碎片或最大块不足的典型表现。

### 碎片分析的工程价值

碎片分析用于回答：

- 系统是否有足够的总 RAM？
- 最大连续空闲块能满足哪些申请？
- 某类对象是否长期占用堆，阻挡相邻空闲块合并？
- 申请失败是容量不足、碎片、泄漏还是尺寸计算错误？
- 哪些对象应该迁移到静态区、固定池或专用内存区域？

碎片指标不能脱离分配器实现和真实 workload 单独解释。某个碎片率高不一定立即造成故障；某个碎片率低也不代表所有申请都能成功。

## 4. 核心特性横向对比

|内存状况|总空闲量|最大连续块|常见表现|主要排查方向|
|---|---|---|---|---|
|健康且有余量|高|高|申请成功|长期趋势和峰值需求|
|堆耗尽|低|低|大小申请都容易失败|总预算、泄漏、资源上限|
|外部碎片|中或高|低|大申请失败，小申请可能成功|分配释放序列、生命周期|
|内部碎片|表面可用量下降|不一定低|RAM 利用率低|对齐、块尺寸、池分级|
|内存泄漏|持续下降|通常持续下降|运行越久越容易失败|未释放对象、引用丢失|
|对象数上限耗尽|可能仍有空闲|可能仍大|池分配失败|固定对象数、归还路径|
|错误尺寸计算|指标可能异常|不一定|越界或损坏|整数溢出、单位错误|

## 5. 底层原理与功能特性深度解析

### 5.1 碎片如何形成

考虑连续堆：

```
初始：
+------------------------------------------------------+
|                    一个大空闲块                      |
+------------------------------------------------------+

分配 A、B、C：
+-------------+------------------+---------+-----------+
| A 使用中    | B 使用中         | C 使用中| 空闲      |
+-------------+------------------+---------+-----------+

释放 A 和 C：
+-------------+------------------+---------+-----------+
| A 空闲      | B 使用中         | C 空闲  | 空闲      |
+-------------+------------------+---------+-----------+
```

A 与 C 中间仍被 B 占用，无法合并。若此时申请一个大块，即使 A、C 和尾部空闲量之和足够，也可能失败。

碎片形成通常需要三个条件：

1. 分配对象尺寸不同或分配块被拆分。
2. 对象生命周期相互交错。
3. 释放后的空闲区域被仍存活对象隔开，或分配器无法有效合并。

### 5.2 `heap_4` 中的碎片与合并

FreeRTOS `heap_4` 通常维护按地址排序的空闲链表，并在释放时合并物理相邻空闲块。它能减少碎片，但无法合并被仍在使用对象隔开的空闲区。

```
可合并：
[A 空闲][B 空闲] -> [A+B 空闲]

不可合并：
[A 空闲][B 使用中][C 空闲]
```

此外，首次适配的分配顺序会影响空闲块的拆分位置。长期运行时的碎片表现取决于具体尺寸和生命周期，不应只根据“释放时合并”推断系统不会碎片化。

### 5.3 内部碎片的计算

对于通用堆，近似计算：

```
实际块尺寸 = align_up(用户请求 + 块头部, 对齐粒度)
内部浪费 = 实际块尺寸 - 用户请求
```

假设：

```
用户请求 R = 73 B
块头 H = 8 B
对齐粒度 A = 8 B

实际块尺寸 = align_up(73 + 8, 8)
           = 88 B
内部浪费 = 88 - 73
           = 15 B
```

示例参数仅用于说明算法。具体块头、标志位、对齐粒度和最小块尺寸必须从目标实现与构建结果取得。

对固定块池：

```
内部浪费 = 块数量 × (池块尺寸 - 实际使用尺寸)
```

例如 20 个 256 字节块，平均只使用 180 字节：

```
内部浪费 ≈ 20 × (256 - 180) = 1520 字节
```

固定池可能消除外部碎片，但并不意味着没有内存浪费。

### 5.4 外部碎片指标

常用的空闲空间碎片指标：

```
F_external = 1 - 最大空闲块 / 总空闲量
```

例如空闲块为 1024、512、256 字节：

```
总空闲量 = 1792 B
最大空闲块 = 1024 B
F_external = 1 - 1024 / 1792
           ≈ 42.9%
```

解释限制：

- 当总空闲量为零时，该公式无定义，应按项目规则处理。
- 不同分配器统计的空闲空间口径可能不同。
- 该指标无法直接预测某个具体尺寸的分配是否成功。
- 最大块大小通常比单一碎片率更直接。

**实际诊断应同时记录总空闲量、最大连续块和失败请求尺寸。**

### 5.5 为什么总空闲量不够

设堆中空闲块：

```
[128 B] [已分配] [128 B] [已分配] [128 B]
```

总空闲量为 384 字节，但最大连续块只有 128 字节。申请 200 字节会失败。

因此：

```
申请成功条件 ≠ 总空闲量 ≥ 请求尺寸
```

还需要满足：

```
某个可用连续块 ≥ 请求尺寸 + 块头和对齐开销
```

并且在多任务系统中，查询统计与实际申请之间可能发生竞争，所以不能用“查询后判断”代替检查分配返回值。

### 5.6 按生命周期分析

将对象按生命周期分类通常比只按大小分类更有效：

|生命周期类型|示例|常用策略|
|---|---|---|
|系统永久存在|任务控制对象、固定服务|静态分配|
|启动期创建，运行期不删|固定队列、模块对象|静态对象或 `heap_1`|
|短时、固定尺寸、高频|网络包、采样记录|固定块池|
|短时、少数尺寸等级|小、中、大消息|分级池|
|低频、尺寸变化、非实时|文件或配置临时对象|受控 `heap_4`|
|DMA/Cache 属性特殊|DMA 帧、描述符|专用区域分配器|

生命周期相似的对象集中管理，可降低长寿命对象把空闲区隔开的概率。

### 5.7 碎片、泄漏和堆耗尽的区分

|现象|总空闲量趋势|最大连续块趋势|分配失败特征|
|---|---|---|---|
|碎片|可能平稳或缓慢下降|明显下降|大申请先失败|
|泄漏|随时间持续下降|通常也下降|多种尺寸逐渐失败|
|堆容量不足|启动时就偏低|低|固定负载下稳定失败|
|内部浪费|实际分配数与请求数差距大|影响不一定明显|申请可成功但容量消耗偏大|
|对象池耗尽|堆可能仍有余量|与池无关|特定池申请失败|
|内存损坏|统计跳变、链表异常|结果不可信|失败模式随机|

### 5.8 源码级排查点

对 FreeRTOS `heap_4/5`，检查目标版本中的：

- 堆块头结构及分配标志位。
- 对齐宏与请求尺寸取整逻辑。
- 空闲块查找策略。
- 拆分条件和最小块限制。
- 释放后的地址排序插入与相邻合并。
- 临界区和统计接口。
- `heap_5` 区域初始化顺序及边界调整。

对 libc `malloc()`，还应检查具体 C 库的分配器、锁、堆区域和统计接口。不要把 FreeRTOS `heap_4` 的碎片行为直接套用于 `heap_3`。

### 5.9 获取最大连续空闲块

FreeRTOS 通用接口通常提供总空闲量和最小历史空闲量，但不一定提供最大连续空闲块。可选方案：

1. 使用目标分配器已有的 trace 或统计接口。
2. 在测试构建中遍历分配器空闲链表。
3. 为分配器增加只读诊断接口，并审查并发保护。
4. 用代表性尺寸申请测试，但这种方式会改变堆状态，不适合作为无扰动监控。

不要在生产代码中未经审查直接访问私有堆结构；结构布局可能随版本变化。

## 6. 性能量化分析

### 6.1 关键指标

建议每次采样或每个分配失败时记录：

```
heap_free_total       总空闲量
heap_free_min_ever    历史最低空闲量
heap_largest_free     最大连续空闲块
heap_frag_ratio       外部碎片参考指标
alloc_fail_count      分配失败次数
alloc_request_size    失败请求大小
alloc_latency_max     最大分配耗时
```

碎片参考指标：

```
F_external = 1 - heap_largest_free / heap_free_total
```

如果 `heap_free_total == 0`，应标记指标无效或采用专门定义，不要执行除法。

### 6.2 需求尺寸与可分配块

对申请尺寸 `R`，分配器所需块大小一般大于 `R`：

```
required_block =
    align_up(R + allocator_header, allocator_alignment)
```

申请是否可成功，取决于：

```
largest_free_block >= required_block
```

但实际实现还可能有最小拆分块、区域限制、保护区和 allocator-specific 元数据。应以目标算法计算。

### 6.3 压力测试参数

碎片测试至少应覆盖：

- 生产环境的分配尺寸分布。
- 最小、典型、最大申请尺寸。
- 长短生命周期对象混合。
- 随机与固定释放顺序。
- 多任务并发分配释放。
- 长时间运行和周期性峰值。
- 堆接近容量上限时的失败路径。
- 删除任务、重连、超时和取消等回收路径。

测试结果应给出平台和配置，例如：

```
MCU、主频、编译器版本、优化等级
FreeRTOS 版本及 heap 实现
堆容量与内存区域
负载模型和运行时长
请求尺寸分布与对象持有时间
总空闲量、最大块、碎片指标、失败次数
```

### 6.4 瓶颈分析与优化收益

|优化方法|主要作用|可量化结果|
|---|---|---|
|固定块池|消除外部碎片|最大块固定、分配失败受池容量约束|
|分级池|降低变尺寸堆压力|内部浪费与堆碎片的取舍|
|生命周期分区|减少长短对象交错|最大连续块退化速度|
|静态分配|从堆中移除长期对象|堆长期占用下降|
|限制最大申请尺寸|避免异常大申请|最大块需求有界|
|申请前预留/复用|减少反复分配|分配次数、延迟和碎片趋势下降|
|受控堆分区|隔离模块影响|故障范围和模块水位可观测|

优化收益要用相同 workload 对比；不能只看某次测试结束时剩余堆大小。

## 7. 应用场景选型指南

### 纯文本决策流程图

```
分配对象的数量和尺寸是否固定？
├─ 是
│  ├─ 生命周期长且固定 -> 静态分配
│  └─ 运行期需要借还 -> 固定块池
└─ 否
   ├─ 尺寸能否归入少量等级？
   │  ├─ 是 -> 分级池
   │  └─ 否
   │     ├─ 是否处于硬实时路径？
   │     │  ├─ 是 -> 重新设计为预分配/池，避免通用堆
   │     │  └─ 否 -> 受控通用堆并监控最大连续块
   │     └─ 是否有多个 RAM 属性区域？
   │        ├─ 是 -> 区域专用分配器或分区管理
   │        └─ 否 -> 单堆方案
   └─ 是否出现大申请失败但总空闲量仍高？
      ├─ 是 -> 检查外部碎片、最大块及申请序列
      └─ 否 -> 排查容量不足、泄漏、尺寸溢出和池耗尽
```

### 典型场景

|场景|推荐方案|选择理由|
|---|---|---|
|固定数量任务和队列|静态对象|不占用运行期通用堆|
|高速网络报文|固定尺寸包池|尺寸上限明确，避免变尺寸碎片|
|多种常见消息大小|分级池|以可控内部浪费换取更稳定的外部碎片表现|
|文件系统临时对象|受控通用堆|尺寸变化较多，通常不在硬实时路径|
|运行期连接对象|固定连接池加少量辅助堆|对象数量可限，避免无限增长|
|大图像或帧缓冲|静态/专用区域分配|连续块需求大且内存属性特殊|

## 8. 工程最佳实践

### 设计原则

- 将静态对象、固定池对象和通用堆对象分开统计。
- 以真实申请尺寸、生命周期和持有时间作为设计输入。
- 对高频短生命周期数据优先使用固定池或分级池。
- 对大块连续申请设置预算和最大块监控。
- 监控总空闲量、最大连续块和失败请求尺寸，不能只监控一个水位值。
- 按模块或内存区域隔离高风险分配，降低互相影响。
- 失败处理必须在分配前设计，不能只在失败后临时补救。
- 定期检查释放路径，尤其是超时、取消、错误回滚和连接断开。

### 选型决策矩阵

|特征|静态分配|固定块池|分级池|`heap_4`/通用堆|
|---|---|---|---|---|
|容量可预测|高|高|高|中|
|运行期借还|低|高|高|高|
|外部碎片风险|无|无|低或无|有|
|内部浪费风险|固定预留|中到高|中|低到中|
|适合变尺寸对象|低|低|中|高|
|实时性可分析性|高|高|高|中低|
|适合高频短对象|一般|高|高|谨慎|

### 工业级编码规范

- 统一封装动态分配接口，记录模块 ID、请求大小和失败原因。
- 分配尺寸采用 `size_t`，并进行乘法、加法和对齐溢出检查。
- 使用明确配对的分配/释放接口，不交叉释放。
- 在对象状态机中定义谁拥有内存、谁释放、异常路径如何回滚。
- 对长期对象优先静态分配，避免它们长期占用通用堆。
- 生产诊断中记录最大块和失败请求，而不是只记录 `malloc failed`。
- 对内存池检测非法索引、重复归还和跨池释放。
- 为所有碎片指标注明采集口径、算法版本和采样时机。

## 9. 常见错误与避坑指南

### 错误一：用总空闲量判断大块申请一定成功

```
if (xPortGetFreeHeapSize() >= request_size) {
    ptr = pvPortMalloc(request_size);
}
```

**根因：** 总空闲量是多个块的合计，不代表存在足够大的连续空闲块；查询到申请之间也可能有并发变化。

**正确实现：** 直接检查 `pvPortMalloc()` 返回值；诊断时同时记录失败尺寸、总空闲量和最大连续块。

**风险影响：** 错误地判断内存充足，申请仍失败，且故障原因被误判为偶发。

### 错误二：把所有对象都交给同一个通用堆

```
/* 网络包、任务对象、DMA 缓冲和日志缓存都使用 pvPortMalloc。 */
```

**根因：** 不同对象尺寸、生命周期和内存属性混杂，容易形成碎片，也会让普通模块耗尽关键资源。

**正确实现：** 任务和长期对象静态化；网络包使用固定池；DMA 使用专用区域；仅非关键、变尺寸对象使用通用堆。

**风险影响：** 低优先级功能可能耗尽关键任务或通信路径所需的连续空间。

### 错误三：以“释放了对象”推断碎片会自动恢复

```
vPortFree(ptr);
/* 假设总空闲空间会变成一个大块。 */
```

**根因：** 释放只把对应块归还给分配器；只有地址相邻且都空闲的块才可能合并。

**正确实现：** 按生命周期组织对象，监控最大空闲块，并通过目标 workload 长时间验证碎片变化。

**风险影响：** 释放统计看似正常，但大块申请仍持续失败。

### 错误四：只做短时间平均负载测试

```
启动 -> 运行正常流程 5 分钟 -> 测试通过
```

**根因：** 碎片通常依赖长时间的申请释放顺序和对象持有时间，短测可能没有覆盖长期退化。

**正确实现：** 执行长时间随机和真实负载测试，覆盖重连、取消、超时、异常回滚及峰值申请，并记录指标趋势。

**风险影响：** 系统经过数小时或数天运行后才出现难以复现的分配失败。

### 错误五：将高碎片率直接当成故障结论

```
if (fragmentation_ratio > 0.4f) {
    system_reset();
}
```

**根因：** 碎片率只是一个摘要指标，未关联真实申请尺寸、最大块需求和业务风险。

**正确实现：** 根据具体申请分布设置策略：跟踪最大块、失败尺寸、总空闲量和应用的最大连续需求；告警阈值通过测试和风险分析制定。

**风险影响：** 可能频繁误报或复位，也可能漏掉“碎片率不高但关键大申请无法满足”的情况。

## 10. 多机制组合使用方案

### 10.1 分层内存架构

```
关键任务、控制对象
  -> 静态分配

固定尺寸消息、网络包、采样记录
  -> 固定块池 / 分级池

低频、变尺寸、非实时对象
  -> 受控通用堆

DMA、Cache 敏感、外部 RAM 对象
  -> 区域专用分配器

监控层
  -> 总空闲量
  -> 最大连续块
  -> 分配失败尺寸
  -> 模块持有量
  -> 生命周期和峰值占用
```

### 10.2 碎片采样结构

```
typedef struct {
    size_t free_total;
    size_t largest_free_block;
    size_t min_free_ever;
    uint32_t allocation_failures;
    size_t largest_failed_request;
} HeapHealth_t;

static HeapHealth_t s_heap_health;

static void heap_health_update(
    size_t free_total,
    size_t largest_free)
{
    s_heap_health.free_total = free_total;
    s_heap_health.largest_free_block = largest_free;

    if (free_total < s_heap_health.min_free_ever) {
        s_heap_health.min_free_ever = free_total;
    }
}

static bool heap_health_fragment_ratio(
    size_t free_total,
    size_t largest_free,
    uint32_t *ratio_permille)
{
    if ((ratio_permille == NULL) || (free_total == 0U)) {
        return false;
    }

    if (largest_free > free_total) {
        return false;
    }

    *ratio_permille =
        (uint32_t)(((free_total - largest_free) * 1000U) /
                   free_total);

    return true;
}
```

`largest_free_block` 需要通过分配器支持、测试构建扩展或专用诊断实现获得。上述乘法也应根据目标 `size_t` 宽度和最大堆容量验证是否溢出。

## 11. 工业级实际案例分析

### 案例一：网络包堆碎片

**需求：** 设备长期运行，网络连接会反复建立和断开，报文尺寸变化且存在突发流量。

**架构设计：**

- 包数据使用固定尺寸块池，必要时使用小、中、大三级池。
- 连接控制块使用固定数量对象池。
- 非关键协议辅助对象使用受控通用堆。
- ISR 只提交 DMA 缓冲区索引，任务负责协议解析和资源归还。

**设计要点：**

- 池块大小按最大报文、协议头和对齐要求确定。
- 队列容量按最大流量和消费者最坏服务时间核算。
- 记录池峰值占用、耗尽次数和块平均持有时间。
- 连续运行覆盖重连、超时、半关闭和错误恢复路径。

### 案例二：数据记录与存储延迟

**需求：** 采集任务持续生成记录，存储设备偶发长延迟，不能因临时缓存增长耗尽系统堆。

**架构设计：**

- 采集记录使用固定池和有界队列。
- 文件系统缓存使用独立的受控堆区域。
- 队列满时按业务要求丢弃、覆盖或触发背压。
- 记录池与文件系统对象分开统计。

**设计要点：**

- 依据最大存储延迟估算缓存记录数。
- 统计每条记录的持有时长，发现消费者长期滞后。
- 不通过无限增加堆容量掩盖处理能力不足。
- 对存储故障和重试路径做长时间测试。

### 案例三：HMI 图形缓存

**需求：** 图像块尺寸变化大，需要连续大块内存；系统还需保留片上 RAM 给控制任务和 RTOS。

**架构设计：**

- 控制数据与任务栈静态放片上 SRAM。
- 图像缓存使用独立 SDRAM 区域或专用内存池。
- 将缓存按固定页面/图块管理，避免长时间变尺寸申请。
- 设置缓存逐出策略和分配失败降级。

**设计要点：**

- 外部 RAM 延迟、DMA 能力和 Cache 属性单独验证。
- 记录最大连续块和图像缓存峰值。
- 大块申请失败时回退到低分辨率、分块显示或重新加载，而不是盲目重试。
- 与通用系统堆隔离，避免图形缓存影响控制任务创建和运行。

## 12. 高频问题深度答疑

### 1. 空闲总量下降一定表示碎片吗？

不一定。总空闲量持续下降可能是泄漏、对象仍被合法持有、缓存增长或固定池峰值增加。碎片通常要结合最大连续块的下降、申请失败尺寸和分配释放记录判断。

### 2. 最大空闲块一定能从 FreeRTOS API 直接得到吗？

不一定。常见的 FreeRTOS 堆统计接口提供总空闲量和最小历史空闲量，但未必暴露最大块。需要查目标实现，或通过受审查的诊断扩展获取。不能通过随意试分配来无扰动地推断最大块。

### 3. `heap_4` 的相邻合并为什么仍会有外部碎片？

因为仍被占用的块会隔开空闲区域。合并只能处理连续地址上的空闲块，无法跨越活跃对象。对象生命周期交错是造成长期碎片的重要因素。

### 4. 固定池是否彻底解决了内存碎片？

固定池通常消除池内部的外部碎片，但会产生内部浪费：请求对象可能明显小于块尺寸。多个尺寸等级可降低浪费，但要承担多个池的容量规划和耗尽处理。

### 5. 碎片率达到多少必须处理？

没有适用于所有系统的统一阈值。要结合最大连续块、关键申请尺寸、总空闲量、峰值并发和系统降级能力。若关键申请接近最大空闲块，哪怕碎片率较低也可能有风险。

### 6. 如何区分碎片和内存泄漏？

记录分配与释放数量、模块归属、请求尺寸和对象持有时间。泄漏通常表现为长期占用量持续增长；碎片则可能总空闲量变化不大，但最大连续块持续下降。两者也可能同时发生。

## 13. 课程核心总结

- 碎片分析至少要区分**内部碎片、外部碎片、泄漏和容量不足**。
- 总空闲量不能代表最大可分配对象尺寸。
- 外部碎片常用指标为 `1 - 最大空闲块 / 总空闲量`，但应与具体申请尺寸一起解释。
- `heap_4` 的合并只能处理物理相邻的空闲块，不能消除所有碎片。
- 碎片主要受分配尺寸、对象生命周期、分配释放顺序和分配器策略影响。
- 长期稳定性必须通过真实尺寸分布和长时间 workload 验证。
- 常见工程策略是：长期对象静态化，高频短生命周期对象使用固定池，低频变尺寸对象使用受控通用堆。
- 诊断时应记录失败尺寸、总空闲量、最大连续块、模块归属和持有时间。

## 14. 快速参考速查表

### 场景选型表

|观察结果|可能原因|下一步|
|---|---|---|
|总空闲低，最大块也低|堆容量不足或泄漏|查预算、持有对象和释放路径|
|总空闲中高，最大块低|外部碎片|查分配序列、生命周期和大对象申请|
|申请成功但耗用远超请求|内部碎片或块头开销|查对齐、尺寸等级和分配器元数据|
|特定池申请失败，通用堆有余量|池耗尽或未归还|查池峰值、所有权和错误回滚|
|指标突变或链表异常|越界写或重复释放|查哨兵、堆保护和并发错误|
|长时间运行后才失败|碎片或泄漏|长测并记录分配/释放轨迹|

### 指标速查

|指标|计算/含义|用途|
|---|---|---|
|总空闲量|所有空闲块总和|判断总体容量|
|最大连续块|最大单块空闲容量|判断大申请可行性|
|外部碎片率|`1 - 最大块/总空闲量`|观察空闲块分散程度|
|内部浪费|实际块大小减用户请求|判断分配粒度效率|
|最小历史空闲量|历史最低总空闲量|容量压力基线|
|持有时间|分配到释放的时间|识别长期占用对象|

## 16. 实践与进阶路径

### 梯度实战任务

1. 在目标堆实现中获取总空闲量，确认统计口径。
2. 为测试构建增加最大连续空闲块统计，并验证并发保护。
3. 写一个分配释放压力测试，按不同尺寸和生命周期混合对象。
4. 每隔固定时间记录总空闲量、最大块、碎片指标和失败请求。
5. 对比 `heap_4`、固定池和分级池在同一 workload 下的 RAM 利用率及失败情况。
6. 加入超时、取消、异常回滚和重连路径，检查是否有泄漏或未归还块。
7. 将长期碎片测试和最大块阈值纳入 CI 或发布测试。

### 性能测试方法

- 使用真实产品分配尺寸分布，而不只用均匀随机尺寸。
- 分别构造短寿命、长寿命和交错生命周期对象。
- 运行到稳定期和峰值期，比较最大块与总空闲量趋势。
- 记录平均、P99、最大分配耗时和失败率。
- 使用故障注入验证碎片导致失败时的降级路径。
- 在发布优化构建和实际内存区域上测试，并保存工具链与 RTOS 版本信息。

### 进阶学习方向

- FreeRTOS `heap_4/5` 空闲链表与相邻块合并源码分析。
- TLSF、buddy allocator、slab 和分级池的碎片特性对比。
- 多区域堆、DMA 区域和缓存属性隔离。
- 通过分配 trace 重建对象生命周期和碎片演化。
- 内存泄漏检测、堆哨兵、重复释放检测与故障注入。
- 建立跨版本 RAM 与最大连续块回归门禁。
