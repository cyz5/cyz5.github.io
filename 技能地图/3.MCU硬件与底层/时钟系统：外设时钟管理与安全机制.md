## 3. 技术概述

### 3.1 核心定义

MCU 时钟系统负责为 CPU、存储器、总线和外设提供时间基准。典型时钟路径为：

```
时钟源
  |
  +-- HSI/IRC：内部 RC
  +-- HSE/OSC：外部晶体或有源时钟
  +-- LSI：低速内部 RC
  +-- LSE：32.768 kHz 晶体
  |
  v
PLL / FLL / DPLL
  |
  v
系统时钟复用器
  |
  +-- CPU/内核时钟
  +-- AHB/AXI/存储器时钟
  +-- APB/IP 总线时钟
  +-- 外设独立功能时钟
  +-- 安全监控参考时钟
```

必须区分三个概念：

- **总线时钟**：使 CPU 能访问外设寄存器。
- **功能时钟**：驱动外设状态机，例如 UART 波特率发生器、ADC 转换核。
- **内核时钟**：驱动 CPU、DMA 或外设内部计算单元。

关闭总线门控后寄存器通常不可访问；关闭功能时钟则可能让外设停止工作。二者在不同 MCU 上可能共用，也可能独立。

### 3.2 技术价值

时钟系统同时决定：

- **性能上限**：CPU、内存和总线吞吐量。
- **实时性**：任务执行时间、定时器分辨率和中断响应。
- **通信可靠性**：UART、CAN、USB、Ethernet 的采样误差。
- **模拟性能**：ADC 采样率、转换精度、时钟馈通噪声。
- **功耗**：动态功耗近似与 `C × V² × f` 成正比。
- **功能安全**：主时钟失效后系统能否检测并进入受控状态。

### 3.3 主流技术分支

1. **固定时钟树**：启动时配置，运行期不调整。
2. **动态频率调整 DFS**：按负载切换分频器或 PLL。
3. **动态电压频率调整 DVFS**：同时调整电压与频率。
4. **外设按需门控**：不用时关闭总线或功能时钟。
5. **独立外设时钟**：USB、ADC、RNG 等不依赖系统主频。
6. **时钟安全监控**：失效检测、自动旁路、频率窗口监测。
7. **多时钟域架构**：高性能域、低功耗域、安全域相互隔离。

## 5. 底层原理与功能特性深度解析

以下代码以 **STM32H743、Cortex-M7、HSE=25 MHz、SYSCLK=400 MHz** 为参考。寄存器位名称应以具体芯片 CMSIS 头文件为准。

### 5.1 时钟源启动与就绪握手

振荡器使能位只表示软件提出启动请求，必须等待硬件就绪标志。所有等待都必须有超时。

```
#include <stdint.h>
#include <stdbool.h>
#include "stm32h7xx.h"

typedef enum {
    CLOCK_OK = 0,
    CLOCK_ERR_TIMEOUT,
    CLOCK_ERR_INVALID,
    CLOCK_ERR_HW_FAULT
} clock_status_t;

static uint32_t cycles_from_us(uint32_t cpu_hz, uint32_t us)
{
    uint64_t cycles = ((uint64_t)cpu_hz * us + 999999ULL) / 1000000ULL;
    return (cycles > UINT32_MAX) ? UINT32_MAX : (uint32_t)cycles;
}

static clock_status_t wait_mask(volatile uint32_t *reg,
                                uint32_t mask,
                                bool expected_set,
                                uint32_t timeout_cycles)
{
    while (timeout_cycles-- != 0U) {
        bool is_set = ((*reg & mask) != 0U);
        if (is_set == expected_set) {
            return CLOCK_OK;
        }
        __NOP();
    }
    return CLOCK_ERR_TIMEOUT;
}

static clock_status_t hse_start(uint32_t timeout_us)
{
    RCC->CR |= RCC_CR_HSEON;

    return wait_mask(&RCC->CR,
                     RCC_CR_HSERDY,
                     true,
                     cycles_from_us(SystemCoreClock, timeout_us));
}
```

生产实现不能无限执行：

```
while ((RCC->CR & RCC_CR_HSERDY) == 0U) {
    /* 错误：晶体损坏时永久卡死，可能导致看门狗复位循环。 */
}
```

更可靠的超时基准应来自**不依赖待配置时钟的独立定时器**，例如 LPTIM、RTC 或 DWT 在已知初始时钟下的计数。简单循环只能作为早期启动阶段的有界保护，不能作为精确定时。

### 5.2 PLL 参数与约束

STM32H7 类 PLL 的典型关系为：

fVCO_in=fsrcMfVCO_in​=Mfsrc​​fVCO=fVCO_in×NfVCO​=fVCO_in​×NfPLL_P=fVCOPfPLL_P​=PfVCO​​

以 `HSE=25 MHz`、`M=5`、`N=160`、`P=2` 为例：

- `fVCO_in = 25 / 5 = 5 MHz`
- `fVCO = 5 × 160 = 800 MHz`
- `fPLL_P = 800 / 2 = 400 MHz`

每个参数必须同时满足数据手册规定的：

- PLL 输入范围；
- VCO 范围；
- 输出最大频率；
- 电压档位最大频率；
- 温度范围降额约束。

```
typedef struct {
    uint32_t source_hz;
    uint16_t m;
    uint16_t n;
    uint16_t p;
} pll_config_t;

static bool pll_validate(const pll_config_t *cfg, uint32_t *output_hz)
{
    if ((cfg == NULL) || (output_hz == NULL) ||
        (cfg->m == 0U) || (cfg->p == 0U)) {
        return false;
    }

    uint64_t vco_in = cfg->source_hz / cfg->m;
    uint64_t vco = vco_in * cfg->n;
    uint64_t out = vco / cfg->p;

    /* 数值仅对应示例器件配置范围，量产代码应从器件约束表生成。 */
    if ((vco_in < 2000000ULL) || (vco_in > 16000000ULL) ||
        (vco < 192000000ULL) || (vco > 836000000ULL) ||
        (out > 400000000ULL)) {
        return false;
    }

    *output_hz = (uint32_t)out;
    return true;
}
```

### 5.3 升频和降频的安全顺序

升频前必须先提升供电能力并增加 Flash Wait State：

```
升频：
提升电压档位
  -> 等待电压稳定
  -> 增加 Flash Wait State
  -> 配置并锁定 PLL
  -> 设置保守的总线分频
  -> 切换 SYSCLK
  -> 更新软件频率状态

降频：
切换或降低 SYSCLK
  -> 调整总线分频
  -> 减少 Flash Wait State
  -> 降低电压档位
```

顺序错误可能导致 CPU 在切换后的第一条 Flash 取指即失效。

```
static clock_status_t switch_sysclk_to_pll(uint32_t timeout_cycles)
{
    /* 调用前必须完成电压、Flash 延迟和 PLL 锁定检查。 */
    if ((RCC->CR & RCC_CR_PLL1RDY) == 0U) {
        return CLOCK_ERR_HW_FAULT;
    }

    uint32_t cfgr = RCC->CFGR;
    cfgr &= ~RCC_CFGR_SW;
    cfgr |= RCC_CFGR_SW_PLL1;
    RCC->CFGR = cfgr;

    __DSB();
    __ISB();

    return wait_mask(&RCC->CFGR,
                     RCC_CFGR_SWS_PLL1,
                     true,
                     timeout_cycles);
}
```

实际器件的状态字段通常是多位枚举值，不宜用通用“非零”判断。推荐专用等待函数：

```
static clock_status_t wait_field(volatile uint32_t *reg,
                                 uint32_t mask,
                                 uint32_t expected,
                                 uint32_t timeout)
{
    while (timeout-- != 0U) {
        if ((*reg & mask) == expected) {
            return CLOCK_OK;
        }
    }
    return CLOCK_ERR_TIMEOUT;
}
```

### 5.4 总线分频与定时器倍频

常见 STM32 定时器规则：

fTIM={fPCLK,APB prescaler=12fPCLK,APB prescaler>1fTIM​={fPCLK​,2fPCLK​,​APB prescaler=1APB prescaler>1​

某些系列还受 `TIMPRE` 控制，不能只根据 `PCLK` 推导。

定时器更新频率：

fupdate=fTIM(PSC+1)(ARR+1)fupdate​=(PSC+1)(ARR+1)fTIM​​

例如 `fTIM=200 MHz`、`PSC=199`、`ARR=999`：

fupdate=200 MHz/(200×1000)=1 kHzfupdate​=200MHz/(200×1000)=1kHz

必须由统一时钟服务计算外设频率，禁止驱动自行假设。

```
uint32_t timer_update_hz(uint32_t timer_hz,
                         uint32_t prescaler,
                         uint32_t auto_reload)
{
    uint64_t divisor = ((uint64_t)prescaler + 1ULL) *
                       ((uint64_t)auto_reload + 1ULL);

    if (divisor == 0ULL) {
        return 0U;
    }
    return (uint32_t)((uint64_t)timer_hz / divisor);
}
```

### 5.5 外设时钟门控与复位

正确顺序一般为：

```
启用：
打开总线时钟 -> 读回/屏障 -> 脉冲复位 -> 配置外设 -> 启动功能

关闭：
停止新事务 -> 等待 BUSY 清除 -> 关闭 DMA/中断
-> 保存上下文（如需要）-> 禁止外设 -> 关闭门控
```

```
static void uart4_clock_enable(void)
{
    RCC->APB1LENR |= RCC_APB1LENR_UART4EN;

    /* 保证门控写入在后续外设访问前生效。 */
    (void)RCC->APB1LENR;
    __DSB();

    RCC->APB1LRSTR |= RCC_APB1LRSTR_UART4RST;
    __DSB();
    RCC->APB1LRSTR &= ~RCC_APB1LRSTR_UART4RST;
    __DSB();
}
```

复位脉冲宽度和是否允许连续写入应以参考手册为准。部分器件要求至少跨越若干外设时钟周期。

### 5.6 引用计数式门控

同一硬件资源可能被多个逻辑客户端共享，必须防止一个客户端提前关闭时钟。

```
typedef enum {
    CLK_PERIPH_UART4 = 0,
    CLK_PERIPH_SPI2,
    CLK_PERIPH_COUNT
} peripheral_clock_id_t;

typedef struct {
    volatile uint16_t refs;
} peripheral_clock_state_t;

static peripheral_clock_state_t g_clk_state[CLK_PERIPH_COUNT];

static void hw_clock_set(peripheral_clock_id_t id, bool enabled)
{
    switch (id) {
    case CLK_PERIPH_UART4:
        if (enabled) {
            RCC->APB1LENR |= RCC_APB1LENR_UART4EN;
            (void)RCC->APB1LENR;
        } else {
            RCC->APB1LENR &= ~RCC_APB1LENR_UART4EN;
        }
        break;

    case CLK_PERIPH_SPI2:
        if (enabled) {
            RCC->APB1LENR |= RCC_APB1LENR_SPI2EN;
            (void)RCC->APB1LENR;
        } else {
            RCC->APB1LENR &= ~RCC_APB1LENR_SPI2EN;
        }
        break;

    default:
        break;
    }
    __DSB();
}

clock_status_t peripheral_clock_acquire(peripheral_clock_id_t id)
{
    if (id >= CLK_PERIPH_COUNT) {
        return CLOCK_ERR_INVALID;
    }

    uint32_t primask = __get_PRIMASK();
    __disable_irq();

    uint16_t refs = g_clk_state[id].refs;
    if (refs == UINT16_MAX) {
        __set_PRIMASK(primask);
        return CLOCK_ERR_HW_FAULT;
    }

    if (refs == 0U) {
        hw_clock_set(id, true);
    }
    g_clk_state[id].refs = (uint16_t)(refs + 1U);

    __set_PRIMASK(primask);
    return CLOCK_OK;
}

clock_status_t peripheral_clock_release(peripheral_clock_id_t id)
{
    if (id >= CLK_PERIPH_COUNT) {
        return CLOCK_ERR_INVALID;
    }

    uint32_t primask = __get_PRIMASK();
    __disable_irq();

    uint16_t refs = g_clk_state[id].refs;
    if (refs == 0U) {
        __set_PRIMASK(primask);
        return CLOCK_ERR_INVALID;
    }

    refs--;
    g_clk_state[id].refs = refs;
    if (refs == 0U) {
        hw_clock_set(id, false);
    }

    __set_PRIMASK(primask);
    return CLOCK_OK;
}
```

在 SMP 或多核 MCU 上，禁止中断不能实现跨核互斥，必须改用硬件信号量、原子操作或跨核资源管理器。

### 5.7 无毛刺切换与时钟域交叉

软件写入时钟复用器并不天然保证无毛刺。安全切换依赖硬件实现：

- 两个时钟先经过门控；
- 等待当前时钟低电平；
- 关闭旧路径；
- 打开新路径；
- 同步状态返回软件。

跨时钟域信号需要：

- 单比特控制：双触发器同步；
- 脉冲：脉冲展宽或握手；
- 多比特状态：Gray Code；
- 数据流：异步 FIFO；
- 复位：异步置位、同步释放。

软件可通过等待 `SWS`、`LOCK`、`READY` 等状态避免在过渡态继续配置，但无法修复硬件未提供的无毛刺能力。

### 5.8 时钟安全系统

时钟安全系统通常用低速独立时钟监控高频外部时钟。失效后硬件可能：

1. 设置故障标志；
2. 触发 NMI/安全中断；
3. 自动切换到 HSI；
4. 关闭 PLL 或依赖时钟；
5. 要求软件进入降级状态。

```
typedef struct {
    volatile bool hse_failed;
    volatile uint32_t css_events;
} clock_fault_state_t;

static clock_fault_state_t g_clock_fault;

void NMI_Handler(void)
{
    if ((RCC->CIFR & RCC_CIFR_HSECSSF) != 0U) {
        RCC->CICR = RCC_CICR_HSECSSC;  /* 写 1 清除，依器件定义 */
        g_clock_fault.hse_failed = true;
        g_clock_fault.css_events++;

        /*
         * NMI 中只执行有界操作：
         * 1. 确认安全时钟已接管；
         * 2. 关闭依赖精确时钟的危险输出；
         * 3. 记录最小故障信息；
         * 4. 通知后台安全管理任务。
         */
        TIM1->BDTR &= ~TIM_BDTR_MOE;    /* 立即关闭电机 PWM 主输出 */
        __DSB();
    }
}
```

NMI 中不能执行日志格式化、阻塞锁、动态分配或等待外设发送完成。

## 6. 性能量化分析

### 6.1 测试平台与边界

以下为工程估算和典型实测区间：

- MCU：STM32H743，Cortex-M7。
- HSE：25 MHz 晶体。
- SYSCLK：400 MHz。

|操作|典型值|最坏设计预算|
|---|---|---|
|HSI 启动|2~10 µs|50 µs|
|HSE 晶体启动|0.5~3 ms|10~20 ms|
|PLL 锁定|50~300 µs|1~2 ms|
|门控寄存器启用|3~20 CPU 周期|加外设同步延迟|
|外设复位脉冲|2~20 总线周期|按手册约束|
|分频器切换|2~20 时钟周期|等待状态确认|
|STOP 恢复至 HSI|5~50 µs|依电源模式|
|STOP 恢复至 PLL|100 µs~2 ms|加 HSE 启动时间|

启动总时间可估算为：

Tboot−clock=Tosc+Tpll−lock+Tswitch+TstabilizeTboot−clock​=Tosc​+Tpll−lock​+Tswitch​+Tstabilize​

Tboot−clock≈max⁡(Tosc,Tvoltage)+Tpll−lock+TswitchTboot−clock​≈max(Tosc​,Tvoltage​)+Tpll−lock​+Tswitch​

### 6.3 门控代码开销

在 400 MHz Cortex-M7 上，短临界区引用计数操作典型约 `20~80 cycles`：

T=cyclesfCPUT=fCPU​cycles​

按 60 cycles 计算：

T=60/400 MHz=150 nsT=60/400MHz=150ns

如果门控操作触发跨时钟域同步，硬件生效时间可能高于软件执行时间。

### 6.4 内存开销

引用计数管理器对每个外设的静态开销近似为：

M=N×(Scounter+Sstate+Salignment)M=N×(Scounter​+Sstate​+Salignment​)

管理 128 个外设，每项 4 字节：

M=128×4=512 bytesM=128×4=512bytes

增加诊断计数、所有者位图和锁后，常见开销为 `1~4 KB`，相对于高端 MCU 可接受，但在小型 MCU 上应按端口分组或使用位图。

### 6.5 动态功耗收益

CMOS 动态功耗近似为：

Pdynamic=αCV2fPdynamic​=αCV2f

其中：

- `α`：节点翻转活动因子；
- `C`：等效开关电容；
- `V`：供电电压；
- `f`：时钟频率。

若频率从 400 MHz 降至 200 MHz，电压不变且活动因子相同，动态功耗理论下降约 **50%** 。若电压从 1.2 V 降至 1.0 V：

P2P1=200400×(1.01.2)2≈34.7%P1​P2​​=400200​×(1.21.0​)2≈34.7%

理论动态功耗下降约 **65.3%** 。实际整机还包含漏电、模拟、I/O、稳压器损耗，因此总体收益较低。

### 6.6 通信误差

UART 波特率误差：

Errorbaud=Baudactual−BaudtargetBaudtarget×100%Errorbaud​=Baudtarget​Baudactual​−Baudtarget​​×100%

异步 UART 链路需同时考虑发送端与接收端误差。工程上常控制单端误差在 **±1%** 左右；可容忍上限取决于数据位数、过采样和采样点。

CAN 位时序：

fbit=fCANPrescaler×(1+TSEG1+TSEG2)fbit​=Prescaler×(1+TSEG1+TSEG2)fCAN​​

除了名义频率误差，还需验证采样点、SJW、振荡器容差和总线传播延迟。

USB Full Speed 要求精确的 48 MHz 时钟，通常不能将普通未校准 RC 直接作为可靠来源，除非器件支持基于 SOF 的自动校准。

### 6.7 主要瓶颈与优化收益

|瓶颈|表现|优化方法|典型收益|
|---|---|---|---|
|HSE 启动慢|冷启动延迟高|先用 HSI 启动，后台切 HSE|提前 0.5~10 ms 执行业务|
|PLL 重锁|变频卡顿|固定 PLL，仅切分频器|从百 µs 降至亚 µs~数 µs|
|高频外设常开|空闲功耗高|引用计数门控|外设域功耗下降 10%~90%|
|Flash Wait State 高|IPC 下降|I-Cache/ITCM/合理主频|热点代码提速 10%~数倍|
|电压长期高档|DVFS 收益不足|频率与电压联动|动态功耗显著下降|
|频繁门控|延迟和寄存器竞争|空闲迟滞策略|降低抖动与启停开销|

### 7.1 决策流程图

系统是否要求精确通信或计量？
├─ 否
│  ├─ 是否强调快速启动/低成本？

│  │  └─ 否：晶体作为主时钟，提高长期稳定性

   ├─ 是否属于安全关键系统？
   │  ├─ 是：独立时钟源 + 时钟监控 + 自动降级

## 8. 工程最佳实践

### 8.1 设计原则

1. **单一所有者**：只有时钟管理模块可修改全局时钟树。
2. **声明式配置**：配置由频率需求和约束生成，不在驱动中散布魔数。
3. **先约束后配置**：先校验电压、Flash、VCO、总线和外设上限。
4. **所有等待有超时**：包括 OSC Ready、PLL Lock、时钟切换和电压稳定。
5. **先建立退路**：关闭当前主时钟前必须确认备用时钟可用。
6. **频率变化可通知**：依赖时钟的 UART、SPI、定时器和 RTOS Tick 必须重算。
7. **安全输出硬件化**：PWM、门极驱动等不能只依赖 NMI 软件关闭。
8. **诊断持久化**：记录故障源、切换结果、复位原因和发生次数。
9. **时钟配置可回读**：软件模型与寄存器实际状态必须一致。
10. **静态策略优先**：安全关键路径避免无必要的运行时 PLL 重配置。

### 8.2 选型决策矩阵

评分：1 表示差，5 表示优。

|方案|精度|启动速度|功耗|成本|安全诊断|综合适用性|
|---|---|---|---|---|---|---|
|单内部 RC|2|5|5|5|2|非关键低成本|
|单外部晶体|5|2|3|3|2|精确通信|
|HSE+HSI 备份|5|4|3|3|4|工业控制|
|双外部时钟|5|3|2|1|5|高安全等级|
|RC+外部参考校准|4|5|4|4|3|USB/低功耗设备|
|独立外设 PLL|5|3|2|3|4|多速率复杂系统|

### 8.3 工业级编码规范

- 不允许在业务模块直接操作 RCC/CCU 寄存器。
- 每个时钟 API 必须返回明确错误码。
- 不允许无限等待 `READY/LOCK/BUSY`。
- 频率计算使用 `uint64_t` 中间值，防止溢出。
- 寄存器字段使用掩码更新，不覆盖保留位。
- 门控后使用数据手册要求的读回或屏障。
- 引用计数必须检查上溢和下溢。
- ISR/NMI 中禁止阻塞式重配时钟树。
- 运行时切频必须通过 prepare/commit/rollback 协议。
- 初始化结束后锁定安全关键时钟寄存器，若芯片支持写保护。
- 对时钟配置做静态断言和启动回读验证。
- 禁止仅修改 `SystemCoreClock` 而不修改真实硬件，反之亦然。

## 9. 常见错误与避坑指南

### 9.1 错误一：切换高频后才增加 Flash 延迟

#### 错误代码

```
RCC->CFGR = (RCC->CFGR & ~RCC_CFGR_SW) | RCC_CFGR_SW_PLL1;
FLASH->ACR = FLASH_ACR_LATENCY_4WS;
```

#### 根因分析

CPU 切换到高频后立即从 Flash 取指，但 Flash 延迟仍按低频配置。可能出现总线错误、错误指令或随机锁死。

#### 正确实现

```
FLASH->ACR = (FLASH->ACR & ~FLASH_ACR_LATENCY_Msk) |
             FLASH_ACR_LATENCY_4WS;

while ((FLASH->ACR & FLASH_ACR_LATENCY_Msk) !=
       FLASH_ACR_LATENCY_4WS) {
    /* 必须增加独立超时；此处省略仅突出顺序。 */
}

RCC->CFGR = (RCC->CFGR & ~RCC_CFGR_SW) | RCC_CFGR_SW_PLL1;
```

#### 风险影响

- 启动偶发失败；
- 高温或低压时故障概率上升；
- 可能导致控制输出失控，属于系统级高风险。

### 9.2 错误二：驱动无条件关闭共享外设时钟

#### 错误代码

```
void uart_debug_close(void)
{
    RCC->APB1LENR &= ~RCC_APB1LENR_UART4EN;
}
```

#### 根因分析

UART 可能同时被诊断服务、Bootloader 或 DMA 日志模块使用。直接关闭导致其他客户端寄存器不可访问或传输中断。

#### 正确实现

```
clock_status_t uart_debug_close(void)
{
    if ((UART4->ISR & USART_ISR_BUSY) != 0U) {
        return CLOCK_ERR_HW_FAULT;
    }

    return peripheral_clock_release(CLK_PERIPH_UART4);
}
```

#### 风险影响

- 日志丢失；
- DMA 总线错误；
- 通信帧截断；
- 难以复现的并发故障。

### 9.3 错误三：无限等待晶体或 PLL

#### 错误代码

```
RCC->CR |= RCC_CR_PLL1ON;
while ((RCC->CR & RCC_CR_PLL1RDY) == 0U) {
}
```

#### 根因分析

晶体、PLL 参数或电源异常时，系统永久卡死。若看门狗启动，则形成无限复位循环。

#### 正确实现

```
RCC->CR |= RCC_CR_PLL1ON;

clock_status_t status = wait_mask(&RCC->CR,
                                  RCC_CR_PLL1RDY,
                                  true,
                                  cycles_from_us(SystemCoreClock, 2000U));
if (status != CLOCK_OK) {
    RCC->CR &= ~RCC_CR_PLL1ON;
    /* 保持 HSI 运行，记录降级状态并限制功能。 */
}
```

#### 风险影响

- 系统不可用；
- OTA 后变砖；
- 现场只能断电或返修。

### 9.4 错误四：忽略定时器倍频规则

#### 错误代码

```
uint32_t timer_hz = pclk1_hz;
TIM2->PSC = timer_hz / 1000000U - 1U;
```

#### 根因分析

当 APB 分频器不为 1 时，定时器可能得到 `2 × PCLK`。结果是定时器频率快一倍。

#### 正确实现

```
uint32_t timer_hz = clock_get_timer_kernel_hz(TIM2);
if ((timer_hz == 0U) || ((timer_hz % 1000000U) != 0U)) {
    return CLOCK_ERR_INVALID;
}

TIM2->PSC = timer_hz / 1000000U - 1U;
```

#### 风险影响

- PWM 频率错误；
- 控制环周期错误；
- 输入捕获和计量结果偏差 100%。

### 9.5 错误五：变频后未更新 RTOS 和通信外设

#### 错误代码

```
clock_switch_to_200mhz();
/* 继续使用旧 SysTick、UART BRR 和超时换算。 */
```

#### 根因分析

软件时间基准和外设分频仍基于旧频率。RTOS Tick、波特率和忙等待同时失真。

#### 正确实现

```
clock_status_t system_frequency_commit(uint32_t new_hz)
{
    SystemCoreClock = new_hz;

    if (SysTick_Config(new_hz / configTICK_RATE_HZ) != 0U) {
        return CLOCK_ERR_INVALID;
    }

    uart_recalculate_baud();
    timer_recalculate_all();
    timeout_service_frequency_changed(new_hz);
    return CLOCK_OK;
}
```

实际系统应先暂停调度或使用 tickless/独立低速时基，避免切换窗口丢 Tick。

#### 风险影响

- 调度周期漂移；
- 通信失效；
- 软件超时过早或过晚；
- 看门狗服务窗口被破坏。

### 9.6 错误六：关闭正在传输的外设时钟

#### 错误代码

```
SPI2->CR1 &= ~SPI_CR1_SPE;
RCC->APB1LENR &= ~RCC_APB1LENR_SPI2EN;
```

#### 根因分析

未等待 TX FIFO、移位寄存器和 `BUSY` 清空，最后若干位仍在发送。

#### 正确实现

```
clock_status_t spi2_stop(uint32_t timeout)
{
    while (((SPI2->SR & SPI_SR_TXC) == 0U) && (timeout-- != 0U)) {
    }

    if ((SPI2->SR & SPI_SR_TXC) == 0U) {
        return CLOCK_ERR_TIMEOUT;
    }

    SPI2->CR1 &= ~SPI_CR1_SPE;
    __DSB();

    return peripheral_clock_release(CLK_PERIPH_SPI2);
}
```

#### 风险影响

- 数据帧截断；
- 片选时序破坏；
- 外部 Flash 写入损坏；
- 从设备状态机失步。

## 10. 多机制组合使用方案

### 10.1 协同架构

```
+-----------------------+
                  | Clock Policy Manager  |
                  | 性能档位/低功耗/安全策略 |
                  +-----------+-----------+
                              |
              +---------------+----------------+
              |                                |
      +-------v--------+               +-------v--------+
      | Clock Tree HAL |               | Peripheral PM  |
      | OSC/PLL/MUX/DIV|               | 引用计数/门控   |
      +-------+--------+               +-------+--------+
              |                                |
      +-------v--------------------------------v-------+
      | RCC/CCU + Voltage Regulator + Flash Controller |
      +-----------------------+-------------------------+
                              |
              +---------------v----------------+
              | Safety Supervisor              |
              | CSS/频率窗口/IWDG/故障持久化    |
              +--------------------------------+
```

### 10.2 事务式切频模式

切频应被视为事务：

```
请求目标档位
 -> 校验所有客户端约束
 -> prepare：暂停敏感外设
 -> 建立备用时钟
 -> 调整电压/Flash/PLL/分频
 -> 硬件状态回读
 -> commit：更新软件频率并恢复客户端
 -> 失败则 rollback 到安全档位
```

### 10.3 完整代码框架

```
typedef enum {
    CLOCK_PROFILE_SAFE_HSI,
    CLOCK_PROFILE_RUN_200M,
    CLOCK_PROFILE_RUN_400M
} clock_profile_t;

typedef struct {
    clock_status_t (*prepare)(clock_profile_t target);
    void (*commit)(clock_profile_t target);
    void (*rollback)(clock_profile_t previous);
} clock_client_t;

#define CLOCK_CLIENT_MAX 8U

static const clock_client_t *g_clients[CLOCK_CLIENT_MAX];
static size_t g_client_count;
static clock_profile_t g_current_profile = CLOCK_PROFILE_SAFE_HSI;

static clock_status_t clock_hw_apply(clock_profile_t target)
{
    switch (target) {
    case CLOCK_PROFILE_SAFE_HSI:
        /* 切换到已确认就绪的 HSI，再关闭非必要 PLL。 */
        return clock_apply_safe_hsi();

    case CLOCK_PROFILE_RUN_200M:
        return clock_apply_200mhz();

    case CLOCK_PROFILE_RUN_400M:
        return clock_apply_400mhz();

    default:
        return CLOCK_ERR_INVALID;
    }
}

clock_status_t clock_profile_set(clock_profile_t target)
{
    if (target == g_current_profile) {
        return CLOCK_OK;
    }

    clock_profile_t previous = g_current_profile;
    size_t prepared = 0U;

    for (; prepared < g_client_count; ++prepared) {
        clock_status_t status = g_clients[prepared]->prepare(target);
        if (status != CLOCK_OK) {
            while (prepared > 0U) {
                prepared--;
                g_clients[prepared]->rollback(previous);
            }
            return status;
        }
    }

    clock_status_t status = clock_hw_apply(target);
    if (status != CLOCK_OK) {
        (void)clock_hw_apply(CLOCK_PROFILE_SAFE_HSI);

        while (prepared > 0U) {
            prepared--;
            g_clients[prepared]->rollback(previous);
        }
        g_current_profile = CLOCK_PROFILE_SAFE_HSI;
        return status;
    }

    g_current_profile = target;
    SystemCoreClockUpdate();

    for (size_t i = 0U; i < g_client_count; ++i) {
        g_clients[i]->commit(target);
    }

    return CLOCK_OK;
}
```

安全关键产品还应增加：

- API 串行化锁；
- ISR 调用限制；
- 变频状态机超时；
- 寄存器配置 CRC；
- 主核与安全核握手；
- 切换过程的看门狗预算；
- 失败次数阈值与永久降级策略。

## 11. 工业级实际案例分析

### 11.1 伺服驱动器主时钟失效保护

#### 需求

- Cortex-M7 主频 400 MHz。
- PWM 20 kHz，控制环 10 kHz。
- 外部晶体失效后功率输出必须在数微秒内关闭。
- 故障信息需在复位后保留。

#### 架构设计

```
25 MHz HSE -> PLL -> 400 MHz CPU
                  -> 200 MHz 定时器域
HSI -------------> 自动备用系统时钟
LSI -------------> IWDG + 时钟监控参考
TIM Break <------- 比较器/驱动器故障
CSS NMI ---------> 软件诊断与永久故障记录
```

#### 核心代码

```
typedef struct {
    uint32_t magic;
    uint32_t css_count;
    uint32_t last_rcc_cifr;
    uint32_t crc;
} retained_fault_log_t;

__attribute__((section(".backup_sram")))
static retained_fault_log_t g_retained_fault;

void NMI_Handler(void)
{
    uint32_t flags = RCC->CIFR;

    if ((flags & RCC_CIFR_HSECSSF) != 0U) {
        /* 第一优先级：关断危险能量。硬件 Break 应更早独立生效。 */
        TIM1->BDTR &= ~TIM_BDTR_MOE;
        TIM8->BDTR &= ~TIM_BDTR_MOE;
        __DSB();

        RCC->CICR = RCC_CICR_HSECSSC;

        g_retained_fault.magic = 0x434C4B46U;
        g_retained_fault.css_count++;
        g_retained_fault.last_rcc_cifr = flags;
        g_retained_fault.crc = fault_log_crc(&g_retained_fault);

        safety_event_set_from_nmi(SAFETY_EVENT_CLOCK_FAILURE);
    }
}
```

#### 设计要点

- PWM 关断必须首先由定时器 Break/门极驱动硬件实现，NMI 只是第二层。
- HSI 降级后禁止继续闭环驱动，只允许故障通信和受控停机。
- 需要故障注入：移除外部时钟、短接晶体、注入幅值衰减。
- 验证从时钟丢失到 PWM 失效的最坏延迟，而不是只验证 NMI 到达。

### 11.2 工业数据采集器的独立采样时钟

#### 需求

- ADC 固定 2 MSPS。
- CPU 根据负载在 100/400 MHz 切换。
- 采样率不得随 CPU DVFS 改变。
- USB 需要固定 48 MHz。

#### 架构设计

```
HSE
├─ PLL1 -> CPU/AXI：100 或 400 MHz
├─ PLL2 -> ADC kernel：固定 80 MHz
└─ PLL3 -> USB：固定 48 MHz
```

#### 核心代码

```
clock_status_t adc_clock_constraint_check(void)
{
    uint32_t adc_hz = clock_get_kernel_hz(CLOCK_KERNEL_ADC);
    uint32_t usb_hz = clock_get_kernel_hz(CLOCK_KERNEL_USB);

    if ((adc_hz != 80000000U) || (usb_hz != 48000000U)) {
        return CLOCK_ERR_INVALID;
    }

    return CLOCK_OK;
}

static clock_status_t acquisition_prepare(clock_profile_t target)
{
    (void)target;

    /*
     * 若目标配置不修改 ADC PLL，则 DMA 采样无需暂停；
     * 但必须验证时钟规划器不会重写 PLL2。
     */
    return adc_clock_constraint_check();
}
```

#### 设计要点

- 用独立功能时钟隔离 CPU 变频影响。
- 时钟规划器必须支持“锁定 PLL2/PLL3”约束。
- ADC 时钟不仅影响采样率，还影响转换精度和模拟稳定时间。
- USB 时钟不能因进入节能档位而超出协议精度。

### 11.3 汽车网关快速启动与降级通信

#### 需求

- 上电 20 ms 内开始接收 CAN。
- HSE 最坏启动时间可能达到 10 ms。
- 时钟故障后仍需发送诊断帧。
- 不允许变频破坏 CAN 位时序。

#### 架构设计

```
复位
 -> HSI 启动 CPU
 -> CAN 使用可接受精度的独立时钟或校准 RC
 -> 并行启动 HSE
 -> HSE 稳定后配置 PLL
 -> 暂停 CAN 新发送
 -> 等待总线空闲
 -> 切换 CAN kernel clock 并重算位时序
 -> 恢复发送
```

#### 核心代码

```
static clock_status_t can_prepare(clock_profile_t target)
{
    uint32_t target_can_hz = clock_profile_can_hz(target);

    if (!can_bit_timing_is_representable(target_can_hz,
                                         500000U,
                                         800U)) { /* 80.0% 采样点 */
        return CLOCK_ERR_INVALID;
    }

    can_block_new_tx();

    if (!can_wait_tx_idle(2000U)) {
        can_allow_tx();
        return CLOCK_ERR_TIMEOUT;
    }

    return CLOCK_OK;
}

static void can_commit(clock_profile_t target)
{
    can_apply_bit_timing(clock_profile_can_hz(target), 500000U, 800U);
    can_allow_tx();
}
```

#### 设计要点

- CAN 接收不能因主频切换出现长时间盲区。
- 诊断降级模式必须预先计算并验证位时序。
- 故障时优先保持网络可诊断性，但不能继续执行不安全控制功能。

## 12. 高频问题深度答疑

### 12.1 为什么更新 `SystemCoreClock` 不等于完成时钟切换？

`SystemCoreClock` 只是软件变量。修改它不会操作振荡器、PLL、分频器或 Flash。反过来，修改硬件后不更新它，会导致 SysTick、延时、驱动分频计算错误。正确流程是完成硬件切换并回读确认后，再调用 `SystemCoreClockUpdate()` 或更新可信的软件时钟模型。

### 12.2 为什么不能直接关闭当前系统 PLL 再重新配置？

CPU 正由 PLL 供钟时关闭 PLL，结果取决于芯片硬件保护：可能拒绝写入、自动切换，也可能直接停钟。正确方式是先启动备用时钟，确认就绪，切换 SYSCLK 并确认状态，然后关闭和重配 PLL。

### 12.3 门控外设时钟是否一定会清空寄存器？

不一定。门控通常只停止时钟，外设寄存器可能保留；复位才恢复默认值。但部分低功耗域掉电后会丢失上下文。必须区分：

- 时钟门控；
- 外设复位；
- 电源域关闭；
- Backup/Retention 保持。

驱动不能依赖跨型号的隐式行为。

### 12.4 为什么 PLL 锁定后仍可能不适合 ADC、Ethernet 或高速串行外设？

`LOCK=1` 只表示 PLL 反馈环进入允许范围，不代表抖动、相位噪声和分数杂散满足目标外设要求。ADC 关注采样抖动导致的 SNR 损失：

SNRjitter=−20log⁡10(2πfintj)SNRjitter​=−20log10​(2πfin​tj​)

输入频率越高，对时钟 RMS 抖动越敏感。高速接口还可能要求专用低抖动 PLL 或外部振荡器。

### 12.5 时钟监控器是否能替代看门狗？

不能。时钟监控器检测特定时钟异常；看门狗检测软件未按时运行。两者可能存在共因失效，因此安全设计通常使用由 LSI 等独立时钟驱动的看门狗，并配合外部窗口看门狗或 PMIC 监控。

### 12.6 动态变频为什么经常导致偶发串口乱码？

常见原因包括：

- UART 功能时钟随总线频率改变；
- BRR 未在切换后重算；
- 正在发送时修改分频器；
- 切换瞬间时钟不连续；
- DMA 完成不代表最后一位已发送；
- 软件超时基准随 CPU 频率改变。

应暂停新发送，等待 `TC/BUSY` 状态，完成切换并重算波特率后再恢复。

### 12.7 安全系统是否应该运行时自动恢复 HSE？

取决于安全概念。晶体间歇失效可能反复触发时钟切换，引入更大风险。常见策略是：

- 首次故障立即降级并锁存；
- 保持内部安全时钟；
- 禁止高风险输出；
- 在受控状态进行有限次数恢复；
- 超过阈值后保持永久降级直到复位或维护。

### 12.8 为什么测得的 MCO 频率正确，系统仍可能有时钟问题？

MCO 只能证明被选择节点的平均输出频率基本正确，不能完整验证：

- 周期抖动；
- 瞬态丢脉冲；
- 内部异步域同步；
- Flash 延迟；
- 电压档位；
- 外设独立功能时钟；
- 温度和电压边界；
- CSS 故障响应。

必须结合寄存器回读、外设行为、示波器统计和环境测试。

## 13. 课程核心总结
### 13.1 核心要点

- 时钟系统不是单一主频配置，而是由**时钟源、PLL、复用器、分频器、门控器、时钟域和监控器**构成的系统资源。
- 升频顺序的核心是：**先提升电压档位，再增加 Flash Wait State，最后切换高频时钟**。
- 降频顺序的核心是：**先切换到低频，再降低 Flash Wait State，最后降低电压档位**。
- 外设管理必须明确区分**总线时钟、功能时钟、内核时钟、外设复位和电源域状态**。
- 共享外设时钟应使用**引用计数、所有权管理或统一电源管理框架**，禁止由驱动直接关闭公共时钟。
- 所有 `READY`、`LOCK`、`BUSY`、电压稳定和时钟切换等待都必须具备**超时、错误码和降级路径**。
- 运行时变频必须同步处理 **RTOS Tick、UART 波特率、CAN 位时序、定时器周期、DMA 超时和软件时间基准**。
- 时钟故障处理必须遵循：**硬件快速隔离，软件完成诊断，系统进入受控降级**。
- 安全输出不能只依赖 NMI 或普通中断，PWM、驱动使能和功率级关断应优先采用**定时器 Break、硬件比较器、门极驱动器和 PMIC**等硬件链路。
- MCO 测频只能验证某个节点的平均频率，不能代替对**抖动、瞬态丢钟、外设功能时钟、Flash 时序和全温全压行为**的验证。

### 13.2 性能与可靠性排序

#### 启动速度排序

```
纯分频切换
  > 内部 RC 启动
  > 已锁定 PLL 的输出切换
  > PLL 重新锁定
  > 外部晶体启动
  > 低速晶体 LSE 启动
```

实际排序取决于芯片实现，但工程上应将**慢启动源与业务启动解耦**：先用内部 RC 建立最小运行环境，再异步启动高精度时钟。

#### 频率精度排序

```
未校准低速 RC
  < 未校准高速 RC
  < 温度/电压校准 RC
  < 普通晶体
  < 高精度晶体或 MEMS
  < 专用低抖动时钟源
```

#### 运行时变频风险排序

```
固定 PLL、只切安全分频
  < 切换独立功能时钟
  < 重配 PLL 输出
  < 同时改变电压、Flash、总线和多个外设时钟域
```

#### 安全机制覆盖能力排序

```
软件轮询
  < PLL Lock/Ready 状态检测
  < CSS + NMI
  < 独立时钟频率窗口监测
  < 定时器硬件保护 + 独立看门狗 + 外部安全监控
```

### 13.3 通用选型结论

1. **非安全、低成本、快速启动产品**：内部 RC 加必要校准，采用固定时钟树。
2. **需要稳定通信或计量的产品**：外部晶体或 MEMS，关键外设使用独立功能时钟。
3. **需要低功耗的产品**：优先采用分频和外设按需门控；只有在电压档位可联动时，DVFS 才能获得明显收益。
4. **需要运行时变频的产品**：使用事务式 `prepare/commit/rollback`，不要在业务线程中直接改 RCC 寄存器。
5. **安全关键产品**：采用独立备用时钟、CSS/频率监测、独立看门狗、硬件输出关断和故障锁存。
6. **高采样率或高速接口产品**：不要仅以 PLL `LOCK` 作为时钟质量判据，必须评估相位噪声、周期抖动和外设专用时钟要求。

**目标**：完成目标 MCU 的时钟树建模与启动验证。

实施要求：

1. 用结构体描述时钟源、PLL、MUX、分频器和外设内核时钟。
2. 启动后回读关键寄存器，计算实际 CPU、总线和外设频率。
3. 将 SYSCLK、PCLK、定时器时钟和功能时钟输出到 MCO 或测试引脚。
4. 对每个频率节点增加范围检查和静态断言。
5. 在启动日志中输出配置频率、实际频率和错误状态。

验收指标：

- 频率计算与频率计测量误差满足芯片和晶体精度要求；
- 任意一个 Ready/Lock 失败都能在有限时间内返回；
- 禁止出现访问未开时钟外设寄存器的路径。

### 任务二：实现外设引用计数门控

**目标**：实现线程安全的外设时钟资源管理器。

实施要求：

1. 为 UART、SPI、I2C、ADC 建立资源 ID。
2. 支持多客户端 acquire/release。
3. 检查引用计数溢出和非法释放。
4. 在关闭前验证外设不处于忙状态。
5. 统计启停次数、累计开启时间和非法调用次数。
6. 增加 RTOS 任务并发、ISR 调用限制和异常路径测试。

验收指标：

- 多客户端同时使用时不会提前关钟；
- acquire/release 配对错误可检测；
- 门控状态与引用计数长期一致；
- 不因门控引入 DMA 总线错误或帧截断。

### 任务三：实现事务式运行时变频

**目标**：支持多性能档位切换和失败回滚。

实施要求：

1. 定义 `SAFE`、`LOW_POWER`、`PERFORMANCE` 三个性能档位。
2. 对 UART、CAN、定时器、ADC 和 RTOS Tick 注册时钟客户端。
3. 实现 `prepare/commit/rollback` 三阶段协议。
4. 切频前暂停敏感事务，等待发送完成或总线空闲。
5. 切频失败时回退到安全时钟，不允许停在未知状态。
6. 对每次切换记录起止时间、目标档位、失败原因和回滚结果。

验收指标：

- 切换期间无 UART 乱码、CAN 位时序错误和定时器周期突变；
- PLL 锁定失败能够在预算时间内回滚；
- RTOS 任务超时和软件延时在切换前后保持一致。

### 任务四：构建时钟故障安全闭环

**目标**：实现从故障检测到安全降级的完整链路。

实施要求：

1. 启用 CSS、独立看门狗和必要的频率窗口监测。
2. 在 NMI/安全中断中只做有界、不可阻塞操作。
3. 用硬件 Break 关断 PWM 或危险输出。
4. 在备份 SRAM 或专用诊断区保存故障信息。
5. 后台安全任务读取故障事件并执行功能降级。
6. 设计故障锁存、有限次数恢复和永久降级策略。

验收指标：

- 故障到硬件输出关闭的最坏延迟满足安全目标；
- 故障记录在软件复位后仍可读取且 CRC 正确；
- 重复故障不会导致无限恢复振荡；
- 看门狗、CSS 和主程序时钟之间不存在单一共因失效。

## 16.3 进阶学习方向

### 方向一：芯片级时钟架构

- 多 PLL、多时钟域和异步桥；
- 时钟域电源管理；
- 时钟树综合与低功耗时钟门控；
- 时钟抖动、相位噪声和 SSC；
- 硬件时钟监测器与频率窗口设计。

### 方向二：实时系统协同

- 独立低速 Tick 与 tickless idle；
- DVFS 对 WCET、调度和响应时间的影响；
- 时间感知通信和确定性调度；
- DMA、缓存一致性与外设时钟域协同；
- 多核 MCU 的跨核时钟资源管理。

### 方向三：功能安全

- 时钟故障模式与影响分析（FMEDA/FMEA）；
- 诊断覆盖率和潜伏故障；
- ISO 26262 时钟监控需求分解；
- IEC 61508 安全完整性等级与独立性；
- 故障注入、故障树分析和安全机制验证。

### 方向四：高性能与高速接口

- Ethernet、USB、PCIe 和 SerDes 时钟要求；
- ADC/DAC 采样抖动预算；
- 外部时钟芯片、抖动清理器和同步网络；
- IEEE 1588、PTP 和硬件时间戳；
- 分数 PLL 杂散与频谱分析。

### 方向五：平台化时钟服务

- 设备树或配置生成式时钟描述；
- 时钟依赖图与拓扑排序；
- 频率约束求解器和自动配置生成；
- 运行时策略、遥测和故障预测；
- 面向多芯片族的统一 Clock HAL。

## 16.4 最终实战交付物

完成本课后，建议形成以下可审计交付物：

1. 一份目标 MCU 的时钟树图和寄存器配置表；
2. 一套带超时、回滚和回读验证的 Clock HAL；
3. 一套外设时钟引用计数及并发测试代码；
4. 一份运行时变频的客户端约束和状态机设计；
5. 一份主时钟失效的安全机制说明书；
6. 一份覆盖启动、变频、低功耗、停振和 PLL 故障的测试报告；
7. 一份包含频率、延迟、功耗、波特率误差和故障响应时间的量化数据表。

**本课的工程结论是：时钟管理的高级能力不在于“把主频配到最高”，而在于让每个时钟域在正确的时间、以可验证的频率、在可控的功耗下运行，并在时钟异常时自动进入安全状态。**
