## 3. 技术概述

### 3.1 定时器的本质

定时器本质上是一个由外设时钟驱动的同步计数器：

```
定时器输入时钟
    |
    v
输入滤波/时钟选择
    |
    v
预分频器 PSC
    |
    v
计数器 CNT
    |
    +--> 自动重载寄存器 ARR：决定周期
    |
    +--> 捕获比较寄存器 CCRx：决定捕获/比较点
    |
    +--> 输出控制逻辑：PWM、翻转、置位、清零
    |
    +--> 事件与中断：更新、捕获、比较、触发
```

核心关系：

```
f_cnt = f_tim / (PSC + 1)

T_update = (ARR + 1) / f_cnt
          = (PSC + 1) × (ARR + 1) / f_tim

f_update = f_tim / ((PSC + 1) × (ARR + 1))
```

其中：

- `f_tim`：定时器实际输入时钟。
- `PSC`：预分频寄存器。
- `ARR`：自动重载寄存器。
- `CNT`：当前计数值。
- `CCR`：捕获/比较寄存器。

### 3.2 基本定时器

基本定时器通常只提供：

- 时基生成。
- 向上计数。
- 更新事件。
- 更新中断。
- 触发 DAC 或其他外设。

典型用途：

- 周期性系统任务。
- DAC 采样触发。
- 软件超时基准。
- 周期性传感器采样。
- 简单蜂鸣器节拍。

基本定时器通常没有：

- 外部输入引脚。
- 输入捕获通道。
- 输出比较通道。
- PWM 输出。
- 编码器接口。

### 3.3 通用定时器

通用定时器通常包含：

- 基本时基。
- 输入捕获。
- 输出比较。
- PWM 输出。
- 单脉冲输出。
- 外部时钟计数。
- 触发输入/输出。
- DMA 请求。
- 部分型号支持编码器接口。

典型用途：

- PWM 控制。
- 脉冲宽度测量。
- 频率测量。
- 超声波回波测距。
- 脉冲计数。
- 步进电机脉冲输出。
- 编码器位置采集。
- ADC 规则组触发。

### 3.4 一个重要平台差异

以下内容以常见 STM32 定时器模型为主，寄存器名称和语义参考 STM32F1/F4/G4 等系列的共同结构。不同 MCU 可能存在以下差异：

- APB 分频不为 1 时，定时器时钟可能自动乘 2。
- 某些型号的 `PSC` 更新需要软件触发更新事件后才生效。
- 某些型号有重复计数器 `RCR`。
- 高级定时器拥有互补输出、死区和刹车输入。
- 某些基本定时器可能支持 16 位或 32 位计数。
- 部分厂商将 `ARR` 缓冲、影子寄存器和更新事件行为实现为不同模式。

实际工程必须以具体芯片 Reference Manual 为准。

## 5. 底层原理与功能特性深度解析

## 5.1 定时器时钟计算

### 5.1.1 APB 定时器时钟

在许多 STM32 系列中：

```
当 APB prescaler = 1：
    f_tim = f_pclk

当 APB prescaler > 1：
    f_tim = 2 × f_pclk
```

例如：

```
SYSCLK = 168 MHz
APB1 = 42 MHz
APB1 prescaler = 4
TIM2 输入时钟 = 84 MHz
```

若错误地把 `42 MHz` 当作定时器时钟，则所有周期都会产生 2 倍误差。

### 5.1.2 生产级频率计算接口

```
#include <stdint.h>
#include <stdbool.h>

typedef enum {
    TIMER_OK = 0,
    TIMER_ERR_PARAM = -1,
    TIMER_ERR_RANGE = -2
} timer_status_t;

typedef struct {
    uint32_t timer_clk_hz;
    uint32_t target_hz;
    uint16_t psc;
    uint32_t arr;
    uint32_t actual_hz;
    uint32_t error_ppm;
} timer_timebase_cfg_t;

static uint32_t abs_u32_diff(uint32_t a, uint32_t b)
{
    return (a >= b) ? (a - b) : (b - a);
}

/*
 * 选择一个满足 ARR 范围的 PSC，并使实际频率误差最小。
 * 这里假设目标定时器为 16 位 ARR；32 位定时器可放宽 arr_max。
 */
timer_status_t timer_calc_timebase(uint32_t timer_clk_hz,
                                   uint32_t target_hz,
                                   uint32_t arr_max,
                                   timer_timebase_cfg_t *out)
{
    if ((timer_clk_hz == 0U) || (target_hz == 0U) ||
        (arr_max == 0U) || (out == NULL)) {
        return TIMER_ERR_PARAM;
    }

    uint64_t best_error = UINT64_MAX;
    uint32_t best_psc = 0U;
    uint32_t best_arr = 0U;
    uint32_t best_actual = 0U;

    for (uint32_t psc = 0U; psc <= UINT16_MAX; ++psc) {
        uint64_t denominator = (uint64_t)(psc + 1U) * target_hz;
        uint64_t arr_plus_one = ((uint64_t)timer_clk_hz + denominator / 2U) /
                                denominator;

        if ((arr_plus_one == 0U) || (arr_plus_one > ((uint64_t)arr_max + 1U))) {
            continue;
        }

        uint32_t arr = (uint32_t)(arr_plus_one - 1U);
        uint32_t actual = timer_clk_hz /
                          ((psc + 1U) * (arr + 1U));
        uint64_t error = abs_u32_diff(actual, target_hz);

        if (error < best_error) {
            best_error = error;
            best_psc = psc;
            best_arr = arr;
            best_actual = actual;
        }
    }

    if (best_error == UINT64_MAX) {
        return TIMER_ERR_RANGE;
    }

    out->timer_clk_hz = timer_clk_hz;
    out->target_hz = target_hz;
    out->psc = (uint16_t)best_psc;
    out->arr = best_arr;
    out->actual_hz = best_actual;
    out->error_ppm = (uint32_t)((best_error * 1000000ULL) / target_hz);

    return TIMER_OK;
}
```

工程注意事项：

- 不要使用浮点数计算定时器参数。
- 计算过程中使用 64 位整数，避免 `(PSC + 1) * (ARR + 1)` 溢出。
- 必须记录实际频率和误差，而不是只记录目标频率。
- 对于通信协议、音频采样和电机 PWM，误差指标应在配置阶段被明确检查。

## 5.2 更新事件与自动重载寄存器

基本向上计数模式：

```
CNT: 0 -> 1 -> 2 -> ... -> ARR -> 0
                              |
                              +--> 更新事件 UEV
```

更新事件可能由以下条件触发：

- 计数器溢出。
- 软件设置 `UG` 位。
- 从模式控制器触发。
- 重复计数器达到条件。

更新事件通常会：

- 更新 `ARR` 影子寄存器。
- 更新 `PSC` 预分频器。
- 产生更新标志 `UIF`。
- 产生更新中断。
- 产生 DMA 请求。
- 触发 TRGO 输出。

### 5.2.1 初始化中的首个中断问题

许多 STM32 定时器在设置 `EGR.UG` 后会立即置位 `SR.UIF`。如果随后开启更新中断而未清除 `UIF`，可能出现：

```
启动定时器
    |
    +--> 立即进入一次中断
    |
    +--> 第一个周期短于预期
```

正确顺序：

```
TIMx->PSC = psc;
TIMx->ARR = arr;
TIMx->EGR = TIM_EGR_UG;       /* 让 PSC/ARR 立即装载 */
TIMx->SR &= ~TIM_SR_UIF;      /* 清除初始化产生的更新标志 */
TIMx->DIER |= TIM_DIER_UIE;   /* 最后开启中断 */
TIMx->CR1 |= TIM_CR1_CEN;
```

不同系列对 `SR` 的写法可能不同，必须依据参考手册确认“写 0 清除”还是“写 0/写 1 清除”。

## 5.3 基本定时器周期中断

### 5.3.1 寄存器级框架

以下示例展示结构，不绑定具体芯片的 RCC 和 NVIC 命名。

```
#include <stdint.h>
#include <stdbool.h>

static volatile uint32_t g_timer_tick;
static volatile bool g_sample_due;

void basic_timer_init(uint16_t psc, uint16_t arr)
{
    /* 1. 开启基本定时器外设时钟 */
    RCC->APB1ENR |= RCC_APB1ENR_TIM6EN;

    /* 2. 停止计数器，避免配置过程中产生不可控事件 */
    TIM6->CR1 = 0U;

    /* 3. 配置时基 */
    TIM6->PSC = psc;
    TIM6->ARR = arr;

    /* 4. 立即装载 PSC/ARR */
    TIM6->EGR = TIM_EGR_UG;

    /* 5. 清除配置阶段产生的 UIF */
    TIM6->SR = 0U;

    /* 6. 开启更新中断 */
    TIM6->DIER = TIM_DIER_UIE;

    /* 7. 配置 NVIC，具体优先级按系统规划设置 */
    NVIC_SetPriority(TIM6_DAC_IRQn, 5U);
    NVIC_EnableIRQ(TIM6_DAC_IRQn);

    /* 8. 启动定时器 */
    TIM6->CR1 = TIM_CR1_CEN;
}

void TIM6_DAC_IRQHandler(void)
{
    uint32_t status = TIM6->SR;

    if ((status & TIM_SR_UIF) != 0U) {
        TIM6->SR = (uint16_t)~TIM_SR_UIF;

        ++g_timer_tick;
        g_sample_due = true;
    }
}
```

### 5.3.2 ISR 设计原则

中断处理函数应当：

- 只读取必要状态。
- 快速清除中断标志。
- 记录时间戳或投递事件。
- 不执行阻塞式驱动。
- 不调用不可重入的日志函数。
- 不进行动态内存分配。
- 不执行复杂浮点计算。
- 不直接执行毫秒级业务逻辑。

推荐模式：

```
void TIM6_DAC_IRQHandler(void)
{
    if ((TIM6->SR & TIM_SR_UIF) != 0U) {
        TIM6->SR = (uint16_t)~TIM_SR_UIF;
        os_event_set_from_isr(EVENT_SAMPLE_TICK);
    }
}
```

## 5.4 输出比较模式

输出比较的基本逻辑：

```
CNT == CCRx
    |
    +--> 产生比较事件
    +--> 产生中断
    +--> 改变 OC 输出电平
    +--> 触发 DMA 或 TRGO
```

适合：

- 产生一次精确边沿。
- 生成多个非等间隔事件。
- 控制步进电机脉冲。
- 产生超声波触发脉冲。
- 实现软件定时器的硬件调度。

### 5.4.1 软件输出比较调度

对于单通道连续事件，可以在比较中断中推进下一次比较点：

```
static volatile uint32_t g_next_compare;

void timer_compare_start(uint32_t first_tick)
{
    g_next_compare = first_tick;
    TIM2->CCR1 = g_next_compare;
    TIM2->DIER |= TIM_DIER_CC1IE;
}

void TIM2_IRQHandler(void)
{
    uint32_t status = TIM2->SR;

    if ((status & TIM_SR_CC1IF) != 0U) {
        /*
         * 使用相对增量更新，避免读取 CNT 后再加延时导致边界竞争。
         */
        g_next_compare += 1000U;
        TIM2->CCR1 = g_next_compare;

        TIM2->SR = (uint16_t)~TIM_SR_CC1IF;
        stepper_event_from_isr();
    }
}
```

关键点：

- `CCR = CCR + delta` 比 `CCR = CNT + delta` 更能保持长期周期稳定。
- `delta` 必须大于系统最大 ISR 延迟，否则可能错过比较点。
- 如果事件间隔小于最坏中断延迟，应改用硬件 PWM 或 DMA。
- 16 位计数器发生回绕时，使用无符号减法判断时间差。

## 5.5 PWM 模式

PWM 的两个核心参数：

```
PWM 频率：
f_pwm = f_tim / ((PSC + 1) × (ARR + 1))

占空比：
duty = CCR / (ARR + 1)
```

在边沿对齐、向上计数、PWM Mode 1 中：

```
CNT < CCR：输出有效
CNT >= CCR：输出无效
```

### 5.5.1 PWM 配置示例

```
typedef struct {
    uint32_t timer_clk_hz;
    uint32_t pwm_hz;
    uint32_t resolution;
    uint16_t psc;
    uint32_t arr;
} pwm_config_t;

bool pwm_set_duty(TIM_TypeDef *tim,
                  volatile uint32_t *ccr,
                  uint32_t duty_permille,
                  uint32_t arr)
{
    if ((tim == NULL) || (ccr == NULL) || (duty_permille > 1000U)) {
        return false;
    }

    uint64_t compare = ((uint64_t)(arr + 1U) * duty_permille) / 1000U;

    if (compare > arr + 1U) {
        compare = arr + 1U;
    }

    *ccr = (uint32_t)compare;
    return true;
}
```

### 5.5.2 PWM 占空比边界

不同芯片对 `CCR = 0` 和 `CCR > ARR` 的输出行为可能存在差异：

|配置|常见结果|风险|
|---|---|---|
|`CCR = 0`|0% 输出|部分芯片存在窄毛刺|
|`CCR = 1`|最小非零脉宽|可能小于 IO/负载响应时间|
|`CCR = ARR / 2`|约 50%|常规|
|`CCR = ARR`|接近 100%|可能有一个计数周期低电平|
|`CCR > ARR`|通常持续无效或持续有效|依芯片实现而定|

工业产品中建议：

- 明确定义 `0%` 和 `100%` 的电气行为。
- 对驱动功率器件的 PWM 使用硬件输出，不使用 GPIO 中断翻转。
- 对占空比更新启用预装载，避免周期中途改变比较值造成毛刺。
- 使用更新事件统一装载多个通道的新占空比。

## 5.6 输入捕获

输入捕获用于在外部边沿到达时，将当前 `CNT` 自动复制到 `CCRx`。

```
外部边沿到达
    |
    +--> 输入滤波/边沿检测
    +--> CNT 锁存到 CCRx
    +--> CCxIF 置位
    +--> 产生中断或 DMA 请求
```

输入捕获测量的基本公式：

```
delta_ticks = current_capture - previous_capture
period      = delta_ticks / f_cnt
frequency   = f_cnt / delta_ticks
```

### 5.6.1 单通道周期测量

```
typedef struct {
    uint32_t last_capture;
    uint32_t timer_modulus;
    uint32_t timer_clk_hz;
    bool     valid;
} capture_measurement_t;

static volatile capture_measurement_t g_capture;

static uint32_t capture_delta(uint32_t current,
                              uint32_t previous,
                              uint32_t modulus)
{
    if (current >= previous) {
        return current - previous;
    }

    return (modulus - previous) + current;
}

void timer_capture_init(uint16_t psc, uint16_t arr)
{
    RCC->APB1ENR |= RCC_APB1ENR_TIM2EN;
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;

    /* GPIO 必须先配置为对应定时器复用输入 */

    TIM2->CR1 = 0U;
    TIM2->PSC = psc;
    TIM2->ARR = arr;

    /*
     * CC1S = 01：TI1 映射到 IC1。
     * CC1P = 0：上升沿捕获。
     * IC1F：输入滤波，具体编码依芯片而定。
     */
    TIM2->CCMR1 = TIM_CCMR1_CC1S_0 |
                  (3U << TIM_CCMR1_IC1F_Pos);

    TIM2->CCER = TIM_CCER_CC1E;
    TIM2->EGR = TIM_EGR_UG;
    TIM2->SR = 0U;
    TIM2->DIER = TIM_DIER_CC1IE;
    TIM2->CR1 = TIM_CR1_CEN;

    NVIC_SetPriority(TIM2_IRQn, 6U);
    NVIC_EnableIRQ(TIM2_IRQn);

    g_capture.timer_modulus = (uint32_t)arr + 1U;
    g_capture.timer_clk_hz = timer_get_counter_clock() /
                             ((uint32_t)psc + 1U);
    g_capture.valid = false;
}

void TIM2_IRQHandler(void)
{
    uint32_t status = TIM2->SR;

    if ((status & TIM_SR_CC1IF) != 0U) {
        uint32_t current = TIM2->CCR1;

        if (g_capture.valid) {
            uint32_t delta = capture_delta(current,
                                           g_capture.last_capture,
                                           g_capture.timer_modulus);

            if (delta != 0U) {
                uint32_t frequency = g_capture.timer_clk_hz / delta;
                capture_publish_frequency(frequency);
            }
        } else {
            g_capture.valid = true;
        }

        g_capture.last_capture = current;
        TIM2->SR = (uint16_t)~TIM_SR_CC1IF;
    }

    if ((status & TIM_SR_UIF) != 0U) {
        /*
         * 如果允许周期大于一个计数器周期，
         * 必须扩展溢出次数，否则捕获差值会不完整。
         */
        TIM2->SR = (uint16_t)~TIM_SR_UIF;
        capture_record_overflow();
    }
}
```

### 5.6.2 输入捕获滤波器

输入滤波器不是“软件去抖”，而是定时器采样器对输入信号进行连续采样，只有满足一定连续采样条件才确认边沿。

它可以抑制：

- 继电器触点抖动。
- 电机换相噪声。
- 长线干扰。
- 窄脉冲毛刺。

但它会引入延迟：

```
滤波确认时间 ≈ 采样周期 × 所需连续采样次数
```

滤波器过强的风险：

- 短脉冲被吞掉。
- 高频信号测量失真。
- 捕获边沿延迟增加。

滤波器过弱的风险：

- 一个物理边沿产生多个捕获事件。
- 频率读数出现异常尖峰。
- ISR 负载上升。

---

## 5.7 PWM 输入模式

PWM 输入模式通常使用两个捕获通道：

- 一个通道捕获周期。
- 另一个通道捕获高电平时间。

计算公式：

```
period_ticks = CCR_period
high_ticks   = CCR_high

frequency = f_cnt / period_ticks
duty      = high_ticks / period_ticks
```

其优势是周期和高电平时间由同一个硬件时间基准采集，避免软件分别读取 GPIO 边沿产生的偏差。

适合：

- 测量风扇 FG 信号。
- 测量舵机 PWM 输入。
- 测量外部控制器输出。
- 采集电机转速脉冲与占空比。

---

## 5.8 单脉冲模式

单脉冲模式用于产生一次确定宽度的脉冲：

```
触发事件
    |
    +--> 输出变为有效电平
    |
    +--> CNT 持续计数
    |
    +--> 比较/更新事件
    |
    +--> 输出关闭
    +--> 定时器停止
```

典型用途：

- 超声波模块触发脉冲。
- 电磁阀精确驱动。
- 相机曝光触发。
- 隔离器件测试脉冲。
- 步进驱动器单步脉冲。

单脉冲模式比“GPIO 拉高 + 软件延时 + GPIO 拉低”具有更低抖动、更低 CPU 占用和更稳定的脉宽。

---

## 5.9 32 位时间戳扩展

16 位定时器最大计数范围为：

```
0 ~ 65535
```

当计数频率为 `1 MHz` 时，最大不溢出时间约为：

```
65536 / 1 MHz = 65.536 ms
```

若要测量秒级周期，需要扩展高位：

```
typedef struct {
    volatile uint32_t high;
    uint32_t modulus;
} timer_timestamp_t;

static timer_timestamp_t g_ts;

void timer_timestamp_init(uint32_t modulus)
{
    g_ts.high = 0U;
    g_ts.modulus = modulus;
}

void timer_update_isr(void)
{
    ++g_ts.high;
}

uint32_t timer_extend_capture(uint32_t capture)
{
    uint32_t high = g_ts.high;
    uint32_t cnt = TIM2->CNT;

    /*
     * 如果捕获发生在溢出之前、但 ISR 尚未处理 UIF，
     * 根据当前 CNT 与捕获值的相对位置修正高位。
     */
    if (((TIM2->SR & TIM_SR_UIF) != 0U) &&
        (cnt < capture)) {
        ++high;
    }

    return high * g_ts.modulus + capture;
}
```

这里存在并发一致性问题：

- `high` 由 ISR 更新。
- `capture` 由硬件锁存。
- `CNT` 继续运行。
- `UIF` 可能与 `CCxIF` 同时置位。

工业实现应严格按照芯片参考手册确认：

- 更新事件与捕获事件的先后关系。
- `SR` 读取顺序。
- `CCR` 读取是否自动清除标志。
- 溢出与捕获同时发生时的硬件定义。

## 5.10 计数模式

### 向上计数

```
CNT: 0 -> ARR -> 0
```

适合：

- 常规周期中断。
- 普通 PWM。
- 单边沿时间测量。

### 向下计数

```
CNT: ARR -> 0 -> ARR
```

适合：

- 某些延时调度。
- 需要从装载值倒计时的脉冲控制。

### 中心对齐计数

```
CNT: 0 -> ARR -> 0
```

通常在上数和下数阶段分别产生比较行为。

适合：

- 电机 PWM。
- 对称 PWM。
- 降低开关谐波。
- 需要中心对齐采样窗口的功率控制。

中心对齐模式的周期通常约为边沿对齐模式的两倍计数长度，具体公式需要根据芯片模式和更新事件规则确认。

## 6. 性能量化分析

## 6.1 计时分辨率与周期范围

假设：

```
定时器输入时钟 f_tim = 84 MHz
PSC = 83
```

则：

```
f_cnt = 84 MHz / (83 + 1)
      = 1 MHz
```

即：

```
1 个计数 = 1 us
```

若：

```
ARR = 999
```

则：

```
T = (999 + 1) / 1 MHz
  = 1 ms
```

更新频率：

```
f_update = 1 kHz
```

### 6.1.1 分辨率与范围权衡

|计数频率|单计数时间|16 位最大测量时间|
|---|---|---|
|84 MHz|11.9 ns|0.780 ms|
|1 MHz|1 us|65.536 ms|
|100 kHz|10 us|655.36 ms|
|10 kHz|100 us|6.5536 s|
|1 kHz|1 ms|65.536 s|

结论：

- 高频计数提升时间分辨率，但缩短无溢出测量范围。
- 低频计数扩大范围，但降低脉宽和周期测量精度。
- 输入捕获场景通常需要根据被测信号频率动态选择 `PSC`。
- 对宽范围频率测量，应组合周期测量和门控计数。

## 6.2 量化误差

单次周期测量的量化误差约为：

```
相对误差 ≈ ±1 / delta_ticks
```

例如：

```
f_cnt = 1 MHz
被测频率 = 1 kHz
delta_ticks = 1000
量化误差约为 ±0.1%
```

若被测频率为：

```
100 kHz
delta_ticks = 10
```

则量化误差约为：

```
±10%
```

因此，高频信号测频不应只依赖“单周期捕获”。更好的方法是：

- 累积多个周期后计算平均值。
- 使用输入捕获 DMA 批量采集。
- 使用外部时钟模式进行门控计数。
- 对低频信号提高计数频率，对高频信号改用固定门控时间。

### 6.2.1 多周期平均

```
typedef struct {
    uint64_t sum_ticks;
    uint32_t sample_count;
} period_accumulator_t;

bool period_average_add(period_accumulator_t *acc,
                        uint32_t delta_ticks,
                        uint32_t target_count)
{
    if ((acc == NULL) || (delta_ticks == 0U) ||
        (target_count == 0U)) {
        return false;
    }

    acc->sum_ticks += delta_ticks;
    ++acc->sample_count;

    if (acc->sample_count >= target_count) {
        uint32_t average = (uint32_t)
            (acc->sum_ticks / acc->sample_count);

        frequency_publish_from_period(average);

        acc->sum_ticks = 0U;
        acc->sample_count = 0U;
        return true;
    }

    return false;
}
```

## 6.3 CPU 占用

假设：

```
CPU 主频：168 MHz
定时器中断频率：10 kHz
单次 ISR 执行时间：1.2 us
```

CPU 占用：

```
Load = 10,000 × 1.2 us
     = 12%
```

如果单次 ISR 为 `3 us`：

```
Load = 10,000 × 3 us
     = 30%
```

这还没有计入：

- 中断入栈/出栈。
- RTOS 中断退出调度。
- cache miss。
- 总线访问等待。
- 其他高优先级中断抢占。

参考测量方法：

```
void TIMx_IRQHandler(void)
{
    DEBUG_GPIO->BSRR = DEBUG_PIN_SET;

    timer_clear_flags();
    timer_process_event();

    DEBUG_GPIO->BSRR = DEBUG_PIN_RESET;
}
```

用逻辑分析仪测量调试 GPIO 高电平宽度，即可得到 ISR 执行时间。

### 6.3.1 中断与 DMA 对比

假设输入捕获频率为 `100 kHz`：

- 每次捕获中断耗时 `1.5 us`：

```
CPU Load = 100,000 × 1.5 us = 150%
```

系统必然无法实时处理。

- 使用 DMA，每 128 个捕获值触发一次半传输/传输完成中断。
- DMA 中断频率约为：

```
100,000 / 128 ≈ 781 Hz
```

若每次 DMA ISR 耗时 `4 us`：

```
CPU Load ≈ 781 × 4 us = 0.31%
```

结论：**高速、连续、数据量大的定时器事件应优先使用 DMA。**

## 6.4 输出抖动

软件 GPIO 翻转的边沿时间为：

```
t_edge = t_event + t_ISR_latency + t_instruction + t_bus_wait
```

其中 `t_ISR_latency` 受以下因素影响：

- 当前是否处于临界区。
- 是否被高优先级中断抢占。
- RTOS 内核是否进行调度。
- Flash 等待状态。
- 总线竞争。
- cache 和预取机制。

硬件 PWM/输出比较的边沿由定时器硬件直接产生，CPU 延迟不会直接影响输出边沿。

典型 Cortex-M 参考结果：

|方式|典型边沿抖动|
|---|---|
|软件延时翻转 GPIO|数十 us 到 ms|
|普通中断翻转 GPIO|0.2 us 到数 us|
|高优先级中断翻转 GPIO|数十 ns 到数百 ns|
|定时器硬件 PWM|一个定时器计数周期以内|
|定时器 DMA 更新|主要受总线和预装载机制影响|

这些数值为典型工程参考值，最终结果必须在目标板上实测。

## 6.5 性能瓶颈与优化手段

|瓶颈|根因|优化|
|---|---|---|
|中断占用过高|事件频率高、ISR 过重|DMA、硬件 PWM、批处理|
|测频抖动大|单周期量化误差、输入噪声|多周期平均、滤波、门控计数|
|PWM 有毛刺|CCR 非预装载、周期中途修改|开启 CCR preload|
|周期偏差|错误的定时器时钟|从 RCC 时钟树重新计算|
|长周期丢失|16 位计数器溢出|降低计数频率或软件扩展高位|
|高频脉冲漏计|ISR 处理速度不足|外部时钟模式、DMA、硬件计数|
|事件延迟不稳定|软件调度和抢占|输出比较硬件化、提高中断优先级|

## 8. 工程最佳实践

## 8.1 设计原则

1. **先确认真实定时器输入时钟，再计算参数。**
2. **所有周期和频率计算使用整数或定点算法。**
3. **硬件能完成的时序不要交给 ISR 生成。**
4. **中断中只处理时序事实，不处理复杂业务。**
5. **配置阶段主动生成更新事件，并清除初始化标志。**
6. **PWM 的 `ARR` 和 `CCR` 更新使用预装载机制。**
7. **输入捕获必须设计溢出处理和无效数据过滤。**
8. **每个定时器通道建立资源表，防止 GPIO、DMA、触发源冲突。**
9. **驱动层不直接依赖业务状态机。**
10. **对实际频率、分辨率、误差和最坏延迟建立可测试指标。**

## 8.2 选型决策矩阵

|指标|基本定时器|通用定时器中断|通用定时器硬件模式|DMA|
|---|---|---|---|---|
|复杂度|低|中|中|高|
|精确周期|高|高|很高|很高|
|CPU 占用|低|中|极低|极低|
|灵活性|低|高|高|很高|
|调试难度|低|中|中|高|
|高频适应性|中|低|高|很高|
|适合数据流|低|低|中|很高|

## 8.3 工业级编码规范

- 使用 `uint32_t` 表示频率、计数和时间戳。
- 使用 `uint64_t` 进行参数乘法和累计时间计算。
- 硬件寄存器映射变量必须使用 `volatile`。
- 中断与主循环共享变量必须明确原子性要求。
- 配置函数返回错误码，不使用静默失败。
- 驱动接口中区分：
    - 配置；
    - 启动；
    - 停止；
    - 更新参数；
    - 获取状态；
    - 清除错误。
- 不在 ISR 中调用 `printf`、阻塞锁、堆分配和文件系统接口。
- 对 `ARR == 0`、`PSC == 0`、`CCR > ARR` 做边界检查。
- 通道配置必须检查是否已经被其他模块占用。
- 关键时序参数在启动后读取寄存器回读验证。

## 9. 常见错误与避坑指南

## 9.1 错误一：APB 分频导致定时器时钟算错

### 错误代码

```
/* APB1 = 42 MHz，错误地认为 TIM2 = 42 MHz */
TIM2->PSC = 41U;
TIM2->ARR = 999U;
```

### 根因分析

当 APB1 分频器大于 1 时，某些 STM32 定时器输入时钟为：

```
TIM2CLK = 2 × PCLK1 = 84 MHz
```

实际计数频率为：

```
84 MHz / 42 = 2 MHz
```

实际更新频率：

```
2 MHz / 1000 = 2 kHz
```

而不是预期的 `1 kHz`。

### 正确实现

从 RCC 配置读取：

```
uint32_t timer_clk = rcc_get_timer_clock(TIM2);
timer_calc_timebase(timer_clk, 1000U, 0xFFFFU, &cfg);
```

### 风险影响

- 周期性任务执行频率错误。
- ADC 采样率错误。
- PWM 频率超出功率器件设计范围。
- 通信波特率或协议时序异常。

---

## 9.2 错误二：初始化更新事件没有清除 UIF

### 错误代码

```
TIM6->PSC = 8399U;
TIM6->ARR = 999U;
TIM6->EGR = TIM_EGR_UG;
TIM6->DIER |= TIM_DIER_UIE;
TIM6->CR1 |= TIM_CR1_CEN;
```

### 根因分析

`EGR.UG` 通常会导致 `SR.UIF` 置位。开启中断后，NVIC 可能立即响应。

### 正确实现

```
TIM6->EGR = TIM_EGR_UG;
TIM6->SR = 0U;
TIM6->DIER = TIM_DIER_UIE;
TIM6->CR1 = TIM_CR1_CEN;
```

### 风险影响

- 首次周期异常短。
- 软件状态机提前执行。
- 采样缓存索引错位。
- 启动阶段产生难以复现的竞态问题。

---

## 9.3 错误三：在 ISR 中执行复杂业务

### 错误代码

```
void TIM2_IRQHandler(void)
{
    if (TIM2->SR & TIM_SR_UIF) {
        TIM2->SR = 0U;

        sensor_read_i2c();
        filter_run();
        printf("sensor=%d\r\n", sensor_value);
        storage_write(sensor_value);
    }
}
```

### 根因分析

ISR 中包含：

- 阻塞式 I2C。
- 复杂滤波。
- 不确定时延日志。
- Flash 或文件系统写入。

这会放大系统最坏响应时间，并可能导致更高优先级中断延迟。

### 正确实现

```
void TIM2_IRQHandler(void)
{
    if ((TIM2->SR & TIM_SR_UIF) != 0U) {
        TIM2->SR = (uint16_t)~TIM_SR_UIF;
        g_sample_due = true;
    }
}

void sensor_task(void)
{
    if (g_sample_due) {
        g_sample_due = false;
        sensor_read_async_start();
    }
}
```

### 风险影响

- 丢失输入捕获事件。
- 高优先级中断响应超时。
- RTOS 调度抖动。
- 看门狗复位。
- 低概率死锁或系统卡死。

---

## 9.4 错误四：忽略计数器溢出

### 错误代码

```
uint16_t delta = capture_now - capture_last;
uint32_t frequency = timer_clock / delta;
```

### 根因分析

如果被测周期超过一个计数器回绕周期，单纯的 16 位差值无法区分：

- 一个周期；
- 多个周期；
- 溢出后的有效时间。

### 正确实现

```
uint32_t delta = (uint32_t)((uint16_t)(capture_now -
                                       capture_last));

if (delta == 0U || delta > CAPTURE_MAX_VALID_TICKS) {
    mark_capture_invalid();
} else {
    frequency = timer_counter_clock / delta;
}
```

如果周期可能超过一个计数器周期，应同时维护溢出计数器。

### 风险影响

- 低频测量突然显示高频。
- 转速反馈跳变。
- 保护逻辑误动作。
- 传感器断线被误判为有效信号。

---

## 9.5 错误五：直接在 PWM 周期中途更新 CCR

### 错误代码

```
void pwm_set_duty(uint16_t duty)
{
    TIM1->CCR1 = duty;
}
```

### 根因分析

如果 `CCR1` 没有启用预装载，写入发生在当前 PWM 周期中间时，比较点可能立即改变，形成窄脉冲或异常占空比。

### 正确实现

```
/* 初始化阶段 */
TIM1->CCMR1 |= TIM_CCMR1_OC1PE;

/* 运行期更新 */
TIM1->CCR1 = duty;

/*
 * 由更新事件统一将影子寄存器装载到活动寄存器。
 */
```

### 风险影响

- 电机电流尖峰。
- LED 闪烁。
- 功率 MOSFET 产生异常开关。
- 多通道 PWM 相位不一致。

---

## 9.6 错误六：软件翻转 GPIO 生成高频 PWM

### 错误代码

```
void TIM3_IRQHandler(void)
{
    if (TIM3->SR & TIM_SR_UIF) {
        GPIOA->ODR ^= GPIO_PIN_0;
        TIM3->SR = 0U;
    }
}
```

### 根因分析

输出边沿依赖 ISR 执行时间和系统中断状态，周期和占空比都会受软件路径影响。

### 正确实现

使用定时器通道复用输出：

```
TIM3->CCMR1 = PWM_MODE_1 | TIM_CCMR1_OC1PE;
TIM3->CCER |= TIM_CCER_CC1E;
TIM3->CCR1 = compare;
TIM3->CR1 |= TIM_CR1_CEN;
```

### 风险影响

- PWM 抖动。
- EMI 增大。
- 电机噪声和转矩脉动。
- CPU 占用随 PWM 频率线性上升。

## 10. 多机制组合使用方案

## 10.1 技术协同架构

一个典型的高可靠定时器子系统可以采用以下架构：

```
                    +----------------------+
                    |       业务层         |
                    | 电机 / 传感器 / 控制 |
                    +----------+-----------+
                               |
                    +----------v-----------+
                    |      设备适配层       |
                    |  pwm_set / capture_get|
                    +----------+-----------+
                               |
                    +----------v-----------+
                    |      定时器驱动层      |
                    | 配置 / 状态 / 错误处理 |
                    +----+----------+--------+
                         |          |
              +----------v--+    +--v-----------+
              | 硬件 PWM/OC |    | 输入捕获 DMA |
              +-------------+    +--------------+
                         |          |
                    +----v----------v----+
                    |       定时器硬件    |
                    +---------------------+
```

组合原则：

- 基本定时器：周期性触发。
- 通用定时器 PWM：连续输出。
- 输入捕获：测量外部信号。
- DMA：搬运高频事件数据。
- RTOS 任务：执行非实时业务。
- GPIO 调试点：验证 ISR 和硬件波形。

## 10.2 定时器驱动框架

```
typedef enum {
    TIMER_MODE_BASE,
    TIMER_MODE_PWM,
    TIMER_MODE_CAPTURE,
    TIMER_MODE_OUTPUT_COMPARE
} timer_mode_t;

typedef enum {
    TIMER_EVENT_UPDATE = 1U << 0,
    TIMER_EVENT_CAPTURE = 1U << 1,
    TIMER_EVENT_COMPARE = 1U << 2,
    TIMER_EVENT_ERROR = 1U << 3
} timer_event_t;

typedef struct {
    TIM_TypeDef *instance;
    timer_mode_t mode;
    uint32_t timer_clk_hz;
    uint32_t counter_hz;
    uint32_t period_ticks;
    uint32_t channel;
    volatile uint32_t events;
    bool initialized;
    bool running;
} timer_driver_t;

int timer_driver_init(timer_driver_t *driver,
                      TIM_TypeDef *instance,
                      timer_mode_t mode,
                      uint32_t timer_clk_hz,
                      uint32_t counter_hz,
                      uint32_t period_ticks)
{
    if ((driver == NULL) ||
        (instance == NULL) ||
        (timer_clk_hz == 0U) ||
        (counter_hz == 0U) ||
        (period_ticks == 0U) ||
        (timer_clk_hz < counter_hz)) {
        return TIMER_ERR_PARAM;
    }

    uint32_t psc = (timer_clk_hz / counter_hz) - 1U;

    if (psc > UINT16_MAX || period_ticks > 0x10000U) {
        return TIMER_ERR_RANGE;
    }

    driver->instance = instance;
    driver->mode = mode;
    driver->timer_clk_hz = timer_clk_hz;
    driver->counter_hz = counter_hz;
    driver->period_ticks = period_ticks;
    driver->channel = 0U;
    driver->events = 0U;
    driver->initialized = true;
    driver->running = false;

    instance->CR1 = 0U;
    instance->PSC = psc;
    instance->ARR = period_ticks - 1U;
    instance->EGR = TIM_EGR_UG;
    instance->SR = 0U;

    return TIMER_OK;
}

int timer_driver_start(timer_driver_t *driver)
{
    if ((driver == NULL) || !driver->initialized) {
        return TIMER_ERR_PARAM;
    }

    driver->instance->SR = 0U;
    driver->instance->CR1 |= TIM_CR1_CEN;
    driver->running = true;

    return TIMER_OK;
}

int timer_driver_stop(timer_driver_t *driver)
{
    if ((driver == NULL) || !driver->initialized) {
        return TIMER_ERR_PARAM;
    }

    driver->instance->CR1 &= ~TIM_CR1_CEN;
    driver->running = false;

    return TIMER_OK;
}
```

这个框架还需要根据芯片补充：

- RCC 时钟控制。
- GPIO 复用。
- NVIC 配置。
- 通道映射。
- DMA 配置。
- 中断处理。
- 设备生命周期管理。

## 10.3 基本定时器 + RTOS 事件通知

```
static volatile uint32_t g_tick_count;

void timer_isr(void)
{
    timer_hw_clear_update_flag();
    ++g_tick_count;
    rtos_notify_from_isr(TIMER_TICK_EVENT);
}

void control_task(void *arg)
{
    (void)arg;

    for (;;) {
        uint32_t event = rtos_wait_event(TIMER_TICK_EVENT,
                                         RTOS_WAIT_FOREVER);

        if ((event & TIMER_TICK_EVENT) != 0U) {
            control_loop_step();
        }
    }
}
```

注意：

- 中断只做事件通知。
- 控制循环执行时间必须小于周期。
- 必须检测任务执行超时。
- 如果多个 tick 在任务运行期间到达，需要明确选择：
    - 累积全部事件；
    - 合并事件；
    - 丢弃过期事件；
    - 进行超时补偿。

## 11. 工业级实际案例分析

## 11.1 案例一：无刷风扇转速测量与失速保护

### 需求

- 风扇输出 FG 脉冲。
- 每转 2 个脉冲。
- 转速范围：300 到 6000 RPM。
- 每 100 ms 更新一次转速。
- 低于 200 RPM 持续 500 ms 触发失速保护。
- 输入信号存在毛刺。

### 架构设计

```
TIM2 CH1 输入捕获
    |
    +--> 捕获周期
    +--> 输入滤波
    +--> DMA/中断采集
    |
    +--> 100 ms 任务计算 RPM
    +--> 500 ms 失速确认
```

RPM 计算：

```
frequency_hz = timer_counter_hz / period_ticks

RPM = frequency_hz × 60 / pulses_per_revolution
```

### 核心代码

```
uint32_t fan_rpm_from_period(uint32_t counter_hz,
                             uint32_t period_ticks,
                             uint32_t pulses_per_rev)
{
    if ((counter_hz == 0U) ||
        (period_ticks == 0U) ||
        (pulses_per_rev == 0U)) {
        return 0U;
    }

    uint64_t rpm = (uint64_t)counter_hz * 60ULL;
    rpm /= ((uint64_t)period_ticks * pulses_per_rev);

    return (rpm > UINT32_MAX) ? UINT32_MAX : (uint32_t)rpm;
}
```

### 设计要点

- 使用输入滤波抑制换相噪声。
- 对连续 3 次周期进行中值或平均滤波。
- 设置输入捕获超时，例如 `300 ms` 无边沿则直接判定停转。
- 不在捕获 ISR 中执行 RPM 计算和保护动作。
- 对捕获周期设置上下限，过滤明显异常值。
- 保护逻辑使用“连续低速确认”，避免单次抖动误触发。

## 11.2 案例二：超声波测距

### 需求

- 产生约 `10 us` 触发脉冲。
- 测量 Echo 高电平宽度。
- 距离范围：20 mm 到 4 m。
- 需要处理无回波、超时和多次触发。

### 架构设计

```
TIM3 CH1 单脉冲输出 Trigger
TIM3 CH2 PWM 输入/双边沿捕获 Echo
    |
    +--> 上升沿记录起点
    +--> 下降沿记录终点
    +--> 计算高电平时间
```

距离计算：

```
distance_mm = echo_us × sound_speed_mm_per_us / 2
```

在 25 摄氏度附近：

```
sound_speed ≈ 0.346 mm/us
distance_mm ≈ echo_us × 0.173
```

### 核心代码

```
uint32_t ultrasonic_distance_mm(uint32_t echo_us)
{
    /*
     * 0.173 mm/us 是工程近似值。
     * 高精度产品应根据温度补偿声速。
     */
    return (echo_us * 173U) / 1000U;
}

bool ultrasonic_validate_echo(uint32_t echo_us)
{
    const uint32_t min_echo_us = 120U;
    const uint32_t max_echo_us = 25000U;

    return (echo_us >= min_echo_us) &&
           (echo_us <= max_echo_us);
}
```

### 设计要点

- Trigger 必须由硬件单脉冲产生。
- Echo 测量使用双边沿捕获，不使用 GPIO 中断读取电平。
- 触发间隔必须满足模块的最大回波等待时间。
- 超时必须由另一个基本定时器或比较通道处理。
- 温度补偿：

```
v_sound ≈ 331.3 + 0.606 × temperature_celsius  m/s
```

- 对近距离目标，需要确认输入捕获滤波不会吞掉短回波。

## 11.3 案例三：步进电机变频脉冲输出

### 需求

- 输出 STEP 脉冲。
- 频率从 500 Hz 加速到 100 kHz。
- 运行期间动态改变频率。
- 脉冲高电平至少 2 us。
- CPU 不能参与每个脉冲的 GPIO 翻转。

### 架构设计

```
定时器 PWM/输出比较
    |
    +--> STEP 硬件输出
    +--> ARR 控制脉冲频率
    +--> CCR 控制高电平宽度
    +--> DMA 更新 ARR 实现加减速曲线
```

频率变化：

```
ARR[n] = counter_hz / frequency[n] - 1
```

### 核心代码

```
bool stepper_set_frequency(TIM_TypeDef *tim,
                           uint32_t counter_hz,
                           uint32_t frequency_hz,
                           uint32_t high_ticks)
{
    if ((tim == NULL) ||
        (counter_hz == 0U) ||
        (frequency_hz == 0U) ||
        (high_ticks == 0U)) {
        return false;
    }

    uint32_t period_ticks = counter_hz / frequency_hz;

    if ((period_ticks < 2U) ||
        (high_ticks >= period_ticks) ||
        (period_ticks > 0x10000U)) {
        return false;
    }

    /*
     * 预装载 ARR/CCR，在更新事件边界统一生效。
     */
    tim->ARR = period_ticks - 1U;
    tim->CCR1 = high_ticks;

    return true;
}
```

### 设计要点

- 100 kHz 下，若每个脉冲进入一次 ISR，CPU 负载通常不可接受。
- 使用 PWM 硬件输出保证脉宽。
- 使用 DMA 表驱动加速曲线。
- 停止时必须等待当前脉冲完成，避免产生半脉冲。
- 修改 `ARR` 时确认当前 `CNT` 不会超过新周期导致异常更新。
- 必须定义最大加速度、减速度和突发停止策略。

## 12. 高频问题深度答疑

## 12.1 为什么同样的 PSC 和 ARR，不同定时器频率不同？

因为不同定时器可能挂在不同 APB 总线上，且 APB 分频器对定时器输入时钟的倍频规则可能不同。

因此不能只看：

```
PCLK1 或 PCLK2
```

必须确认：

```
Timer Clock = 哪个 APB 时钟 × 是否存在定时器倍频
```

工程上建议统一提供：

```
uint32_t rcc_get_timer_clock(TIM_TypeDef *tim);
```

所有驱动禁止自行复制时钟树计算逻辑。

---

## 12.2 PSC 应该尽量大还是尽量小？

没有绝对答案。

- `PSC` 小：计数分辨率高，但周期范围小。
- `PSC` 大：周期范围大，但测量量化误差增大。
- PWM 设计中通常希望 `ARR` 尽可能大，以获得更高占空比分辨率。
- 低频输入捕获中，计数频率通常应提高，再使用溢出扩展。
- 高频信号计数可能需要降低计数频率，避免计数器过快回绕。

常用原则：

```
PWM：优先提高 ARR
周期中断：根据目标频率选择易计算参数
输入捕获：优先保证被测周期覆盖至少几百个计数
高速计数：使用硬件计数或 DMA
```

---

## 12.3 更新 ARR 后为什么周期没有立即变化？

常见原因是开启了 `ARR preload`。

此时：

```
CPU 写 ARR
    |
    +--> 写入影子寄存器
    |
更新事件 UEV
    |
    +--> 影子寄存器装载到活动 ARR
```

这是为了防止当前周期中途改变周期边界。对于 PWM、周期调制和多通道同步更新，预装载通常是正确选择。

如果业务要求立即生效，则必须确认：

- 是否关闭预装载；
- 是否主动触发 UEV；
- 是否会截断当前周期；
- 是否会生成异常脉冲。

---

## 12.4 输入捕获中断里应该先读 CCR 还是先清标志？

通常应先读取 `CCRx`，再清除标志，但具体行为依 MCU 手册而定。

原因：

- `CCRx` 是硬件锁存的捕获值。
- 读取顺序可能影响溢出标志或过捕获标志。
- 某些芯片读取 `SR` 再读取 `CCR` 才能正确清除捕获状态。
- 高频信号下，如果清标志后才读 CCR，可能错过后续捕获或覆盖数据。

应按照参考手册规定的顺序实现，并在示波器和压力测试下验证。

---

## 12.5 什么时候使用输入捕获，什么时候使用外部时钟计数？

使用输入捕获：

- 需要知道每个边沿的到达时间。
- 需要测量周期、脉宽和占空比。
- 需要分析抖动、丢脉冲和信号质量。

使用外部时钟计数：

- 只关心固定时间窗内的脉冲数量。
- 信号频率很高。
- 不需要记录每个边沿的时间。
- 希望完全避免捕获 ISR。

频率测量可以采用倒数法和门控法：

```
倒数法：
    测量相邻边沿时间差
    适合低频信号

门控法：
    固定 100 ms 时间窗统计脉冲数
    适合中高频信号
```

---

## 12.6 RTOS 软件定时器和硬件定时器如何分工？

硬件定时器用于：

- 精确边沿。
- PWM。
- ADC/DAC 触发。
- 输入捕获。
- 高速事件计数。
- 实时控制采样。

RTOS 软件定时器用于：

- 非严格实时超时。
- 周期性状态检查。
- 通信保活。
- 业务层重试。
- 低频维护任务。

判断标准不是“哪个更方便”，而是：

```
如果任务对边沿、抖动或采样时刻敏感，使用硬件定时器。
如果任务只要求大致周期且允许调度延迟，使用 RTOS 软件定时器。
```

## 13. 课程核心总结

### 核心要点

- 定时器周期由 `f_tim`、`PSC` 和 `ARR` 共同决定。
- **实际定时器时钟不一定等于 APB 时钟**。
- 基本定时器适合周期节拍和外设触发。
- 通用定时器适合 PWM、输入捕获、输出比较和外部计数。
- PWM 和精确边沿应优先使用硬件输出。
- 高频输入事件应优先使用 DMA 或硬件计数。
- 输入捕获必须处理计数器溢出、过捕获和异常脉宽。
- 更新事件可能同时承担寄存器装载、中断、DMA 和触发输出功能。
- ISR 只负责采集硬件事实和投递事件。
- 预装载机制是避免 PWM 毛刺和实现同步更新的关键。

### 性能排序

按实时输出确定性排序：

```
硬件 PWM/输出比较
    >
定时器 DMA
    >
输入捕获硬件锁存
    >
定时器中断
    >
RTOS 软件定时器
    >
SysTick 轮询
    >
软件延时
```

按实现复杂度排序：

```
基本定时器
    <
PWM
    <
输入捕获
    <
输出比较调度
    <
DMA 波形/捕获
    <
多定时器同步与动态变频
```

### 通用选型结论

- **周期性任务：** 基本定时器或通用定时器更新中断。
- **连续波形输出：** PWM。
- **精确单次脉冲：** 单脉冲模式。
- **周期/脉宽测量：** 输入捕获。
- **高速脉冲统计：** 外部时钟模式。
- **高频数据流：** 输入捕获 DMA。
- **高实时控制：** 硬件定时器触发 + DMA + RTOS 任务处理。

## 16. 实践与进阶路径

## 16.1 梯度实战任务

### 任务一：基本定时器周期中断

要求：

- 使用基本定时器产生 `1 ms` 更新中断。
- 每 1000 次中断翻转一次 GPIO。
- 用逻辑分析仪测量实际 1 秒周期。
- 统计周期误差和 ISR 执行时间。

验收指标：

```
周期误差 <= 0.1%
ISR 执行时间 < 周期的 5%
启动后不存在异常首个中断
```

### 任务二：多频率 PWM 输出

要求：

- 输出 `1 kHz`、`20 kHz` 和 `100 kHz` 三组 PWM。
- 分别测试 10%、50%、90% 占空比。
- 记录频率误差、占空比误差和边沿抖动。
- 动态修改占空比，确认无窄脉冲毛刺。

### 任务三：输入捕获测频

要求：

- 使用信号发生器产生 10 Hz 到 100 kHz 输入。
- 使用输入捕获计算频率。
- 对单周期测量和 16 周期平均进行对比。
- 注入窄毛刺，验证滤波配置。

验收内容：

```
测量范围
频率误差
丢边沿比例
CPU 占用
滤波延迟
```

### 任务四：PWM 输入测量

要求：

- 同时测量周期和高电平时间。
- 输出频率范围 100 Hz 到 20 kHz。
- 占空比范围 5% 到 95%。
- 对输入信号增加抖动和噪声，验证测量稳定性。

### 任务五：DMA 波形输出

要求：

- 使用 DMA 循环更新 `ARR` 或 `CCR`。
- 生成加速、匀速、减速的步进脉冲。
- 禁止 CPU 参与每个脉冲的生成。
- 测量加减速过程中是否存在缺脉冲和异常脉宽。

### 任务六：定时器综合驱动

实现一个统一驱动接口：

```
timer_init()
timer_start()
timer_stop()
timer_set_period()
timer_set_duty()
timer_get_capture()
timer_get_status()
timer_clear_error()
```

要求：

- 配置和运行状态分离。
- 参数有边界检查。
- ISR 与业务层解耦。
- 支持错误状态记录。
- 支持单元测试和硬件回归测试。

## 16.2 性能测试方法

### 周期精度

使用逻辑分析仪：

```
测量连续 N 个周期
计算：
    平均周期
    最大周期
    最小周期
    峰峰值抖动
    标准差
```

### ISR 执行时间

使用 GPIO 包围 ISR：

```
ISR 入口：GPIO 置高
ISR 出口：GPIO 置低
```

记录：

```
t_isr_max
t_isr_min
t_isr_avg
```

实时性设计应以 `t_isr_max` 而不是平均值为依据。

### 输入捕获准确性

使用信号发生器输出已知频率：

```
误差 ppm = (measured - reference) × 1,000,000 / reference
```

分别测试：

- 低频；
- 高频；
- 占空比极限；
- 计数器回绕；
- 输入毛刺；
- 中断抢占；
- DMA 缓冲满载。

### 资源压力测试

必须测试：

- 多个通道同时捕获。
- PWM 与输入捕获并存。
- DMA 与 ADC 共用总线。
- 高优先级通信中断抢占定时器 ISR。
- RTOS 临界区阻塞定时器响应。
- 动态修改 `ARR`、`CCR` 时的输出连续性。

## 16.3 进阶学习方向

- 高级控制定时器：互补 PWM、死区、刹车输入和重复计数器。
- 定时器主从同步与触发链。
- 定时器触发 ADC 注入组和规则组采样。
- 定时器 DMA burst 传输。
- 编码器接口与速度估算。
- 外部时钟模式和门控计数。
- 多定时器相位同步。
- 电机 FOC 中的中心对齐 PWM 与 ADC 采样窗口。
- 高精度时间基准与温度补偿。
- RTOS 中硬件定时器与软件定时器的分层设计。
- 基于示波器、ETM、DWT CYCCNT 和 tracealyzer 的实时性分析。
- 低功耗模式下定时器时钟保持、唤醒和时基漂移问题。
