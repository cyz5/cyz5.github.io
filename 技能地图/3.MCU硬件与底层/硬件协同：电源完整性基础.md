
## 1. 学习目标

### 理解

- 理解**电源完整性（Power Integrity，PI）是负载在规定频率范围、时间尺度和工作边界内获得合格供电电压的能力**。
- 理解电源树、VRM、PCB 平面、过孔、去耦电容、封装和芯片片上电容共同构成完整的电源分配网络（Power Distribution Network，PDN）。
- 理解以下关键关系：
    - 负载瞬态与电压跌落。
    - 允许纹波与目标阻抗。
    - 电容、ESR、ESL 与自谐振。
    - 多电容并联与反谐振。
    - 电源噪声、地弹、时钟抖动和信号完整性。
    - 稳压器控制环路、输出网络与系统稳定性。
- 理解**直流压降合格不代表动态供电合格，低频纹波小也不代表高频 PDN 阻抗足够低**。

### 掌握

- 掌握电源树、电压容差、负载预算、启动时序和故障状态的审查方法。
- 掌握目标阻抗、负载阶跃、去耦容量和走线压降的基础计算。
- 掌握 MLCC 直流偏压、温度、容差和老化对有效容量的影响。
- 掌握 Buck、LDO、负载开关、磁珠和去耦网络的基本选型原则。
- 掌握示波器纹波测量、负载瞬态测试、阻抗扫描和电流波形测量方法。

### 精通

- 能够按频段划分 VRM、大容量电容、板级 MLCC、封装与片上电容的职责。
- 能够识别反谐振、控制环路不稳定、平面谐振、共阻抗耦合和同时开关噪声。
- 能够区分电源源端问题、分配路径问题、负载点问题和测量伪影。
- 能够量化评估压降、纹波、瞬态恢复、热损耗和去耦回路寄生参数。

### 能够设计

- 能够从芯片动态负载和允许电压偏差反推 PDN 目标阻抗。
- 能够设计 MCU、FPGA、SoC、ADC、通信收发器和电机控制器的分层供电架构。
- 能够建立硬件、PCB、固件、测试和生产协同的 PI 验证流程。
- 能够设计具备上电监控、欠压保护、故障记录、降频和安全关断能力的系统。

## 3. 技术概述

### 3.1 核心定义

电源完整性关注负载端实际电压：

Vload(t)=Vsource(t)−ΔVdistribution(t)−ΔVtransient(t)−Vnoise(t)Vload​(t)=Vsource​(t)−ΔVdistribution​(t)−ΔVtransient​(t)−Vnoise​(t)

负载端必须在全部工作条件下满足：

Vmin≤Vload(t)≤VmaxVmin​≤Vload​(t)≤Vmax​

其中工作条件至少包括：

- 输入电压上下限。
- 全温范围。
- 静态和峰值负载。
- 多电源域同时切换。
- 启动、关断、复位和休眠唤醒。
- 通信突发、Flash 擦写、射频发射和电机换相。
- 器件容差、老化与不同生产批次。
- EFT、ESD、浪涌等外部干扰。

### 3.2 PDN 的组成

```
外部电源
└─ 连接器与保护
   └─ 输入滤波
      └─ DC/DC 或 LDO
         └─ 大容量储能电容
            └─ PCB 电源平面/走线
               └─ 板级去耦电容
                  └─ BGA/QFN/LQFP 封装寄生
                     └─ 芯片片上电容
                        └─ 晶体管负载
```

每一级都有非理想参数：

- 电阻：产生直流压降和功耗。
- 电感：限制快速电流变化。
- 电容：提供局部电荷，但存在 ESR 和 ESL。
- 控制环路：只能在有限带宽内调节。
- 平面与过孔：产生频率相关的阻抗和谐振。

### 3.3 电源完整性的技术价值

PI 设计不足可能表现为：

- 随机复位、HardFault、ECC 错误。
- DDR、QSPI、Ethernet 或高速 ADC 偶发错误。
- PLL 失锁、时钟抖动增加。
- ADC ENOB、SNR 和 SFDR 下降。
- GPIO 门限漂移、地弹和误触发。
- 开关电源振荡、啸叫或过热。
- 启动失败、反复重启或上电时序违规。
- EMC 测试失败。
- 板卡仅在高温、低压或特定业务负载下失效。

### 3.4 主流技术分支

|分支|关注内容|典型指标|
|---|---|---|
|电源架构|电源树、效率、时序、冗余|电压、功率、启动顺序|
|直流完整性|走线和平面压降|IR Drop、温升|
|低频 PI|VRM 环路和大负载变化|稳定性、恢复时间|
|中频 PI|储能电容和板级 PDN|目标阻抗、反谐振|
|高频 PI|MLCC、封装和片上电容|ESL、地弹、SSO|
|模拟电源完整性|基准、ADC、PLL、RF|噪声谱密度、PSRR|
|电源时序|上电、掉电、复位|Ramp、Delay、PG|
|电源可靠性|降额、热、故障保护|结温、寿命、SOA|
|PI 测试|时域与频域验证|Ripple、Z(f)、瞬态响应|

## 5. 底层原理与功能特性深度解析

### 5.1 目标阻抗

PDN 设计的基础关系为：

ΔV=ΔI⋅ZPDNΔV=ΔI⋅ZPDN​

允许的最大目标阻抗为：

Ztarget=ΔVallowΔIstepZtarget​=ΔIstep​ΔVallow​​

假设：

- 核心电压：1.0 V。
- 允许动态偏差：±30 mV。
- 最大负载阶跃：2 A。

则：

Ztarget=0.032=15mΩZtarget​=20.03​=15mΩ

这意味着在目标频率范围内，应尽量保证：

∣ZPDN(f)∣<15mΩ∣ZPDN​(f)∣<15mΩ

#### 使用边界

目标阻抗方法必须明确：

- ΔVallowΔVallow​ 是总容差还是仅分配给动态噪声的预算。
- ΔIstepΔIstep​ 是整板峰值电流还是特定时间尺度内的电流变化。
- VRM 静态精度、IR Drop、纹波和温漂会消耗电压预算。
- 平坦低于目标阻抗是设计目标，不代表任何频率下都能理想实现。

#### 电压预算示例

```
芯片允许电压误差：        ±50 mV
├─ VRM 静态误差：          10 mV
├─ 直流路径压降变化：       8 mV
├─ 温度与器件容差：         7 mV
├─ 低频纹波预算：          10 mV
└─ 动态瞬态剩余预算：      15 mV
```

不能直接把全部 ±50 mV 都用于负载瞬态设计。

### 5.2 PDN 的频段分工

负载电流变化跨越多个时间尺度，单一器件不能覆盖全部频率。

```
低频                                                  高频
DC ───── kHz ───── MHz ───── 数十/数百 MHz ───── GHz
│         │          │               │               │
VRM       大容量电容   板级 MLCC       封装电容         片上电容
```

典型职责如下：

|频段|主要供能组件|限制因素|
|---|---|---|
|DC～控制环路带宽|VRM|环路带宽、输出能力|
|数百 Hz～数百 kHz|Bulk 电容|ESR、容量、布局|
|数百 kHz～数十 MHz|板级 MLCC|ESL、安装电感|
|数十 MHz～数百 MHz|小封装 MLCC、平面对|过孔和封装寄生|
|数百 MHz 以上|封装与片上电容|外部路径电感过大|

具体边界取决于器件和布局，表中频段不能作为统一规则。

### 5.3 电容的真实模型

理想电容阻抗为：

ZC=1jωCZC​=jωC1​

真实电容可近似为串联 RLC：

Z(jω)=ESR+jωESL+1jωCZ(jω)=ESR+jωESL+jωC1​

自谐振频率：

fSRF=12πESL⋅CfSRF​=2πESL⋅C​1​

在不同频段：

```
低于 SRF：主要表现为电容性
等于 SRF：阻抗接近 ESR 最小值
高于 SRF：主要表现为电感性
```

例如：

- C=100nFC=100nF
- 总 ESL 为 1 nH

则：

fSRF≈12π1nH⋅100nF≈15.9MHzfSRF​≈2π1nH⋅100nF​1​≈15.9MHz

高于该频率后，继续把它视作理想 100 nF 电容将产生错误结论。

### 5.4 MLCC 有效容量

MLCC 标称 10 µF 不代表工作时仍为 10 µF。有效容量受以下因素影响：

- 直流偏压。
- 介质类型。
- 封装尺寸。
- 温度。
- 制造容差。
- 老化。
- AC 激励幅度。

可使用：

Ceffective=Cnominal⋅Kbias⋅Ktemp⋅Ktol⋅KagingCeffective​=Cnominal​⋅Kbias​⋅Ktemp​⋅Ktol​⋅Kaging​

假设：

- 标称容量 10 µF。
- 直流偏压系数 0.45。
- 温度系数 0.90。
- 负容差系数 0.80。
- 老化系数 0.95。

则：

Ceffective=10μF×0.45×0.90×0.80×0.95≈3.08μFCeffective​=10μF×0.45×0.90×0.80×0.95≈3.08μF

因此，稳压器数据手册要求“最少 10 µF 输出电容”时，应确认要求指的是**标称容量还是最差条件有效容量**。

### 5.5 负载瞬态与储能计算

在稳压器控制环路尚未响应的时间内，局部电容承担负载阶跃：

ΔVC=ΔI⋅ΔtCΔVC​=CΔI⋅Δt​

同时还要考虑 ESR 引起的瞬时跳变：

ΔVESR=ΔI⋅ESRΔVESR​=ΔI⋅ESR

ESL 引起的电压变化：

ΔVESL=ESL⋅dIdtΔVESL​=ESL⋅dtdI​

总跌落可近似为：

ΔV≈ΔI⋅ESR+ESL⋅dIdt+ΔI⋅ΔtCΔV≈ΔI⋅ESR+ESL⋅dtdI​+CΔI⋅Δt​

例如：

- 负载阶跃 1 A。
- 稳压环路有效响应时间 20 µs。
- 允许电容放电造成 30 mV 跌落。

所需有效容量：

C≥1A×20μs30mV≈667μFC≥30mV1A×20μs​≈667μF

这个结果说明：若完全依靠电容支撑 20 µs，容量会很大。工程上需要联合优化：

- 提高控制环路响应。
- 降低供电路径阻抗。
- 减小负载阶跃。
- 增加局部储能。
- 采用动态电压调节或负载分级启动。

### 5.6 安装电感与去耦布局

电容本体 ESL 只是总寄生的一部分。安装电感还包括：

- 电容焊盘。
- 电源走线。
- 地走线。
- 电源和地过孔。
- 平面扩散电感。
- 芯片封装路径。

不合理布局：

```
电源平面 ────── 电容 ────── 芯片引脚
                    │
                  长地线
                    │
                   GND
```

推荐布局：

```
电源平面
   │
近端电源过孔
   │
去耦电容 ── 最短宽连接 ── 芯片电源引脚
   │
近端地过孔
   │
完整地平面
```

关键原则：

- 电容必须靠近**所服务的电源引脚或电源域**。
- 电源和地回路面积应最小。
- 大容量电容靠近负载区域不等于高频去耦有效。
- BGA 器件应结合逃线、过孔阵列和引脚分组布置电容。
- 同一电源域的去耦要考虑电流路径，不按外观均匀摆放。

### 5.7 多电容并联与反谐振

两个不同容值电容并联时，一个可能已经呈感性，另一个仍呈容性，从而形成反谐振峰。

简化反谐振频率：

fanti≈12πLeqCeqfanti​≈2πLeq​Ceq​​1​

若阻尼不足，反谐振频率处的阻抗可能高于单颗电容方案。

#### 抑制手段

- 优先使用模型一致的同容值电容阵列。
- 引入适度 ESR 或阻尼网络。
- 使用聚合物电容提供宽频阻尼。
- 避免无依据地按十倍容值级联。
- 使用厂商 S 参数或宽带模型仿真。
- 通过阻抗扫描验证实际 PDN。

**结论：去耦不是“100 pF 到 100 µF 每档各放一颗”。**

### 5.8 VRM 控制环路

开关稳压器通过反馈环路调节输出。环路增益可写为：

T(s)=Gpower(s)⋅Gcomp(s)⋅H(s)T(s)=Gpower​(s)⋅Gcomp​(s)⋅H(s)

稳定性通常关注：

- 交越频率。
- 相位裕量。
- 增益裕量。
- 输出电容及 ESR。
- 输入滤波器与转换器负阻抗效应。
- 轻载模式、连续导通模式和跳脉冲模式切换。

一般工程目标常见为：

- 相位裕量大于约 45°。
- 更稳健设计通常目标为 50°～60°以上。
- 增益裕量大于约 10 dB。

实际要求以控制器厂商建议和动态测试结果为准。

#### 常见不稳定原因

- 输出电容有效容量不足。
- 使用超低 ESR MLCC 改变了原补偿设计。
- 反馈走线拾取 SW 节点噪声。
- 输入 LC 滤波器与转换器相互作用。
- 电感饱和导致功率级参数突变。
- 布局寄生未纳入环路模型。
- 强制 PWM、PFM、Burst 模式切换造成低频包络。

### 5.9 LDO 的 PI 边界

LDO 常被视为“低噪声万能器件”，但仍需检查：

- Dropout。
- 最小和最大输出电容。
- 输出电容 ESR 稳定区间。
- PSRR 随频率变化。
- 输入噪声和参考噪声。
- 启动时间。
- 反向电流。
- 热耗散。

LDO 功耗：

PLDO=(Vin−Vout)Iout+VinIqPLDO​=(Vin​−Vout​)Iout​+Vin​Iq​

例如：

- 输入 5 V。
- 输出 3.3 V。
- 负载 300 mA。
- 忽略静态电流。

P≈(5−3.3)×0.3=0.51WP≈(5−3.3)×0.3=0.51W

结温估算：

TJ=TA+P⋅θJATJ​=TA​+P⋅θJA​

若：

### 5.10 磁珠隔离

磁珠不是理想高频开路，其阻抗由频率决定：

Zbead(f)=R(f)+jX(f)Zbead​(f)=R(f)+jX(f)

磁珠与负载侧电容会形成 LC 或 RLC 网络，可能出现谐振。还需检查：

- 额定电流。
- 直流电阻。
- 偏置电流下阻抗下降。
- 温升。
- 谐振峰值。
- 负载瞬态压降。

典型结构：

```
数字电源 ── 磁珠 ── 模拟电源
                      │
                    本地电容
                      │
                     GND
```

该结构适用于限制某些频段的噪声传播，但不应代替：

- 正确的电源分区。
- 连续地平面。
- 合理的回流管理。
- 低噪声稳压器。
- 对敏感频段的实际阻抗验证。

### 5.11 地弹与同时开关噪声

- 避免大量 IO 在同一周期翻转。
- 分组启动外设。
- 控制总线驱动强度。

### 5.12 电源时序与反向供电

多电源域系统必须检查：

- 上电顺序。
- 电压斜率。
- Power-Good 延迟。
- 复位释放时间。
- 掉电顺序。
- IO 是否在对端掉电时仍驱动。
- ESD 二极管是否产生反向供电。
- 电源域间最大允许压差。

典型反向供电路径：

```
已上电 MCU GPIO
       │
       ▼
未上电外设输入引脚
       │
内部 ESD 二极管
       │
       ▼
外设 VDD 被异常抬高
```

后果包括：

- 外设进入未定义状态。
- 上电时序违规。
- 静态电流增大。
- 闩锁风险。
- 掉电后系统无法彻底复位。

### 5.13 电源监控与故障记录

生产系统应监控关键电源，而不是只在启动时读一次 ADC。

```
#include <stdint.h>
#include <stdbool.h>

typedef enum {
    RAIL_STATE_UNKNOWN = 0,
    RAIL_STATE_NORMAL,
    RAIL_STATE_UNDERVOLTAGE,
    RAIL_STATE_OVERVOLTAGE
} rail_state_t;

typedef struct {
    uint16_t low_trip_mv;
    uint16_t low_release_mv;
    uint16_t high_release_mv;
    uint16_t high_trip_mv;
    uint16_t debounce_samples;
    uint16_t violation_count;
    rail_state_t state;
} rail_monitor_t;

bool rail_monitor_update(rail_monitor_t *monitor, uint16_t voltage_mv)
{
    if ((monitor == NULL) ||
        (monitor->debounce_samples == 0U) ||
        !(monitor->low_trip_mv < monitor->low_release_mv) ||
        !(monitor->low_release_mv < monitor->high_release_mv) ||
        !(monitor->high_release_mv < monitor->high_trip_mv)) {
        return false;
    }

    switch (monitor->state) {
    case RAIL_STATE_UNDERVOLTAGE:
        if (voltage_mv >= monitor->low_release_mv) {
            monitor->state = RAIL_STATE_NORMAL;
            monitor->violation_count = 0U;
        }
        break;

    case RAIL_STATE_OVERVOLTAGE:
        if (voltage_mv <= monitor->high_release_mv) {
            monitor->state = RAIL_STATE_NORMAL;
            monitor->violation_count = 0U;
        }
        break;

    case RAIL_STATE_UNKNOWN:
    case RAIL_STATE_NORMAL:
    default:
        if (voltage_mv < monitor->low_trip_mv) {
            if (++monitor->violation_count >=
                monitor->debounce_samples) {
                monitor->state = RAIL_STATE_UNDERVOLTAGE;
            }
        } else if (voltage_mv > monitor->high_trip_mv) {
            if (++monitor->violation_count >=
                monitor->debounce_samples) {
                monitor->state = RAIL_STATE_OVERVOLTAGE;
            }
        } else {
            monitor->state = RAIL_STATE_NORMAL;
            monitor->violation_count = 0U;
        }
        break;
    }

    return true;
}
```

设计注意事项：

- 欠压监控必须有迟滞，避免门限附近反复切换。
- 软件采样不能替代硬件 Brownout 和独立复位监控器。
- ADC 带宽可能无法捕获纳秒级或微秒级跌落。
- 快速瞬态应使用硬件比较器、示波器或专用监控器。

## 8. 工程最佳实践

### 8.1 设计原则

1. **先建立电压、电流和功率预算，再选稳压器。**
2. **用有效容量而不是标称容量完成设计。**
3. **去耦设计同时优化电容、焊盘、过孔、平面和封装。**
4. **目标阻抗必须按电源域和频段定义。**
5. **反馈取样必须代表真正需要调节的位置。**
6. **开关电源高 di/dt 热回路面积必须最小。**
7. **SW 节点铜面积只满足电流和热需求，不能无节制扩大。**
8. **模拟地与数字地优先通过回流管理隔离，而不是粗暴分割。**
9. **电源时序必须覆盖上电、关断、Brownout 和异常重启。**
10. **电源监控应与复位、看门狗、安全输出和日志协同。**
11. **所有电源轨均需定义测试点，但测试点不能形成高频长 Stub。**
12. **仿真模型必须包含 ESR、ESL、DC Bias 和安装寄生。**

### 8.2 电源选型决策矩阵

评分 1 表示差，5 表示优秀。

|方案|效率|噪声|瞬态能力|热性能|成本|设计难度|
|---|---|---|---|---|---|---|
|单级 LDO|1～4|5|3|1～3|5|5|
|单级 Buck|5|2～3|4|4～5|4|3|
|Buck + LDO|3～4|5|4|3|2～3|3|
|多相 Buck|5|3|5|5|1|1|
|隔离 DC/DC + LDO|2～3|4|3|2～3|1|2|

### 8.3 工业级原理图审查项

- 输入电压范围是否覆盖浪涌和掉电。
- 保护器件能量等级是否足够。
- 稳压器绝对最大值和推荐工作范围是否满足。
- 电感峰值电流和饱和电流是否满足。
- MOSFET、二极管和电容是否充分降额。
- 输出电容有效值和 ESR 是否满足稳定要求。
- 补偿参数是否对应实际 L/C/ESR。
- Enable、PG 和复位门限是否确定。
- 反馈分压是否考虑偏置电流和噪声。
- 是否存在反向供电。
- 是否有放电路径。
- 测试点和电流测量位置是否充分。

### 8.4 PCB 审查项

- 输入电容、功率开关、电感和输出电容位置。
- 高 di/dt 回路面积。
- SW 节点面积及其下方/邻层布线。
- Bootstrap 回路。
- 反馈 Kelvin 取样和安静地。
- 电源平面瓶颈、过孔数量和铜厚。
- 去耦回路长度。
- 模拟电源与数字电源的实际回流。
- 热焊盘、散热过孔和铜扩散。
- 大电流路径是否穿过敏感器件区域。

关键电源状态必须显式建模：

禁止：

- 忽略电源稳定时间。

- 电压恢复后无迟滞地频繁重启负载。

## 9. 常见错误与避坑指南

### 9.1 错误一：按标称容量设计输出电容

#### 错误代码

```
#define OUTPUT_CAPACITANCE_UF  10U

bool regulator_configuration_valid(void)
{
    /*
     * 错误：仅按 BOM 标称值判断，
     * 未考虑 DC Bias、温度、容差和老化。
     */
    return OUTPUT_CAPACITANCE_UF >= 10U;
}
```

#### 根因分析

10 µF MLCC 在实际偏压下可能只剩 3～6 µF。若稳压器要求最小有效输出容量为 8 µF，设计将不满足稳定性或瞬态要求。

#### 正确实现

设计阶段使用最差有效值，并由器件数据库或计算表生成参数：

```
typedef struct {
    uint32_t nominal_nf;
    uint16_t bias_factor_permille;
    uint16_t temperature_factor_permille;
    uint16_t tolerance_factor_permille;
    uint16_t aging_factor_permille;
} capacitor_model_t;

uint32_t capacitor_effective_nf(const capacitor_model_t *cap)
{
    if (cap == NULL) {
        return 0U;
    }

    uint64_t value = cap->nominal_nf;

    value = value * cap->bias_factor_permille / 1000U;
    value = value * cap->temperature_factor_permille / 1000U;
    value = value * cap->tolerance_factor_permille / 1000U;
    value = value * cap->aging_factor_permille / 1000U;

    return (value > UINT32_MAX) ? UINT32_MAX : (uint32_t)value;
}
```

#### 风险影响

- 稳压器振荡。
- 负载瞬态越界。
- 低温或高温启动失败。
- 不同电容品牌替换后批量失效。

### 9.2 错误二：所有电源引脚共用一个远端去耦电容

#### 错误实现

```
MCU 多个 VDD 引脚
├─ 长走线
├─ 长走线
└─ 统一连接到板边的一颗 10 µF 电容
```

#### 根因分析

高频下，走线和过孔电感使远端电容无法及时向芯片供电。大容量不能补偿过大的安装电感：

V=LdIdtV=LdtdI​

#### 正确实现

- 每个关键电源引脚或引脚组配置近端去耦。
- 使用短、宽连接。
- 电源和地过孔紧靠电容焊盘。
- 电源域入口配置适当 Bulk。
- 根据封装电源引脚分布建立去耦映射表。

#### 固件辅助验证

```
bool board_run_io_switching_stress_test(uint32_t cycles)
{
    if (cycles == 0U) {
        return false;
    }

    for (uint32_t i = 0U; i < cycles; ++i) {
        gpio_write_bus(0x0000U);
        gpio_write_bus(0xFFFFU);

        if (platform_brownout_pending()) {
            gpio_write_bus(0x0000U);
            return false;
        }
    }

    gpio_write_bus(0x0000U);
    return true;
}
```

#### 风险影响

- 同时开关输出时复位。
- GPIO 串扰和地弹。
- ADC 转换噪声增大。
- EMC 测试中随机故障。

### 9.3 错误三：使用长地夹测量电源纹波

#### 错误操作

```
被动探头尖端接 VDD
10 cm 鳄鱼夹地线接远端 GND
示波器全带宽测得 150 mVpp 振铃
```

#### 根因分析

探头地线寄生电感与探头输入电容形成谐振，测得的高频尖峰可能是测量回路伪影。

#### 正确实现

```
优先顺序：
1. 电源轨专用低噪声探头
2. 同轴焊接探测 + 合适端接
3. 被动探头短地弹簧
4. 在负载电源/地最近点测量
```

同时记录：

- 20 MHz 限带结果。
- 全带宽结果。
- 负载模式。
- 探头和测量位置。
- 峰值统计周期。

#### 风险影响

- 对不存在的问题进行整改。
- 错误修改补偿网络。
- 忽略真实的低频跌落。
- 测试结果无法复现。

### 9.4 错误四：欠压时仍继续写 Flash

#### 错误代码

```
void power_fault_handler(void)
{
    /*
     * 错误：电源已经下降，此时执行大块 Flash 写入。
     */
    flash_write(CONFIG_ADDRESS,
                &runtime_config,
                sizeof(runtime_config));

    system_reset();
}
```

#### 根因分析

Flash 擦写需要：

- 最低工作电压。
- 足够保持时间。
- 稳定时钟。
- 较高瞬态电流。

欠压期间写入可能破坏当前数据、相邻数据或元数据。

#### 正确实现

使用硬件提前告警、预留保持时间，并只写入小型掉电日志；配置数据采用事务式双备份：

```
typedef struct {
    uint32_t sequence;
    uint32_t reset_reason;
    uint32_t crc32;
} power_fail_record_t;

void power_fail_isr(void)
{
    power_fail_record_t record;

    platform_disable_high_power_loads();
    platform_force_outputs_safe();

    record.sequence = backup_counter_increment();
    record.reset_reason = RESET_REASON_POWER_FAIL;
    record.crc32 = crc32_compute(&record,
        sizeof(record) - sizeof(record.crc32));

    /*
     * 仅当储能时间经过验证且存储器支持时才执行。
     * 更稳妥的实现可写入 FRAM/MRAM 或备份 SRAM。
     */
    if (platform_power_hold_time_sufficient()) {
        nonvolatile_emergency_write(&record, sizeof(record));
    }

    platform_wait_for_reset();
}
```

#### 风险影响

- 配置损坏。
- Bootloader 无法启动。
- 文件系统损坏。
- 现场出现不可恢复设备。

### 9.5 错误五：磁珠后无限增加 MLCC

#### 错误实现

```
3.3 V ── 磁珠 ── 100 nF + 1 µF + 10 µF + 22 µF ── AVDD
```

未分析磁珠与电容形成的谐振。

#### 根因分析

磁珠在某频段表现为电感，与低 ESR MLCC 形成高 Q 网络。负载阶跃可能激发明显振铃。

#### 正确实现

- 获取磁珠偏置电流下阻抗曲线。
- 使用电容实际 RLC 模型。
- 仿真输入与输出阻抗。
- 必要时增加阻尼。
- 测试 AVDD 的负载阶跃和噪声谱。
- 如果噪声要求严格，评估低噪声 LDO 替代方案。

#### 风险影响

- 模拟电源振铃。
- ADC 噪声增大。
- PLL 失锁或抖动增加。
- 某一业务频率下出现周期性错误。

### 9.6 错误六：反馈线从开关节点附近穿过

#### 错误布局

```
Buck SW 节点 ═══════════
反馈线       ───────────  与 SW 长距离平行
反馈分压地接入功率回流区
```

#### 根因分析

SW 节点具有高 dv/dtdv/dt，反馈线通过寄生电容拾取噪声。反馈地共享大电流路径后，还会把功率地压降直接叠加到反馈信号。

#### 正确实现

- 反馈从输出电容或负载点 Kelvin 取样。
- 反馈线远离 SW、电感和栅极驱动节点。
- 反馈分压靠近控制器。
- 反馈地接入安静参考点。
- 必要时按数据手册配置前馈或滤波电容。

#### 风险影响

- 输出抖动。
- 次谐波或异常脉冲。
- 负载调整率变差。
- EMI 和音频噪声恶化。

### 9.7 错误七：软件轮询代替硬件 Brownout

#### 错误代码

```
void main_loop(void)
{
    if (adc_read_supply_mv() < 3000U) {
        system_reset();
    }
}
```

#### 根因分析

- ADC 采样率和软件调度延迟不足以捕获快速跌落。
- ADC 参考也可能随供电下降。
- CPU 可能在执行判断前已经进入非法状态。
- 软件复位无法保证输出立即进入安全状态。

#### 正确实现

```
void power_protection_init(void)
{
    platform_configure_brownout_reset(BOR_LEVEL_SAFE);
    platform_configure_power_voltage_detector(PVD_LEVEL_WARNING);
    platform_enable_pvd_interrupt();
}

void pvd_warning_isr(void)
{
    platform_force_outputs_safe();
    platform_disable_noncritical_loads();
    fault_log_stage_in_backup_ram(FAULT_SUPPLY_LOW);

    /*
     * 最终复位由 BOR 或独立电源监控器保证。
     */
}
```

#### 风险影响

- CPU 跑飞。
- 功率输出失控。
- 非易失存储损坏。
- 欠压时系统无法可靠复位。

### 10.2 组合设计模式

工业级 PI 设计推荐使用：

- **硬件稳压与限流**：保证基本供电边界。
- **本地分层去耦**：覆盖不同频率的负载电流。
- **硬件电压监控**：快速识别欠压和过压。
- **复位与看门狗**：在 CPU 不可信时完成恢复。
- **固件负载调度**：减少同时浪涌。
- **降频和功能降级**：降低故障期间的动态电流。
- **非易失故障记录**：保留现场证据。
- **独立安全关断**：防止电源异常导致危险输出。

### 10.3 完整电源管理代码框架
```
#include <stdint.h>
#include <stdbool.h>

typedef enum {
    PM_STATE_OFF = 0,
    PM_STATE_PRECHARGE,
    PM_STATE_RAIL_START,
    PM_STATE_VERIFY,
    PM_STATE_RUN,
    PM_STATE_DEGRADED,
    PM_STATE_FAULT
} pm_state_t;

typedef enum {
    PM_OK = 0,
    PM_ERR_ARGUMENT,
    PM_ERR_INPUT_VOLTAGE,
    PM_ERR_RAIL_TIMEOUT,
    PM_ERR_RAIL_RANGE,
    PM_ERR_POWER_GOOD
} pm_result_t;

typedef struct {
    pm_state_t state;
    uint16_t input_mv;
    uint16_t rail_3v3_mv;
    uint16_t rail_1v2_mv;
    uint32_t fault_bitmap;
    uint32_t brownout_count;
} power_manager_t;

enum {
    PM_FAULT_INPUT_UNDERVOLTAGE = 1UL << 0,
    PM_FAULT_INPUT_OVERVOLTAGE  = 1UL << 1,
    PM_FAULT_3V3_TIMEOUT        = 1UL << 2,
    PM_FAULT_3V3_RANGE          = 1UL << 3,
    PM_FAULT_1V2_TIMEOUT        = 1UL << 4,
    PM_FAULT_1V2_RANGE          = 1UL << 5,
    PM_FAULT_POWER_GOOD         = 1UL << 6,
    PM_FAULT_BROWNOUT           = 1UL << 7,
    PM_FAULT_WATCHDOG           = 1UL << 8
};

/*
 * 以下阈值必须依据实际系统电源规格、采样误差、
 * ADC 量化误差、温漂和保护器件容差进行分配。
 */
#define INPUT_MIN_MV             9000U
#define INPUT_MAX_MV            36000U

#define RAIL_3V3_MIN_MV          3135U
#define RAIL_3V3_MAX_MV          3465U

#define RAIL_1V2_MIN_MV          1140U
#define RAIL_1V2_MAX_MV          1260U

#define POWER_RAIL_TIMEOUT_MS      100U
#define POWER_VERIFY_TIMEOUT_MS     50U

#define PM_RETRY_MAX                 2U

static bool voltage_in_range(uint16_t voltage_mv,
                             uint16_t min_mv,
                             uint16_t max_mv)
{
    return (voltage_mv >= min_mv) &&
           (voltage_mv <= max_mv);
}

static pm_result_t pm_check_input(power_manager_t *pm)
{
    if (pm == NULL) {
        return PM_ERR_ARGUMENT;
    }

    pm->input_mv = platform_measure_input_voltage_mv();

    if (pm->input_mv < INPUT_MIN_MV) {
        pm->fault_bitmap |= PM_FAULT_INPUT_UNDERVOLTAGE;
        return PM_ERR_INPUT_VOLTAGE;
    }

    if (pm->input_mv > INPUT_MAX_MV) {
        pm->fault_bitmap |= PM_FAULT_INPUT_OVERVOLTAGE;
        return PM_ERR_INPUT_VOLTAGE;
    }

    return PM_OK;
}

static pm_result_t pm_enable_3v3(power_manager_t *pm)
{
    if (pm == NULL) {
        return PM_ERR_ARGUMENT;
    }

    platform_rail_enable(RAIL_3V3, true);

    if (!platform_wait_power_good(RAIL_3V3,
                                  POWER_RAIL_TIMEOUT_MS)) {
        pm->fault_bitmap |= PM_FAULT_3V3_TIMEOUT;
        return PM_ERR_RAIL_TIMEOUT;
    }

    pm->rail_3v3_mv = platform_measure_rail_voltage_mv(RAIL_3V3);

    if (!voltage_in_range(pm->rail_3v3_mv,
                          RAIL_3V3_MIN_MV,
                          RAIL_3V3_MAX_MV)) {
        pm->fault_bitmap |= PM_FAULT_3V3_RANGE;
        return PM_ERR_RAIL_RANGE;
    }

    return PM_OK;
}

static pm_result_t pm_enable_1v2(power_manager_t *pm)
{
    if (pm == NULL) {
        return PM_ERR_ARGUMENT;
    }

    platform_rail_enable(RAIL_1V2, true);

    if (!platform_wait_power_good(RAIL_1V2,
                                  POWER_RAIL_TIMEOUT_MS)) {
        pm->fault_bitmap |= PM_FAULT_1V2_TIMEOUT;
        return PM_ERR_RAIL_TIMEOUT;
    }

    pm->rail_1v2_mv = platform_measure_rail_voltage_mv(RAIL_1V2);

    if (!voltage_in_range(pm->rail_1v2_mv,
                          RAIL_1V2_MIN_MV,
                          RAIL_1V2_MAX_MV)) {
        pm->fault_bitmap |= PM_FAULT_1V2_RANGE;
        return PM_ERR_RAIL_RANGE;
    }

    return PM_OK;
}

static pm_result_t pm_verify_all_rails(power_manager_t *pm)
{
    uint32_t start_ms;

    if (pm == NULL) {
        return PM_ERR_ARGUMENT;
    }

    start_ms = platform_get_tick_ms();

    while ((platform_get_tick_ms() - start_ms) <
           POWER_VERIFY_TIMEOUT_MS) {
        pm->rail_3v3_mv =
            platform_measure_rail_voltage_mv(RAIL_3V3);

        pm->rail_1v2_mv =
            platform_measure_rail_voltage_mv(RAIL_1V2);

        if (!voltage_in_range(pm->rail_3v3_mv,
                              RAIL_3V3_MIN_MV,
                              RAIL_3V3_MAX_MV)) {
            continue;
        }

        if (!voltage_in_range(pm->rail_1v2_mv,
                              RAIL_1V2_MIN_MV,
                              RAIL_1V2_MAX_MV)) {
            continue;
        }

        if (!platform_power_good_all()) {
            continue;
        }

        return PM_OK;
    }

    pm->fault_bitmap |= PM_FAULT_POWER_GOOD;
    return PM_ERR_POWER_GOOD;
}

static void pm_enter_safe_state(power_manager_t *pm)
{
    if (pm == NULL) {
        return;
    }

    /*
     * 安全动作必须在软件最小依赖下完成。
     * 对电机、加热器、继电器等危险负载，
     * 应同时由硬件互锁、比较器或驱动器 EN/BREAK 引脚保证。
     */
    platform_force_outputs_safe();

    platform_disable_high_power_loads();

    platform_rail_enable(RAIL_1V2, false);
    platform_rail_enable(RAIL_3V3, false);

    pm->state = PM_STATE_FAULT;
}

static void pm_record_failure(const power_manager_t *pm,
                              pm_result_t result)
{
    if (pm == NULL) {
        return;
    }

    platform_fault_log_write(FAULT_POWER_MANAGER,
                             (uint32_t)result,
                             pm->fault_bitmap,
                             pm->input_mv,
                             pm->rail_3v3_mv,
                             pm->rail_1v2_mv);
}

pm_result_t power_manager_start(power_manager_t *pm)
{
    pm_result_t result;
    uint32_t retry = 0U;

    if (pm == NULL) {
        return PM_ERR_ARGUMENT;
    }

    pm->state = PM_STATE_OFF;
    pm->fault_bitmap = 0U;
    pm->brownout_count = 0U;
    pm->input_mv = 0U;
    pm->rail_3v3_mv = 0U;
    pm->rail_1v2_mv = 0U;

    platform_force_outputs_safe();

    /*
     * 先检查输入，再打开任何下游电源。
     */
    result = pm_check_input(pm);
    if (result != PM_OK) {
        pm_record_failure(pm, result);
        pm_enter_safe_state(pm);
        return result;
    }

    pm->state = PM_STATE_PRECHARGE;

    /*
     * 预充电阶段可用于：
     * 1. 限制大容量电容的浪涌电流；
     * 2. 等待输入滤波网络稳定；
     * 3. 检查输入电压是否持续有效。
     */
    platform_input_precharge_enable(true);
    platform_delay_ms(2U);

    result = pm_check_input(pm);
    if (result != PM_OK) {
        pm_record_failure(pm, result);
        pm_enter_safe_state(pm);
        return result;
    }

    pm->state = PM_STATE_RAIL_START;

    /*
     * 必须限制启动重试次数。
     * 无限重试会导致电源反复冲击和故障日志刷写。
     */
    for (retry = 0U; retry <= PM_RETRY_MAX; ++retry) {
        result = pm_enable_3v3(pm);
        if (result == PM_OK) {
            break;
        }

        platform_rail_enable(RAIL_3V3, false);
        platform_delay_ms(5U);
    }

    if (result != PM_OK) {
        pm_record_failure(pm, result);
        pm_enter_safe_state(pm);
        return result;
    }

    /*
     * 核心电源通常应在 IO/辅助电源有效后启动，
     * 但具体顺序必须服从芯片数据手册。
     */
    for (retry = 0U; retry <= PM_RETRY_MAX; ++retry) {
        result = pm_enable_1v2(pm);
        if (result == PM_OK) {
            break;
        }

        platform_rail_enable(RAIL_1V2, false);
        platform_delay_ms(5U);
    }

    if (result != PM_OK) {
        pm_record_failure(pm, result);
        pm_enter_safe_state(pm);
        return result;
    }

    pm->state = PM_STATE_VERIFY;

    result = pm_verify_all_rails(pm);
    if (result != PM_OK) {
        pm_record_failure(pm, result);
        pm_enter_safe_state(pm);
        return result;
    }

    /*
     * 电源稳定后再释放外设复位。
     * 如果 MCU/SoC 需要外部时钟或 PLL 稳定，
     * 还应在此处增加时钟有效性检查。
     */
    if (!platform_clock_tree_ready()) {
        pm->fault_bitmap |= PM_FAULT_POWER_GOOD;
        pm_record_failure(pm, PM_ERR_POWER_GOOD);
        pm_enter_safe_state(pm);
        return PM_ERR_POWER_GOOD;
    }

    platform_release_peripheral_reset();
    platform_input_precharge_enable(false);

    pm->state = PM_STATE_RUN;

    platform_fault_log_write(FAULT_POWER_START_OK,
                             pm->input_mv,
                             pm->rail_3v3_mv,
                             pm->rail_1v2_mv,
                             0U,
                             0U);

    return PM_OK;
}
```

### 10.4 运行时电源监控

```
typedef struct {
    uint16_t input_mv;
    uint16_t rail_3v3_mv;
    uint16_t rail_1v2_mv;
    int32_t temperature_mc;
    bool power_good;
    bool brownout_warning;
} power_sample_t;

static bool power_manager_sample(power_sample_t *sample)
{
    if (sample == NULL) {
        return false;
    }

    sample->input_mv =
        platform_measure_input_voltage_mv();

    sample->rail_3v3_mv =
        platform_measure_rail_voltage_mv(RAIL_3V3);

    sample->rail_1v2_mv =
        platform_measure_rail_voltage_mv(RAIL_1V2);

    sample->temperature_mc =
        platform_get_mcu_temperature_mc();

    sample->power_good =
        platform_power_good_all();

    sample->brownout_warning =
        platform_brownout_warning_active();

    return true;
}

void power_manager_periodic(power_manager_t *pm)
{
    power_sample_t sample;

    if (pm == NULL) {
        return;
    }

    if (!power_manager_sample(&sample)) {
        pm->fault_bitmap |= PM_FAULT_POWER_GOOD;
        pm_enter_safe_state(pm);
        return;
    }

    pm->input_mv = sample.input_mv;
    pm->rail_3v3_mv = sample.rail_3v3_mv;
    pm->rail_1v2_mv = sample.rail_1v2_mv;

    if (sample.brownout_warning) {
        pm->brownout_count++;

        /*
         * 欠压预警阶段只执行无破坏性动作：
         * - 停止高功率外设；
         * - 禁止非必要 Flash 擦写；
         * - 使能安全输出；
         * - 保存最小故障上下文。
         */
        platform_disable_high_power_loads();
        platform_force_outputs_safe();

        platform_fault_log_write(FAULT_BROWNOUT_WARNING,
                                 pm->brownout_count,
                                 sample.input_mv,
                                 sample.rail_3v3_mv,
                                 sample.rail_1v2_mv,
                                 (uint32_t)sample.temperature_mc);

        /*
         * 最终复位由硬件 BOR、外部复位监控器或独立看门狗完成。
         */
        return;
    }

    if (!sample.power_good ||
        !voltage_in_range(sample.rail_3v3_mv,
                          RAIL_3V3_MIN_MV,
                          RAIL_3V3_MAX_MV) ||
        !voltage_in_range(sample.rail_1v2_mv,
                          RAIL_1V2_MIN_MV,
                          RAIL_1V2_MAX_MV)) {
        pm->fault_bitmap |= PM_FAULT_POWER_GOOD;
        pm_record_failure(pm, PM_ERR_POWER_GOOD);
        pm_enter_safe_state(pm);
        return;
    }

    if (pm->state == PM_STATE_DEGRADED) {
        /*
         * 恢复必须具备迟滞和连续有效采样条件，
         * 禁止单次采样后立即恢复全部负载。
         */
        if (platform_power_rails_stable_for_ms(100U)) {
            platform_restore_noncritical_loads();
            pm->state = PM_STATE_RUN;
        }
    }
}
```

### 10.5 动态降级策略

当供电能力不足、温度过高或输入电压接近边界时，可采用以下降级顺序：

```
检测电源异常
├─ 关闭非关键外设
├─ 降低通信速率
├─ 降低 CPU 主频
├─ 降低采样频率
├─ 限制电机/加热器输出功率
├─ 保留故障记录和通信能力
└─ 进入安全状态或等待硬件复位
```

```
typedef enum {
    POWER_DEGRADE_NONE = 0,
    POWER_DEGRADE_DISABLE_OPTIONAL,
    POWER_DEGRADE_REDUCE_CLOCK,
    POWER_DEGRADE_LIMIT_OUTPUT,
    POWER_DEGRADE_SAFE_STATE
} power_degrade_level_t;

bool power_manager_degrade(power_manager_t *pm,
                            power_degrade_level_t level)
{
    if (pm == NULL) {
        return false;
    }

    switch (level) {
    case POWER_DEGRADE_DISABLE_OPTIONAL:
        platform_disable_optional_peripherals();
        pm->state = PM_STATE_DEGRADED;
        break;

    case POWER_DEGRADE_REDUCE_CLOCK:
        platform_set_cpu_clock(CPU_CLOCK_REDUCED);
        platform_set_bus_clock(BUS_CLOCK_REDUCED);
        pm->state = PM_STATE_DEGRADED;
        break;

    case POWER_DEGRADE_LIMIT_OUTPUT:
        platform_limit_power_output();
        pm->state = PM_STATE_DEGRADED;
        break;

    case POWER_DEGRADE_SAFE_STATE:
        pm_enter_safe_state(pm);
        break;

    case POWER_DEGRADE_NONE:
        return true;

    default:
        return false;
    }

    platform_fault_log_write(FAULT_POWER_DEGRADED,
                             (uint32_t)level,
                             pm->input_mv,
                             pm->rail_3v3_mv,
                             pm->rail_1v2_mv);

    return true;
}
```

### 10.6 设计要点

上述框架体现了几个关键原则：

1. **电源轨必须按状态机管理，不能散落在各业务模块中随意开启和关闭。**
2. **Power-Good 只能作为一个条件，不能替代负载点电压测量。**
3. **软件监控不能替代 Brownout、硬件比较器和独立复位监控器。**
4. **电源异常时必须先关闭危险输出，再记录日志。**
5. **重试次数必须受限，避免反复冲击电源和刷写存储器。**
6. **恢复路径应有迟滞、稳定时间和连续采样要求。**
7. **核心电源、IO 电源和模拟电源应分别定义电压范围和故障策略。**

# 11. 工业级实际案例分析

## 11.1 案例一：Cortex-M7 控制器随机 Brownout 复位

### 需求

- 输入电压：9～36 V。
- MCU 核心电压：1.2 V。
- IO 电压：3.3 V。
- Ethernet、CAN、RS-485。
- 继电器和电磁阀输出。
- 工作温度：-40°C～85°C。
- 现场存在长线缆和感性负载。

### 故障现象

- 实验室正常。
- 现场电磁阀关闭时 MCU 偶发复位。
- 复位原因记录为 Brownout。
- 复位后设备可以自动恢复，但有少量配置丢失。

### 初步误判

团队首先更换了：

- 更大容量输入电容。
- 更高耐压 TVS。
- 更大额定电流的 Buck。

问题没有根本消失。

### 根因

通过示波器和电流探头发现：

1. 电磁阀关断瞬间，输入电源出现 2.5 µs 负向扰动。
2. TVS 距离连接器较远，泄放回路穿过数字地。
3. 3.3 V Buck 输入陶瓷电容安装回路过长。
4. MCU 负载点没有足够的局部高频去耦。
5. NRST 线路靠近继电器驱动线。
6. 软件只在正常启动后读取复位原因，部分早期日志被覆盖。

### 整改

硬件：

- TVS 移至输入连接器附近。
- 感性负载增加独立续流和吸收路径。
- 缩小 Buck 输入高 di/dt 回路。
- 3.3 V 和 1.2 V 负载点增加近端去耦。
- NRST 远离继电器和电磁阀控制网络。
- 增加独立电源监控器。

固件：

- 最早启动阶段保存原始复位原因。
- Brownout 发生前停止非关键存储器写入。
- 记录输入电压、关键电源轨和温度。
- 复位后执行最小化恢复流程。

### 结果

|指标|整改前|整改后|
|---|---|---|
|现场每 24 小时复位次数|3～8 次|0 次|
|3.3 V 最低电压|2.86 V|3.18 V|
|配置损坏概率|偶发|未复现|
|EFT 预兼容复位|失败|通过|
|故障定位时间|约 2 天|小于 2 小时|

### 设计要点

- 输入保护器件的**位置和回流路径**比单纯提高额定规格更重要。
- 电源异常必须与继电器、电机、线缆和机壳地协同分析。
- Brownout 日志必须在系统最早阶段保存。

## 11.2 案例二：FPGA 电源反谐振导致配置失败

### 需求

- FPGA 核心电压：0.95 V。
- 峰值负载：8 A。
- 负载跳变：2 A/100 ns。
- 配置 Flash：1.8 V。
- 多个高速 SERDES 通道。
- 要求上电配置成功率大于 99.99%。

### 故障现象

- 低速测试通过。
- FPGA 配置阶段偶发失败。
- 失败频率与某个业务时钟相关。
- 增加 47 µF 电容后，问题概率反而上升。

### 测试结果

通过阻抗扫描发现：

```
0.8 MHz：阻抗较低
4.5 MHz：存在 110 mΩ 反谐振峰
23 MHz：阻抗再次下降
```

负载在配置阶段产生约 4.5 MHz 的周期性电流分量，导致：

ΔV=2A×110mΩ=220mVΔV=2A×110mΩ=220mV

对 0.95 V 电源而言已经远超允许范围。

### 根因

1. 10 µF、22 µF、47 µF MLCC 并联。
2. 不同封装和不同有效容量造成多个谐振点。
3. 低 ESR 陶瓷阵列缺少阻尼。
4. FPGA 电源过孔数量不足。
5. 大容量电容距 FPGA 较远，无法提供高频电流。

### 整改

- 使用模型一致的 MLCC 阵列。
- 在中频区域增加具有适度 ESR 的聚合物电容。
- 增加靠近 FPGA 电源引脚的低 ESL 去耦。
- 增加电源和地过孔。
- 调整 Buck 补偿参数。
- 对配置时钟和 SERDES 启动顺序进行错峰。
- 固件在进入高速业务前执行电源稳定性检查。

### 结果

|指标|整改前|整改后|
|---|---|---|
|4.5 MHz PDN 阻抗峰值|110 mΩ|24 mΩ|
|FPGA 核心电压跌落|220 mV|39 mV|
|配置失败率|10−310−3 量级|未观测到|
|SERDES 启动失败|偶发|未复现|
|负载阶跃恢复时间|95 µs|28 µs|

### 设计要点

- **电容数量增加不一定改善 PI。**
- 反谐振必须通过阻抗曲线识别，不能只观察低频纹波。
- 电容网络需要容量、ESR、ESL 和安装寄生联合建模。

## 11.3 案例三：高精度 ADC 电源噪声导致测量偏差

### 需求

- 24 位 ADC。
- 输入测量范围：±10 V。
- 目标有效分辨率：19 bit。
- 采样速率：10 kS/s。
- 数字处理器与 ADC 共用 5 V 输入。
- 系统包含 Ethernet 和开关电源。

### 故障现象

- 直流输入测量值基本正确。
- Ethernet 满负荷传输时，ADC 输出出现周期性纹波。
- 频谱中存在开关频率及其倍频。
- 更换 ADC 芯片无效。

### 根因

1. ADC 模拟电源与数字电源仅使用磁珠隔离。
2. 磁珠后串联大量低 ESR MLCC，形成高 Q 网络。
3. ADC 参考源地回流经过数字电源换层区域。
4. 参考电压去耦电容离 ADC 引脚较远。
5. Ethernet PHY 负载突发通过共用电源路径耦合到 ADC。

### 整改

- 重新规划模拟电源回流。
- 使用低噪声 LDO 为 ADC 和参考源供电。
- 磁珠选型增加 DC 偏置下阻抗验证。
- 参考源使用近端低 ESL 去耦。
- 数字电源与模拟电源采用不同电源路径。
- 将 ADC 参考、输入和模拟地集中布置。
- 增加 ADC 输入采样窗口和数字平均策略。

### 结果

|指标|整改前|整改后|
|---|---|---|
|ADC RMS 噪声|18.7 LSB|4.1 LSB|
|Ethernet 满负荷时误差|2.8 mV|0.35 mV|
|参考电压纹波|1.6 mVpp|0.28 mVpp|
|有效分辨率|约 16.5 bit|约 19 bit|

### 设计要点

- 磁珠不是天然的模拟隔离器。
- ADC 电源完整性必须同时审查：
    - 电源轨；
    - 参考源；
    - 输入回路；
    - 地回流；
    - 数字负载耦合；
    - 采样时序。
- 高精度测量系统应关注噪声频谱，而不只是示波器上的总峰峰值。

# 12. 高频问题深度答疑

## 12.1 为什么电源纹波很小，系统仍然会复位？

因为示波器上看到的纹波可能没有覆盖真正的失效瞬态。

常见原因：

- 测量带宽不足。
- 测量点远离芯片负载端。
- 探头地线引入伪影。
- 负载阶跃未被测试场景激发。
- 复位由地弹、NRST 串扰或外部接口瞬态引起。
- 电源在微秒级跌落，但示波器只记录了毫秒级平均波形。
- 电源监控器检测到的是芯片引脚处的电压，而不是稳压器输出端。

应同时测量：

```
稳压器输出
├─ 负载点电源
├─ 负载点地
├─ NRST
├─ 电源监控器输出
├─ 关键时钟
└─ 负载电流
```

## 12.2 去耦电容越靠近芯片越好吗？

通常越靠近越好，但“靠近”应定义为**低电感供电回路最短**，而不是几何中心距离最小。

需要综合考虑：

- 电源引脚位置。
- 地过孔位置。
- 电容焊盘结构。
- 电源层和地层距离。
- 过孔数量。
- 回路面积。
- 电容有效容量。
- 目标频率范围。

一颗距离芯片 1 mm、但经过两个细长过孔的电容，可能不如距离 3 mm、通过低电感平面对直接连接的电容有效。

## 12.3 为什么增加电容后负载瞬态反而恶化？

可能存在：

1. 反谐振。
2. 稳压器环路稳定性被改变。
3. 过大的输出电容导致控制器响应变慢。
4. 电容安装位置不正确。
5. 电容直流偏压下有效容量远低于预期。
6. 大电容激发输入滤波器或输出网络振铃。

因此增加电容前应确认：

- 控制器支持的容量范围。
- ESR 范围。
- 有效容量。
- 电容位置。
- PDN 阻抗曲线。
- 负载阶跃波形。

## 12.4 LDO 后面是否还需要去耦？

通常需要。LDO 仍然具有：

- 输出阻抗。
- 有限 PSRR。
- 有限控制环路带宽。
- 负载瞬态限制。
- 输出电容稳定性要求。

LDO 输出电容承担：

- 高频局部储能。
- 负载瞬态支撑。
- 降低输出阻抗。
- 稳定控制环路。

但必须遵守具体器件对电容量和 ESR 的要求。

## 12.5 磁珠和 LDO 哪个更适合模拟电源隔离？

没有绝对结论。

### 选择磁珠的条件

- 数字电源与模拟电源电压相同。
- 模拟负载电流较小。
- 关注的是特定中高频噪声。
- 能够验证磁珠偏置下阻抗。
- 能够控制后端电容网络的谐振。

### 选择 LDO 的条件

- 需要明确的低噪声和 PSRR。
- 输入输出之间有足够压差。
- 负载电流和热耗散可接受。
- 需要更稳定、可预测的输出阻抗。

实际工业设计中常见：

```
Buck 预稳压
└─ 低噪声 LDO
   └─ 模拟/参考/PLL 负载
```

## 12.6 电源完整性是否只和硬件有关？

不是。固件会改变负载电流的时间分布。

固件行为可能造成：

- 多个外设同时启动。
- DMA、Cache、Flash、SDRAM 同时访问。
- 无线发射突发。
- 大量 GPIO 同时翻转。
- 电机输出和通信任务同时产生峰值负载。
- 休眠唤醒时多个电源域同时启动。

因此应进行硬件—固件协同：

```
硬件：
├─ 稳压器容量和补偿
├─ 电源平面和去耦
├─ 电源监控和保护
└─ 热设计

固件：
├─ 分阶段上电
├─ 负载错峰
├─ 降频降载
├─ 故障记录
└─ 安全状态
```

## 12.7 为什么系统在低温时比常温更容易出问题？

低温可能导致：

- 电容有效容量变化。
- 电解电容 ESR 增大。
- 晶振启动特性变化。
- MOSFET 导通和开关特性变化。
- 电池内阻增大。
- 稳压器补偿和负载动态不同。
- 连接器、焊点和机械结构应力变化。

必须在全温范围验证：

- 启动。
- 负载阶跃。
- 最低输入电压。
- 最大负载。
- 低功耗唤醒。
- 外部接口突发活动。

## 12.8 为什么 Power-Good 为高，但负载仍然异常？

Power-Good 的检测点可能位于：

- 稳压器输出端。
- 反馈点。
- 芯片内部。
- 某个分压节点。

它不一定代表：

- 芯片电源引脚实际电压。
- 负载瞬态期间电压。
- 所有并行电源轨均正常。
- 电源纹波满足要求。
- 电源时序全部合格。

因此 Power-Good 应与以下条件联合判断：

```
PG 有效
+ 负载点电压在范围内
+ 纹波合格
+ 电源时序合格
+ 时钟稳定
+ 负载自检通过
```

# 13. 课程核心总结

## 核心要点

- **电源完整性不是“加电容”，而是建立可验证的低阻抗电源分配网络。**
- **负载端电压是最终判据，不能只看稳压器输出端。**
- **目标阻抗是将允许电压波动和负载阶跃转换为可执行设计指标的核心方法。**
- **标称电容不等于有效电容，必须考虑直流偏压、温度、容差、老化和安装寄生。**
- **电容、过孔、焊盘和电源平面共同决定高频 PDN 性能。**
- **多电容并联可能产生反谐振，去耦设计必须关注阻尼。**
- **Buck 的热回路、反馈回路、SW 节点和补偿网络是布局重点。**
- **LDO 低噪声不等于无热问题，也不等于全频段高 PSRR。**
- **磁珠不是万能隔离器，必须结合后端电容网络和偏置条件分析。**
- **硬件监控负责快速保护，固件监控负责诊断、降级和恢复，两者不能互相替代。**
- **电源设计必须覆盖启动、正常运行、负载突变、掉电、Brownout、异常重启和全温全压。**

## 性能排序

典型工业数字系统中，PI 设计优先级建议为：

```
电压/电流/功率预算
> 电源架构与稳压器选型
> 高 di/dt 回路布局
> 负载点去耦与回流
> 电源平面、过孔和直流压降
> 控制环路稳定性
> 反谐振与宽频 PDN
> 电源时序和故障保护
> 热设计
> 固件负载调度与降级
```

## 通用选型结论

- 中等功率数字系统：优先采用 **Buck + 本地 MLCC + 适当 Bulk**。
- 高速核心或 FPGA/SoC：优先采用 **低阻抗平面、多级去耦、目标阻抗设计和 PI 仿真**。
- 高精度 ADC/PLL/RF：常用 **Buck 预稳压 + 低噪声 LDO + 近端参考去耦**。
- 大电流负载：必须同时进行 **IR Drop、温升、负载阶跃和过孔电流密度**分析。
- 有外部线缆或感性负载：必须联合分析 **浪涌、共模回流、输入保护和 Brownout**。
- 安全相关系统：必须具备 **独立硬件监控、硬件关断和受限软件恢复路径**。

# 16. 实践与进阶路径

## 16.1 梯度实战任务

### 任务一：建立 MCU 电源树和预算

选择一块实际 MCU 控制板，完成：

```
输入电源
├─ 保护和滤波
├─ 主 Buck
├─ 3.3 V IO
├─ 1.2 V 核心
├─ 模拟 LDO
└─ 外设负载开关
```

输出：

- 每个电源轨的静态电流。
- 峰值电流。
- 启动电流。
- 最大功耗。
- 电压容差。
- Power-Good 条件。
- 允许的动态纹波。

### 任务二：电容有效值实验

选择 10 µF、22 µF 和 47 µF MLCC，分别测试：

- 不同直流偏压。
- 不同温度。
- 不同封装。
- 不同额定电压。
- 不同品牌或料号。

建立：

```
标称容量
→ 偏压后容量
→ 温度修正
→ 容差修正
→ 最差有效容量
```

### 任务三：负载阶跃实验

使用电子负载构造：

```
0.1 A → 1.0 A
0.1 A → 1.5 A
0.1 A → 2.0 A
```

记录：

- 瞬时跌落。
- 瞬时过冲。
- 恢复时间。
- 振铃频率。
- 负载电流边沿。
- 不同探测方式下的测量差异。

### 任务四：去耦布局对比

制作或选择三种版本：

```
版本 A：远端去耦
版本 B：近端去耦但长地回路
版本 C：近端低电感电源/地回路
```

比较：

- 高频纹波。
- 负载阶跃。
- MCU 复位次数。
- SPI/QSPI 误码率。
- ADC RMS 噪声。
- 近场辐射。

### 任务五：反谐振实验

配置不同电容组合：

```
10 µF
10 µF + 100 nF
10 µF + 1 µF + 100 nF
22 µF + 10 µF + 1 µF + 100 nF
```

使用阻抗分析或网络分析设备观察：

- 串联谐振点。
- 反谐振点。
- 阻抗峰值。
- 负载阶跃时的时域响应。

### 任务六：硬件—固件负载协同

设计以下两种启动方式：

```
方案 A：所有外设同时开启
方案 B：外设分阶段开启
```

对比：

- 输入浪涌。
- 各电源轨跌落。
- 启动时间。
- Brownout 次数。
- 峰值功耗。
- 稳压器温升。

### 任务七：建立电源故障注入系统

依次注入：

- 输入欠压。
- 输入过压。
- 3.3 V 瞬时跌落。
- 1.2 V Power-Good 拉低。
- 外部监控器复位。
- 负载短时过流。
- 电源轨启动超时。

验证：

- 是否关闭危险输出。
- 是否保存故障原因。
- 是否禁止高风险 Flash 操作。
- 是否进入正确降级状态。
- 是否能够自动恢复或安全复位。

## 16.2 性能测试方法

|测试对象|推荐方法|关键指标|
|---|---|---|
|DC 压降|四线法、负载扫描|负载点电压、IR Drop|
|纹波|低噪声探头、短回路|mVpp、频谱峰值|
|负载瞬态|电子负载阶跃|跌落、过冲、恢复时间|
|PDN 阻抗|VNA/阻抗分析仪|Z(f)Z(f)、谐振峰|
|电源稳定性|环路增益测试|相位裕量、增益裕量|
|电感温升|热像仪、热电偶|饱和前后温升|
|过孔温升|热仿真、热像|电流密度、局部温升|
|启动时序|多通道示波器|Ramp、Delay、PG|
|欠压恢复|电源扰动设备|检测时间、恢复时间|

|全温验证|温箱 + 可编程电源|全边界通过率|

## 16.3 进阶学习方向

1. **PDN 阻抗设计**
    
    - 目标阻抗法。
    - 频域阻抗扫描。
    - 平面对电容。
    - 封装与片上 PDN。
    - VRM 与负载联合建模。
2. **电源环路稳定性**
    
    - Bode 图。
    - 环路增益。
    - 相位裕量与增益裕量。
    - Type-II/Type-III 补偿。
    - 输入滤波器与负阻抗耦合。
3. **高级电容建模**
    
    - S 参数。
    - ESR/ESL 频率模型。
    - DC Bias 曲线。
    - 温度和老化模型。
    - 反谐振阻尼设计。
4. **高功率 PCB 设计**
    
    - 大电流铜排。
    - 多层并流。
    - 过孔阵列。
    - 热—电联合仿真。
    - Kelvin 采样和功率回路优化。
5. **模拟电源完整性**
    
    - ADC/DAC 参考源。
    - PLL 电源噪声。
    - RF 电源隔离。
    - PSRR 频率特性。
    - 噪声密度和相位噪声。
6. **电源可靠性**
    
    - 器件降额。
    - 电容寿命。
    - 电感饱和。
    - MOSFET SOA。
    - 热循环与功率循环。
    - FMEA、FTA 和 FMEDA。
7. **硬件—固件协同电源管理**
    
    - DVFS。
    - 负载调度。
    - 电源域状态机。
    - 欠压安全状态。
    - 故障注入。
    - 现场电源质量统计。
8. **自动化 PI 验证**
    
    - 自动采集电源波形。
    - 批量负载阶跃测试。
    - 自动判断纹波、跌落和恢复时间。
    - 电源日志与生产序列号绑定。
    - 将 PI 测试结果纳入 CI/CD 和量产质量门禁。
