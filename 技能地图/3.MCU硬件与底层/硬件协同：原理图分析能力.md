
## 1. 学习目标

### 理解

完成本课后，应能够：

- 理解原理图不是“器件连线图”，而是由**电源域、时钟域、复位域、数据域、控制域和保护域**构成的系统约束模型。
- 理解 MCU、SoC、存储器、传感器、收发器、电源芯片之间的电气依赖关系。
- 理解 GPIO 复用、上拉下拉、开漏输出、终端匹配、电平转换、模拟地与数字地等设计意图。
- 理解原理图中的关键标识：`NC`、`DNP`、`TP`、`0R`、`Net-Tie`、`Power Flag`、`No ERC` 等。

### 掌握

能够：

- 从原理图快速识别系统的主要功能模块。
- 建立完整的**电源树、时钟树、复位树、通信拓扑和启动配置表**。
- 分析 MCU 引脚的复用冲突、电气属性和上电状态。
- 判断电阻、电容、磁珠、TVS、保险丝、共模电感等器件的功能。
- 依据数据手册核对关键引脚的供电、电平、电流和时序条件。
- 对 I²C、SPI、UART、CAN、USB、以太网等接口进行原理图级审查。

### 精通

能够：

- 发现原理图中不会立即暴露、但会在量产或现场出现的隐患。
- 对电源完整性、信号完整性、EMC、ESD、热设计和可制造性进行协同分析。
- 从“网络名连接正确”进一步判断“系统行为是否正确”。
- 通过静态检查、波形测量、功耗预算和故障注入验证硬件设计。
- 针对异常现象反向定位到电源、时钟、复位、引脚复用或外围器件问题。

### 能够设计

能够设计一套面向量产的原理图审查方法，包括：

- 分层审查清单。
- 关键网络风险等级。
- 电气约束表。
- 软件启动和硬件默认状态的协同方案。
- 可测试性、可维护性和故障诊断机制。
- 原理图—PCB—BOM—固件之间的一致性管理流程。

## 3. 技术概述

### 3.1 原理图分析的本质

原理图分析的核心不是确认“线有没有接上”，而是回答以下问题：

1. **系统如何供电？**
2. **各器件何时上电、何时复位、何时可访问？**
3. **MCU 启动后每个引脚是什么状态？**
4. **各接口是否满足电压、电流、时序和阻抗要求？**
5. **异常状态下，电流是否会从不允许的路径反向灌入？**
6. **软件是否能够控制硬件进入安全状态？**
7. **硬件是否能够被测试、诊断和恢复？**

原理图分析可以抽象为：

```
原理图
  ├── 电源约束
  ├── 时钟约束
  ├── 复位约束
  ├── 引脚复用约束
  ├── 电气兼容约束
  ├── 时序约束
  ├── EMC/ESD 约束
  ├── 热与功耗约束
  └── 制造与测试约束
```

### 3.2 主要分析对象

|分析对象|关注内容|常见失效|
|---|---|---|
|电源树|电压、电流、时序、纹波、压差|掉压、反灌、启动失败|
|复位链路|POR、外部复位、看门狗、手动复位|随机复位、无法下载|
|时钟链路|晶振、负载电容、时钟源、容差|启动失败、通信误码|
|GPIO|复用、默认状态、上拉下拉、5 V 容忍|外设不工作、上电误动作|
|总线|电平、拓扑、终端、上拉、带宽|波形畸变、仲裁异常|
|模拟链路|参考电压、采样阻抗、滤波、地|ADC 误差、噪声过大|
|高速接口|阻抗、差分、回流、ESD|枚举失败、掉线|
|保护电路|TVS、限流、保险丝、反接保护|ESD 损坏、浪涌失效|
|测试接口|SWD/JTAG/UART/TP|量产无法测试或调试|
|热设计|损耗、结温、铜箔散热|降频、失效、寿命降低|

## 5.1 建立电源树

### 5.1.1 电源树分析方法

示例：

```
24V_IN
  ├── 反接保护
  ├── TVS
  ├── 输入保险丝
  └── Buck 5V
        ├── USB_VBUS
        ├── LDO 3V3
        │     ├── MCU_VDD
        │     ├── Sensor_3V3
        │     └── Flash_VCC
        └── 负载开关
              └── Radio_VCC
```

每一个电源节点至少记录：

|字段|示例|
|---|---|
|名称|`3V3_MCU`|
|输入范围|4.5～5.5 V|
|标称输出|3.3 V|
|最大负载|180 mA|
|峰值负载|350 mA，持续 2 ms|
|允许纹波|< 30 mVpp|
|上电顺序|早于 `SENSOR_EN`|
|关断条件|MCU 进入低功耗后关闭|
|反灌风险|来自外部 UART、USB、GPIO|
|测试点|`TP_3V3`|

### 5.1.2 LDO 功耗计算

LDO 功耗：

PLDO=(VIN−VOUT)IOUTPLDO​=(VIN​−VOUT​)IOUT​

例如：

- 输入：5 V
- 输出：3.3 V
- 负载：200 mA

P=(5−3.3)×0.2=0.34WP=(5−3.3)×0.2=0.34W

若封装热阻为 θJA=45∘C/WθJA​=45∘C/W，环境温度为 60 ℃：

TJ=60+0.34×45=75.3∘CTJ​=60+0.34×45=75.3∘C

若设计要求结温低于 105 ℃，理论上可行；但还需要考虑 PCB 铜面积、封装热阻实际变化和输入容差。

### 5.1.3 生产级电源监控代码

```
#include <stdint.h>
#include <stdbool.h>

typedef enum {
    POWER_OK = 0,
    POWER_UVLO,
    POWER_OVLO,
    POWER_TIMEOUT
} power_status_t;

typedef struct {
    uint32_t min_mv;
    uint32_t max_mv;
    uint32_t stable_time_ms;
} power_limit_t;

static uint32_t adc_to_mv(uint16_t raw)
{
    /*
     * 示例：12 位 ADC，参考电压 3.3 V，分压比为 1/11。
     * 实际项目中应使用校准后的 VREF 和分压电阻实测值。
     */
    const uint32_t adc_full_scale = 4095U;
    const uint32_t vref_mv = 3300U;
    const uint32_t divider_ratio_num = 11U;

    return ((uint32_t)raw * vref_mv * divider_ratio_num)
           / adc_full_scale;
}

power_status_t power_check(uint16_t adc_raw,
                           const power_limit_t *limit,
                           uint32_t stable_ms)
{
    if (limit == NULL) {
        return POWER_TIMEOUT;
    }

    const uint32_t voltage_mv = adc_to_mv(adc_raw);

    if (voltage_mv < limit->min_mv) {
        return POWER_UVLO;
    }

    if (voltage_mv > limit->max_mv) {
        return POWER_OVLO;
    }

    if (stable_ms < limit->stable_time_ms) {
        return POWER_TIMEOUT;
    }

    return POWER_OK;
}
```

**设计要点：**

- ADC 电压换算必须考虑分压比、参考源误差和 ADC 校准。
- 不能只判断一次电压，必须加入稳定时间和去抖。
- 电源状态应成为系统状态机的输入，而不是分散在各业务模块中。

## 5.2 GPIO 电气状态与上电行为

### 5.2.1 必须确认的 GPIO 属性

对每个关键 GPIO 建立如下表格：

|项目|需要确认|
|---|---|
|默认状态|输入、模拟、上拉、下拉、浮空|
|电压容忍|是否 5 V tolerant|
|输出类型|推挽、开漏、三态|

|最大灌电流|Sink current|
|复用功能|启动时是否自动占用|
|上电瞬态|是否短暂输出高/低|
|外部驱动|外部器件能否在 MCU 未上电时驱动|
|安全状态|复位、异常和低功耗时状态|

### 5.2.2 上拉电阻选择

对于 I²C，电阻不能任意选择。

上升时间近似为：

tr≈0.8473RpCbtr​≈0.8473Rp​Cb​

因此：

Rp≤tr0.8473CbRp​≤0.8473Cb​tr​​

IOL=VDD−VOLRpIOL​=Rp​VDD​−VOL​​

示例：

- 总线电容 Cb=200pFCb​=200pF
- Fast-mode 要求 tr≤300nstr​≤300ns
- VDD=3.3VVDD​=3.3V
- 允许 VOL=0.4VVOL​=0.4V

上限：

Rp≤300ns0.8473×200pF≈1.77kΩRp​≤0.8473×200pF300ns​≈1.77kΩ

若选择 1.8 kΩ，近似接近边界；选择 2.2 kΩ 可能已经不满足上升时间要求。

## 5.3 复位链路分析

典型复位链路：

```
上电复位 POR
    ├── PMIC_PGOOD
    ├── 外部复位芯片
    ├── 手动复位按键
    ├── 看门狗复位
    └── MCU NRST
```

### 5.3.1 常见问题

- `NRST` 没有合理上拉。
- 复位按键直接接地但没有去抖。
- PMIC 的 `PGOOD` 电平与 MCU 不兼容。
- 外设复位释放早于其电源稳定。
- 复位线上挂接过大的电容，导致调试器无法正常连接。
- 复位芯片输出为开漏，但原理图未配置上拉。
- 外部接口能把复位线拉低，造成现场随机复位。

### 5.3.2 复位时序模型

```
VIN 上升
  │
  ├── DC/DC 输出开始建立
  │
  ├── PGOOD = 0
  │
  ├── 3V3 达到有效范围
  │
  ├── PGOOD = 1
  │
  ├── 延时 Tdelay
  │
  └── MCU_NRST 释放
```

系统设计中应明确：

Treset_release>Tpower_stable+Tclock_stable+Tperipheral_initTreset_release​>Tpower_stable​+Tclock_stable​+Tperipheral_init​

### 5.3.3 软件复位原因记录

```
#include <stdint.h>

typedef enum {
    RESET_UNKNOWN = 0,
    RESET_POWER_ON,
    RESET_PIN,
    RESET_WATCHDOG,
    RESET_SOFTWARE,
    RESET_BROWNOUT
} reset_reason_t;

typedef struct {
    uint32_t magic;
    reset_reason_t reason;
    uint32_t boot_count;
    uint32_t fault_pc;
    uint32_t fault_lr;
    uint32_t crc;
} reset_record_t;

#define RESET_RECORD_MAGIC 0x52535452UL

static reset_record_t g_reset_record
    __attribute__((section(".noinit")));

void reset_reason_capture(uint32_t reset_flags,
                          uint32_t fault_pc,
                          uint32_t fault_lr)
{
    reset_record_t record = {0};

    record.magic = RESET_RECORD_MAGIC;
    record.fault_pc = fault_pc;
    record.fault_lr = fault_lr;
    record.boot_count = g_reset_record.boot_count + 1U;

    if (reset_flags & (1UL << 0)) {
        record.reason = RESET_POWER_ON;
    } else if (reset_flags & (1UL << 1)) {
        record.reason = RESET_WATCHDOG;
    } else if (reset_flags & (1UL << 2)) {
        record.reason = RESET_BROWNOUT;
    } else {
        record.reason = RESET_UNKNOWN;
    }

    record.crc = 0; /* 实际实现需计算 CRC */
    g_reset_record = record;
}
```

**工程要求：**

- 复位原因必须在最早启动阶段读取。
- 故障现场至少保存 PC、LR、SP、任务名、复位寄存器。
- 对频繁复位进行计数和限流，防止设备陷入无限重启。

## 5.4 时钟和晶振分析

### 5.4.1 晶振回路基本模型

晶振负载电容通常近似为：

CL=C1C2C1+C2+CstrayCL​=C1​+C2​C1​C2​​+Cstray​

若晶振要求 CL=12pFCL​=12pF，寄生电容估计为 3 pF，且 C1=C2=CC1​=C2​=C：

12=C2+312=2C​+3

得到：

C≈18pFC≈18pF

但不能机械套公式，还要考虑 MCU 内部电容、PCB 走线、封装和晶振实际规格。

### 5.4.2 重点检查

- 晶振是否靠近 MCU。
- 晶振走线是否短且对称。
- 是否有不必要的过孔。
- 晶振地参考是否干净。
- 负载电容是否符合晶振数据手册。
- 是否误将有源晶振接到无源晶振引脚。
- HSE/LSE 的启动时间和驱动能力是否匹配。
- 时钟失败后是否有备用时钟或降级策略。

## 5.5 通信接口原理图审查

### UART

```
MCU_TX ─────> 外设_RX
MCU_RX <───── 外设_TX
MCU_GND ───── 外设_GND
```

检查：

- 是否交叉连接。
- 是否共地或具备隔离。
- 是否存在 5 V/3.3 V 电平冲突。
- 是否需要串联 22～100 Ω 阻尼电阻。
- 外设掉电时是否通过 TX/RX 反向供电。
- 流控 RTS/CTS 是否被错误配置。

### SPI

必须检查：

- `CS` 是否每个从设备独立。
- 从设备未选中时 MISO 是否真正高阻。
- SPI 模式 CPOL/CPHA 是否匹配。
- 多个设备是否存在总线争用。
- 时钟线是否需要串联电阻。
- 片选线上电默认状态是否安全。

### CAN/RS-485

典型 CAN 终端：

```
CAN_H ───────────────┬────────────── CAN_H
                     │
                    120Ω
                     │
CAN_L ───────────────┴────────────── CAN_L
```

总线两端各一个 120 Ω：

Req=120∥120=60ΩReq​=120∥120=60Ω

发送显性位时，驱动器需要承受相应差分电流。若总线只安装一个终端，等效阻抗为 120 Ω，会导致幅度、边沿和 EMI 特性发生变化。

### I²C 总线电容预算

总线电容包括：

Cb=CMCU+∑Cdevice+Cconnector+CtraceCb​=CMCU​+∑Cdevice​+Cconnector​+Ctrace​

不能只查看 MCU 和传感器的数据手册，还需要估计连接器、排线和外部线缆。

## 5.6 模拟链路和 ADC 输入

### 5.6.1 ADC 输入阻抗问题

ADC 通常由采样保持电容构成。采样期间，外部信号源需要给内部采样电容充电。若源阻抗过大，会导致采样误差。

一阶近似：

Verror=Vinitiale−ts/(RsCs)Verror​=Vinitial​e−ts​/(Rs​Cs​)

若要求误差低于 0.5 LSB，12 位 ADC 的相对误差约为：

0.54096=0.0122%40960.5​=0.0122%

因此需要足够的采样时间，或者降低源阻抗、增加缓冲运放。

### 5.6.2 原理图检查重点

- ADC 输入是否超过模拟电源范围。
- 分压电阻是否过大。
- RC 滤波截止频率是否满足动态要求：

fc=12πRCfc​=2πRC1​

- 模拟地是否存在大电流回流。
- 参考电压是否单独去耦。
- 输入是否需要过压钳位。
- ADC 多通道切换时，前一通道残留是否影响后一通道。

## 5.7 保护电路分析

### TVS

检查：

- 工作电压 VWMVWM​ 是否高于正常最大电压。
- 箝位电压 VCVC​ 是否低于后级器件耐压。
- 峰值脉冲功率是否满足 IEC 测试等级。
- TVS 是否放在接口入口附近。
- ESD 电流回路是否经过敏感器件地。

### 反接保护

常见方案：

|方案|压降|复杂度|适用|
|---|---|---|---|
|串联二极管|0.3～0.8 V|低|小功率|
|肖特基|0.2～0.5 V|低|中低功率|
|P-MOS 高边|数十 mV～数百 mV|中|高效率|
|理想二极管控制器|极低|高|高电流、高可靠性|

## 8. 工程最佳实践

### 8.1 设计原则

#### 原则一：先看电源，再看信号

任何外设“不能工作”，首先检查：

1. 外设电源是否存在。
2. 电源是否达到有效范围。
3. 上电时序是否满足要求。
4. 复位是否释放。
5. 时钟是否启动。
6. 最后才是数据线和软件协议。

#### 原则二：所有关键网络必须有默认状态

关键控制信号应明确：

- 上电默认值。
- 复位期间状态。
- MCU 未上电时状态。
- 软件初始化完成前状态。
- 故障状态。
- 低功耗状态。

#### 原则三：避免外设通过 GPIO 反向供电

当 MCU 或外设掉电，而另一侧 GPIO 仍输出高电平时：

```
外部 GPIO 高电平
      │
      └── MCU 输入保护二极管
              │
             VDD_MCU
```

可能造成：

- 芯片半上电。
- 功耗异常。
- 无法彻底复位。
- IO 失效或长期可靠性下降。

#### 原则四：原理图必须可验证

关键节点至少应考虑：

- 电源测试点。
- 复位测试点。
- 时钟观察点或备用调试方案。
- 通信接口测试点。
- 电流测量位置。
- Boot/下载模式配置。

### 8.2 选型决策矩阵

|维度|低风险方案|高风险方案|审查要点|
|---|---|---|---|
|电源监控|专用监控芯片，带 `PG/UVLO/OVLO`|仅依赖 MCU ADC 轮询|ADC 采样不能替代硬件级掉电保护|
|复位|专用复位监控器 + 看门狗|纯 RC 复位|RC 无法可靠识别欠压和时钟异常|
|电平转换|明确方向、带 OE 控制|依靠电阻硬连或不明双向器件|核对上电状态、传播延迟和失效模式|
|外部接口保护|接口入口处 TVS、限流、共模器件|TVS 远离连接器或无回流路径|ESD 电流不得穿过敏感器件区域|
|总线终端|按拓扑和线缆长度计算|“默认全部加终端”|CAN/RS-485 终端应只位于物理端点|
|调试接口|保留 SWD/JTAG、UART 和测试点|量产板完全移除调试能力|需要考虑返修、日志和安全熔断策略|
|关键控制|硬件默认安全态 + 软件二次确认|仅由软件初始化后设置|MCU 复位或固件崩溃时仍必须安全|
|器件替代|参数窗口、封装、温度等级均明确|只按标称值替代|替代料需重新核对时序、漏电和电容|

### 8.3 工业级编码与文档规范

1. 每个关键网络使用唯一、语义明确的网络名，例如 `VDD_MCU_3V3`、`PWR_GOOD_3V3`、`MOTOR_EN_SAFE`。
2. 不使用无意义的 `NET1`、`SIG_A` 作为跨页关键网络名。
3. 原理图符号中的引脚编号、封装、引脚类型必须与数据手册一致。
4. 为每个电源域维护**最大连续电流、峰值电流、允许纹波、启动时间和关断条件**。
5. 对 `NC`、`DNP`、`0R`、`TP` 和 `No ERC` 添加设计说明，禁止仅依赖图形记忆。
6. 所有关键器件建立“数据手册版本—BOM 料号—PCB 封装—固件驱动”关联。
7. 把“未连接”分为允许悬空、必须上拉、必须下拉、必须接地和保留禁止连接五类。
8. 对每个高风险网络指定验证方法：万用表、示波器、逻辑分析仪、电子负载或环境试验。

## 9. 常见错误与避坑指南

### 9.1 只看网络连接，不看电气属性

**错误代码/配置：**

```
/* 错误：默认假设所有 MCU GPIO 都可承受 5 V */
GPIO_ConfigInput(GPIO_PIN_5);
```

**根因：** 未核对该引脚是否 5 V tolerant，且未考虑外部器件上电早于 MCU。

**正确实现：**

```
static bool gpio_input_is_safe(uint32_t pin, uint32_t voltage_mv)
{
    const gpio_spec_t *spec = gpio_get_spec(pin);

    if (spec == NULL || voltage_mv > spec->max_input_mv) {
        return false;
    }

    if (!spec->five_volt_tolerant && voltage_mv > spec->vdd_mv) {
        return false;
    }

    return true;
}
```

工程上应同时增加电平转换、串联限流或外设使能时序。

**风险影响：** 半上电、漏电、输入保护结构长期损伤，甚至造成现场间歇性死机。

### 9.2 I²C 上拉电阻凭经验选择

**错误代码/配置：** 固定所有板卡使用 `4.7 kΩ`，不计算总线电容。

**根因：** 忽略连接器、排线、器件输入电容和 PCB 走线。

**正确实现：**

```
static bool i2c_pullup_valid(uint32_t pullup_ohm,
                             uint32_t bus_cap_pf,
                             uint32_t rise_time_ns,
                             uint32_t vdd_mv,
                             uint32_t vol_mv,
                             uint32_t iol_max_ua)
{
    uint64_t tr_ns = 8473ULL * pullup_ohm * bus_cap_pf / 10000000000ULL;
    uint32_t iol_ua = ((vdd_mv - vol_mv) * 1000U) / pullup_ohm;

    return tr_ns <= rise_time_ns && iol_ua <= iol_max_ua;
}
```

**风险影响：** 上升沿不满足规范、通信偶发 NACK、温度变化后故障概率上升。

### 9.3 复位线采用过大的 RC 电容

**错误配置：** 在 `NRST` 上直接并联数十至数百 nF 电容，且未核对调试器和复位芯片驱动能力。

**根因：** 把复位延时问题简单等同于“电容越大越稳定”。

**正确实现：** 使用带明确延时、欠压检测和手动复位输入的监控芯片；若必须使用 RC，应核对复位低电平脉宽、释放斜率、漏电流和调试器连接时序。

**风险影响：** 无法下载、复位释放慢、按键复位不可靠、低温下启动失败。

### 9.4 SPI 多从设备 MISO 争用

**错误配置：** 多个从设备共用 MISO，却未确认未选中器件是否真正高阻。

**根因：** 仅检查 `CS` 连接，不检查器件三态条件。

**正确实现：**

```
bool spi_select_device(const spi_device_t *dev)
{
    if (dev == NULL || !dev->miso_tristate_when_deselected) {
        return false;
    }

    spi_set_all_cs_high();
    delay_ns(dev->cs_guard_ns);
    gpio_write(dev->cs_pin, GPIO_LOW);
    return true;
}
```

必要时使用独立总线、总线开关或三态缓冲器。

**风险影响：** 波形被拉扁、读回数据随机错误、器件发热和 EMI 增大。

### 9.5 外部接口保护位置错误

**错误配置：** TVS 放在连接器后端，ESD 电流必须穿过 MCU 区域后才到地。

**根因：** 只关注器件存在，不分析瞬态电流回路和寄生电感。

**正确实现：** TVS 紧靠连接器，保护地采用最短、最低阻抗路径；高速差分接口选择低电容器件，并重新核对眼图。

**风险影响：** ESD 测试通过率低、通信掉线、MCU 端口击穿。

### 9.6 忽略反向灌电和掉电状态

**错误代码：**

```
/* MCU 已掉电，但外设仍保持高电平 */
gpio_write(PERIPHERAL_INT, GPIO_HIGH);
```

**根因：** 未定义电源域之间的关断顺序和 IO 隔离策略。

**正确实现：** 掉电前先关闭输出、拉到安全态或置高阻；必要时使用带 `OE` 的电平转换器和电源开关。

**风险影响：** 芯片半上电、功耗无法下降、无法彻底复位、掉电保持时间异常。

## 10. 多机制组合使用方案

### 10.1 推荐协同架构

```
输入保护
  ├── TVS / 反接保护 / 限流
  └── 输入电压监控
        │
        ▼
     DC/DC
        │
        ├── PGOOD ─────┐
        ├── 负载开关 ──┤
        └── LDO ───────┤
                       ▼
                 MCU 复位监控器
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
   电源状态机       GPIO 安全态      故障记录
        │              │              │
        └─────── 总线驱动与诊断 ──────┘
```

核心原则是：**硬件保证底线，软件负责状态管理，测试接口负责可观测性**。

### 10.2 电源—复位—外设状态机框架

```
typedef enum {
    SYS_OFF = 0,
    SYS_POWER_RISING,
    SYS_POWER_STABLE,
    SYS_PERIPHERAL_ENABLE,
    SYS_RUNNING,
    SYS_DEGRADED,
    SYS_FAULT
} system_state_t;

typedef struct {
    system_state_t state;
    uint32_t state_enter_ms;
    uint32_t fault_bitmap;
} system_ctrl_t;

static system_ctrl_t g_system;

static bool power_is_stable(void)
{
    return power_good_read() && power_voltage_in_range()
           && clock_is_ready();
}

void system_control_step(uint32_t now_ms)
{
    switch (g_system.state) {
    case SYS_OFF:
        gpio_set_safe_state();
        if (input_power_present()) {
            g_system.state = SYS_POWER_RISING;
            g_system.state_enter_ms = now_ms;
        }
        break;

    case SYS_POWER_RISING:
        gpio_set_safe_state();
        if (power_is_stable() &&
            now_ms - g_system.state_enter_ms >= 5U) {
            g_system.state = SYS_POWER_STABLE;
            g_system.state_enter_ms = now_ms;
        } else if (now_ms - g_system.state_enter_ms > 100U) {
            g_system.state = SYS_FAULT;
            g_system.fault_bitmap |= (1UL << 0);
        }
        break;

    case SYS_POWER_STABLE:
        peripheral_reset_assert(true);
        peripheral_power_enable(true);
        g_system.state = SYS_PERIPHERAL_ENABLE;
        g_system.state_enter_ms = now_ms;
        break;

    case SYS_PERIPHERAL_ENABLE:
        if (now_ms - g_system.state_enter_ms >= 10U &&
            peripheral_power_good()) {
            peripheral_reset_assert(false);
            g_system.state = SYS_RUNNING;
        }
        break;

    case SYS_RUNNING:
        if (!power_is_stable()) {
            g_system.state = SYS_DEGRADED;
            g_system.fault_bitmap |= (1UL << 1);
            gpio_set_safe_state();
        }
        break;

    case SYS_DEGRADED:
        peripheral_reset_assert(true);
        peripheral_power_enable(false);
        if (power_is_stable()) {
            g_system.state = SYS_POWER_STABLE;
        }
        break;

    case SYS_FAULT:
    default:
        gpio_set_safe_state();
        watchdog_service_allowed(false);
        break;
    }
}
```

该框架可与硬件 `PGOOD`、欠压锁定、看门狗、复位原因记录、通信超时和故障日志组合使用。

## 11. 工业级实际案例分析

### 11.1 24 V 工业控制器随机重启

**需求：** 24 V 输入，MCU 控制继电器和 RS-485，现场存在电机启停和长线干扰。

**初始现象：** 继电器吸合时 MCU 偶发复位，软件日志显示部分为未知复位。

**分析路径：**

1. 示波器同时测量 MCU `3V3`、`NRST` 和继电器线圈电压。
2. 发现 Buck 输出在负载瞬态时下降 180 mV，`NRST` 出现 80 µs 低脉冲。
3. 原理图中复位芯片的地回流与继电器驱动回流共用细线。
4. 输入 TVS 距离连接器较远，浪涌回流经过控制地。

**改进架构：**

- 输入端增加合适工作电压和箝位电压的 TVS。
- 继电器线圈增加续流/吸收网络。
- Buck 增加瞬态裕量，并在 MCU 电源域使用独立 LDO。
- 复位监控器地回流直接连接 MCU 电源参考点。
- 增加电源测试点和欠压复位记录。

**结果：** 负载阶跃时 `3V3` 下降由 180 mV 降至 42 mV；复位低脉冲消失，欠压事件在温度和输入电压范围内不再复现。

### 11.2 多传感器 I²C 总线现场间歇失效

**需求：** MCU 通过 30 cm 排线连接 6 个传感器，速率 400 kHz。

**初始现象：** 常温正常，低温或更换线束后出现 NACK。

**分析：**

- 总线电容实测约 240 pF。
- 原理图采用 4.7 kΩ 上拉，对应上升时间约 956 ns，远超 400 kHz 要求。
- 多个模块各自带有上拉，等效电阻随装配变化。

**改进：**

- 统一上拉位置，删除重复上拉。
- 按 `t_r≈0.8473R_pC_b` 重新选择 1.8～2.2 kΩ，并核对 `IOL`。
- 软件增加总线恢复：释放 SDA、产生 9 个 SCL 脉冲、发送 STOP。
- 降级模式下将速率切换为 100 kHz。

**结果：** 上升时间降至约 410 ns 以内；在允许的器件电流范围内，现场 NACK 显著下降。

### 11.3 电机控制板掉电后无法彻底关机

**需求：** MCU、栅极驱动器和通信模块分属不同电源域，要求待机功耗低于 100 µA。

**初始现象：** 关闭主电源开关后，MCU 电源仍保持约 1.2 V，待机电流达到数 mA。

**根因：** MCU UART 和使能 GPIO 仍被外部通信模块驱动，通过 IO 保护二极管反向供电。

**改进：**

- 电源关闭前将所有跨域 GPIO 设置为高阻或安全低电平。
- UART 增加带 `OE` 控制的电平转换器。
- 通信模块电源关闭后再关闭 MCU 电源。
- 在验证阶段测量每条跨域信号的掉电电流。

**结果：** 各电源域可完全关断，待机电流降至目标范围，重新上电启动稳定。

## 12. 高频问题深度答疑

### Q1：为什么 ERC 通过，板子仍然可能不能启动？

ERC 主要验证符号连接和引脚电气类型，通常无法验证实际电压范围、上电时序、负载瞬态、晶振布局、反向灌电和器件内部状态。因此必须把 ERC 作为 **L0 网络检查**，再进行数据手册约束、时序、波形和异常状态验证。

### Q2：电源有额定电流裕量，为什么仍会掉压？

额定电流是稳态指标。瞬态掉压还受控制环路带宽、输出电容有效值、ESR、走线电阻和寄生电感影响。应分别计算：

```
ΔV_total ≈ I_step × ESR
          + I_step × R_path
          + I_step × Δt / C_eff
          + L_path × di/dt
```

不能只按平均功耗选型。

### Q3：磁珠能否替代电感或保险丝？

不能。磁珠主要用于特定频段的阻抗隔离和高频噪声抑制，其直流电阻、额定电流和阻抗频率特性与功率电感、保险丝完全不同。磁珠还可能与去耦电容形成谐振，必须结合阻尼和实际阻抗曲线评估。

### Q4：为什么 I²C 上拉越小不一定越好？

上拉越小，上升时间越短，但低电平时灌电流越大，器件功耗、`VOL` 和驱动能力压力越高。正确做法是同时满足上升时间上限和低电平电流下限，并验证最坏情况下的总线电容和电源电压。

### Q5：模拟地和数字地应该完全分开吗？

“完全分开”不是通用答案。关键是控制高电流、高 `di/dt` 回流路径，避免数字噪声穿过模拟参考区域。分区、单点连接、完整参考平面和合理器件布局通常比机械切地更可靠。最终必须通过回流分析和 ADC 噪声测试验证。

### Q6：软件能否弥补原理图中的硬件缺陷？

软件可以缓解协议超时、重试、降速、故障记录等问题，但无法可靠弥补耐压不足、错误终端、错误电源时序、无保护接口和严重信号完整性问题。凡涉及**绝对最大额定值、硬件安全态和能量路径**的约束，都必须在硬件层解决。

### Q7：如何判断一个网络是否属于最高风险网络？

满足以下任一条件即可列为高风险：

- 连接外部线缆或用户可触达接口。
- 承载高能量或大电流。
- 直接影响启动、复位、功率级或安全动作。
- 跨电源域或跨隔离边界。
- 连接晶振、参考电压、ADC 输入或高速差分线。
- 失效后无法通过软件恢复。

## 13. 课程核心总结

### 13.1 核心要点

1. **原理图分析是约束分析，不是连线检查。**
2. 审查顺序应为：**电源 → 复位 → 时钟 → 引脚默认态 → 接口电气 → 时序 → 保护 → 测试与量产**。
3. 每个关键网络都必须定义正常态、上电态、复位态、掉电态和故障态。
4. 计算必须覆盖最坏输入、最大负载、最高总线电容、温度、器件容差和老化条件。
5. 硬件安全态应独立于软件正常运行；软件应提供状态机、诊断和降级策略。
6. 可测试性不是后期补充，而是原理图阶段的设计输入。

### 13.2 典型性能/可靠性优先级

```
安全与绝对最大额定值
  > 电源和复位稳定性
  > 时序与电气兼容性
  > 信号完整性与 EMC
  > 功耗与热设计
  > 成本与器件数量
```

### 13.3 通用选型结论

- **高压到低压、大电流：优先 Buck；低噪声小电流：再考虑 LDO。**
- **外部接口：保护器件靠近连接器，先规划回流路径，再选器件。**
- **开漏总线：按电容和灌电流计算上拉，不采用固定经验值。**
- **关键复位：优先专用监控芯片，而不是单纯 RC。**
- **跨电源域：优先使用具备明确方向、使能和掉电行为的电平转换方案。**

### 16.1 梯度实战任务

#### 任务一：单 MCU 控制板审查

- 复位树。
- 时钟检查表。

#### 任务二：I²C 多设备板卡分析

输入：6 个传感器、30 cm 排线、400 kHz 总线。

要求：

- 计算上拉范围。
- 实测上升时间和低电平电流。

- 设计总线恢复和降速策略。

#### 任务三：24 V 工业控制器审查

输入：24 V 输入、Buck、MCU、继电器、RS-485、外部连接器。

- 计算电源热损耗和负载瞬态。
- 测试继电器动作时的 `3V3`、`NRST` 和地弹噪声。
- 建立复位原因统计和故障注入方案。

输出完整包：

```
原理图审查报告

```

### 16.2 性能测试方法

1. **电源测试：** 电子负载执行阶跃，记录稳态误差、过冲、恢复时间、纹波和温升。
2. **复位测试：** 调整输入电压、负载和温度，统计误复位、复位脉宽和复位原因覆盖率。
3. **总线测试：** 使用逻辑分析仪和示波器测量上升/下降时间、建立保持时间、重试率和误码率。
4. **信号完整性：** 在接收端测量振铃、过冲、眼图或差分幅度，不只在发送端观察。
5. **掉电测试：** 逐个关闭电源域，测量每条跨域信号电压和反向电流。
6. **EMC/ESD 测试：** 记录测试等级、放电点、功能失效类型、自动恢复时间和永久损伤情况。
7. **热测试：** 在最高环境温度、最大负载和最差输入电压下记录关键器件壳温、结温估算和降额余量。

### 16.3 进阶学习方向

- 电源完整性与 PDN 阻抗建模。
- 高速数字信号完整性、差分阻抗和眼图分析。
- EMC 预一致性测试与电流回路建模。
- 复杂 SoC 的 DDR、PCIe、USB 3.x 原理图审查。
- 安全相关硬件设计、故障树分析和 FMEDA。
- 硬件抽象层与原理图约束自动生成固件配置。
- 原理图、PCB、BOM、测试和固件之间的自动化一致性检查。

**最终能力标准：** 面对一张陌生原理图，不仅能说明“每根线连接了什么”，还能够回答“系统在正常、启动、复位、掉电、异常和量产测试状态下会如何工作，以及如何用数据证明它确实可靠”。
