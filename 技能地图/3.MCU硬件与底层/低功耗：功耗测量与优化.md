

> 本课面向具备 MCU/RTOS 工程经验的开发者，重点解决“如何正确测量、定位功耗来源、建立能量模型，并将优化结果固化为可回归验证的工业流程”。示例以 Cortex-M + STM32 风格伪接口说明，具体配置必须以目标 MCU、PMIC、传感器和通信模块数据手册为准。

## 1. 学习目标

### 理解

- 理解电流、功率、能量、平均功耗、峰值电流、漏电流和静态电流的区别。

- 理解分流电阻、电流探头、电子负载、功耗分析仪和示波器的测量原理及误差来源。
- 理解“降低睡眠电流”和“减少唤醒能量”是两类不同优化目标。

### 掌握

- 正确搭建低功耗测量链路，选择分流电阻、量程、采样率和带宽。
- 测量 Run、Sleep、Stop、Standby 各状态的稳态电流、进入时间、唤醒延迟和恢复能量。
- 使用电流波形定位 SysTick 唤醒、GPIO 漏电、外设未关断、调试器影响和电源反灌。
- 建立工作周期和电池寿命计算模型，并区分典型值、最大值和实测值。

### 精通

- 分析低功耗系统中微安级静态电流与毫安级脉冲电流的动态范围冲突。
- 量化单次唤醒能量、伪唤醒损耗、稳压器 IQ、负载开关漏电和电池内阻压降。
- 设计自动化功耗测试、波形分类、阈值判定和低功耗回归机制。
- 处理不同温度、电压、老化状态和外设组合下的最坏功耗问题。

### 能够设计

- MCU 到整机的分层功耗预算；
- Sleep/Stop/Standby 多级功耗策略；
- 具备可观测、可定位、可回归的功耗测试平台；
- 面向电池寿命、响应延迟和通信可靠性的联合优化方案。

```

│   ├── CPU/内核
│   ├── Flash/SRAM
```

### 3.2 优化目标分类

1. **静态功耗优化**：降低睡眠电流、漏电流和电源芯片 IQ。
2. **动态功耗优化**：降低运行频率、工作电压、活动因子和外设运行时间。
3. **唤醒次数优化**：合并定时器、批量采样、批量通信，减少频繁启动。
4. **单次唤醒能量优化**：缩短初始化、减少无线握手、使用 DMA 和硬件加速。
5. **系统级优化**：调整电源架构、外部器件断电和协议工作窗口。

## 5. 底层原理与功能特性深度解析

### 5.1 分流电阻测量原理

在电源路径串联分流电阻 RsRs​，测量其两端压差：

I=VshuntRsI=Rs​Vshunt​​

例如 Rs=10ΩRs​=10Ω，测得 78 μV，则：

I=78μV10Ω=7.8μAI=10Ω78μV​=7.8μA

分流电阻不能只追求“大阻值”。其引入的压降为：

Vdrop=IloadRsVdrop​=Iload​Rs​

若 Run 电流 100 mA、分流 10 Ω，将产生 1 V 压降，可能改变系统工作点。因此常采用：

- 微安级测量：较大分流或高增益仪表；
- 毫安级脉冲：较小分流并使用高带宽差分探头；
- 宽动态范围：功耗分析仪自动量程或多量程切换。

### 5.2 测量接口与波形打点

测试固件应在关键状态翻转 GPIO，形成可与电流波形对齐的标记：

```
void lp_measure_marker(measure_marker_t marker)
{
    /* GPIO 翻转必须是确定、短时、低开销操作 */
    gpio_write(MEASURE_MARKER_PIN, (marker != MARKER_END));
    __DSB();
}

bool enter_stop_measured(void)
{
    lp_measure_marker(MARKER_PREPARE);

    if (!peripherals_prepare_for_stop()) {
        lp_measure_marker(MARKER_ABORT);
        return false;
    }

    lp_measure_marker(MARKER_SLEEP_ENTRY);
    __DSB();
    __WFI();
    __ISB();
    lp_measure_marker(MARKER_WAKE);

    if (!clock_restore_pll()) {
        lp_measure_marker(MARKER_CLOCK_FAIL);
        enter_safe_clock();
        return false;
    }

    peripherals_restore_after_stop();
    lp_measure_marker(MARKER_END);
    return true;
}
```

**注意：** 测量打点本身会改变 GPIO 翻转、端口时钟和动态电流，正式功耗结果应分别记录“带打点”和“无打点”两组数据，并扣除或评估打点开销。

### 5.3 采样率、带宽和动态范围

若要观察持续时间为 tptp​ 的脉冲，采样间隔应显著小于脉冲宽度。工程上通常要求：

fs≥10∼20×feffectivefs​≥10∼20×feffective​

或至少保证脉冲内有 **10 个以上采样点**。例如 5 μs 唤醒脉冲，100 kSa/s 的采样间隔为 10 μs，必然无法准确捕获，至少应提高到数 MSa/s 量级。

测量系统同时受以下因素限制：

- 放大器带宽；
- 采样 ADC 分辨率；
- 自动量程切换的空洞或瞬态；
- 分流电阻热噪声；
- 示波器输入共模范围；
- 探头接地回路和寄生电感。

### 5.4 静态功耗定位：二分隔离法

不要一开始就修改大量软件。推荐采用电源域二分法：

```
整机功耗异常
├── 断开外部模块
│   ├── 功耗恢复正常 → 外部模块/IO/反灌路径
│   └── 仍异常
├── 断开通信收发器
│   ├── 恢复正常 → DE/RE/电源/总线电平问题
│   └── 仍异常
├── 关闭 RTC、BOR、温度传感器等功能
│   ├── 恢复正常 → MCU 保持域配置
│   └── 仍异常
└── 逐组配置 GPIO 为模拟/确定输出并测量
```

常见反向供电路径：

```
外部模块 VDD 仍有电
    ↓
模块 GPIO 输出高电平
    ↓
MCU 已掉电或部分掉电的 IO 保护二极管
    ↓
MCU 电源域被反向供电
```

这种问题不能靠软件降低 MCU 时钟解决，必须断开信号、电源或增加隔离。

### 5.5 动态功耗与时钟门控

动态功耗近似为：

Pdynamic=αCV2fPdynamic​=αCV2f

降低电压比降低频率更有效，但电压受时序、Flash 等待周期和外设规格限制。对外设而言，应做到：

- 不使用的总线时钟关闭；
- DMA 完成后关闭 DMA 和请求源；
- ADC 转换结束后关闭 ADC、参考源和模拟缓冲；
- 定时器停止后关闭触发链路；
- 不让高频中断无意义运行。

```
void adc_suspend(void)
{
    adc_stop_conversion();
    adc_disable_dma_request();
    dma_disable_channel(ADC_DMA_CHANNEL);
    adc_disable();
    adc_disable_clock();
}
```

### 5.6 平均功耗不是简单平均电流

电池供电时，DCDC 效率和电池电压变化不可忽略。若负载侧功率为 PoutPout​，稳压器效率为 ηη，输入功率为：

Pin=Poutη+VbatIQPin​=ηPout​​+Vbat​IQ​

在不同负载下，LDO、DCDC 的优劣可能反转：

- 极低负载：DCDC 的轻载效率和 IQ 可能较差；
- 中高负载：DCDC 通常由于效率高而占优；
- 脉冲负载：需考虑输出电容、控制环响应和电池内阻。

### 5.7 电池寿命估算

基础估算：

Lifehour=CusableIavgLifehour​=Iavg​Cusable​​

但有效容量不是铭牌容量，需考虑：

- 放电倍率；
- 温度；
- 截止电压；
- 老化；
- 自放电；
- 峰值电流导致的电压跌落；
- 无线模块重试。

工程上应采用：

Cusable=Crated×ktemp×krate×kagingCusable​=Crated​×ktemp​×krate​×kaging​

而不是直接用额定容量除以平均电流。

## 6. 性能量化分析

### 6.1 示例平台

- MCU：Cortex-M4，80 MHz，3.3 V；
- 电源：3.7 V 电池，经 DCDC 输出 3.3 V；
- 测量仪器：1 MSa/s 功耗分析仪，带宽 200 kHz；
- 条件：25 ℃，调试器断开，外部模块单独供电测量。

|状态|MCU/整机实测电流|持续时间/说明|
|---|---|---|
|Run 空载|8.6 mA|80 MHz|
|Sleep|1.42 mA|RTC、UART 保持|
|Stop|7.8 μA|SRAM 保持、LSE 运行|
|Standby|0.83 μA|RTC 和唤醒逻辑保持|
|单次唤醒峰值|42 mA|含传感器启动|
|无线发送峰值|180 mA|外部模块|

这些是测试示例，不是通用规格。

### 6.2 周期平均电流

假设每秒运行 20 ms，Run 电流 8.6 mA，其余 980 ms 处于 Stop，Stop 电流 7.8 μA：

Iavg=8.6×20+0.0078×9801000≈0.1796mAIavg​=10008.6×20+0.0078×980​≈0.1796mA

若每 10 分钟无线发送 2 s，发送电流 120 mA，则通信贡献为：

Iradio=120×2600=0.4mAIradio​=600120×2​=0.4mA

这说明即使 MCU 长期处于亚微安或微安级，**通信窗口仍可能主导整机能耗**。

### 6.3 单次唤醒能量与优化收益

唤醒恢复阶段 3.3 V、8.6 mA、100 μs：

Ewake=3.3×8.6mA×100μs≈2.84μJEwake​=3.3×8.6mA×100μs≈2.84μJ

若每天发生 10,000 次伪唤醒，额外能量为：

Eday=2.84μJ×10000=28.4mJEday​=2.84μJ×10000=28.4mJ

若每次伪唤醒还启动无线模块，实际损失可能达到数十焦耳，必须通过硬件滤波、边沿策略和事件合并治理。

### 6.4 量测不确定度

分流测量的相对误差可近似表示为：

δII≈(δVVshunt)2+(δRRs)2IδI​≈(Vshunt​δV​)2+(Rs​δR​)2​

在微安级时，VshuntVshunt​ 很小，电压测量误差通常占主导；在大电流时，分流电阻温升和压降又会改变被测系统工作点。

建议报告至少包含：

- 仪器型号和量程；
- 采样率、带宽和积分窗口；
- 电源电压与温度；
- 是否连接调试器；
- 外部负载状态；
- 典型值、最大值、P95/P99 和重复次数。

## 8. 工程最佳实践

### 8.1 设计原则

1. **先定义测量问题，再选择仪器。**
2. **先测整机基线，再逐级拆分电源域。**
3. **稳态电流、峰值电流、平均能量必须分别报告。**
4. 测量时断开调试器、USB、LED 和非必要外部设备。
5. 低功耗测试必须覆盖温度、电压、板级版本和软件版本。
6. 使用 GPIO 时间标记，但正式结果必须关闭测量侵入代码复测。
7. 电池寿命使用有效容量、稳压效率和老化系数估算。
8. 任何优化都必须验证功能、时序、通信和故障恢复。

### 8.2 选型决策矩阵

评分 1~5，分数越高越适合。

|指标|万用表|示波器+分流|功耗分析仪|SMU|
|---|---|---|---|---|
|稳态 μA 精度|4|3|5|5|
|微秒脉冲捕获|1|5|5|3|
|长时间记录|2|3|5|4|
|能量积分|1|3|5|4|
|成本|5|4|2|2|
|研发回归自动化|1|3|5|4|

### 8.3 工业级编码规范

- 统一记录 `state_enter`、`state_exit`、`wake_reason`、`fault_code` 和 RTC 时间戳。
- 功耗测试接口与业务逻辑解耦，支持编译开关关闭。
- 禁止用忙等待制造“看似稳定”的低功耗状态。
- 所有外设驱动提供 `prepare_suspend()`、`resume()` 和 `force_shutdown()`。
- 测试数据保存固件版本、板卡版本、序列号、温度、电压和仪器配置。
- 量产阈值采用统计分布而非单个典型值。

## 9. 常见错误与避坑指南

### 9.1 错误一：直接用万用表测低功耗

**错误代码/操作：**

```
将万用表串入电池回路，看到 0.00 mA，认定系统为 0 μA。
```

**根因：** 自动量程响应慢、显示分辨率有限，且无法捕获唤醒脉冲。

**正确实现：** 使用功耗分析仪或低噪声分流+示波器，分别测稳态、峰值和积分能量。

**风险影响：** 误判待机功耗，产品现场出现电池快速耗尽。

### 9.2 错误二：分流电阻过大导致系统行为改变

**错误代码/操作：**

```
Run 电流 100 mA，直接串联 10 Ω 分流电阻。
```

**根因：** 压降达到 1 V，导致 MCU 复位、DCDC 工作点变化或无线发射失败。

**正确实现：** 根据最大电流限制压降，使用小阻值高带宽测量；微安级另设高阻量程或分阶段测量。

**风险影响：** 测量结果不代表真实产品，甚至误把测量故障当成固件故障。

### 9.3 错误三：只优化 MCU，忽略外部模块

**错误代码/操作：**

```
mcu_enter_standby();
/* 传感器、RS-485、LED 和分压器仍保持上电 */
```

**根因：** 整机功耗由外部器件、IO 反灌和电阻网络主导。

**正确实现：** 使用负载开关或硬件 Shutdown，设置收发器安全电平，核算电源芯片 IQ 和分压电流。

**风险影响：** MCU 数据手册中的亚微安指标无法转化为整机指标。

### 9.4 错误四：只看平均电流，不看峰值和能量

**错误代码/操作：**

```
I_avg = 0.3 mA;
/* 因此认为电源设计一定满足要求 */
```

**根因：** 无线发射或传感器启动可能有 180 mA 峰值，电池内阻和供电路径导致电压跌落。

**正确实现：** 同时验证 `I_avg`、`I_peak`、`V_min`、纹波、脉冲宽度和单次能量。

**风险影响：** 现场随机复位、通信失败、数据损坏。

### 9.5 错误五：测量打点代码污染结果

**错误代码/操作：**

```
printf("enter stop\\n");
GPIO_TOGGLE();
__WFI();
```

**根因：** 日志、GPIO 时钟和串口本身产生额外活动，且 `printf` 可能阻塞。

**正确实现：** 使用最小化硬件打点；对带打点/无打点固件分别测量，并校正差值。

**风险影响：** 睡眠电流被高估，唤醒时序被改变。

### 9.6 错误六：只测试典型温度和新电池

**错误代码/操作：**

```
25 ℃、3.7 V、实验室新板通过，即判定量产合格。
```

**根因：** 漏电、晶振误差、DCDC 效率、电池内阻和传感器启动行为都随条件变化。

**正确实现：** 覆盖温度、电压、器件批次、老化和异常唤醒，并使用最坏值/P99 判定。

**风险影响：** 低温启动失败、寿命不足和批次间功耗离散。

### 10.2 统一接口框架

```
typedef enum {
    PM_RUN,
    PM_SLEEP,
    PM_STOP,
    PM_STANDBY,
    PM_FAILSAFE,
} pm_state_t;

typedef struct {
    bool (*prepare)(void);
    bool (*suspend)(void);
    bool (*resume)(void);
    void (*shutdown)(void);
    uint32_t (*estimate_current_ua)(void);
} pm_device_ops_t;

typedef struct {
    uint32_t idle_us;
    bool retain_ram;
    bool need_fast_response;
    uint32_t allowed_wakeup_sources;
} pm_request_t;

static pm_state_t pm_select(const pm_request_t *req)
{
    if (req == NULL || req->need_fast_response || req->idle_us < 2000U) {
        return PM_SLEEP;
    }
    if (req->retain_ram) {
        return PM_STOP;
    }
    return PM_STANDBY;
}

bool pm_enter(const pm_request_t *req)
{
    pm_state_t state = pm_select(req);
    power_log_state_enter(state);

    if (!wakeup_prepare(req->allowed_wakeup_sources)) {
        power_log_fault(PM_FAULT_WAKE_CONFIG);
        platform_enter_sleep();
        return false;
    }

    if (!all_devices_suspend()) {
        all_devices_shutdown_best_effort();
        platform_enter_sleep();
        return false;
    }

    switch (state) {
    case PM_SLEEP:
        platform_enter_sleep();
        break;
    case PM_STOP:
        if (!platform_enter_stop()) {
            platform_enter_sleep();
        }
        break;
    case PM_STANDBY:
        if (!backup_context_save_with_crc()) {
            platform_enter_stop();
        } else {
            platform_enter_standby();
        }
        break;
    default:
        platform_enter_sleep();
        break;
    }

    if (!clock_restore_and_validate()) {
        enter_safe_clock();
        power_log_fault(PM_FAULT_CLOCK);
        return false;
    }

    if (!all_devices_resume()) {
        enter_safe_mode();
        power_log_fault(PM_FAULT_RESUME);
        return false;
    }

    power_log_state_exit(state, wake_reason_collect());
    return true;
}
```

## 11. 工业级实际案例分析

### 11.1 案例一：无线环境传感器

**需求：** 每 60 秒采样一次，每 10 分钟上报一次，2400 mAh 电池，目标寿命超过一年。

**初始测量：**

- Stop 稳态：8 μA；
- 传感器采样：8 mA、50 ms/次；
- 无线发送：120 mA、2 s/600 s；
- 外部电源和反灌：35 μA。

通信贡献：

Iradio=120×2600=0.4mAIradio​=120×6002​=0.4mA

采样贡献：

Isensor=8×0.0560=6.67μAIsensor​=8×600.05​=6.67μA

**优化架构：**

```
RTC 唤醒
  ↓
负载开关打开传感器
  ↓
采样并关闭模拟前端
  ↓
累计数据，达到批量阈值后启动无线
  ↓
发送、确认、关闭无线电源
  ↓
Standby
```

**设计要点：**

- 先优化无线发送时长和重试次数，而不是继续压低 MCU 的 8 μA；
- 传感器和无线模块必须硬件断电；
- 使用绝对 RTC 时间，避免周期漂移；
- 通信失败采用指数退避；
- 通过波形积分计算每次采样和发送能量。

若将发送时间由 2 s 降至 0.8 s，通信贡献从 0.4 mA 降至 0.16 mA，收益远高于将 Stop 从 8 μA 优化到 3 μA。

### 11.2 案例二：低功耗 RS-485 从站

**需求：** 总线空闲进入 Stop，主站访问时唤醒，不能因收发器漏电影响整机待机。

**架构：**

```
总线收发器 Shutdown
  ↓
UART 起始位/地址唤醒
  ↓
恢复 PLL 和 UART
  ↓
DMA 接收完整帧
  ↓
地址过滤 + CRC16
  ↓
响应并重新进入 Stop
```

**测量重点：**

- 收发器 DE/RE 静态电流；
- A/B 线偏置电阻形成的直流电流；
- 唤醒到首个可用字节的延迟；
- 发射峰值导致的电源压降；
- 首字节丢失后的协议重同步。

**结论：** 总线偏置和收发器电源策略往往比 MCU Stop 电流更重要。

### 11.3 案例三：资产追踪终端

**需求：** 待机数月，每 6 小时定位一次，振动或开箱立即唤醒。

**架构：**

```
加速度计自身运动检测 ─┐
RTC Alarm ────────────┼→ Standby 唤醒
开箱 GPIO ───────────┘
                         ↓
                 读取复位/唤醒原因
                         ↓
                 启动定位模块并上传
                         ↓
                 记录上下文后再次待机
```

**设计要点：**

- 外部传感器在待机时只保留运动检测；
- 关键状态使用 Backup SRAM/FRAM 双槽位 CRC 保存；
- 唤醒后先记录原因，再开启高功耗模块；
- 测量必须包含模块启动峰值和网络重试；
- 检查 PCB LED、调试接口、分压器和 ESD 器件漏电。

## 12. 高频问题深度答疑

### 问题一：为什么数据手册的待机电流比实测低很多？

数据手册通常是在特定电压、温度、时钟、RAM 保持、外设关闭和无外部负载条件下给出的 MCU 芯片指标。实测板级结果还包括稳压器 IQ、GPIO 外部通路、LED、传感器、调试器和测量设备。应先分别测 MCU 电源域和整机电源，再用二分法定位差值。

### 问题二：低采样率能否测平均功耗？

能测长时间平均趋势，但不能可靠捕获短脉冲、唤醒峰值和单次能量。若脉冲宽度小于采样间隔，峰值会被漏采样，积分也可能产生较大误差。应根据最短事件选择采样率，并用高低量程交叉验证。

### 问题三：降低工作频率一定能降低电池能耗吗？

不一定。虽然动态功耗近似与频率成正比，但降低频率可能延长任务执行时间，增加静态电流和外设保持时间。应比较完整活动窗口能量：

Eactive=∫V(t)I(t)dtEactive​=∫V(t)I(t)dt

对于“能量优先”系统，应优化任务完成能量，而非只看瞬时电流。

### 问题四：为什么减少一次唤醒有时比降低几微安更有效？

每次唤醒可能包含时钟启动、传感器稳定、无线注册和协议重试，其能量远高于 MCU 睡眠一段时间的静态消耗。应将唤醒次数、活动窗口、峰值和单次能量纳入模型，优先合并事件和批量处理。

### 问题五：如何判断 DCDC 还是 LDO 更适合？

需要比较全工作区间的输入功率，而不是只比较标称效率。低负载关注 IQ 和轻载效率，中高负载关注转换效率，脉冲负载关注瞬态压降和稳定性。实际决策应使用：

Pin=Pout/η+VbatIQPin​=Pout​/η+Vbat​IQ​

并在真实负载波形下积分验证。

### 问题六：功耗优化后如何证明没有破坏实时性？

为每种模式定义最坏唤醒延迟、任务截止时间、通信首字节容忍度和故障响应指标；使用外部触发信号、测试 GPIO、逻辑分析仪和长时间压力测试测量 P99/最大值，而不是只测一次典型值。

## 13. 课程核心总结

### 核心要点

1. **功耗优化必须以波形和能量为依据，不能只看一个稳态电流数字。**
2. 低功耗测量首先要保证测量设备不会改变被测系统。
3. MCU、外部模块、稳压器和 PCB 漏电必须分层测量。
4. 平均电流决定长期续航，峰值电流决定供电稳定性，唤醒能量决定事件型系统效率。
5. 低功耗优化应优先处理最大能耗项和最高唤醒频率。
6. 典型值用于理解趋势，最坏值/P99 用于产品设计和量产判定。
7. 功耗回归必须绑定固件、硬件、温度、电压和测试条件。

### 性能排序

典型优化收益优先级通常为：

```
关闭/断电高功耗外设
  > 减少无线通信时间与重试
  > 减少唤醒次数
  > 消除 GPIO/PCB 反灌与漏电
  > 关闭无用时钟和外设
  > 降低运行频率/电压
  > 微调 MCU 深睡眠电流
```

### 通用选型结论

- **稳态初筛：万用表或 SMU**；
- **瞬态和唤醒分析：分流电阻 + 示波器**；
- **宽动态范围、长时间积分和自动回归：功耗分析仪**；
- **产品优化：以整机周期能量和电池寿命为最终指标**。

## 16. 实践与进阶路径

### 16.1 梯度实战任务

#### 任务一：搭建测量基线

- 分别测量 Run、Sleep、Stop、Standby；
- 记录稳态电流、进入时间和唤醒延迟；
- 对比调试器连接与断开状态。

验收：每项数据包含仪器量程、采样率、温度、电压和重复次数。

#### 任务二：波形定位

- 使用 GPIO 标记任务开始、睡眠入口、唤醒和外设启动；
- 观察 SysTick、RTC、GPIO 和 UART 唤醒波形；
- 统计伪唤醒率。

验收：能够从波形定位至少 4 类功耗异常。

#### 任务三：整机功耗拆分

- 分别断开传感器、无线模块、收发器和 LED；
- 建立各电源域功耗表；
- 分析反向供电和分压器耗电。

验收：整机电流能够由各模块贡献近似闭合。

#### 任务四：周期能量优化

- 建立采样、处理、通信和睡眠的能量模型；
- 比较单次通信与批量通信；
- 比较 Sleep、Stop、Standby 的交叉点。

验收：优化前后平均功耗下降，并且通信成功率和响应时间不恶化。

#### 任务五：自动化低功耗回归

- 使用脚本控制电源、复位、唤醒和数据采集；
- 自动提取稳态电流、峰值、积分能量和唤醒次数；
- 生成 P50/P95/P99 报告。

验收：固件提交后可自动输出功耗回归结果，超阈值阻断发布。
