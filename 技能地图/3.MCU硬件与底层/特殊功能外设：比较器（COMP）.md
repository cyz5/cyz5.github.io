## 3. 技术概述

COMP 本质上是一个高速 1-bit 模拟判决器：

```
V+ > V-  ->  输出为有效态
V+ < V-  ->  输出为无效态
```

典型内部结构：

```
外部模拟输入 ─┐
内部 DAC ─────┼─> 输入 MUX ─> 比较核心 ─> 迟滞/极性 ─> 同步器/事件路由
内部 VREF ────┘                              ├─> GPIO 输出
                                              ├─> EXTI/NVIC
                                              ├─> 定时器捕获
                                              └─> PWM Break/关断
```

### 主流技术分支

1. **异步比较器**：输出直接反映模拟比较结果，延迟低，适合硬件保护。
2. **同步比较器**：输出经过时钟采样，抗毛刺能力较强，但增加延迟和时序不确定性。
3. **外部输入比较**：两个输入来自 GPIO 模拟通道，灵活但占用引脚且受外部噪声影响。
4. **内部参考比较**：一端连接 DAC、VREF、带隙基准或分压节点，适合阈值监控。
5. **窗口比较**：两个 COMP 分别检测上限和下限，组成窗口故障检测器。
6. **事件联动比较**：比较器输出直接连接定时器、ADC 触发、PWM 刹车或 DMA，避免 CPU 参与。

## 4. 核心特性横向对比

|方案|延迟|CPU 负载|抗毛刺|阈值灵活性|典型用途|主要风险|
|---|---|---|---|---|---|---|
|COMP 轮询|高且不确定|高|由软件决定|中|低速状态检测|漏检、任务调度影响|
|COMP 中断|中|中|需软件处理|中|故障通知、边沿检测|中断风暴、抖动|

|COMP + 内部 DAC|低|低|中|高|可编程阈值|DAC 误差、更新瞬态|

## 5. 底层原理与功能特性深度解析

### 5.1 典型寄存器模型

不同 MCU 名称不同，但通常存在以下字段：

```
COMPx_CSR
├─ EN       比较器使能
├─ INPSEL   正输入选择
├─ INMSEL   负输入选择
├─ POL      输出极性
├─ HYST     内部迟滞档位
├─ SPEED    速度/功耗档位
├─ BLANK    消隐或滤波配置
├─ OUT      当前比较结果
├─ LOCK     配置锁定
└─ WNDEN    窗口模式使能
```

### 5.2 生产级初始化框架

```
#include <stdint.h>
#include <stdbool.h>

#define COMP_CSR_EN       (1u << 0)
#define COMP_CSR_POL      (1u << 1)
#define COMP_CSR_OUT      (1u << 2)
#define COMP_CSR_LOCK     (1u << 31)
#define COMP_CSR_HYST_Pos 4u
#define COMP_CSR_INP_Pos  8u
#define COMP_CSR_INM_Pos  12u

#define COMP_HYST_20MV    2u
#define COMP_SPEED_FAST   1u

struct comp_regs {
    volatile uint32_t CSR;
    volatile uint32_t RESERVED[3];
};

static struct comp_regs *const COMP1 =
    (struct comp_regs *)0x40010000u; /* 示例地址，禁止直接用于具体产品 */

enum comp_input {
    COMP_IN_GPIO0 = 0,
    COMP_IN_DAC1  = 1,
    COMP_IN_VREF  = 2,
};

enum comp_status {
    COMP_OK = 0,
    COMP_EINVAL = -1,
    COMP_EBUSY = -2,
};

int comp_init(enum comp_input inp, enum comp_input inm,
              bool inverted, uint32_t hyst)
{
    if (inp > COMP_IN_VREF || inm > COMP_IN_VREF) {
        return COMP_EINVAL;
    }
    if (hyst > 3u) {
        return COMP_EINVAL;
    }

    /* 1. 先关闭，避免切换模拟 MUX 时产生伪输出 */
    COMP1->CSR &= ~COMP_CSR_EN;

    /* 2. GPIO 应先切换为模拟模式；DAC/VREF 应先稳定 */
    uint32_t cfg = ((uint32_t)inp << COMP_CSR_INP_Pos) |
                   ((uint32_t)inm << COMP_CSR_INM_Pos) |
                   (hyst << COMP_CSR_HYST_Pos) |
                   (COMP_SPEED_FAST << 16);

    if (inverted) {
        cfg |= COMP_CSR_POL;
    }

    /* 3. 一次性写入关键配置，减少中间状态 */
    COMP1->CSR = cfg;
    COMP1->CSR |= COMP_CSR_EN;

    /* 4. 按数据手册要求等待启动时间，而不是盲目延时 */
    for (volatile uint32_t i = 0; i < 100u; ++i) {
        __asm volatile ("nop");
    }
    return COMP_OK;
}

bool comp_get_output(void)
{
    return (COMP1->CSR & COMP_CSR_OUT) != 0u;
}
```

> 实际产品中应使用厂商头文件、位域定义和读回校验；不要假设 CSR 可任意读改写，尤其要注意写 1 清零、锁定位和保留位。

### 5.3 迟滞的工程含义

无迟滞时，输入接近阈值会因噪声在两个状态间快速翻转。引入迟滞后：

```
上升触发阈值：VTH+ = VREF + VH/2
下降释放阈值：VTH- = VREF - VH/2
窗口宽度：     ΔV = VH
```

例如，输入噪声峰峰值为 12 mV，则至少应满足：

```
VH > 12 mV + 设计裕量
```

若要求噪声触发概率很低，不能只按峰峰值选取，还应考虑温漂、参考误差、输入失调和 PCB 耦合。

### 5.4 异步输出与同步输出

- **异步路径**：适合硬件保护，典型传播延迟为几十至数百 ns；但输入毛刺也可能传到 PWM 刹车端。
- **同步路径**：输出在时钟边沿采样，延迟近似为 `1~2 × Tclk + tpd`，可降低随机毛刺影响，但不适合要求最短关断时间的场景。

工业设计通常采用：

```
COMP 异步输出 -> PWM 硬件刹车
COMP 同步/中断输出 -> CPU 记录故障、执行恢复策略
```

### 5.5 窗口比较

```
COMP_LOW:  VINPUT < VLOW  -> 欠压
COMP_HIGH: VINPUT > VHIGH -> 过压
正常区间： VLOW <= VINPUT <= VHIGH
```

窗口逻辑应同时处理两路故障，并对“两个输出同时异常”保留诊断信息，不能简单 OR 后丢弃来源。

## 6. 性能量化分析

### 6.1 测试条件示例

以下为工程估算示例，平台假设为 3.3 V MCU、COMP 时钟 80 MHz、室温 25 °C；最终数据必须以目标芯片实测为准。

|指标|典型值|影响因素|
|---|---|---|
|模拟传播延迟|80 ns|速度档位、输入过驱幅度、温度|
|同步路径延迟|100~125 ns|80 MHz 时钟量化|
|输入失调电压|±5 mV|温度、工艺、共模电压|
|内部迟滞|5/10/20/40 mV|迟滞档位误差|
|使能启动时间|1~5 μs|模拟偏置建立时间|
|运行电流|5~50 μA|速度/低功耗配置|
|配置内存|约 0~100 B|是否带驱动状态结构体|
|ISR 处理时间|0.5~3 μs|主频、日志和故障路径|

### 6.2 保护链路延迟

```
Ttrip = Tinput_filter + Tcomp + Troute + Tbrake + Tpower_stage
```

示例：

```
Tinput_filter = 120 ns
Tcomp         = 80 ns
Troute        = 20 ns
Tbrake        = 60 ns
Tpower_stage  = 150 ns
Ttrip         = 430 ns
```

如果改为中断关断：

```
Ttrip_irq = Tcomp + Tsync + TNVIC + TISR + Twrite + Tpower_stage
```

即使 CPU 中断平均只需 2 μs，也可能因关中断、缓存、RTOS 临界区而出现几十 μs 的最坏延迟，因此快速保护不应依赖软件中断链路。

### 6.3 阈值误差预算

```
Etotal = sqrt(Eref² + Edac² + Eoffset² + Edivider² + Etemp² + Enoise²)
```

若各误差分别为 3、4、5、2、4、3 mV：

```
Etotal = sqrt(3² + 4² + 5² + 2² + 4² + 3²) ≈ 9.1 mV
```

阈值保护裕量应至少覆盖 `Etotal`，并根据安全等级增加系统裕量，而不是只按 DAC 分辨率计算。

### 6.4 优化手段

- 用硬件事件路由代替 ISR 关断，可将最坏延迟从微秒级降至亚微秒级。
- 用内部 DAC 替代高阻外部分压，可减少 BOM，但必须评估 DAC INL、噪声和更新毛刺。
- 选择合适迟滞而非一味增大：迟滞越大，抗噪越强，但检测死区也越宽。
- 将高速保护与慢速诊断分离：高速链路负责关断，ADC/CPU 负责测量和记录。

## 7. 应用场景选型指南

### 纯文本决策流程图

```
是否要求亚微秒级关断？
├─ 是 -> 是否允许输入毛刺直接触发？
│      ├─ 否 -> COMP + 硬件消隐/迟滞/定时器过滤
│      └─ 是 -> COMP 异步输出 -> PWM Break/门极关断
└─ 否 -> 是否需要可编程阈值？
       ├─ 是 -> COMP + DAC/VREF
       └─ 否 -> 是否需要区间判断？
              ├─ 是 -> 双 COMP 窗口检测
              └─ 否 -> COMP 中断或轮询
```

|需求|方案|理由|
|---|---|---|
|电机过流保护|COMP + 分流放大器 + PWM Break|不依赖 CPU，故障响应快|
|电源过压/欠压|双 COMP + 内部 DAC|阈值可调，支持窗口诊断|
|电池低电量唤醒|COMP + VREF + 低功耗唤醒|静态功耗低，CPU 可休眠|
|零交叉检测|COMP + 迟滞 + 定时器捕获|可直接测量周期和相位|
|模拟传感器阈值报警|COMP + 中断/事件|比 ADC 周期采样更及时|
|高频开关电源保护|高速 COMP + 硬件消隐|抑制开关瞬间尖峰|

## 8. 工程最佳实践

### 设计原则

1. **保护路径硬件化**：安全相关关断不依赖 RTOS 任务和普通 ISR。
2. **配置前先断开输出**：切换输入 MUX、极性和参考源时，避免中间状态误触发。
3. **模拟输入独立布局**：远离高 dv/dt 开关节点、栅极驱动线和高速时钟。
4. **阈值可追溯**：记录参考电压、DAC 码值、分压比例、温度和校准版本。
5. **故障必须锁存**：瞬态故障不能因信号恢复而丢失诊断证据。
6. **提供自检机制**：通过测试 MUX、内部已知电平或受控 DAC 阈值验证信号链。

### 选型决策矩阵

|指标|轮询|中断|异步硬件|外部比较器|
|---|---|---|---|---|
|低延迟|1|3|5|4|
|低 CPU 占用|1|3|5|5|
|灵活性|4|4|3|5|
|低成本|5|5|5|2|
|抗 MCU 软件故障|1|2|5|5|

### 工业级编码规范

- 所有输入编号、极性、阈值和迟滞使用枚举，不使用裸数字。
- 初始化函数返回错误码，不在底层驱动中静默修正非法配置。
- 对寄存器写入后进行关键字段读回或状态确认。
- 故障 ISR 只做硬件安全动作和事件入队，日志、通信和恢复放到任务上下文。
- 不在比较器 ISR 中执行阻塞 API、动态内存分配和复杂 printf。

## 9. 常见错误与避坑指南

### 错误一：GPIO 未切换为模拟模式

错误代码：

```
/* 错误：引脚仍为推挽输出或带上下拉 */
GPIOA->MODE &= ~(3u << 6);
GPIOA->MODE |=  (1u << 6); /* 普通数字输入 */
COMP1->CSR |= COMP_CSR_EN;
```

根因：数字输入缓冲器、上下拉和模拟开关未按手册关闭。

正确实现：

```
GPIOA->MODE &= ~(3u << 6);
GPIOA->ANALOG |= (1u << 6);
GPIOA->PULL &= ~(3u << 6);
/* 再配置 COMP 输入 MUX */
```

风险：输入泄漏、阈值偏移、数字噪声耦合，严重时无法稳定翻转。

### 错误二：无迟滞直接连接慢变化信号

错误代码：

```
COMP1->CSR = COMP_CSR_EN; /* HYST = 0 */
```

根因：传感器信号在阈值附近包含噪声，输出产生多次边沿。

正确实现：

```
COMP1->CSR = (COMP_HYST_20MV << COMP_CSR_HYST_Pos) | COMP_CSR_EN;
```

风险：中断风暴、继电器抖动、PWM 反复关断、状态机异常。

### 错误三：用中断代替硬件保护

错误代码：

```
void COMP_IRQHandler(void)
{
    PWM->CTRL &= ~PWM_ENABLE; /* 依赖 CPU 才关断 */
}
```

根因：中断可能被屏蔽、延迟或被更高优先级抢占。

正确实现：

```
COMP 异步输出 -> PWM Break 输入 -> 硬件关断
                         └-> COMP ISR：锁存故障、记录时间戳
```

风险：MOSFET、IGBT 或功率级在软件响应前已损坏。

### 错误四：切换 DAC 阈值时未处理更新毛刺

错误代码：

```
DAC->DATA = new_code;
/* 立即认为 COMP 输出稳定 */
```

根因：DAC 输出建立时间和码间切换毛刺可能暂时跨越比较阈值。

正确实现：

```
COMP1->CSR &= ~COMP_CSR_EN;
DAC->DATA = new_code;
wait_us(DAC_SETTLE_US);
COMP1->CSR |= COMP_CSR_EN;
/* 重新确认输出，并清除旧事件标志 */
```

风险：产生伪过压/欠压事件，尤其危险于门限动态调整系统。

### 错误五：忽略输入绝对最大额定值

错误代码：

```
/* 直接将可能超过 VDDA 的外部信号接入 COMP */
COMP_INPUT_PIN = EXTERNAL_SIGNAL;
```

根因：把“可比较电压范围”误认为“绝对允许输入范围”。

正确实现：

```
外部信号 -> 限流电阻 + 分压/钳位 -> COMP 输入
并验证：输入电压、注入电流、共模范围、断电状态行为
```

风险：ESD 二极管导通、模拟开关损伤、断电反灌和长期可靠性下降。

## 10. 多机制组合使用方案

推荐的保护架构：

```
电流采样 -> 放大器 -> COMP
                       ├─异步-> PWM Break
                       ├─事件-> 定时器停止触发
                       └─中断-> 故障锁存/诊断任务
DAC ------------------┘
ADC <----------------- 采样与故障前后波形记录
看门狗 ---------------- 系统级兜底复位
```

核心框架：

```
typedef struct {
    volatile bool tripped;
    volatile uint32_t edge_count;
    volatile uint32_t last_tick;
} comp_fault_state_t;

static comp_fault_state_t g_fault;

void comp_fault_irq(void)
{
    uint32_t flags = COMP1->CSR;

    /* 第一优先级：确认硬件保护已动作 */
    PWM->BREAK |= PWM_BREAK_LATCH;

    /* 只做不可延迟的锁存和最小诊断 */
    g_fault.tripped = true;
    g_fault.edge_count++;
    g_fault.last_tick = TIMER->CNT;

    /* 按芯片定义清除事件；避免错误写法清掉其他外设标志 */
    COMP1->CSR = flags | COMP_EVENT_CLEAR;
}

bool comp_fault_take(void)
{
    bool value;
    ENTER_CRITICAL();
    value = g_fault.tripped;
    g_fault.tripped = false;
    EXIT_CRITICAL();
    return value;
}
```

注意：`PWM Break` 应具备硬件锁存；恢复动作必须由上层安全状态机决定，不能在 ISR 中自动重启功率级。

## 11. 工业级实际案例分析

### 案例一：无刷电机过流保护

**需求**：母线电流超过 35 A 时，在 1 μs 内关闭 PWM；CPU 需记录故障。

**架构**：分流电阻 + 电流放大器 + COMP + DAC 阈值 + PWM Break。

**设计要点**：

- 按最坏放大器输出和 COMP 输入共模范围校核。
- 使用硬件消隐覆盖 PWM 开通瞬间尖峰，例如 300 ns。
- 保护阈值必须包含分流电阻容差、放大器增益误差、COMP 失调和温漂。
- 硬件关断后锁存，软件仅允许人工或受控策略恢复。

**核心时序**：

```
过流发生 -> COMP 80 ns -> 路由 20 ns -> PWM Break 60 ns -> 功率级关断
```

### 案例二：24 V 工业电源窗口监控

**需求**：输入低于 18 V 或高于 30 V 时进入安全状态，支持欠压/过压来源诊断。

**架构**：输入分压 + COMP_LOW + COMP_HIGH + 内部 VREF/DAC + 低功耗唤醒。

**设计要点**：

- 两路阈值独立校准，不能只通过软件假设窗口对称。
- 分压电阻的容差和输入漏电必须纳入误差预算。
- 断电时检查 GPIO 注入电流，避免通过 COMP 输入反向给 MCU 供电。
- 记录故障方向、持续时间和恢复次数，防止电源抖动导致反复启动。

### 案例三：电池供电设备的低功耗唤醒

**需求**：系统深睡眠时监控电池欠压，静态功耗小于 10 μA。

**架构**：低功耗 COMP + 内部低功耗参考 + 迟滞 + 唤醒事件。

**设计要点**：

- 选择低功耗速度档位，接受更大的传播延迟。
- 迟滞必须足以覆盖负载切换造成的电池电压跌落。
- 唤醒后由 ADC 复测，区分真实欠压和瞬态负载波动。
- 防止唤醒后立即关闭再唤醒，采用最小保持时间和恢复门限。

## 12. 高频问题深度答疑

### 1. COMP 能否替代 ADC？

不能完全替代。COMP 只提供 1-bit 判决，适合阈值、边沿和快速保护；ADC 才能提供幅值、趋势和诊断信息。工程上常用 COMP 保证实时性、ADC 提供可观测性。

### 2. 为什么输入已高于参考，输出仍可能不稳定？

可能原因包括输入过驱不足、共模范围越界、输入失调、参考噪声、迟滞不足、模拟开关未稳定和 PCB 耦合。应测量比较器两端的实际电压，而不是只看软件配置值。

### 3. 迟滞越大是否越好？

不是。迟滞提高抗噪能力，但会造成触发和释放阈值分离，使检测精度下降。应按噪声统计、温漂和允许死区共同确定，并通过实测验证误触发概率。

### 4. 为什么不建议在 ISR 中直接恢复 PWM？

故障恢复涉及原因确认、功率器件状态、热状态、重试次数和系统安全策略。ISR 只能完成快速关断和记录；直接恢复可能在短路尚未消失时重复开通，形成灾难性振荡。

### 5. COMP 输出是否需要同步到 CPU 时钟域？

若进入异步硬件保护路径，不应为了 CPU 同步而增加保护延迟。若进入数字逻辑、计数器或跨时钟域模块，应使用芯片提供的同步器或事件同步机制，并评估亚稳态概率与延迟。

### 6. 内部 DAC 阈值是否足够精确？

取决于 DAC 分辨率、INL/DNL、参考精度、温漂、输出噪声和 COMP 失调。若系统阈值误差预算小于这些误差之和，应使用外部精密参考、外部比较器或增加校准。

## 13. 课程核心总结

- **COMP 是模拟信号到数字事件的低延迟边界器件**，价值不在于“读取一个 GPIO”，而在于建立确定性的硬件判决链。
- **快速保护优先选择异步 COMP + 硬件事件路由**，CPU 仅承担记录、诊断和恢复管理。
- **阈值设计必须进行完整误差预算**：参考、DAC、分压、失调、温漂、噪声和迟滞缺一不可。
- **慢边沿信号必须配合迟滞、滤波或消隐**，否则现场容易出现抖动和中断风暴。
- **窗口比较、DAC 阈值、定时器捕获和 PWM Break 是 COMP 的高价值组合**。
- 典型性能排序：

```
硬件异步保护 > 硬件同步事件 > 中断处理 > RTOS 任务处理 > 轮询
```

## 16. 实践与进阶路径

### 梯度实战任务

1. **基础驱动任务**：完成 COMP 外部输入、极性、迟滞和状态读取；验证静态电平切换。
2. **阈值任务**：使用内部 DAC 产生可调阈值，扫描输入电压并生成触发/释放曲线。
3. **抗干扰任务**：注入可控噪声，比较无迟滞、不同迟滞和 RC 滤波下的误触发率。
4. **事件路由任务**：实现 COMP 直接触发定时器捕获和 PWM Break，测量 CPU 参与与否的延迟差异。
5. **窗口监控任务**：实现欠压/过压双路检测、故障锁存、恢复门限和事件统计。
6. **工业验证任务**：开展温度、电源变化、输入过压、断电反灌、EMI 注入和故障注入测试。

### 性能测试方法

- 使用函数发生器输出缓慢斜坡，测量上升触发阈值和下降释放阈值。
- 使用示波器同时观察 COMP 输入、输出、PWM Break 和功率级关断信号。
- 以不同输入过驱幅度测量传播延迟，建立 `tpd = f(Voverdrive)` 曲线。
- 在高低温和最小/最大 VDDA 下重复测试，验证阈值漂移。
- 注入窄脉冲、PWM 尖峰和共模干扰，统计误触发率与漏检率。
- 对事件路由执行最坏情况测试：关中断、最高负载、RTOS 临界区和低功耗唤醒。

### 进阶学习方向

- 高速模拟比较器与输入噪声建模。
- 定时器 Break、事件系统和跨时钟域安全设计。
- 电机控制中的 cycle-by-cycle current limit。
- 电源管理 IC、窗口监控和 SIL/ASIL 诊断覆盖率。
- COMP 与 ADC、DAC、DMA、低功耗域协同设计。
- 基于示波器自动化测量的硬件在环测试与故障注入平台。
