
> 本课聚焦 **GPIO/EXTI、RTC、LPTIM、UART、低功耗比较器、看门狗、复位/唤醒标志** 等唤醒源的底层机制、配置时序、竞态控制、功耗影响和组合架构。示例采用 **Cortex-M + STM32 风格伪 HAL/寄存器接口**，寄存器名称必须以目标 MCU Reference Manual 为准。

## 3. 技术概述

### 3.1 唤醒源的本质

低功耗模式下，CPU 主时钟可能停止，但芯片仍保留一组始终在线或低功耗时钟域，用于检测事件。一个典型唤醒链路如下：

```
外部物理信号
    ↓
GPIO 输入缓冲/模拟比较器/串口接收器
    ↓
同步器、边沿检测、数字滤波
    ↓
EXTI / RTC / LPTIM / UART Wakeup Flag
    ↓
PWR Wakeup Logic
    ↓
CPU 唤醒或系统复位
    ↓
ISR、PendSV 或 Boot 阶段读取唤醒原因
```

唤醒源可分为：

1. **外部源**：GPIO 边沿、电平、按键、开盖、振动、外部中断。
2. **内部时基源**：RTC Alarm、RTC Wakeup Timer、LPTIM、低功耗定时器。
3. **通信源**：UART Start Bit、特定地址、帧匹配、LIN Break、低功耗串口。
4. **安全与监控源**：独立看门狗、窗口看门狗、掉电检测、温度/电压监控。
5. **复位型源**：Standby 唤醒脚、RTC 唤醒、系统复位事件。

### 3.2 中断唤醒与事件唤醒

- **中断唤醒**：事件进入 NVIC，CPU 唤醒后执行 ISR。
- **事件唤醒**：事件寄存器被置位，可用于 `WFE`；不一定产生完整中断服务流程。
- **复位型唤醒**：CPU 上下文丢失，启动代码重新执行，必须通过 PWR/RTC/备份域判断原因。

**工程结论：唤醒能力不等于业务可用性。** 一个 GPIO 可能能唤醒 CPU，但如果没有正确配置 EXTI、清除旧标志、设置上下拉和 ISR 分发，系统仍可能出现丢事件或唤醒风暴。

## 5. 底层原理与功能特性深度解析

### 5.1 唤醒标志的分层模型

不要将所有标志当成同一种状态。通常至少存在四层：

```
外设原始标志：RTC_ALRAF / LPTIM_ARRM / UART_WUF
        ↓
线路挂起标志：EXTI_PR / EXTI_RPR / EXTI_FPR
        ↓
NVIC 状态：ISPR / ICPR / 中断服务状态
        ↓
电源唤醒标志：PWR_WUFx / Standby Wake Flag
```

清除某一层不一定清除其他层。例如清除了 GPIO 的 EXTI Pending，NVIC Pending 可能仍然存在；清除了 PWR 唤醒标志，也不一定清除了 RTC Alarm 标志。

工业级处理应采用：

1. 读取并保存所有原因寄存器；
2. 按芯片规定顺序清除外设和 PWR 标志；
3. 再使能唤醒源；
4. 最后进入 `WFI`/Standby。

### 5.2 GPIO/EXTI 唤醒

#### 边沿和电平

- **上升沿**：适合按钮释放、传感器高有效脉冲；
- **下降沿**：适合开门开关、低有效告警；
- **双边沿**：适合状态变化检测，但必须在 ISR 中重新读取 GPIO 电平；
- **电平唤醒**：适合保持有效直到 CPU 处理的告警，但若有效电平不解除，会反复唤醒。

```
typedef enum {
    GPIO_WAKE_RISING,
    GPIO_WAKE_FALLING,
    GPIO_WAKE_BOTH,
} gpio_wake_edge_t;

typedef struct {
    uint32_t pin;
    gpio_wake_edge_t edge;
    gpio_pull_t pull;
    uint32_t debounce_us;
} gpio_wake_cfg_t;

bool gpio_wakeup_configure(const gpio_wake_cfg_t *cfg)
{
    if (cfg == NULL || cfg->pin == 0U) {
        return false;
    }

    exti_disable_line(cfg->pin);
    exti_clear_pending(cfg->pin);
    nvic_clear_pending(gpio_irqn(cfg->pin));

    gpio_config_input_pull(cfg->pin, cfg->pull);
    exti_set_edge(cfg->pin, cfg->edge);
    exti_clear_pending(cfg->pin);
    exti_enable_line(cfg->pin);
    nvic_enable_irq(gpio_irqn(cfg->pin));

    return true;
}
```

#### 中断服务函数

ISR 不应直接执行复杂业务、延时去抖或启动无线模块，应只完成确认、记录和投递事件：

```
void EXTI0_IRQHandler(void)
{
    uint32_t pending = exti_get_pending(GPIO_WAKE_PIN);

    if ((pending & GPIO_WAKE_PIN) != 0U) {
        exti_clear_pending(GPIO_WAKE_PIN);

        /* 记录时间和当前电平，供任务级去抖 */
        wake_event_post_isr(WAKE_SRC_GPIO,
                             gpio_read(GPIO_WAKE_PIN),
                             rtc_timestamp());
    }

    nvic_clear_pending(EXTI0_IRQn);
}
```

### 5.3 GPIO 去抖与伪唤醒率

机械触点在 1~10 ms 内可能产生多个边沿；长线和工业环境还会引入 EMI 脉冲。硬件 RC 可降低高频噪声，软件去抖可验证稳定时间。

```
bool gpio_event_is_stable(uint32_t pin, uint32_t stable_ms)
{
    bool first = gpio_read(pin);
    delay_ms(stable_ms);
    return gpio_read(pin) == first;
}
```

上述代码只适合任务上下文，**禁止在 ISR 中阻塞**。更好的生产方案是时间戳过滤：

```
static volatile uint32_t s_last_gpio_event_ms;

void gpio_wake_event_isr(void)
{
    uint32_t now = low_power_time_ms();

    if ((now - s_last_gpio_event_ms) >= GPIO_DEBOUNCE_MS) {
        s_last_gpio_event_ms = now;
        event_queue_push_from_isr(EVENT_DOOR_CHANGED);
    }
}
```

注意：去抖窗口不能大于系统允许的最小响应时间。对于安全急停信号，应使用硬件安全链路，不能用软件去抖替代。

### 5.4 RTC Alarm 与 Wakeup Timer

使用 LSE 32.768 kHz 时：

Ttick=30.5176 μsTtick​=30.5176 μs

若计数器时钟为 1 Hz，预约 TT 秒后的唤醒，需要根据硬件定义配置 `T-1` 或 `T`，不能凭经验统一处理。

```
typedef struct {
    uint32_t timeout_s;
    bool periodic;
} rtc_wake_cfg_t;

bool rtc_wakeup_arm(const rtc_wake_cfg_t *cfg)
{
    if (cfg == NULL || cfg->timeout_s == 0U) {
        return false;
    }

    rtc_wakeup_disable();
    rtc_clear_wakeup_flag();
    exti_clear_pending(RTC_WAKE_LINE);
    nvic_clear_pending(RTC_IRQn);

    if (!rtc_wakeup_set_counter(cfg->timeout_s - 1U)) {
        return false;
    }

    rtc_enable_wakeup_interrupt();
    rtc_wakeup_enable();
    return true;
}
```

必须考虑：

- LSE 误差：32 kHz 晶振 ±20 ppm，长期误差约为每天 ±1.728 秒；
- LSI 温漂可能远大于 LSE；
- RTC 写保护和同步等待；
- Alarm 标志与 EXTI 标志都要清除；
- 周期唤醒应根据绝对时间重算，避免每次相对累加造成漂移。

### 5.5 UART 唤醒

UART 唤醒通常有三类实现：

1. 起始位唤醒；
2. 地址/匹配字节唤醒；
3. LIN Break 或特定帧唤醒。

关键问题是：低功耗期间 UART 接收时钟是否运行、首字节是否被硬件缓存、唤醒后波特率是否准确。

```
bool uart_wakeup_prepare(uint32_t baudrate)
{
    if (!uart_set_wakeup_source(UART_WAKE_START_BIT)) {
        return false;
    }

    uart_set_wakeup_baudrate(baudrate);
    uart_clear_wakeup_flag();
    exti_clear_pending(UART_WAKE_LINE);
    uart_enable_wakeup();
    return true;
}

void UART_IRQHandler(void)
{
    uint32_t status = uart_status();

    if ((status & UART_STATUS_WAKEUP) != 0U) {
        uart_clear_wakeup_flag();
        wake_event_post_isr(WAKE_SRC_UART, 0U, low_power_timestamp());
    }
}
```

如果硬件只能靠起始位唤醒，首字节可能被用于唤醒而无法交给应用。协议层应设计 **前导字节、同步字节和 CRC**，例如：

```
0x55 0x55 0xA5 LEN PAYLOAD CRC16
```

唤醒后丢弃前导字节，等待完整同步帧，避免把半帧交给协议栈。

### 5.6 LPTIM 与外部计数

LPTIM 常适合 Stop 模式下周期唤醒或低频脉冲计数。配置时要验证：

- 计数器时钟是否来自保持的时钟域；
- ARR 写入是否需要同步等待；
- 唤醒事件是 Update、Compare 还是外部触发；
- Stop 唤醒后是否需要重新启动计数器；
- 计数器溢出和重装载行为。

```
bool lptim_arm(uint32_t ticks)
{
    if (ticks == 0U || ticks > LPTIM_MAX_RELOAD) {
        return false;
    }

    lptim_disable();
    lptim_clear_all_flags();
    lptim_set_autoreload(ticks - 1U);
    lptim_enable_update_interrupt();
    lptim_enable();
    lptim_start_counter();
    return true;
}
```

### 5.7 唤醒源配置的原子时序

典型安全时序：

```
关闭目标唤醒源
    ↓
清除外设原始标志
    ↓
清除 EXTI/PWR/NVIC 挂起标志
    ↓
配置触发边沿、计数器、滤波和上下拉
    ↓
再次清除可能由配置动作产生的标志
    ↓
使能外设中断和 PWR 唤醒通道
    ↓
DSB
    ↓
WFI/WFE
```

进入前应在关闭中断或 RTOS 内核规定的临界区内完成“检查空闲条件—配置唤醒源—执行等待”，否则会出现：

```
检查无事件 → 事件到达 → 清标志/配置覆盖事件 → WFI
```

结果是事件已发生但 CPU 继续睡眠。

### 5.8 多个唤醒源同时发生

唤醒原因必须使用位图而非单一枚举：

```
typedef uint32_t wake_reason_mask_t;

enum {
    WAKE_REASON_RTC   = 1UL << 0,
    WAKE_REASON_GPIO  = 1UL << 1,
    WAKE_REASON_UART  = 1UL << 2,
    WAKE_REASON_WDG   = 1UL << 3,
    WAKE_REASON_RESET = 1UL << 4,
};

wake_reason_mask_t wake_reason_collect(void)
{
    wake_reason_mask_t r = 0U;

    if (rtc_wakeup_flag()) r |= WAKE_REASON_RTC;
    if (gpio_wakeup_flag()) r |= WAKE_REASON_GPIO;
    if (uart_wakeup_flag()) r |= WAKE_REASON_UART;
    if (watchdog_reset_flag()) r |= WAKE_REASON_WDG;
    if (reset_cause_flag()) r |= WAKE_REASON_RESET;

    return r;
}
```

**不要通过 `if ... else if ...` 丢弃并发发生的第二个原因。** 业务层可以定义优先级，例如安全告警 > 通信 > 周期采样，但底层日志应保留完整位图。

### 6.3 GPIO 伪唤醒率

长时间统计：

Rfalse=NfalseTobservationRfalse​=Tobservation​Nfalse​​

若每次伪唤醒额外消耗能量 EwakeEwake​，平均功率损失为：

Pfalse=Rfalse×EwakePfalse​=Rfalse​×Ewake​

例如伪唤醒率为 0.2 次/分钟、每次恢复能量 30 μJ：

Pfalse=0.260×30μJ=0.1μWPfalse​=600.2​×30μJ=0.1μW

虽然数值可能不大，但频繁启动无线模块时，单次能量会从几十 μJ 增至数 mJ，必须重点治理。

### 6.4 RTC 漂移

晶振误差为 ppmppm 时，时间误差近似为：

Δt=t×ppm×10−6Δt=t×ppm×10−6

20 ppm 晶振运行 24 小时：

Δt=86400×20×10−6=1.728sΔt=86400×20×10−6=1.728s

优化手段：温度补偿、生产校准、网络对时、按绝对时间计算下一次 Alarm。典型校准可将长期误差从 ±20 ppm 降至 ±2~5 ppm，收益取决于晶体、温度和校准算法。

### 6.5 唤醒能量

Ewake=∫V(t)I(t)dtEwake​=∫V(t)I(t)dt

若电压恒定：

Ewake=V×I×tEwake​=V×I×t

假设 3.3 V、8.6 mA、100 μs：

Ewake≈2.84μJEwake​≈2.84μJ

但若唤醒后还要启动传感器和无线模块，真正主导能耗的是整个活动窗口，而不是 MCU 的唤醒瞬间。

## 7. 应用场景选型指南

### 7.1 决策流程图

```
是否需要 CPU 上下文继续执行？
├─ 否：允许系统复位？
│  ├─ 是：使用 RTC/唤醒脚 → Standby/Shutdown
│  └─ 否：保存上下文 → Stop
└─ 是：
   ├─ 外设必须保持运行？ → Sleep
   ├─ 预计空闲时间 < 唤醒交叉点？ → Sleep
   └─ 需要低功耗时基唤醒？
      ├─ 周期/绝对时间 → RTC
      ├─ 高精度短周期 → LPTIM
      ├─ 外部状态变化 → GPIO/EXTI
      └─ 总线数据到达 → UART Wakeup
```

### 7.2 典型场景

|需求|推荐唤醒源/模式|理由|
|---|---|---|
|门磁变化立即响应|GPIO 下降沿 + Stop|硬件事件直接唤醒，RAM 保持|
|每 10 秒采样|RTC Wakeup Timer + Stop|低速时钟保持，周期可预测|
|每天固定时间上报|RTC Alarm + Standby|支持绝对时间，静态功耗最低|
|低功耗串口接收|UART 起始位/地址唤醒|避免全速运行等待总线|
|电机故障|硬件 Break + GPIO/比较器|安全动作不能依赖软件轮询|
|工业设备无人值守|RTC + GPIO + 看门狗|周期维护、外部告警和故障自恢复组合|

## 8. 工程最佳实践

### 8.1 设计原则

1. **唤醒源必须有唯一责任模块**，禁止业务层直接改 EXTI/PWR 寄存器。
2. **先读取、后清除、再配置、最后使能**。
3. 所有唤醒源必须定义：触发条件、去抖方式、超时、优先级和恢复路径。
4. ISR 只做硬件确认、时间戳和事件投递，不做阻塞操作。
5. 唤醒原因使用位图并保留原始寄存器快照。
6. 进入 Standby 前必须保存带 **Magic、版本、长度、序号、CRC** 的上下文。
7. 任何唤醒源配置失败都必须回退到 Sleep 或安全时钟运行。
8. 对安全信号使用硬件链路；软件唤醒只负责诊断和恢复。

### 8.2 选型决策矩阵

评分 1~5，分数越高越优。

|指标|GPIO|RTC|LPTIM|UART|看门狗|
|---|---|---|---|---|---|
|低功耗能力|5|5|4|3|4|
|时间准确性|不适用|4|3~5|不适用|2|
|响应速度|5|3|4|4|1|
|抗噪声能力|2~4|5|4|3|5|
|软件复杂度|3|4|4|5|2|
|适合安全恢复|4|2|2|1|5|

## 9. 常见错误与避坑指南

### 9.1 错误一：只清 PWR 标志，不清外设标志

**错误代码：**

```
pwr_clear_wakeup_flags();
configure_rtc_wakeup();
enter_standby();
```

**根因：** RTC Alarm 或 EXTI Pending 仍有效，刚进入就再次唤醒。

**正确实现：**

```
rtc_wakeup_disable();
rtc_clear_alarm_flag();
exti_clear_pending(RTC_WAKE_LINE);
nvic_clear_pending(RTC_IRQn);
pwr_clear_wakeup_flags();
rtc_configure_next_alarm();
rtc_wakeup_enable();
```

**风险：** Standby 进入失败、唤醒风暴、平均电流异常升高。

### 9.2 错误二：GPIO 输入悬空

**错误代码：**

```
gpio_config_input(WAKE_PIN);
```

**根因：** 输入端受 EMI 和漏电影响随机翻转。

**正确实现：** 根据外部电路使用确定上拉/下拉，必要时增加 RC、施密特触发或数字滤波。

**风险：** 伪唤醒、事件计数失真、电池寿命下降。

### 9.3 错误三：在 ISR 中延时去抖

**错误代码：**

```
void EXTI_IRQHandler(void)
{
    exti_clear_pending(WAKE_PIN);
    delay_ms(20);
    if (gpio_read(WAKE_PIN)) {
        handle_door_open();
    }
}
```

**根因：** ISR 长时间占用 CPU，阻塞高优先级中断和 RTOS 调度。

**正确实现：** ISR 记录时间戳并投递事件，由任务或定时器完成稳定性确认。

**风险：** 实时性下降、优先级反转、看门狗复位。

### 9.4 错误四：配置完唤醒源后才清标志

**错误代码：**

```
rtc_enable_wakeup();
rtc_clear_wakeup_flag();
__WFI();
```

**根因：** 清标志动作和使能动作之间可能产生或丢失边沿。

**正确实现：** 禁用 → 清除全部相关标志 → 配置 → 再清一次 → 使能 → `DSB` → `WFI`。

**风险：** 丢失真实事件或立即伪唤醒。

### 9.5 错误五：UART 起始位唤醒后直接解析首字节

**错误代码：**

```
void uart_wakeup_handler(void)
{
    uint8_t b = uart_read_byte();
    protocol_parse(b);
}
```

**根因：** 起始位或唤醒过程可能消耗首字节，UART 时钟尚未稳定。

**正确实现：** 使用前导码/同步帧，唤醒后重新同步并校验 CRC。

**风险：** 半帧解析、协议状态机永久失步、偶发通信丢包。

### 9.6 错误六：多个原因使用 `else if` 判断

**错误代码：**

```
if (rtc_flag()) {
    reason = WAKE_RTC;
} else if (gpio_flag()) {
    reason = WAKE_GPIO;
}
```

**根因：** 同时发生时丢弃第二个及后续原因。

**正确实现：** 使用位图采集全部状态，再按业务优先级处理。

**风险：** 安全告警被周期任务覆盖，故障追踪困难。

## 10. 多机制组合使用方案

### 10.1 统一唤醒管理器

```
typedef enum {
    LP_RUN,
    LP_SLEEP,
    LP_STOP,
    LP_STANDBY,
    LP_FAILSAFE,
} lp_state_t;

typedef struct {
    uint32_t deadline_ms;
    bool retain_ram;
    bool peripherals_run;
    uint32_t allowed_sources;
} lp_request_t;

static uint32_t collect_wakeup_flags(void)
{
    uint32_t flags = 0U;
    if (gpio_wakeup_flag()) flags |= WAKE_REASON_GPIO;
    if (rtc_wakeup_flag())  flags |= WAKE_REASON_RTC;
    if (uart_wakeup_flag())  flags |= WAKE_REASON_UART;
    if (watchdog_reset_flag()) flags |= WAKE_REASON_WDG;
    return flags;
}

static bool prepare_wakeup_sources(const lp_request_t *req)
{
    if (req == NULL) return false;

    wake_sources_disable_all();
    wake_sources_clear_all_flags();

    if ((req->allowed_sources & WAKE_REASON_GPIO) != 0U &&
        !gpio_wakeup_arm()) return false;
    if ((req->allowed_sources & WAKE_REASON_RTC) != 0U &&
        !rtc_wakeup_arm_for_deadline(req->deadline_ms)) return false;
    if ((req->allowed_sources & WAKE_REASON_UART) != 0U &&
        !uart_wakeup_prepare(115200U)) return false;

    wake_sources_clear_residual_flags();
    wake_sources_enable_all();
    return true;
}

bool low_power_enter(const lp_request_t *req)
{
    if (!prepare_wakeup_sources(req)) {
        platform_enter_sleep();
        return false;
    }

    peripheral_prepare_for_low_power();

    if (req->peripherals_run) {
        platform_enter_sleep();
    } else if (req->retain_ram) {
        if (!platform_enter_stop()) {
            platform_enter_sleep();
        }
    } else {
        if (!standby_save_context(application_get_state())) {
            platform_enter_stop();
        } else {
            platform_enter_standby();
        }
    }

    return true;
}

void low_power_after_wakeup(void)
{
    uint32_t reasons = collect_wakeup_flags();
    wake_log_record(reasons, rtc_timestamp());

    if ((reasons & WAKE_REASON_WDG) != 0U) {
        enter_safe_recovery_mode();
        return;
    }

    if ((reasons & WAKE_REASON_GPIO) != 0U) {
        schedule_high_priority_event(EVENT_EXTERNAL_ALARM);
    }
    if ((reasons & WAKE_REASON_UART) != 0U) {
        uart_resynchronize_protocol();
    }
    if ((reasons & WAKE_REASON_RTC) != 0U) {
        schedule_periodic_measurement();
    }
}
```

### 10.2 组合策略

```
短空闲：WFI + 普通中断
中等空闲：RTC/LPTIM + GPIO + Stop + Tickless
长空闲：RTC Alarm + 唤醒脚 + Standby + 备份上下文
故障场景：独立看门狗 + 复位原因 + 安全启动
通信场景：UART 唤醒 + 前导码 + DMA + CRC
```

## 11. 工业级实际案例分析

### 11.1 案例一：工业门禁控制器

**需求：** 门磁变化 1 ms 内响应；正常状态每 30 秒上报；电池供电。

**架构：**

```
门磁 GPIO 下降沿 ─┐
RTC 30 s 周期 ────┼→ Stop 唤醒 → 恢复时钟 → 读取全部标志 → 任务调度
看门狗 ──────────┘
```

**设计要点：**

- 门磁输入使用硬件上拉和施密特输入；
- EXTI ISR 只记录边沿时间戳；
- 任务级验证门磁稳定 10 ms；
- RTC 负责周期上报，门磁事件优先级高于周期采样；
- 看门狗超时进入安全模式并记录复位原因；
- 若门磁保持有效，不重复执行同一事件，而是采用状态变化检测。

### 11.2 案例二：低功耗 RS-485 从站

**需求：** 总线空闲时进入 Stop；主站发送地址后唤醒；不能误响应其他从站帧。

**架构：**

```
UART 起始位唤醒 → 接收同步字节 → DMA 接收完整帧 → 地址过滤 → CRC 校验
```

**设计要点：**

- 使用低功耗 UART 时钟；
- 协议增加 `0x55` 前导码和设备地址；
- 唤醒后先恢复系统时钟，再配置 UART 波特率；
- DMA 缓冲区使用环形或双缓冲；
- 总线收发器的 DE/RE 状态必须定义安全默认值；
- 首字节丢失时由协议重发或前导码补偿。

### 11.3 案例三：电池振动记录器

**需求：** 平时待机数月，振动立即唤醒，每 6 小时 RTC 唤醒一次维护。

**方案：**

- 加速度计使用自身运动检测并连接 Standby 唤醒脚；
- RTC Alarm 作为周期维护源；
- 唤醒后读取 PWR、RTC、GPIO 和外部传感器状态；
- 普通 SRAM 不作为可靠上下文，关键计数保存于 Backup SRAM/FRAM；
- 上下文使用双槽位、序号和 CRC，防止掉电写入中断。

**关键结论：** 外部传感器在低功耗状态下的静态电流和中断输出电平，往往比 MCU 唤醒逻辑更决定整机续航。

## 12. 高频问题深度答疑

### 问题一：为什么清除了 EXTI 标志，仍然会立即唤醒？

因为 PWR 唤醒标志、RTC 原始标志或 NVIC Pending 可能仍处于置位状态。必须按芯片规定清理完整链路，而不是只操作 EXTI。

### 问题二：GPIO 电平唤醒和边沿唤醒如何选择？

边沿适合“状态变化”且事件短暂的信号；电平适合“保持有效直到处理”的告警。电平唤醒必须在业务确认并解除有效状态后重新布防，否则会形成唤醒—再次睡眠—立即唤醒循环。

### 问题三：为什么 RTC 定时唤醒存在误差？

误差来自 LSE/LSI 频率容差、温度、电压和校准误差。应以绝对 RTC 时间计算下一次事件，并通过生产校准或网络对时补偿，而不是反复累加相对延时。

### 问题四：UART 唤醒是否能保证收到完整首帧？

不能默认保证。某些硬件用起始位唤醒，首字节可能正在被采样或丢弃。应设计前导码、同步字、地址和 CRC，并通过协议重传保证可靠性。

### 问题五：能否同时开启 GPIO 和 RTC 唤醒？

可以，但必须定义并发语义：保存全部原因，规定优先级，分别清除标志，并确保一个源的清除操作不会误清另一个源。安全告警通常优先于周期任务。

### 问题六：看门狗应不应该在 Stop 中继续运行？

取决于看门狗时钟和系统需求。若 Stop 时间可能超过看门狗窗口，应在进入前计算剩余时间，或使用支持低功耗冻结/低速运行的策略。禁止简单关闭安全看门狗来掩盖恢复异常。

## 13. 课程核心总结

### 核心要点

1. **唤醒源配置是跨 GPIO、外设、EXTI、NVIC 和 PWR 的完整链路问题。**
2. **清标志必须覆盖原始外设、EXTI、NVIC 和 PWR 多层状态。**
3. GPIO 需要正确上下拉、边沿选择、滤波和去抖。
4. RTC/LPTIM 需要校验低功耗时钟、计数边界、同步和漂移。
5. UART 唤醒必须从协议层补偿首字节和时钟恢复风险。
6. 多源并发必须使用位图保留全部原因。
7. ISR 应短小、确定、不可阻塞。
8. Standby 唤醒应按启动流程处理，并校验持久化上下文。

### 性能排序

响应速度通常为：

```
GPIO/硬件比较器 > UART/LPTIM > RTC > Standby 复位启动
```

静态功耗通常为：

```
GPIO/RTC 唤醒逻辑 < LPTIM < UART 低功耗接收 < 保持更多外设的模式
```

### 通用选型结论

- **外部状态变化：GPIO/EXTI**；
- **绝对时间事件：RTC Alarm**；
- **相对周期定时：RTC Wakeup Timer/LPTIM**；
- **总线数据到达：UART Wakeup + 协议前导码**；
- **故障自恢复：独立看门狗 + 复位原因记录**。
