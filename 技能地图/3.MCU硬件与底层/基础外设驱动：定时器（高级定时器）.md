
## 1. 学习目标

### 理解

- 理解通用定时器、高级定时器、基本定时器、低功耗定时器和高分辨率定时器的硬件差异。
- 理解定时器时钟树、预分频器、自动重装载寄存器、捕获比较寄存器和更新事件之间的关系。
- 理解边沿对齐、中心对齐、单脉冲、输入捕获、输出比较、PWM、编码器和触发同步机制。

### 掌握

- 掌握基于寄存器和 HAL/LL 的定时器驱动初始化方法。
- 掌握定时器中断、DMA、触发输入、主从模式和多定时器同步。
- 掌握 PWM 频率、占空比、分辨率和死区时间的计算。
- 掌握输入捕获测频、测脉宽、测占空比和超时检测。

### 精通

- 能够分析定时器更新事件、影子寄存器和预装载寄存器导致的时序问题。
- 能够处理计数器溢出、捕获竞态、DMA 缓冲区一致性和中断延迟。
- 能够解决高级定时器中的互补输出、刹车输入、死区、重复计数器和故障关断问题。
- 能够基于 worst-case latency 验证实时性，而不是仅验证平均执行时间。

### 能够设计

- 能够设计可复用、可测试、支持多实例和故障安全的定时器驱动框架。
- 能够完成电机 PWM、周期任务调度、脉冲测量、超声测距和多定时器同步架构。
- 能够建立定时器参数选型、性能测试和现场故障诊断方案。

## 3. 技术概述

定时器本质上是一个由时钟驱动的**离散时间状态机**。它通常包含：

```
定时器时钟
    |
    v
预分频器 PSC
    |
    v
计数器 CNT <--> 自动重装载 ARR
    |
    +--> 更新事件 UE
    |
    +--> 捕获/比较通道 CCRx
    |
    +--> 输出控制 OCx / PWM
    |
    +--> 触发 TRGO / 输入触发 TIx
    |
    +--> 中断请求 / DMA 请求
```

常见分类：

|类型|典型用途|主要特征|
|---|---|---|
|基本定时器|周期中断、DAC 触发|通常无 GPIO 通道|
|通用定时器|PWM、输入捕获、输出比较|功能均衡|
|高级定时器|三相电机、逆变器|互补输出、死区、刹车、重复计数器|
|低功耗定时器|低功耗唤醒、异步计时|可由低速时钟或外部输入驱动|
|高分辨率定时器|高频 PWM、数字电源|亚纳秒级时间分辨率，依赖专用硬件|
|RTC/LPTIM|长时间计时|低功耗、低频、低精度或高稳定性|

## 5. 底层原理与功能特性深度解析

### 5.1 计数频率与更新频率

设定时器输入时钟为 `f_tim`，预分频器为 `PSC`，自动重装载值为 `ARR`：

```
f_cnt = f_tim / (PSC + 1)

边沿对齐更新频率：
f_update = f_cnt / (ARR + 1)

中心对齐更新频率：
f_update = f_cnt / (2 × (ARR + 1))
```

例如 STM32G4 定时器时钟为 170 MHz，配置：

```
PSC = 169
ARR = 999
```

则：

```
f_cnt = 170 MHz / 170 = 1 MHz
f_update = 1 MHz / 1000 = 1 kHz
```

对应周期为 1 ms。

### 5.2 寄存器更新与影子寄存器

多数高级定时器支持：

- `ARR preload`：ARR 写入预装载寄存器，在更新事件时转移到实际寄存器。
- `CCR preload`：占空比在更新事件时统一生效。
- `UG`：软件产生更新事件。
- `URS`：限制更新请求来源。
- `RCR`：重复计数器，用于降低更新事件频率。

如果 PWM 中途直接修改 `CCR`，可能产生窄脉冲：

```
/* 错误：在计数器已经接近 CCR 时直接更新 */
TIM1->CCR1 = new_compare;
```

建议：

```
static void pwm_set_compare_shadow(TIM_TypeDef *tim,
                                   uint32_t channel,
                                   uint32_t compare)
{
    if (compare > tim->ARR) {
        compare = tim->ARR;
    }

    switch (channel) {
    case 1:
        tim->CCR1 = compare;
        break;
    case 2:
        tim->CCR2 = compare;
        break;
    case 3:
        tim->CCR3 = compare;
        break;
    default:
        break;
    }
    /*
     * CCxP=1 时，CCR 通常进入预装载路径。
     * 由下一个更新事件统一生效，避免半周期波形撕裂。
     */
}
```

### 5.3 PWM 频率、分辨率和中心对齐

PWM 分辨率近似为：

```
resolution_bits = floor(log2(ARR + 1))
```

若计数频率为 170 MHz，PWM 目标频率为 20 kHz：

```
ARR ≈ 170 MHz / 20 kHz - 1 = 8499
```

分辨率约为：

```
log2(8500) ≈ 13.05 bit
```

中心对齐模式下，周期计数路径变长：

```
ARR ≈ 170 MHz / (2 × 20 kHz) - 1 = 4249
```

分辨率约为 12 bit，但具有更好的谐波特性，适合电机和功率变换器。

### 5.4 高级定时器互补输出和死区

半桥驱动需要避免上下管同时导通。死区时间计算近似为：

```
t_dead = DTG_code × t_DTS
```

其中：

```
t_DTS = timer_clock_period × CKD_divider
```

死区必须覆盖：

```
t_dead >= max(
    MOSFET_turn_off_time,
    driver_propagation_mismatch,
    diode_reverse_recovery_time,
    PCB_skew
)
```

死区过小会导致直通；过大会增加体二极管导通时间，降低效率并引入电流畸变。

### 5.5 输入捕获测频

输入捕获的基本流程：

```
边沿到达
    |
    v
锁存 CNT 到 CCR
    |
    v
产生 CCx 中断或 DMA 请求
    |
    v
读取两个时间戳
    |
    v
delta = current - previous
    |
    v
frequency = f_cnt / delta
```

必须使用无符号减法处理计数器回绕：

```
uint32_t timer_delta(uint32_t current, uint32_t previous)
{
    return current - previous;
}
```

对于 `uint32_t`，模 `2^32` 的无符号运算天然支持一次回绕，只要相邻捕获间隔小于计数器完整周期。

### 5.6 输入捕获工程代码

```
typedef struct {
    uint32_t last_capture;
    uint32_t period_ticks;
    uint32_t frequency_hz;
    uint8_t  valid;
} capture_state_t;

static capture_state_t g_capture;

void tim_capture_irq_handler(TIM_TypeDef *tim)
{
    uint32_t status = tim->SR;

    if ((status & TIM_SR_CC1IF) != 0U) {
        uint32_t capture = tim->CCR1;
        uint32_t delta = capture - g_capture.last_capture;

        g_capture.last_capture = capture;

        if (delta != 0U) {
            g_capture.period_ticks = delta;
            /*
             * 若计数频率固定为 1 MHz：
             * f = 1,000,000 / delta
             */
            g_capture.frequency_hz =
                1000000U / delta;
            g_capture.valid = 1U;
        }

        tim->SR = (uint32_t)~TIM_SR_CC1IF;
    }

    if ((status & TIM_SR_CC1OF) != 0U) {
        /*
         * 溢出表示 CPU 或 DMA 未及时处理捕获事件。
         * 当前样本无效，必须清除并记录诊断计数。
         */
        tim->SR = (uint32_t)~TIM_SR_CC1OF;
        g_capture.valid = 0U;
    }
}
```

实际芯片的状态寄存器清除方式必须以参考手册为准，不能盲目套用 `SR = ~mask`。

### 5.7 定时器 DMA

DMA 适用于：

- 连续改变 PWM 占空比。
- 输出精确脉冲序列。
- 采集多个输入捕获时间戳。
- 触发 ADC 并同步读取结果。
- 生成协议波形，例如红外、WS2812、DALI。

DMA 环形缓冲区应使用生产者/消费者边界：

```
#define PWM_DMA_LEN  128U

static uint32_t pwm_dma_buf[PWM_DMA_LEN];

/* 半传输回调 */
void pwm_dma_half_complete(void)
{
    /*
     * 只允许修改前半区。
     * DMA 当前正在使用后半区。
     */
    prepare_pwm_samples(&pwm_dma_buf[0], PWM_DMA_LEN / 2U);
}

/* 全传输回调 */
void pwm_dma_complete(void)
{
    /*
     * 只允许修改后半区。
     */
    prepare_pwm_samples(&pwm_dma_buf[PWM_DMA_LEN / 2U],
                        PWM_DMA_LEN / 2U);
}
```

带数据 Cache 的 Cortex-M7/M55 平台还必须处理：

```
SCB_CleanDCache_by_Addr((uint32_t *)pwm_dma_buf,
                        sizeof(pwm_dma_buf));
```

地址和长度通常需要按 Cache line 对齐，具体规则取决于 Cortex-M 内核和 CMSIS 实现。

## 6. 性能量化分析

以下数据以 **STM32G474，170 MHz，`-O2`，Flash 运行，DWT 周期计数器测量** 为参考样本。实际结果会受编译器、Flash wait state、总线竞争和中断嵌套影响。

|操作|周期数|170 MHz 下时间|
|---|---|---|
|读取 `CNT`|2~5 cycles|12~29 ns|
|直接写 `CCR`|2~6 cycles|12~35 ns|
|LL 风格设置 CCR|8~15 cycles|47~88 ns|
|HAL PWM 设置|80~160 cycles|0.47~0.94 us|
|普通定时器 ISR 入口到退出|70~130 cycles|0.41~0.76 us|
|FreeRTOS ISR 通知|180~350 cycles|1.06~2.06 us|
|DMA 更新一个 32 位 CCR|CPU 近似 0|总线传输约数十 ns|

周期中断的 CPU 占用率：

```
CPU_load = f_interrupt × C_ISR / f_CPU
```

例如：

```
f_interrupt = 20 kHz
C_ISR = 250 cycles
f_CPU = 170 MHz

CPU_load = 20,000 × 250 / 170,000,000
         ≈ 2.94%
```

若使用 HAL，ISR 每次为 1000 cycles：

```
CPU_load ≈ 11.76%
```

### 主要瓶颈

1. 高频 ISR 进入退出开销。
2. ISR 中执行浮点运算、日志和锁操作。
3. 多个定时器同时触发导致 NVIC 峰值延迟。
4. DMA 与 CPU 访问同一总线造成仲裁延迟。
5. Cache 未维护导致 DMA 读到旧数据。
6. PWM 频率过高导致 ARR 太小，分辨率下降。

### 优化措施

- 高频路径使用寄存器或 LL，初始化路径可使用 HAL。
- 使用 DMA 替代逐周期 ISR。
- 将控制计算与波形输出分离。
- 使用中心对齐和重复计数器降低控制中断频率。
- 将日志、格式化和复杂计算移出 ISR。
- 对共享结构使用双缓冲或序列锁。
- 使用 DWT、ETM、逻辑分析仪验证实际 worst-case latency。

## 7. 应用场景选型指南

### 决策流程图

```
是否需要输出周期波形？
├─ 否
│  ├─ 是否需要测量外部边沿时间？
│  │  ├─ 是 -> 输入捕获；高频或多通道时使用 DMA
│  │  └─ 否 -> 更新中断或基本定时器
│  └─ 是否要求低功耗长期计时？
│     ├─ 是 -> RTC / LPTIM
│     └─ 否 -> 通用定时器
└─ 是
   ├─ 是否需要互补输出、死区或故障关断？
   │  ├─ 是 -> 高级定时器
   │  └─ 否 -> PWM 输出比较
   ├─ 波形是否连续且高速变化？
   │  ├─ 是 -> PWM + DMA
   │  └─ 否 -> PWM + CCR 预装载
   └─ 是否需要多个定时器相位同步？
      ├─ 是 -> 主从触发 + TRGO/ITR
      └─ 否 -> 独立定时器
```

|场景|方案|理由|
|---|---|---|
|1 ms 系统节拍|基本/通用定时器更新中断|结构简单，资源消耗低|
|三相 PMSM|高级定时器中心对齐 PWM + ADC 触发|支持互补输出、死区、同步采样|
|编码器测速|编码器接口模式 + 输入捕获|硬件计数避免边沿 ISR|
|超声测距|输入捕获 + 超时更新中断|同时处理回波和无回波场景|
|WS2812|PWM + DMA|精确控制高低电平时序|
|高频采样|定时器 TRGO 触发 ADC|降低软件触发抖动|
|低功耗唤醒|LPTIM/RTC|主时钟关闭后仍可运行|

## 8. 工程最佳实践

### 设计原则

1. **初始化、控制、采集、故障处理分层**。
2. **所有定时器参数使用明确单位**，禁止裸数字。
3. **禁止在 ISR 中调用不可证明实时的函数**。
4. **CCR 更新使用预装载，并明确生效时刻**。
5. **故障关断路径必须独立于软件主循环**。
6. **所有捕获数据必须带有效标志、溢出标志和超时状态**。
7. **定时器配置必须验证时钟源，而不是假设 APB 频率**。
8. **驱动 API 不泄漏 HAL 句柄或芯片寄存器细节**。

### 选型决策矩阵

|需求|优先机制|
|---|---|
|最低 CPU 负载|DMA|
|最低软件复杂度|更新中断|
|最高输出精度|输出比较/PWM|
|高速事件时间戳|输入捕获 DMA|
|电机功率级安全|高级定时器刹车输入|
|多模块同步|TRGO + ITR 主从链路|
|低功耗|LPTIM/RTC|
|高可诊断性|驱动状态机 + 诊断计数器|

### 编码规范

```
#define TIMER_COUNTER_HZ       1000000UL
#define MOTOR_PWM_HZ            20000UL
#define TIMER_DEADTIME_NS      500UL

_Static_assert(MOTOR_PWM_HZ > 0UL, "invalid PWM frequency");
```

不要用：

```
timer->ARR = 8499;
timer->CCR1 = 4250;
```

应使用：

```
timer->ARR = pwm_arr;
timer->CCR1 = duty_to_compare(duty_permille, pwm_arr);
```

## 9. 常见错误与避坑指南

### 错误一：忽略 APB 定时器倍频

错误代码：

```
uint32_t timer_clk = SystemCoreClock / 2U;
```

根因：部分 STM32 在 APB 分频器不为 1 时，定时器时钟为 APB 时钟的 2 倍。

正确实现：

```
uint32_t timer_kernel_clock_hz(void)
{
    /*
     * 必须依据具体 MCU 时钟树和 RCC 配置计算。
     * 不允许简单使用 SystemCoreClock 代替。
     */
    return rcc_get_timer_kernel_clock(TIM1);
}
```

风险：PWM 频率、测频结果和控制周期全部偏差，且可能恰好偏差 2 倍。

### 错误二：直接修改运行中的 CCR

错误代码：

```
TIM1->CCR1 = next_duty;
```

根因：计数器可能已经超过新 CCR，造成当前周期出现窄脉冲。

正确实现：

```
TIM1->CCMR1 |= TIM_CCMR1_OC1PE;
TIM1->CCR1 = next_duty;
/* 等待硬件更新事件统一生效 */
```

风险：电机电流尖峰、功率管误导通、输出波形不连续。

### 错误三：捕获时间戳使用有符号类型

错误代码：

```
int32_t delta = capture - previous;
if (delta > 0) {
    frequency = timer_hz / delta;
}
```

根因：计数器回绕后有符号结果可能为负。

正确实现：

```
uint32_t delta = (uint32_t)(capture - previous);
if (delta != 0U) {
    frequency = timer_hz / delta;
}
```

风险：低频信号在特定回绕点被判定为无效或产生异常高频。

### 错误四：在定时器 ISR 中执行复杂业务

错误代码：

```
void TIM1_UP_IRQHandler(void)
{
    HAL_TIM_IRQHandler(&htim1);
    printf("timer tick\r\n");
    motor_control_float();
}
```

根因：串口阻塞、浮点计算和 HAL 分发路径增加不可控延迟。

正确实现：

```
void TIM1_UP_IRQHandler(void)
{
    uint32_t status = TIM1->SR;

    TIM1->SR = ~TIM_SR_UIF;

    if ((status & TIM_SR_UIF) != 0U) {
        motor_control_tick_isr();
        BaseType_t woken = pdFALSE;
        vTaskNotifyGiveFromISR(control_task_handle, &woken);
        portYIELD_FROM_ISR(woken);
    }
}
```

风险：高优先级中断被阻塞，产生控制周期超时和优先级反转。

### 错误五：DMA 缓冲区未处理 Cache

错误代码：

```
pwm_dma_buf[0] = value;
start_dma(pwm_dma_buf);
```

根因：CPU 修改了 D-Cache，但 DMA 从 SRAM 读取到旧数据。

正确实现：

```
pwm_dma_buf[0] = value;
SCB_CleanDCache_by_Addr((uint32_t *)pwm_dma_buf,
                        sizeof(pwm_dma_buf));
start_dma(pwm_dma_buf);
```

风险：示波器显示旧占空比，问题具有随机性，重启后可能暂时消失。

## 10. 多机制组合使用方案

### 技术协同架构

```
TIM1 高级定时器
├─ CH1/CH2/CH3：三相 PWM
├─ CH1N/CH2N/CH3N：互补输出
├─ BKIN：硬件刹车输入
├─ TRGO：触发 ADC 注入组采样
├─ Update IRQ：控制周期同步
└─ RCR：每 N 个 PWM 周期产生一次控制事件

TIM2
└─ 编码器接口：位置计数

TIM3
└─ 输入捕获：测速或外部同步

DMA
├─ TIM1 CCR1/CCR2/CCR3 更新
└─ TIM3 捕获时间戳采集
```

### 控制周期框架

```
typedef struct {
    uint16_t duty_u;
    uint16_t duty_v;
    uint16_t duty_w;
    uint8_t  fault;
} pwm_command_t;

static volatile pwm_command_t pending_cmd;
static volatile pwm_command_t active_cmd;

void motor_pwm_submit(const pwm_command_t *cmd)
{
    taskENTER_CRITICAL();
    pending_cmd = *cmd;
    taskEXIT_CRITICAL();
}

void motor_timer_update_isr(void)
{
    /*
     * 在 PWM 周期边界切换命令，保证三相占空比一致。
     */
    taskENTER_CRITICAL_FROM_ISR();
    active_cmd = pending_cmd;
    taskEXIT_CRITICAL_FROM_ISR(0);

    if (active_cmd.fault != 0U) {
        advanced_timer_disable_outputs();
        return;
    }

    TIM1->CCR1 = active_cmd.duty_u;
    TIM1->CCR2 = active_cmd.duty_v;
    TIM1->CCR3 = active_cmd.duty_w;
}
```

实际 RTOS 中应使用与架构匹配的 ISR 临界区 API，不能在普通中断中直接使用任务态 API。

## 11. 工业级实际案例分析

### 案例一：三相 PMSM 电机控制

#### 需求

- PWM：20 kHz。
- 中心对齐模式。
- 三相互补输出。
- 死区：500 ns。
- ADC 在 PWM 中点同步采样。
- 硬件刹车输入在微秒级关断功率输出。

#### 架构

```
TIM1 CH1/2/3       -> 上桥臂 PWM
TIM1 CH1N/2N/3N    -> 下桥臂互补 PWM
TIM1 TRGO2         -> ADC 注入组触发
TIM1 BKIN          -> 硬件过流关断
TIM2 Encoder       -> 位置和速度
DMA                 -> ADC 数据搬运
```

#### 设计要点

- 使用中心对齐模式降低电流采样噪声。
- CCR 使用预装载，三个通道在同一个更新事件生效。
- BKIN 直接关闭主输出，不能依赖 ISR。
- 死区由功率管和驱动器实测波形确定。
- 控制算法执行时间必须小于控制周期预算。

若控制周期为 50 us，控制算法最大允许执行时间不能只按平均值设计：

```
T_algorithm_worst
+ T_interrupt_jitter
+ T_ADC_latency
+ T_output_update
< 50 us
```

### 案例二：工业流量计脉冲输入

#### 需求

- 输入频率：1 Hz 至 100 kHz。
- 需要测量周期并过滤毛刺。
- 断线后 500 ms 内报告故障。
- 不能因输入捕获 ISR 丢失导致累计流量错误。

#### 架构

```
TIM3 输入捕获 -> DMA 环形时间戳
TIM3 更新事件 -> 输入超时检测
DMA 半传输/全传输 -> 批量处理
软件滤波 -> 中值滤波 + 合法范围检查
```

对于计数频率 1 MHz，32 位计数器完整回绕时间为：

```
2^32 / 1 MHz ≈ 4294.967 s
```

对 1 Hz 输入，单周期只有 1 s，因此可以直接使用 32 位差值。若计数频率提高到 100 MHz，则回绕时间约 42.95 s，仍需保证连续捕获与超时逻辑不会跨越多次回绕。

### 案例三：精确脉冲序列输出

#### 需求

- 输出 1000 个可变宽度脉冲。
- 脉宽误差小于一个定时器 tick。
- CPU 不参与每个脉冲的时序控制。

#### 方案

- 定时器输出比较或 PWM。
- CCR 由 DMA 逐项更新。
- DMA 使用循环或普通模式。
- 完成中断只处理序列结束，不处理每个脉冲。

这种方案的关键不是“DMA 更快”，而是**将时序决策与波形执行解耦**，避免 ISR 延迟进入波形时间域。

## 12. 高频问题深度答疑

### 1. 为什么同样配置的定时器频率可能差两倍？

最常见原因是 APB 定时器时钟倍频。部分 MCU 在 APB 分频器大于 1 时，定时器内核接收 `2 × PCLK`。此外，还要检查独立的 timer kernel clock 选择器。

### 2. 边沿对齐和中心对齐如何选择？

边沿对齐具有更高计数分辨率和更简单的更新时序，适合普通 PWM 和通信波形。中心对齐可降低部分偶次谐波和开关噪声，适合电机控制和功率变换，但同样 PWM 频率下需要更低 ARR，且采样和更新时序更复杂。

### 3. 为什么启用 CCR 预装载后占空比仍会突变？

可能原因包括：

- 没有真正开启 `OCxPE`。
- 软件产生了错误的 `UG`。
- `ARR` 和 `CCR` 没有在同一更新边界切换。
- 当前模式下更新事件来源与预期不同。
- 高级定时器重复计数器导致更新延迟。

必须通过示波器同时观察 PWM 边沿和更新事件对应的控制信号。

### 4. 输入捕获为什么会出现偶发错误周期？

常见原因：

- 输入毛刺。
- 捕获溢出 `CCxOF`。
- 中断延迟导致读取过晚。
- DMA 缓冲区被覆盖。
- 输入信号频率超过捕获处理能力。
- 定时器计数频率与计算公式不一致。

高可靠方案应使用输入滤波、DMA 时间戳、溢出检测和范围校验。

### 5. 如何减少定时器中断抖动？

- 提高定时器中断优先级，但必须评估对其他实时任务的影响。
- 减少 ISR 指令数。
- 将控制计算固定在最高优先级周期任务。
- 关闭不必要的日志和动态内存分配。
- 使用 DMA、硬件触发和影子寄存器。
- 用 DWT/示波器测量最大延迟，而不是根据代码行数估算。

### 6. 死区越大是否越安全？

不是。死区过小可能造成直通，死区过大则会导致体二极管长时间导通、输出电压误差、电流畸变和效率下降。正确方法是测量上下管实际栅极波形、驱动延迟和功率器件关断时间，再留出经过验证的裕量。

## 13. 课程核心总结

- 定时器驱动的核心不是配置寄存器，而是建立**时间基准、事件边界和数据所有权**。
- `PSC` 决定计数粒度，`ARR` 决定周期，`CCR` 决定比较点或占空比。
- PWM 更新必须考虑预装载、更新事件和边界一致性。
- 输入捕获必须处理回绕、溢出、毛刺和超时。
- 高级定时器的硬件刹车、互补输出和死区是功率控制系统的安全边界。
- 高频周期任务优先使用硬件触发和 DMA。
- 性能评估必须以最大 ISR 延迟、最大总线占用和最大控制执行时间为依据。
- 通用选型结论：

```
低频周期任务       -> 更新中断
稳定 PWM           -> 输出比较/PWM
高频波形变化       -> PWM + DMA
外部边沿测量       -> 输入捕获
三相功率控制       -> 高级定时器
低功耗计时         -> RTC/LPTIM
多模块严格同步     -> TRGO + ITR 主从模式
```

## 14. 快速参考速查表

### 场景选型表

|需求|推荐配置|
|---|---|
|1 ms 系统节拍|`PSC + ARR + Update IRQ`|
|20 kHz 电机 PWM|中心对齐 + CCR 预装载|
|三相逆变|高级定时器 + 互补输出 + 死区|
|测频|输入捕获 + 时间戳差值|
|测占空比|双边沿捕获或 PWM 输入模式|
|精确协议波形|PWM + DMA|
|ADC 同步采样|TRGO/TRGO2 触发 ADC|
|故障快速关断|BKIN/硬件保护输入|

### 关键公式

```
f_cnt = f_tim / (PSC + 1)

f_edge = f_cnt / (ARR + 1)

f_center = f_cnt / (2 × (ARR + 1))

duty = CCR / (ARR + 1)

frequency = f_cnt / capture_delta

CPU_load = interrupt_rate × ISR_cycles / CPU_frequency

counter_wrap_time = 2^counter_bits / f_cnt
```

## 16. 实践与进阶路径

### 梯度实战任务

1. 使用寄存器实现 1 kHz 更新中断，并测量 ISR 抖动。
2. 实现 20 kHz PWM，占空比支持千分比输入。
3. 添加 CCR 预装载，对比直接写 CCR 和预装载的波形差异。
4. 实现输入捕获测频，覆盖计数器回绕和输入超时。
5. 使用 DMA 输出一组动态 PWM 占空比序列。
6. 实现三相互补 PWM、死区和硬件刹车。
7. 使用主从定时器同步 PWM、ADC 和编码器采样。
8. 在 FreeRTOS 中实现硬件定时器 ISR 到控制任务的通知链路。

### 性能测试方法

- 使用 DWT `CYCCNT` 测量 ISR 平均值和最大值。
- 使用 GPIO 翻转配合逻辑分析仪测量中断响应延迟。
- 使用示波器测量 PWM 周期、占空比、死区和更新毛刺。
- 进行高优先级中断压力注入，测量 worst-case latency。
- 逐步提高输入频率，记录捕获溢出阈值。
- 对 DMA 缓冲区进行 Cache 开关对比测试。
- 通过总线和 DMA 负载注入验证波形稳定性。
- 进行长时间运行测试，至少覆盖计数器回绕、DMA 循环和故障恢复。

### 进阶方向

- 电机控制定时器同步：PWM、ADC、编码器和位置环。
- 高级定时器重复计数器与低采样率控制环。
- 定时器触发链路与硬件事件系统。
- 高分辨率定时器和数字电源控制。
- Cortex-M7/M55 Cache、DMA 和内存屏障。
- 基于 ETM/ITM 的实时性分析。
- 功能安全中的硬件关断路径、诊断覆盖率和失效模式分析。
- 基于定时器的时间触发架构和 TSN/工业以太网同步。
