
## 1. 学习目标

### 理解

- 理解示波器从探头、模拟前端、ADC、采样存储到触发系统的完整信号链。
- 理解**带宽、采样率、存储深度、垂直分辨率、探头负载**之间的约束关系。
- 理解示波器显示波形与被测节点真实电压之间可能存在的差异。
- 理解 MCU 软件事件、数字总线活动与模拟电气行为之间的关联。

### 掌握

- 掌握无源探头、有源探头、差分探头、电流探头的选型与补偿方法。
- 掌握边沿、脉宽、欠幅、建立保持、协议触发等常用触发机制。
- 掌握电源纹波、时钟、PWM、SPI、I²C、UART、复位和中断时序的测量方法。
- 掌握通过 GPIO、定时器输出和事件追踪点实现软硬件协同调试。

### 精通

- 精通探头接地电感、输入电容、混叠、欠采样、触发抖动对测量结果的影响。
- 精通上升时间、传播延迟、抖动、占空比、建立保持时间和瞬态电流的量化分析。
- 能区分**真实故障、测量伪影、仪器限制和软件行为**。
- 能构建可重复、可自动化、具有测量不确定度说明的测试流程。

### 能够设计

- 能设计面向示波器调试的 PCB 测试点、地弹簧连接位和电流测量接口。
- 能设计固件诊断脉冲、事务标记和故障冻结机制。
- 能设计覆盖电源完整性、信号完整性、实时性和协议一致性的硬件协同测试架构。
- 能建立生产测试、回归测试和现场故障复现所需的波形判据。

## 3. 技术概述

### 3.1 核心定义

示波器不是单纯的“波形显示器”，而是一个由以下模块组成的采集系统：

```
被测节点
  │
  ├─ 探头及连接附件
  │
  ├─ 输入衰减器与模拟前端
  │
  ├─ 模拟带宽限制
  │
  ├─ ADC 采样
  │
  ├─ 采集存储器
  │
  ├─ 触发系统
  │
  └─ 波形重建、测量与协议解码
```

硬件协同调试的核心是把以下三类信息映射到同一时间轴：

1. **软件事件**：任务切换、中断进入、DMA 启动、状态机迁移。
2. **数字行为**：GPIO、时钟、片选、数据和复位。
3. **模拟行为**：电源跌落、振铃、过冲、地弹、噪声和电流瞬态。

### 3.2 技术价值

- 定位软件日志无法发现的微秒级或纳秒级故障。
- 验证数据手册中的电气与时序约束。
- 区分协议逻辑错误和信号完整性错误。
- 量化中断响应、任务抖动和执行时间。
- 验证电源设计在动态负载下是否稳定。
- 建立可回归的硬件测试基线。

### 3.3 主流技术分支

- **时域测量**：幅值、周期、上升时间、脉宽、传播延迟。
- **频域分析**：FFT、时钟谐波、开关电源频谱、周期性干扰。
- **协议分析**：UART、SPI、I²C、CAN、LIN 等。
- **电源完整性测量**：纹波、负载瞬态、启动时序、掉电行为。
- **信号完整性测量**：反射、串扰、振铃、边沿质量。
- **实时性分析**：ISR 延迟、任务周期、最坏执行时间。
- **功率分析**：电压、电流、瞬时功率和能量积分。

## 5. 底层原理与功能特性深度解析

### 5.1 带宽与上升时间

示波器带宽通常定义为幅值下降到低频幅值 **-3 dB** 的频率点。对于近似单极点系统：

tr≈0.35BWtr​≈BW0.35​

被测系统、探头和示波器的上升时间近似满足：

tmeasured=tsignal2+tprobe2+tscope2tmeasured​=tsignal2​+tprobe2​+tscope2​​

例如，测量真实上升时间为 2 ns 的信号，探头和示波器上升时间均为 1.4 ns：

tmeasured=22+1.42+1.42=2.81nstmeasured​=22+1.42+1.42​=2.81ns

测量误差达到 **40.5%** 。工程上若要求上升时间误差低于约 3%，测量系统带宽通常至少应达到被测有效带宽的 **3~5 倍**。

### 5.2 采样率与混叠

采样定理要求：

fs>2fmaxfs​>2fmax​

但方波包含高次谐波，仅满足两倍采样率无法恢复边沿。工程上建议：

- 正弦波：每周期至少 5~10 点。
- 一般数字时序：每周期至少 10~20 点。
- 边沿和信号完整性：按信号上升时间选择带宽和采样率，而不是按时钟频率选择。

一个 10 MHz SPI 时钟若上升时间为 2 ns，其有效频谱远高于 10 MHz。使用 20 MHz 示波器虽然能显示“10 MHz 方波”，但无法可靠观察振铃和建立保持裕量。

### 5.3 存储深度与时间窗

MemoryDepth=SampleRate×CaptureTimeMemoryDepth=SampleRate×CaptureTime

以 1 GS/s 捕获 20 ms：

1×109×20×10−3=20Mpts1×109×20×10−3=20Mpts

如果设备只有 1 Mpts 存储深度，则在 20 ms 时间窗下有效采样率最多为：

1Mpts20ms=50MS/s20ms1Mpts​=50MS/s

因此，**面板标称最大采样率不等于当前时基下的实际采样率**。

### 5.4 探头负载

10× 无源探头可近似为：

```
被测节点 ── 10 MΩ || 10 pF ── GND
```

电容阻抗为：

∣XC∣=12πfC∣XC​∣=2πfC1​

当 `C = 10 pF`、`f = 100 MHz` 时：

∣XC∣≈159Ω∣XC​∣≈159Ω

因此，高频时所谓“10 MΩ 探头”可能只表现为约 **159 Ω 的容性负载**。它可能改变晶振、反馈补偿、栅极驱动和高阻模拟节点的真实行为。

### 5.5 探头接地电感

普通鳄鱼夹地线常有 10~~20 cm 长度，寄生电感可能达到 100~~200 nH。瞬态电压为：

V=LdidtV=Ldtdi​

若 `L = 150 nH`，电流变化率为 `0.2 A/ns`：

V=150nH×0.2A/ns=30VV=150nH×0.2A/ns=30V

这说明长地线测得的大幅振铃可能主要来自测量回路，而非 PCB 本身。高速测量应使用：

- 探头地弹簧。
- 同轴测试点。
- 极短的信号与地回路。
- 差分探头。

### 5.6 触发系统

触发决定采集数据在时间轴上的对齐位置。常用机制：

- **边沿触发**：周期、延迟和普通数字信号。
- **脉宽触发**：捕获异常窄脉冲或超时脉冲。
- **欠幅触发**：捕获未跨越完整逻辑阈值的信号。
- **超时触发**：检测总线长期保持某状态。
- **建立保持触发**：检测数据相对时钟的时序违规。
- **协议触发**：按地址、数据、错误帧触发。
- **区域触发**：捕获穿过或避开屏幕区域的波形。

### 5.7 软件事件映射到示波器时间轴

建议保留至少 2~4 个诊断 GPIO：

```
#include <stdint.h>
#include "stm32h7xx.h"

#define TRACE_PORT GPIOB
#define TRACE_ISR_PIN  (1U << 0)
#define TRACE_TASK_PIN (1U << 1)
#define TRACE_DMA_PIN  (1U << 2)

static inline void trace_set(uint32_t pin)
{
    TRACE_PORT->BSRR = pin;          /* 原子置位 */
    __DSB();                         /* 对精确边界测量保证写入完成 */
}

static inline void trace_clear(uint32_t pin)
{
    TRACE_PORT->BSRR = pin << 16U;   /* 原子复位，避免读改写竞争 */
    __DSB();
}

void ADC_IRQHandler(void)
{
    trace_set(TRACE_ISR_PIN);

    uint32_t status = ADC1->ISR;
    if ((status & ADC_ISR_OVR) != 0U) {
        ADC1->ISR = ADC_ISR_OVR;
        /* 记录溢出，但不要在 ISR 中执行阻塞日志输出 */
    }

    if ((status & ADC_ISR_EOC) != 0U) {
        uint16_t sample = (uint16_t)ADC1->DR;
        adc_push_from_isr(sample);
    }

    trace_clear(TRACE_ISR_PIN);
}
```

测得高电平宽度近似为 ISR 执行时间，但应扣除 GPIO 写入和总线传播开销：

TISR=Tpulse−Tset−TclearTISR​=Tpulse​−Tset​−Tclear​

在 Cortex-M7 上，GPIO 通过 AHB/APB 桥访问时，写操作可能因写缓冲和总线仲裁产生数十纳秒到数百纳秒不确定性。`__DSB()` 能增强边界可观察性，但会改变被测执行时间。最终 WCET 应结合 DWT 周期计数器交叉验证。

### 5.8 使用定时器生成低抖动硬件标记

软件翻转 GPIO 会受中断和总线等待影响。对 ADC 触发、PWM 边界等硬件事件，应直接输出定时器通道：

```
static void tim1_reference_output_init(void)
{
    RCC->APB2ENR |= RCC_APB2ENR_TIM1EN;
    RCC->AHB4ENR |= RCC_AHB4ENR_GPIOAEN;

    /* PA8 -> TIM1_CH1，具体 AF 需按芯片数据手册确认。 */
    GPIOA->MODER = (GPIOA->MODER & ~(3U << (8U * 2U)))
                 |  (2U << (8U * 2U));
    GPIOA->AFR[1] = (GPIOA->AFR[1] & ~(0xFU << 0U))
                  | (1U << 0U);

    TIM1->PSC  = 0U;
    TIM1->ARR  = 239U;      /* 240 MHz / 240 = 1 MHz */
    TIM1->CCR1 = 120U;      /* 50% 占空比 */
    TIM1->CCMR1 = TIM_CCMR1_OC1M_2
                | TIM_CCMR1_OC1M_1
                | TIM_CCMR1_OC1PE;
    TIM1->CCER = TIM_CCER_CC1E;
    TIM1->BDTR = TIM_BDTR_MOE;
    TIM1->CR1  = TIM_CR1_ARPE | TIM_CR1_CEN;
}
```

该输出可作为：

- 示波器稳定触发源。
- ADC 采样基准。
- 多通道传播延迟测量基准。
- 软件 GPIO 标记的时间参考。

### 5.9 DWT 与示波器交叉测量

```
typedef struct {
    uint32_t start;
} cycle_probe_t;

static bool cycle_counter_init(void)
{
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
    DWT->CYCCNT = 0U;
    DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
    return (DWT->CTRL & DWT_CTRL_CYCCNTENA_Msk) != 0U;
}

static inline void cycle_probe_start(cycle_probe_t *probe)
{
    probe->start = DWT->CYCCNT;
}

static inline uint32_t cycle_probe_stop(const cycle_probe_t *probe)
{
    return DWT->CYCCNT - probe->start; /* 无符号减法正确处理单次回绕 */
}
```

DWT 测量代码执行周期；示波器测量引脚上的外部可见时间。二者差值可以暴露：

- 总线写缓冲。
- GPIO 外设时钟延迟。
- 中断抢占。
- Cache miss。
- DMA 和 CPU 总线竞争。

### 6.3 中断响应时间

Tresponse=Tsync+Tstack+Tpriority+Tbus+Tflash/cacheTresponse​=Tsync​+Tstack​+Tpriority​+Tbus​+Tflash/cache​

最坏情况还需加入：

Tworst=Tresponse+Tcritical+Thigher−priorityTworst​=Tresponse​+Tcritical​+Thigher−priority​

其中：

- `T_sync`：外部信号进入 NVIC 前的同步延迟。
- `T_stack`：硬件压栈时间。
- `T_priority`：当前指令完成、屏蔽和优先级判定。
- `T_bus`：总线争用。
- `T_flash/cache`：取指和数据访问等待。

测量方法：

```
CH1：外部中断源
CH2：ISR 第一条可控 GPIO 置位
CH3：ISR 结束 GPIO 清零

CH1 -> CH2：中断响应时间
CH2 高电平：ISR 可见执行时间
CH1 -> CH3：端到端服务时间
```

### 6.4 随机噪声平均收益

若噪声不相关，平均 `N` 次后的 RMS 噪声近似为：

Vnoise,new=VnoiseNVnoise,new​=N​Vnoise​​

|平均次数|理论噪声下降|
|---|---|
|4|2 倍|
|16|4 倍|
|64|8 倍|
|256|16 倍|

平均不能消除与触发同步的开关噪声，也会掩盖偶发毛刺。

### 6.5 主要瓶颈与优化收益

|瓶颈|表现|优化方法|典型收益|
|---|---|---|---|
|探头地线过长|高频振铃、过冲放大|地弹簧或同轴连接|假性尖峰降低 50%~90%|
|存储深度不足|长时间窗采样率下降|分段存储、缩短时间窗|有效采样率提升 10~1000 倍|
|通道开启过多|每通道采样率下降|关闭无关通道|采样率可提升 2~4 倍|
|垂直量程过大|小纹波分辨率不足|偏置后缩小量程|有效码利用率提升 4~20 倍|
|软件触发标记侵入|执行时间被改变|硬件定时器输出或 ETM|扰动由百纳秒降至近零|
|自动测量窗口错误|统计包含无效波形|门控测量、区域限定|消除错误样本|

## 7. 应用场景选型指南

### 7.1 决策流程图

```
开始
├─ 被测节点是否相对示波器保护地浮动？
│  ├─ 是
│  │  ├─ 共模电压高于安全低压？ -> 高压差分探头
│  │  └─ 高速低压差分信号？     -> 高速差分探头
│  └─ 否
│     ├─ 边沿快于 5 ns？
│     │  ├─ 是 -> 有源探头或短接地 10× 探头
│     │  └─ 否 -> 通用 10× 无源探头
│     └─ 信号源阻抗很高？
│        ├─ 是 -> 低电容有源探头
│        └─ 否 -> 10× 无源探头
├─ 目标是偶发故障？
│  ├─ 是
│  │  ├─ 窄毛刺       -> 脉宽/欠幅触发 + Peak Detect
│  │  ├─ 协议错误     -> 协议错误触发
│  │  └─ 稀疏长周期事件 -> 分段存储
│  └─ 否 -> 普通边沿触发
├─ 目标是电源纹波？
│  ├─ 是 -> AC 耦合 + 20 MHz 限带 + 地弹簧
│  └─ 否
├─ 目标是软件实时性？
│  ├─ 是 -> 事件 GPIO + DWT/ETM 交叉验证
│  └─ 否
└─ 需要长时间多通道状态？
   ├─ 是 -> 示波器 + 逻辑分析仪
   └─ 否 -> 示波器独立完成
```

### 7.2 典型场景

|需求|推荐方案|理由|
|---|---|---|
|测 MCU 电源纹波|10× 探头、地弹簧、AC 耦合、20 MHz 限带|抑制探测回路与宽带噪声|
|测半桥高边栅极|高压差分探头|禁止用接地夹直接连接开关节点|
|定位 SPI 偶发 CRC 错误|4 通道示波器 + 协议触发|同时观察时钟、数据、片选和电气质量|
|测 ISR 最坏延迟|外部源 + ISR GPIO + 分段存储|捕获稀疏长尾事件|
|测任务抖动|GPIO 脉冲 + 统计直方图|获得周期分布而非单次值|
|测低功耗平均电流|电流探头或分流器 + 差分探头|可观察状态切换与能量积分|
|分析 I²C 上升沿|低电容探头，同时测 SCL/SDA|验证 RC 上升时间和建立保持时间|

## 8. 工程最佳实践

### 8.1 设计原则

1. **先验证测量系统，再判断被测系统。**
2. 探头接地回路面积必须最小化。
3. 带宽应由被测边沿决定，而不是只由基频决定。
4. 电源纹波必须说明带宽限制、耦合方式和探头连接方法。
5. 不用自动量程作为最终测量依据。
6. 软件标记应原子操作，且必须量化自身开销。
7. 所有关键结论至少使用一种独立方法交叉验证。
8. 保存原始波形、仪器配置、固件版本和环境条件。

### 8.2 选型决策矩阵

评分：1 为较差，5 为优秀。

|方案|高速能力|节点负载|共模安全|成本|通用性|
|---|---|---|---|---|---|
|10× 无源探头|3|3|1|5|5|
|有源单端探头|5|5|1|2|4|
|高速差分探头|5|5|4|1|3|
|高压差分探头|2~4|3|5|2|3|
|50 Ω 同轴直连|5|1|1|4|2|
|电流探头|3|5|5|1|3|

### 8.3 PCB 可测性规范

- 每个关键电源域至少提供一个信号测试点和邻近地测试点。
- 高速测试点避免长支路，必要时使用可拆卸零欧姆电阻。
- 电源测试点预留探头地弹簧可夹持的裸铜地环。
- 调试 GPIO 应布置在连接器或测试点，不与启动配置脚冲突。
- 差分总线测试点保持对称，避免形成不等长 stub。
- 电流测量位置预留分流电阻和 Kelvin 引线。
- 量产板保留最少测试资源，但不能完全删除故障诊断接口。

### 8.4 固件诊断编码规范

```
typedef enum {
    TRACE_EVT_CONTROL_START = 0U,
    TRACE_EVT_CONTROL_END,
    TRACE_EVT_ADC_READY,
    TRACE_EVT_FAULT,
    TRACE_EVT_COUNT
} trace_event_t;

static const uint16_t g_trace_pin[TRACE_EVT_COUNT] = {
    [TRACE_EVT_CONTROL_START] = 1U << 0,
    [TRACE_EVT_CONTROL_END]   = 1U << 1,
    [TRACE_EVT_ADC_READY]     = 1U << 2,
    [TRACE_EVT_FAULT]         = 1U << 3
};

static inline void trace_event_set(trace_event_t event)
{
    if ((uint32_t)event < (uint32_t)TRACE_EVT_COUNT) {
        GPIOB->BSRR = g_trace_pin[event];
    }
}

static inline void trace_event_clear(trace_event_t event)
{
    if ((uint32_t)event < (uint32_t)TRACE_EVT_COUNT) {
        GPIOB->BSRR = (uint32_t)g_trace_pin[event] << 16U;
    }
}
```

规范要求：

- 禁止使用 GPIO `ODR` 读改写实现并发事件标记。
- 发布版本由编译开关关闭非必要标记。
- 诊断引脚默认处于安全状态。
- 明确标记电平含义和时间边界。
- 不在硬实时 ISR 中执行 `printf`。

## 9. 常见错误与避坑指南

### 9.1 错误一：使用长接地夹测高速边沿

#### 错误代码与操作

```
GPIOB->BSRR = GPIO_BSRR_BS0;
/* 使用 15 cm 鳄鱼夹地线观察该高速边沿。 */
```

#### 根因分析

长接地线与探头输入电容形成 LC 谐振，同时接地回路拾取磁场。屏幕上的振铃可能是测量回路生成的。

#### 正确实现

```
/* 固件无需修改；测量端改用地弹簧，并将探测回路控制在 10 mm 内。 */
GPIOB->BSRR = GPIO_BSRR_BS0;
__DSB();
```

先用探头校准方波比较长地线与地弹簧结果，再测目标节点。

#### 风险影响

- 误判 PCB 存在严重信号完整性问题。
- 错误增加串联电阻，导致真实边沿过慢。
- 将测量伪影误认为 ESD 或电源异常。

### 9.2 错误二：用 ODR 读改写翻转诊断 GPIO

#### 错误代码

```
GPIOB->ODR ^= (1U << 0);
```

#### 根因分析

该操作包含读取、异或和写回。ISR 或其他任务若同时修改同一端口，可能丢失更新。生成的波形无法可靠代表事件边界。

#### 正确实现

```
static inline void trace_high(void)
{
    GPIOB->BSRR = 1U << 0;
}

static inline void trace_low(void)
{
    GPIOB->BSRR = 1U << 16;
}
```

#### 风险影响

- 诊断波形随机缺失。
- 破坏同端口其他输出。
- 错误估计中断执行时间。

### 9.3 错误三：用错误探头衰减比读取幅值

#### 错误配置

```
/* 实际使用 10× 探头，但示波器通道配置为 1×。 */
```

示波器将 3.3 V 信号显示为约 0.33 V。

#### 根因分析

探头和示波器通道的衰减比配置不一致。测量数学运算、触发阈值和协议阈值也会随之错误。

#### 正确实现

- 探头拨档设置为 10×。
- 通道探头倍率设置为 10×。
- 测量前进行低频补偿。
- 使用已知电压源验证幅值。

#### 风险影响

- 错判逻辑电平不满足 VIH。
- 触发不稳定。
- 电源纹波和过冲数据失真。

### 9.4 错误四：在浮地高压节点连接示波器地夹

#### 错误操作

```
示波器保护地夹 -> 半桥开关节点
探头尖端       -> 高边栅极
```

#### 根因分析

台式示波器 BNC 外壳和地夹通常连接保护地。连接到开关节点会形成短路路径。

#### 正确实现

使用额定 CAT 等级、差模范围和共模范围均满足要求的高压差分探头：

```
差分探头正端 -> 高边栅极
差分探头负端 -> 高边源极
示波器       -> 差分探头隔离输出
```

#### 风险影响

- 功率器件炸毁。
- 示波器损坏。
- 电击、起火和人身伤害。

### 9.5 错误五：测量 ISR 时使用 HAL GPIO API

#### 错误代码

```
void EXTI0_IRQHandler(void)
{
    HAL_GPIO_WritePin(GPIOB, GPIO_PIN_0, GPIO_PIN_SET);
    process_event();
    HAL_GPIO_WritePin(GPIOB, GPIO_PIN_0, GPIO_PIN_RESET);
}
```

#### 根因分析

HAL 调用包含参数处理、函数调用和额外分支。标记开销可能与被测代码同量级。

#### 正确实现

```
void EXTI0_IRQHandler(void)
{
    GPIOB->BSRR = GPIO_PIN_0;
    __DSB();

    process_event();

    GPIOB->BSRR = (uint32_t)GPIO_PIN_0 << 16U;
    __DSB();
}
```

同时测量空标记开销，并从结果中扣除。

#### 风险影响

- 增加 ISR 延迟。
- 改变缓存和总线行为。
- 测得结果不再代表原始系统。

### 9.6 错误六：通过平均模式寻找偶发毛刺

#### 错误配置

```
采集模式：Average 64
目标：寻找每数万次出现一次的 20 ns 低脉冲
```

#### 根因分析

平均模式将非同步偶发毛刺稀释，最终波形可能完全看不到异常。

#### 正确配置

```
触发类型：负脉宽
条件：脉宽 < 30 ns
采集模式：Peak Detect 或 Sample
存储模式：Segmented
保持时间：略大于正常事务周期
```

#### 风险影响

- 错误得出“信号稳定”的结论。
- 偶发复位、CRC 错误长期无法定位。

## 10. 多机制组合使用方案

### 10.1 技术协同架构

```
外部事件/传感器
       │
       ├───────────────> 示波器 CH1：物理输入
       │
       v
MCU 外设 -> DMA -> ISR -> RTOS 任务 -> 控制输出
   │        │      │         │           │
   │        │      │         │           └─ CH4：实际输出
   │        │      │         └─ GPIO 标记
   │        │      └─ GPIO 标记 CH3
   │        └─ 定时器硬件事件 CH2
   └─ DWT/ETM/SWO 内部周期记录

示波器：模拟电气行为与外部可见时序
DWT：代码周期
ETM/SWO：执行路径
逻辑分析仪：长时间协议和多通道状态
```

### 10.2 完整诊断代码框架

```
#include <stdbool.h>
#include <stdint.h>
#include "stm32h7xx.h"

#define TRACE_ISR_PIN      (1U << 0)
#define TRACE_TASK_PIN     (1U << 1)
#define TRACE_FAULT_PIN    (1U << 2)

typedef struct {
    volatile uint32_t adc_irq_count;
    volatile uint32_t adc_overrun_count;
    volatile uint32_t max_isr_cycles;
    volatile uint32_t max_task_cycles;
    volatile uint16_t latest_sample;
    volatile bool sample_ready;
} diagnostic_t;

static diagnostic_t g_diag;

static inline uint32_t cycles_now(void)
{
    return DWT->CYCCNT;
}

static inline void trace_set(uint32_t pin)
{
    GPIOB->BSRR = pin;
    __DSB();
}

static inline void trace_clear(uint32_t pin)
{
    GPIOB->BSRR = pin << 16U;
    __DSB();
}

static inline void update_max(volatile uint32_t *maximum, uint32_t value)
{
    uint32_t old = *maximum;
    if (value > old) {
        *maximum = value;
    }
}

bool diagnostics_init(void)
{
    RCC->AHB4ENR |= RCC_AHB4ENR_GPIOBEN;
    (void)RCC->AHB4ENR;

    GPIOB->MODER &= ~((3U << 0U) | (3U << 2U) | (3U << 4U));
    GPIOB->MODER |=  ((1U << 0U) | (1U << 2U) | (1U << 4U));
    GPIOB->BSRR = (TRACE_ISR_PIN | TRACE_TASK_PIN | TRACE_FAULT_PIN) << 16U;

    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
    DWT->CYCCNT = 0U;
    DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;

    return (DWT->CTRL & DWT_CTRL_CYCCNTENA_Msk) != 0U;
}

void ADC_IRQHandler(void)
{
    uint32_t start = cycles_now();
    uint32_t status;

    trace_set(TRACE_ISR_PIN);
    status = ADC1->ISR;

    if ((status & ADC_ISR_OVR) != 0U) {
        ADC1->ISR = ADC_ISR_OVR;
        g_diag.adc_overrun_count++;
        trace_set(TRACE_FAULT_PIN);
    }

    if ((status & ADC_ISR_EOC) != 0U) {
        g_diag.latest_sample = (uint16_t)ADC1->DR;
        g_diag.sample_ready = true;
        g_diag.adc_irq_count++;
    }

    trace_clear(TRACE_ISR_PIN);
    update_max(&g_diag.max_isr_cycles, cycles_now() - start);
}

void control_task_step(void)
{
    uint16_t sample;
    uint32_t start;

    if (!g_diag.sample_ready) {
        return;
    }

    __disable_irq();
    sample = g_diag.latest_sample;
    g_diag.sample_ready = false;
    __enable_irq();

    start = cycles_now();
    trace_set(TRACE_TASK_PIN);

    control_update(sample);

    trace_clear(TRACE_TASK_PIN);
    update_max(&g_diag.max_task_cycles, cycles_now() - start);
}
```

### 10.3 组合设计要点

- 定时器输出作为绝对时间基准。
- GPIO 标记软件边界。
- DWT 记录内部执行周期。
- 示波器捕获外部输入、电源和输出响应。
- 协议解码验证事务内容。
- 分段存储捕获低概率故障。
- 故障 GPIO 保持置位，避免异常脉冲过短而丢失。

## 11. 工业级实际案例分析

### 11.1 电机控制器 PWM 异常关断

#### 需求

FOC 控制器在高负载时偶发过流关断。软件只记录到过流标志，无法区分真实过流、采样噪声或栅极驱动异常。

#### 架构设计

```
CH1：相电流分流放大器输出
CH2：低边 MOSFET 栅极
CH3：PWM 定时器参考输出
CH4：过流 ISR 诊断 GPIO
触发：CH4 上升沿，预触发 80%
```

#### 核心代码

```
void COMP1_IRQHandler(void)
{
    GPIOB->BSRR = TRACE_FAULT_PIN;
    __DSB();

    TIM1->BDTR &= ~TIM_BDTR_MOE; /* 第一时间关闭功率输出 */

    uint32_t csr = COMP1->CSR;
    fault_snapshot.comp_status = csr;
    fault_snapshot.tim_counter = TIM1->CNT;
    fault_snapshot.timestamp = DWT->CYCCNT;
    fault_snapshot.valid = true;

    COMP1->CSR |= COMP_CSR_SCALEN; /* 示例占位：清除方式必须按具体 MCU 修正 */
}
```

生产实现必须严格依据目标 MCU 的比较器中断清除机制，不能照搬占位寄存器操作。

#### 测量结论

- 相电流放大器在 PWM 开关后出现约 180 ns 尖峰。
- 比较器消隐窗口只有 100 ns。
- 软件 ISR 在故障后约 620 ns 才可见，但硬件刹车已在约 70 ns 内关闭 PWM。

#### 设计要点

- 保护必须走定时器硬件 Break 链路，不能依赖 ISR。
- 延长比较器消隐窗口至 250 ns。
- 优化采样点，避开开关瞬态。
- 示波器同时验证“故障产生”和“功率输出停止”，不能只测 ISR。

### 11.2 SPI Flash 高温读写错误

#### 需求

设备在 85°C 下偶发 Flash CRC 错误，室温无法复现。

#### 架构设计

```
CH1：SPI_CLK
CH2：MOSI
CH3：MISO
CH4：CS
触发：协议解码命中错误地址，或 CS 异常脉宽
附加：逻辑分析仪记录长时间事务
```

#### 核心代码

```
typedef struct {
    uint32_t address;
    uint32_t expected_crc;
    uint32_t actual_crc;
    uint32_t spi_status;
} spi_fault_record_t;

static spi_fault_record_t g_spi_fault;

void flash_report_crc_error(uint32_t address,
                            uint32_t expected,
                            uint32_t actual)
{
    __disable_irq();
    g_spi_fault.address = address;
    g_spi_fault.expected_crc = expected;
    g_spi_fault.actual_crc = actual;
    g_spi_fault.spi_status = SPI1->SR;
    __enable_irq();

    GPIOB->BSRR = TRACE_FAULT_PIN; /* 示波器单次触发 */
}
```

#### 测量结论

- 高温下 MISO 数据有效时间缩短。
- MCU 在 40 MHz、SPI Mode 0 下采样位置接近有效窗口边缘。
- 插入探头后错误率下降，说明探头电容改变了边沿，属于典型 Heisenbug。

#### 设计要点

- 将 SPI 降至 25 MHz 后建立保持裕量恢复。
- 对 CLK 增加 22 Ω 源端串联电阻，降低反射。
- 使用低电容探头复测。
- 必须验证全温度、电压和批次角落。

### 11.3 低功耗设备随机复位

#### 需求

电池设备在无线发射瞬间偶发复位，但软件日志在复位时丢失。

#### 架构设计

```
CH1：MCU VDD，地弹簧，20 MHz 限带
CH2：无线模块电源
CH3：MCU NRST
CH4：无线发送标记 GPIO
触发：NRST 下降沿或 VDD 欠幅
```

#### 核心代码

```
typedef struct {
    uint32_t magic;
    uint32_t reset_flags;
    uint32_t tx_sequence;
} retained_reset_log_t;

/* 链接到不被启动代码清零的备份 SRAM。 */
__attribute__((section(".backup_sram")))
static retained_reset_log_t g_reset_log;

void radio_tx_begin(uint32_t sequence)
{
    g_reset_log.magic = 0x5253544CU;
    g_reset_log.tx_sequence = sequence;
    __DSB();

    GPIOB->BSRR = TRACE_TASK_PIN;
    radio_start_dma_tx();
}

void capture_reset_reason_early(void)
{
    if (g_reset_log.magic == 0x5253544CU) {
        g_reset_log.reset_flags = RCC->RSR;
    }
    RCC->RSR |= RCC_RSR_RMVF;
}
```

#### 测量结论

- 发射瞬间 VDD 从 3.3 V 跌至 2.71 V，持续约 38 µs。
- BOR 阈值配置约 2.9 V，因此触发复位。
- 平均电流仅 42 mA，但瞬态峰值达到 410 mA。

#### 设计要点

- 电源设计不能只依据平均电流。
- 增加低 ESR 储能电容并降低供电路径阻抗。
- 调整 BOR 只能作为满足芯片安全工作电压后的辅助策略。
- 使用欠幅触发，而非普通边沿触发，能直接捕获电源跌落。

## 12. 高频问题深度答疑

### 12.1 示波器带宽是否只需高于时钟频率？

不是。数字信号质量取决于边沿，而非仅取决于重复频率。1 MHz 信号也可能具有 1 ns 边沿，其频谱延伸到数百 MHz。带宽应根据目标上升时间估算：

BW≈0.35trBW≈tr​0.35​

若要准确测量 2 ns 边沿，测量系统带宽至少应达到数百 MHz。

### 12.2 为什么使用探头后故障消失？

探头引入输入电容、阻抗和接地路径，改变了节点的极点和阻尼。常见场景包括：

- 晶振节点被探头加载。
- SPI 时钟振铃被探头电容抑制。
- 反馈网络相位裕量被改变。
- 悬空节点通过探头获得泄放路径。

这不是故障不存在，而是测量系统改变了被测对象。应改用低电容有源探头、缓冲输出或间接测量。

### 12.3 为什么电源纹波测得比预期大很多？

优先检查：

1. 是否使用长地线。
2. 是否开启全带宽。
3. 探头是否形成大回路并拾取开关磁场。
4. 测量点是否远离负载去耦电容。
5. 是否错误使用 1× 探头。
6. 是否把开关尖峰和规定带宽内纹波混为一谈。

报告电源纹波时必须注明“探头类型、连接方式、带宽限制、耦合方式和测量位置”。

### 12.4 GPIO 脉冲能否直接等价为函数执行时间？

不能完全等价。它包含：

Tpulse=TGPIO−set+Tcode+TGPIO−clear+TbusTpulse​=TGPIO−set​+Tcode​+TGPIO−clear​+Tbus​

还可能受到写缓冲、编译器重排和中断抢占影响。应采用：

- `volatile` 外设寄存器访问。
- 必要时使用 `__DSB()`。
- 单独测量空脉冲开销。
- 与 DWT 周期计数交叉验证。
- 对极低扰动需求使用 ETM。

### 12.5 何时使用 20 MHz 带宽限制？

适合：

- 电源纹波。
- 低频传感器噪声。
- 数据手册明确规定 20 MHz 测量带宽的场景。

不适合：

- 高速数字边沿。
- 开关节点尖峰。
- 纳秒级毛刺。
- 信号完整性分析。

限带不是为了让波形“更好看”，而是为了定义可比较的测量条件。

### 12.6 自动测量值为何会跳变？

自动测量算法依赖阈值、周期识别和采集窗口。以下情况会导致错误：

- 窗口中周期不足。
- 波形存在多次阈值穿越。
- 振铃被识别为额外边沿。
- 信号超出屏幕或 ADC 范围。
- 采样率随时基变化。
- 触发不稳定。

关键时序应使用游标、门控测量、统计直方图和原始数据联合确认。

## 13. 课程核心总结

### 13.1 核心要点

- **测量系统是被测系统的一部分**，探头会加载节点。
- 高速数字测量应关注**上升时间**，不能只关注时钟频率。
- 长探头地线是高频测量中最常见的伪影来源。
- 示波器的实际采样率受时间窗、存储深度和通道数影响。
- 软件 GPIO、DWT、ETM、逻辑分析仪和示波器应交叉使用。
- 电源问题应使用动态负载、欠幅触发和短接地方式测量。
- 安全上，禁止将接地示波器地夹连接到浮地高压节点。

### 13.2 性能排序

#### 高速节点探测能力

```
高速有源/差分探头
> 短接地高带宽无源探头
> 普通 10× 无源探头
> 1× 探头
> 长地线无源探头
```

#### 软件时序测量侵入性

```
ETM 硬件追踪
< 定时器硬件输出
< DWT 周期计数
< 寄存器 GPIO 标记
< HAL GPIO 标记
< 串口 printf
```

#### 偶发故障捕获能力

```
协议/脉宽触发 + 分段存储
> 单次高级触发
> Peak Detect
> 普通边沿触发
> 自动触发
> Average 模式
```

### 13.3 通用选型结论

- 通用 MCU 调试优先使用 **10× 探头 + 地弹簧**。
- 浮地、高边和差分节点必须使用合适的差分探头。
- 高阻高速节点使用低输入电容有源探头。
- 稀疏故障使用分段存储。
- 长时间多路协议分析使用逻辑分析仪，电气根因分析使用示波器。
- 关键实时路径优先通过硬件输出、DWT 或 ETM 观测。

## 16. 实践与进阶路径

### 16.1 梯度实战任务

#### 任务一：建立测量基线

- 补偿 10× 无源探头。
- 分别使用长地线和地弹簧测量同一 GPIO 边沿。
- 记录过冲、上升时间和振铃频率差异。
- 计算长地线引入的测量误差。

#### 任务二：量化 GPIO 标记开销

- 比较 HAL API、直接 BSRR、BSRR 加 `DSB` 三种实现。
- 每种实现采集至少 10,000 次。
- 输出最小值、最大值、平均值、P99 和峰峰抖动。
- 使用 DWT 对同一代码段交叉验证。

#### 任务三：测量 RTOS 实时性

- 创建 1 kHz 高优先级控制任务。
- 加入网络、DMA 和低优先级负载。
- 通过 GPIO 测量任务唤醒延迟与执行时间。
- 分析平均延迟不能代表 WCET 的原因。

#### 任务四：分析 SPI 时序裕量

- 在不同 SPI 频率下测量 CLK、MOSI、MISO 和 CS。
- 测量数据相对采样边沿的建立保持时间。
- 改变串联电阻并比较过冲和边沿速度。
- 在高低温、电压角落下重复测试。

#### 任务五：电源瞬态测试

- 使用 GPIO 控制动态负载。
- 同时测量负载控制、电源轨和复位信号。
- 计算电压跌落、恢复时间和等效供电阻抗：

Zsource≈ΔVΔIZsource​≈ΔIΔV​

- 验证去耦电容、走线阻抗和稳压器环路的影响。

#### 任务六：自动化回归测试

- 使用示波器 SCPI 接口配置通道、触发和采集。
- 自动导出波形 CSV 或二进制数据。
- 对上升时间、过冲、纹波和响应延迟设置上下限。
- 将结果纳入硬件在环 CI，保存仪器型号和校准状态。

### 16.2 性能测试方法

每组测试至少记录：

|类别|必须记录内容|
|---|---|
|被测对象|硬件版本、固件提交、工作模式|
|仪器|型号、带宽、采样率、存储深度|
|探头|型号、倍率、带宽、输入电容|
|连接|地弹簧、同轴、差分连接方式|
|通道|垂直档位、偏置、耦合、带宽限制|
|时基|时间窗、实际采样率|
|触发|类型、电平、保持时间、位置|
|环境|温度、输入电压、负载|
|统计|样本数、最小、最大、平均、P99|
|不确定度|仪器精度、探头误差、测量侵入性|

### 16.3 进阶学习方向

1. **信号完整性**：传输线、反射系数、端接、眼图和 TDR。
2. **电源完整性**：PDN 阻抗、目标阻抗、环路稳定性和负载瞬态。
3. **高速串行总线**：USB、Ethernet、LVDS、MIPI 的一致性测试。
4. **功率电子测量**：双脉冲测试、开关损耗、共模瞬态与探头 CMRR。
5. **实时系统分析**：ETM、SWO、Tracealyzer、WCET 和响应时间分析。
6. **自动化测试**：SCPI、PyVISA、波形数据库、硬件在环回归。
7. **测量不确定度**：探头校准、时基误差、幅值精度和统计置信度。
8. **EMC 故障关联**：近场探头、瞬态注入和示波器时域定位。
