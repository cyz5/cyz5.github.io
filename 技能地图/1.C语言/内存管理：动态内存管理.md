
动态内存管理的核心，是在对象数量、尺寸或生命周期无法完全静态确定时，建立一套**容量可预算、失败可恢复、时延可分析、所有权可追踪**的资源管理机制。

在工业嵌入式系统中，真正困难的问题通常不是调用 API，而是：

- 为什么剩余堆空间充足，仍然分配失败？
- 为什么设备运行数周后，偶尔出现分配延迟尖峰？
- 为什么故障发生在 `free()`，根因却是数秒前的越界写？
- 为什么 `realloc()` 失败后，旧数据反而丢失？
- 如何让启动阶段使用动态分配，同时让实时运行阶段具有确定性？
- 如何证明所有失败路径都没有泄漏、重复释放和悬空引用？

本课以 **C11/C17、32 位 MCU、GNU Arm 工具链、裸机与 FreeRTOS** 为主要背景。涉及 Linux 时单独说明差异。

**量化说明**：本课提供明确的计算示例、平台配置和可执行测量方法。未在真实硬件上采集的数据标注为假设或预算，不作为实测结果。

## 3. 技术概述

### 3.1 动态内存的语言模型

```
#include <stdlib.h>

void example(void)
{
    int *value = malloc(sizeof(*value));

    if (value == NULL) {
        return;
    }

    *value = 42;

    free(value);
}
```

这里包含两个不同对象：

1. `value`：局部指针对象，通常具有自动存储期。
2. `malloc()` 得到的区域：具有分配存储期，持续到被释放。

函数返回不会自动释放第二个对象。

**指针变量的生命周期与其指向对象的生命周期必须分别分析。**

### 3.2 三个核心接口

```
void *malloc(size_t size);
void free(void *ptr);
void *realloc(void *ptr, size_t size);
```

标准语义：

|API|成功时|失败时|关键约束|
|---|---|---|---|
|`malloc(n)`|返回可容纳至少 `n` 字节的区域|返回空指针|内容未初始化|
|`free(p)`|结束分配区域的生命周期|无错误返回值|`p` 必须满足释放前提|
|`realloc(p, n)`|返回新的分配结果，可能移动|返回空指针，旧对象保持有效|新尺寸为零时存在标准版本差异|

`free(NULL)` 不执行任何操作。

对 `malloc(0)`：

- C11/C17 允许返回空指针；
- 也允许返回不能用于访问对象的非空结果；
- 返回的非空结果仍可交给 `free()`。

工程上建议统一：

> **业务接口禁止零长度分配，或者明确把零长度定义为“空对象”；不要把标准允许的差异传播到业务代码。**

### 3.3 为什么必须谨慎处理 `realloc(p, 0)`

不同标准版本与实现之间存在差异。

- C11/C17 下，零尺寸重分配具有实现相关行为；C17 对此用法作了弃用处理。
- C23 下，对非空指针进行零尺寸 `realloc()` 属于未定义行为。

建议统一写成：

```
if (new_size == 0u) {
    free(buffer);
    buffer = NULL;
} else {
    /* 正常重分配。 */
}
```

**生产接口不要依赖 `realloc(p, 0)` 完成释放。**

### 3.4 `calloc()` 的位置

```
void *calloc(size_t count, size_t size);
```

它负责：

- 分配数组所需空间；
- 将分配区域的所有字节置零；
- 正确处理无法表示的数组总尺寸，不能按回绕后的较小尺寸成功分配。

但要注意：

**字节全零不等于所有 C 类型都获得其语义上的零值。**

例如，C 标准不保证空指针一定使用全零位表示。普通 MCU ABI 通常如此，但可移植代码不能把这当作语言保证。

## 4. 核心特性横向对比

### 4.1 内存管理方案对比

|方案|分配时延|外部碎片|尺寸灵活性|生命周期管理|适用场景|
|---|---|---|---|---|---|
|静态对象|无运行期分配|无|低|全生命周期|永久状态、固定工作区|
|栈|通常很低|通常无|受栈预算限制|自动|小型同步临时对象|
|通用堆|依赖算法和状态|可能存在|高|手动|非固定尺寸对象|
|固定块池|通常容易界定|无跨块外部碎片|低至中|手动归还|报文、事件、描述符|
|arena|常见为指针推进|阶段内无逐对象回收碎片|中至高|批量释放|解析、事务、阶段性工作|
|TLSF 类分配器|元数据操作有常数级设计|仍可能存在|高|手动|需要有界管理开销的动态对象|

**TLSF 的常数级分配器操作，不代表任意环境下整个调用都具有固定时延。** 锁等待、缓存未命中、页故障、清零或复制仍需单独分析。

### 4.2 常见分配策略

|策略|搜索方式|优点|主要问题|
|---|---|---|---|
|First-fit|找到第一个足够大的块|实现简单|搜索长度和碎片依赖历史|
|Best-fit|找到最接近需求的块|尽量减少当前剩余量|可能产生大量微小块|
|Next-fit|从上次位置继续搜索|避免总从头开始|不保证更好的碎片结果|
|分离适配|按尺寸类别查找|搜索更快|类别设计带来额外内部浪费|
|Buddy|按二次幂拆分与合并|合并规则简单|尺寸取整损耗可能较大|
|TLSF|两级尺寸索引和位图|管理操作可有界|实现和验证复杂度较高|

### 4.3 FreeRTOS 堆实现对比

|实现|支持释放|相邻块合并|多区域|主要用途|
|---|---|---|---|---|
|`heap_1`|否|不适用|否|启动期创建后不销毁|
|`heap_2`|是|否|否|需谨慎控制分配模式|
|`heap_3`|是|依赖 C 库|依赖集成|复用 C 库分配器|
|`heap_4`|是|是|否|常见单区域动态分配|
|`heap_5`|是|是|是|多片可用 RAM|

**`heap_4/heap_5` 支持合并，不代表不会产生外部碎片。**

仍被活对象隔开的空闲区域无法合并。

## 5. 底层原理与功能特性深度解析

### 5.1 分配器如何描述一个内存块

一种常见设计：

```
低地址
┌──────────────────────┐
│ 块头：尺寸、状态等     │
├──────────────────────┤
│ 返回给用户的有效载荷   │
├──────────────────────┤
│ 对齐或未使用尾部       │
└──────────────────────┘
高地址
```

分配器可能使用如下内部结构：

```
#include <stddef.h>

typedef struct free_block {
    size_t block_size;
    struct free_block *next;
} free_block_t;
```

这只是结构示意，不能直接作为完整分配器：

- 用户区对齐尚未解决；
- 尺寸溢出尚未检查；
- 没有并发保护；
- 没有相邻块合并；
- 没有完整性检查。

源码分析时需要首先确认：

1. 块大小是否包含块头。
2. 分配状态是否复用尺寸字段的某一位。
3. 空闲链表按地址还是按尺寸排序。
4. 最小可拆分块是多少。
5. 对齐要求是多少。
6. 空闲块合并依赖链表还是边界标记。

### 5.2 尺寸调整与溢出

常见需求：

B(n)=align_up⁡(n+h,a)B(n)=align_up(n+h,a)

其中：

- nn：请求尺寸；
- hh：块头成本；
- aa：对齐；
- B(n)B(n)：候选块占用。

必须先检查加法和对齐计算是否溢出。

```
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

bool size_add_checked(size_t a, size_t b, size_t *out)
{
    if ((out == NULL) || (a > SIZE_MAX - b)) {
        return false;
    }

    *out = a + b;
    return true;
}

bool size_mul_checked(size_t a, size_t b, size_t *out)
{
    if (out == NULL) {
        return false;
    }

    if ((b != 0u) && (a > SIZE_MAX / b)) {
        return false;
    }

    *out = a * b;
    return true;
}

bool size_align_up_checked(size_t value,
                           size_t alignment,
                           size_t *out)
{
    if ((out == NULL) ||
        (alignment == 0u) ||
        ((alignment & (alignment - 1u)) != 0u)) {
        return false;
    }

    const size_t mask = alignment - 1u;

    if (value > SIZE_MAX - mask) {
        return false;
    }

    *out = (value + mask) & ~mask;
    return true;
}
```

**安全检查必须发生在运算前。先计算，再检查结果是否异常，可能已经失去原始信息。**

### 5.3 块分裂

假设找到 256 B 空闲块，请求调整后需要 80 B：

```
原始：
[              空闲 256 B              ]

分裂：
[ 已分配 80 B ][       空闲 176 B       ]
```

但只有当剩余空间足够容纳：

- 新空闲块元数据；
- 最小有效载荷；
- 对齐需求；

才应分裂。

否则可能整体交给调用方，产生内部浪费。

典型逻辑：

```
/*
 * 已由调用方保证：
 * 1. original_size >= required_size；
 * 2. 尺寸和地址合法且对齐；
 * 3. minimum_free_block 已包含完整元数据需求。
 */
bool should_split(size_t original_size,
                  size_t required_size,
                  size_t minimum_free_block)
{
    if (original_size < required_size) {
        return false;
    }

    return (original_size - required_size) >= minimum_free_block;
}
```

### 5.4 释放与合并

```
释放前：
[ 空闲 A ][ 已用 B ][ 空闲 C ]

释放 B：
[          合并后的空闲块          ]
```

相邻块合并可以缓解碎片，但无法穿过仍然存活的对象：

```
[ 空闲 ][ 长期对象 ][ 空闲 ]
```

因此：

**短期对象与长期对象混合分配，是长期碎片的重要来源。**

工程解法往往是分离生命周期：

- 长期配置：启动期专用区；
- 高频小对象：固定池；
- 大型临时对象：专用工作区；
- 低频可变对象：受控通用堆。

### 5.5 `malloc()` 返回内容未初始化

```
#include <stdbool.h>
#include <stdlib.h>

typedef struct {
    unsigned state;
    unsigned retries;
} connection_t;

bool connection_create(connection_t **out)
{
    if (out == NULL) {
        return false;
    }

    *out = NULL;

    connection_t *connection = malloc(sizeof(*connection));

    if (connection == NULL) {
        return false;
    }

    *connection = (connection_t) {
        .state = 0u,
        .retries = 0u
    };

    *out = connection;
    return true;
}
```

显式结构体初始化表达业务初始状态，避免依赖旧堆内容。

也要区分：

- 分配器返回了可用存储；
- 对象已经建立业务不变量。

前者成立不代表后者成立。

### 5.6 对齐保证与过度对齐

`malloc()` 适用于具有基本对齐要求的对象。

但以下需求不能默认满足：

- 32 B 缓存行对齐；
- 64 B DMA 描述符对齐；
- 某些 SIMD 扩展对齐；
- 自定义过度对齐类型。

C11 的 `aligned_alloc()` 还要求：

- 对齐值满足实现要求；
- 尺寸是对齐值的整数倍；
- 库实现提供该接口。

嵌入式库可能不支持完整 C11 分配接口。

**对齐只是 DMA 可用性的一个条件；还必须满足地址可达性、边界和缓存一致性要求。**

### 5.7 `free()` 的准确前提

以下释放合法：

```
free(NULL);
```

以下通常合法：

```
void *buffer = malloc(128u);

if (buffer != NULL) {
    free(buffer);
}
```

以下均有问题：

```
int local;
free(&local);       /* 非分配器返回对象。 */
```

```
unsigned char *buffer = malloc(128u);

if (buffer != NULL) {
    free(buffer + 8); /* 非原始返回地址。 */
}
```

```
free(buffer);
free(buffer);      /* 重复释放。 */
```

`free()` 没有标准错误码可供恢复。

**非法释放是调用方违反契约，不应指望分配器安全拒绝。**

### 5.8 `realloc()` 的保留规则

对旧尺寸 OO、新尺寸 NN：

保留字节数=min⁡(O,N)保留字节数=min(O,N)

扩容新增的部分未初始化。

可能的实现路径：

```
realloc(p, n)
├── 当前块已足够
│   └── 保持原地址，可能分裂尾部
├── 后续相邻空闲空间足够
│   └── 原地扩张
└── 必须移动
    ├── 分配新块
    ├── 复制 min(old_size, new_size) 字节
    └── 释放旧块
```

失败时，非零尺寸调用的旧对象保持有效。

正确调用：

```
#include <stdbool.h>
#include <stddef.h>
#include <stdlib.h>

bool buffer_resize(void **buffer, size_t new_size)
{
    if (buffer == NULL) {
        return false;
    }

    if (new_size == 0u) {
        free(*buffer);
        *buffer = NULL;
        return true;
    }

    void *new_buffer = realloc(*buffer, new_size);

    if (new_buffer == NULL) {
        return false;
    }

    *buffer = new_buffer;
    return true;
}
```

使用时应传入真正的 `void *` 对象：

```
void *storage = NULL;

if (!buffer_resize(&storage, 256u)) {
    /* 处理失败。 */
}
```

**不要把任意 `T **` 强制转换为 `void **` 作为通用写回接口。** `void *` 的转换规则不意味着二级指针可以这样互换。

### 5.9 `realloc()` 成功后的旧别名全部失效

```
unsigned char *buffer = malloc(128u);
unsigned char *field = buffer + 16u;
```

一旦成功执行重分配：

- `buffer` 的旧分配生命周期结束；
- `field` 不能继续用于访问；
- 即使返回地址的数值看起来没有变化，也应使用新返回值重建引用。

推荐保留偏移：

```
#include <stddef.h>
#include <stdlib.h>

bool grow_and_locate(unsigned char **buffer,
                     size_t new_size,
                     size_t field_offset,
                     unsigned char **field)
{
    if ((buffer == NULL) ||
        (field == NULL) ||
        (field_offset >= new_size)) {
        return false;
    }

    unsigned char *new_buffer = realloc(*buffer, new_size);

    if (new_buffer == NULL) {
        return false;
    }

    *buffer = new_buffer;
    *field = new_buffer + field_offset;
    return true;
}
```

接口前提：传入指针具有有效分配契约，且没有其他持续使用的借用者。

### 6.5 `realloc()` 的瞬时容量峰值

旧对象 8 KiB，新对象 12 KiB。

- 对齐；
- 其他活对象；
- 分配器保留量。

### 6.6 逐字节扩容与几何扩容

每增加一个字节都按精确尺寸重分配，在每次都移动的情况下，总复制量：

1+2+⋯+(N−1)=N(N−1)21+2+⋯+(N−1)=2N(N−1)​

### 6.7 测量成本

Cortex-M4 可用 DWT：

```
#include <stdint.h>

/* 依赖目标平台 CMSIS 头文件。 */

static inline uint32_t measure_begin(void)
{
    __asm volatile ("" ::: "memory");
    __DSB();
    __ISB();

    return DWT->CYCCNT;
}

static inline uint32_t measure_end(uint32_t start)
{
    __DSB();
    __ISB();
    __asm volatile ("" ::: "memory");

    return DWT->CYCCNT - start;
}
```

测量分配：

```
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdlib.h>

bool measure_malloc(size_t size,
                    uint32_t *cycles,
                    void **allocated)
{
    if ((size == 0u) ||
        (cycles == NULL) ||
        (allocated == NULL)) {
        return false;
    }

    *allocated = NULL;

    const uint32_t begin = measure_begin();
    void *memory = malloc(size);
    *cycles = measure_end(begin);

    *allocated = memory;
    return memory != NULL;
}
```

约束：

- 先初始化并确认 DWT 计数器可用。
- 测量空区间以确定测量开销。
- 记录失败调用的耗时，失败路径可能最慢。
- `malloc()` 与 `free()` 分开统计。
- 最大观测值不能直接声明为 WCET。
- 168 MHz 下 32 位周期计数约 **25.6 s** 回绕一次。

## 8. 工程最佳实践

### 8.1 所有权必须进入接口契约

至少明确：

|属性|示例|
|---|---|
|创建者|`session_create()`|
|唯一所有者|会话管理任务|
|借用者|日志函数，仅调用期间有效|
|释放者|`session_destroy()`|
|所有权转移|队列发送成功后交给接收方|
|失败规则|发送失败，仍由发送方负责|
|异步边界|DMA 完成前不得释放或扩容|

推荐使用语义明确的命名：

```
create / destroy
acquire / release
borrow
take_ownership
submit
```

### 8.2 统一分配域

避免出现以下情况：

```
业务 malloc
协议栈自己的堆
FreeRTOS heap_4
图形库自己的堆
TLS 库自己的堆
```

这些域可以并存，但必须分别预算。

**统一接口不要求所有对象共用一片堆；它要求资源来源、限制和释放配对可追踪。**

### 8.3 不要为了“线程安全”粗暴包围整个分配过程

若用长临界区包围线性搜索或大块复制：

- 中断延迟变大；
- 控制回路可能超期；
- 调度受影响。

若使用互斥锁：

- 需要分析优先级反转；
- 优先级继承不能缩短临界区本身；
- 还要检查锁顺序和递归调用。

特别注意：一些 FreeRTOS 堆实现通过挂起调度器保护任务间访问，**挂起调度器不等于屏蔽所有中断**，也不因此允许 ISR 调用。

### 8.4 工业级规范

1. 所有分配均检查失败。
2. 所有数组尺寸计算均检查溢出。
3. 不使用 `realloc(p, 0)`。
4. 不在 ISR 中调用未明确支持 ISR 的分配器。
5. 不跨分配器释放。
6. 不对被借用或被 DMA 使用的对象重分配。
7. 对象销毁函数应允许空对象。
8. 对部分初始化对象提供统一回收路径。
9. 内存耗尽路径不得依赖新的堆分配。
10. 日志路径不得递归触发分配器。
11. 对长期对象与短期对象分域。
12. 为关键模块设置容量上限。
13. 将峰值、失败次数和最大块纳入诊断。
14. 默认通过完整架构改造消除硬实时路径动态分配。

### 8.5 部分初始化失败的回收模式

```
#include <stddef.h>
#include <stdlib.h>

typedef struct {
    unsigned char *rx;
    unsigned char *tx;
} channel_t;

void channel_destroy(channel_t *channel)
{
    if (channel == NULL) {
        return;
    }

    free(channel->tx);
    free(channel->rx);
    free(channel);
}

channel_t *channel_create(size_t rx_size, size_t tx_size)
{
    if ((rx_size == 0u) || (tx_size == 0u)) {
        return NULL;
    }

    channel_t *channel = malloc(sizeof(*channel));

    if (channel == NULL) {
        return NULL;
    }

    *channel = (channel_t) {
        .rx = NULL,
        .tx = NULL
    };

    channel->rx = malloc(rx_size);

    if (channel->rx == NULL) {
        goto fail;
    }

    channel->tx = malloc(tx_size);

    if (channel->tx == NULL) {
        goto fail;
    }

    return channel;

fail:
    channel_destroy(channel);
    return NULL;
}
```

这里的 `goto fail` 让所有失败路径收敛到同一个资源释放点，通常比重复清理代码更可靠。

## 9. 常见错误与避坑指南

### 9.1 错误一：直接覆盖 `realloc()` 的原指针

错误代码：

```
buffer = realloc(buffer, new_size);

if (buffer == NULL) {
    return false;
}
```

根因：

- 失败时旧对象仍存在；
- 唯一指针却已经被覆盖；
- 造成泄漏。

正确实现：

```
void *temporary = realloc(buffer, new_size);

if (temporary == NULL) {
    return false;
}

buffer = temporary;
```

风险影响：

- 内存逐步耗尽；
- 失败路径无法回滚；
- 低内存时触发更严重的持续退化。

### 9.2 错误二：数组尺寸乘法溢出

错误代码：

```
sample_t *samples = malloc(count * sizeof(*samples));
```

根因：

- 乘法在 `size_t` 范围内回绕；
- 分配得到小块；
- 后续仍按原 `count` 写入。

正确实现：

```
#include <stdint.h>
#include <stdlib.h>

sample_t *samples_create(size_t count)
{
    if ((count == 0u) ||
        (count > SIZE_MAX / sizeof(sample_t))) {
        return NULL;
    }

    return malloc(count * sizeof(sample_t));
}
```

风险影响：

- 堆越界；
- 元数据破坏；
- 在输入可控时形成安全漏洞。

### 9.3 错误三：释放后继续通过别名访问

错误代码：

```
unsigned char *buffer = malloc(128u);
unsigned char *alias = buffer;

free(buffer);
buffer = NULL;

alias[0] = 1u;
```

根因：

- 将一个变量置空，并不会消除其他引用。
- 释放改变的是对象生命周期。

正确实现：

```
/*
 * 设计约束：
 * inspect_buffer() 只能在调用期间借用，不保存地址。
 */
inspect_buffer(buffer, 128u);

free(buffer);
buffer = NULL;
```

异步共享必须使用所有权转移、引用计数或明确的完成协议。

风险影响：

- 修改已被其他对象复用的内存；
- 错误表现随分配历史变化；
- 故障位置与根因相距很远。

### 9.4 错误四：分配器混用

错误代码：

```
void *buffer = pvPortMalloc(256u);
free(buffer);
```

正确实现：

```
void *buffer = pvPortMalloc(256u);

if (buffer != NULL) {
    use_buffer(buffer);
    vPortFree(buffer);
}
```

根因：

- 分配器可能管理不同区域；
- 块头格式与同步机制不同。

风险影响：

- 空闲链表破坏；
- 后续分配崩溃；
- 难以在错误调用处立即定位。

### 9.5 错误五：忽略扩容新增区域未初始化

错误代码：

```
unsigned char *new_buffer = realloc(buffer, 512u);

if (new_buffer != NULL) {
    buffer = new_buffer;
    consume(buffer, 512u);
}
```

假设原对象只有 128 B，后面 384 B 未获得业务初始化。

正确实现：

```
#include <string.h>

unsigned char *new_buffer = realloc(buffer, new_capacity);

if (new_buffer == NULL) {
    return false;
}

if (new_capacity > old_capacity) {
    memset(new_buffer + old_capacity,
           0,
           new_capacity - old_capacity);
}

buffer = new_buffer;
```

风险影响：

- 未初始化读取；
- 协议字段随机；
- 历史堆内容泄露。

如果新增区域马上被完整写入，不需要无意义地先清零，应由数据流证明。

### 9.6 错误六：分配后按指针大小清零

错误代码：

```
device_t *device = malloc(sizeof(*device));

if (device != NULL) {
    memset(device, 0, sizeof(device));
}
```

根因：

- `sizeof(device)` 是指针大小；
- 不是结构体大小。

正确实现：

```
device_t *device = malloc(sizeof(*device));

if (device != NULL) {
    *device = (device_t) {
        .state = DEVICE_IDLE,
        .buffer = NULL
    };
}
```

风险影响：

- 部分字段保留旧数据；
- 销毁时释放随机地址；
- 状态机进入非法分支。

### 9.7 错误七：用 `realloc()` 扩容含内部指针的对象

错误代码：

```
typedef struct {
    unsigned char *cursor;
    unsigned char data[128];
} parser_t;
```

如果 `cursor` 指向自身 `data`，对象移动后它仍指向旧地址。

正确设计：

```
typedef struct {
    size_t cursor_offset;
    size_t length;
    unsigned char data[];
} parser_t;
```

使用时：

```
unsigned char *cursor = parser->data + parser->cursor_offset;
```

仍需验证：

cursor_offset≤lengthcursor_offset≤length

风险影响：

- 对旧对象的悬空访问；
- 原地扩容时测试正常，移动扩容时失败。

## 10. 多机制组合使用方案

### 10.1 协同架构

```
系统启动
├── 静态区
│   ├── 任务控制信息
│   ├── DMA 缓冲池
│   └── 故障日志
├── 启动期 arena
│   └── 配置解析临时对象
└── 受控堆
    └── 可变长管理缓冲区

进入实时运行
├── 控制路径：静态对象 + 固定池
├── 通信路径：池 + 队列所有权转移
└── 管理路径：有配额、有上限的 malloc/realloc

阶段结束
└── arena 批量复位
```

下面实现一个**单所有者任务使用的配额堆包装层**。

它提供：

- 请求尺寸配额；
- 活对象数量；
- 当前和历史峰值；
- 分配失败统计；
- 零尺寸统一语义；
- 失败不破坏原对象的扩容。

**适用边界**：

- 仅由同一个任务调用，或者由上层串行化。
- 返回指针只允许交回本模块。
- 不支持过度对齐对象。
- 统计的是业务请求字节，不是底层真实堆占用。
- 不提供非法指针安全检测；传错指针仍然违反接口契约。

### 10.2 完整代码框架

```
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdlib.h>

typedef union {
    max_align_t alignment;

    struct {
        size_t requested_size;
    } meta;
} mem_header_t;

typedef struct {
    size_t quota;
    size_t current;
    size_t peak;
    size_t live_blocks;
    size_t failures;
} mem_stats_t;

/*
 * 单所有者任务模型。
 * quota == 0 时，不允许新建非零尺寸分配。
 */
static mem_stats_t g_mem;

static void count_failure(void)
{
    if (g_mem.failures != SIZE_MAX) {
        ++g_mem.failures;
    }
}

bool mem_init(size_t quota)
{
    if (g_mem.live_blocks != 0u) {
        return false;
    }

    g_mem = (mem_stats_t) {
        .quota = quota
    };

    return true;
}

mem_stats_t mem_get_stats(void)
{
    return g_mem;
}

void *mem_alloc(size_t size)
{
    if (size == 0u) {
        return NULL;
    }

    if ((g_mem.current > g_mem.quota) ||
        (size > g_mem.quota - g_mem.current) ||
        (size > SIZE_MAX - sizeof(mem_header_t))) {
        count_failure();
        return NULL;
    }

    mem_header_t *header =
        malloc(sizeof(*header) + size);

    if (header == NULL) {
        count_failure();
        return NULL;
    }

    header->meta.requested_size = size;

    g_mem.current += size;
    ++g_mem.live_blocks;

    if (g_mem.current > g_mem.peak) {
        g_mem.peak = g_mem.current;
    }

    return header + 1;
}

void mem_free(void *pointer)
{
    if (pointer == NULL) {
        return;
    }

    /*
     * 前提：pointer 是 mem_alloc/mem_resize 当前有效返回值，
     * 且尚未被释放。
     */
    mem_header_t *header =
        (mem_header_t *)pointer - 1;

    const size_t size = header->meta.requested_size;

    g_mem.current -= size;
    --g_mem.live_blocks;

    free(header);
}

bool mem_resize(void **pointer, size_t new_size)
{
    if (pointer == NULL) {
        return false;
    }

    if (new_size == 0u) {
        mem_free(*pointer);
        *pointer = NULL;
        return true;
    }

    if (*pointer == NULL) {
        void *created = mem_alloc(new_size);

        if (created == NULL) {
            return false;
        }

        *pointer = created;
        return true;
    }

    mem_header_t *old_header =
        (mem_header_t *)(*pointer) - 1;

    const size_t old_size =
        old_header->meta.requested_size;

    const size_t base_usage =
        g_mem.current - old_size;

    if ((base_usage > g_mem.quota) ||
        (new_size > g_mem.quota - base_usage) ||
        (new_size > SIZE_MAX - sizeof(mem_header_t))) {
        count_failure();
        return false;
    }

    mem_header_t *new_header =
        realloc(old_header,
                sizeof(*new_header) + new_size);

    if (new_header == NULL) {
        count_failure();
        return false;
    }

    new_header->meta.requested_size = new_size;

    g_mem.current = base_usage + new_size;

    if (g_mem.current > g_mem.peak) {
        g_mem.peak = g_mem.current;
    }

    *pointer = new_header + 1;
    return true;
}
```

### 10.3 设计分析

`max_align_t` 保证头部后的用户区具有基本类型所需的对齐。

这个包装层会叠加两类元数据：

```
底层分配器元数据
包装层 mem_header_t
业务有效载荷
```

因此不能按 `g_mem.current` 推算实际剩余堆。

配额检查限制的是：

∑requested_size∑requested_size

它没有限制：

- 底层块头；
- 包装层头部；
- 对齐损耗；
- `realloc()` 移动期间的瞬时峰值；
- 外部碎片。

如果要求严格的物理域隔离，应使用独立堆区域或专用池。

### 10.4 带上限的可增长缓冲区

```
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <string.h>

typedef struct {
    void *storage;
    size_t length;
    size_t capacity;
    size_t limit;
} byte_buffer_t;

bool byte_buffer_init(byte_buffer_t *buffer, size_t limit)
{
    if (buffer == NULL) {
        return false;
    }

    *buffer = (byte_buffer_t) {
        .storage = NULL,
        .length = 0u,
        .capacity = 0u,
        .limit = limit
    };

    return true;
}

void byte_buffer_destroy(byte_buffer_t *buffer)
{
    if (buffer == NULL) {
        return;
    }

    mem_free(buffer->storage);

    *buffer = (byte_buffer_t) { 0 };
}

bool byte_buffer_reserve(byte_buffer_t *buffer, size_t required)
{
    if ((buffer == NULL) ||
        (required > buffer->limit)) {
        return false;
    }

    if (required <= buffer->capacity) {
        return true;
    }

    size_t new_capacity = buffer->capacity;

    if (new_capacity == 0u) {
        new_capacity =
            (buffer->limit < 64u) ? buffer->limit : 64u;
    }

    while (new_capacity < required) {
        if (new_capacity > buffer->limit / 2u) {
            new_capacity = buffer->limit;
        } else {
            new_capacity *= 2u;
        }
    }

    if (!mem_resize(&buffer->storage, new_capacity)) {
        return false;
    }

    buffer->capacity = new_capacity;
    return true;
}

/*
 * 前提：
 * data 指向的输入区域不属于 buffer 自身存储，
 * 并在整个调用期间有效。
 */
bool byte_buffer_append(byte_buffer_t *buffer,
                        const void *data,
                        size_t length)
{
    if ((buffer == NULL) ||
        ((data == NULL) && (length != 0u))) {
        return false;
    }

    if (length == 0u) {
        return true;
    }

    if ((buffer->length > buffer->limit) ||
        (length > buffer->limit - buffer->length)) {
        return false;
    }

    const size_t required = buffer->length + length;

    if (!byte_buffer_reserve(buffer, required)) {
        return false;
    }

    unsigned char *destination = buffer->storage;

    memcpy(destination + buffer->length, data, length);

    buffer->length = required;
    return true;
}
```

此接口特别声明输入不能来自自身缓冲区，因为扩容可能使输入地址失效。若要支持自追加，应设计基于偏移的专用接口。

**这里的事务保证是：分配失败时，原长度、容量和内容保持有效。**

## 11. 工业级实际案例分析

以下为工业场景的工程设计案例，数值用于分析，不代表特定项目的硬件实测报告。

### 11.1 案例一：工业网关配置热更新

#### 需求

- 配置最大 32 KiB；
- 正在运行的配置必须持续有效；
- 新配置解析失败不得影响现有业务；
- 配置切换后才能释放旧配置。

#### 架构设计

```
活动配置 A
    │ 继续服务业务
    │
接收新配置
    ↓
构建候选配置 B
    ↓
完整校验
    ↓
在安全点切换 A → B
    ↓
确认所有旧借用结束
    ↓
释放 A
```

容量预算必须考虑：

Mpeak≥MA+MB+Mparse-workspaceMpeak​≥MA​+MB​+Mparse-workspace​

假设：

- 活动配置 24 KiB；
- 候选配置 28 KiB；
- 解析工作区 8 KiB；

则业务有效载荷峰值：

24+28+8=60 KiB24+28+8=60 KiB

还未包含分配器开销。

#### 核心代码

```
bool config_update(const unsigned char *data, size_t length)
{
    config_t *candidate = config_parse(data, length);

    if (candidate == NULL) {
        return false;
    }

    if (!config_validate(candidate)) {
        config_destroy(candidate);
        return false;

    /*
     * 约定：
     * config_replace_at_quiescent_point() 返回时，

     * 成功后接管 candidate。
     */

        return false;
    }

}
```

#### 设计要点

- 原子交换一个指针不等于旧对象可以立即释放。
- 必须解决借用结束问题。
- 可选方案包括单所有者任务、安全点、引用计数或读侧宽限期。
- 内存不足时保留旧配置，并明确返回更新失败。
- 不使用 `realloc()` 原地修改活动配置，避免破坏回滚能力。

### 11.2 案例二：通信协议可变长接收缓冲区

#### 需求

- 报文最大 4096 B；
- 网络分片尺寸不固定；
- 管理任务允许动态分配；
- 控制任务不得因接收异常耗尽资源。

#### 架构

- 每连接具有独立长度上限。
- 全模块具有总配额。
- 使用几何扩容。
- 超限或内存不足时终止当前报文。
- 解析器使用偏移，不保存跨扩容指针。

#### 核心代码

```
typedef enum {
    RX_OK,
    RX_TOO_LARGE,
    RX_NO_MEMORY,
    RX_INVALID
} rx_result_t;

rx_result_t receive_fragment(byte_buffer_t *buffer,
                             const void *data,
                             size_t length)
{
    if ((buffer == NULL) ||
        ((data == NULL) && (length != 0u))) {
        return RX_INVALID;
    }

    if ((buffer->length > buffer->limit) ||
        (length > buffer->limit - buffer->length)) {
        return RX_TOO_LARGE;
    }

    if (!byte_buffer_append(buffer, data, length)) {
        return RX_NO_MEMORY;
    }

    return RX_OK;
}
```

#### 设计要点

- 报文长度来自网络，先验证再分配。
- 不能只限制单报文长度，还要限制连接数和排队数量。
- 失败日志使用静态缓冲区。
- 连接中止时必须释放接收缓冲区。
- 几何扩容降低复制次数，但应考虑瞬时旧块与新块并存。

### 11.3 案例三：电机控制器后台日志导致实时性抖动

#### 需求

- 电流环 20 kHz；
- 通信与日志运行在低优先级任务；
- 现场出现偶发控制周期超限；
- 日志模块频繁分配格式化字符串。

#### 根因路径

可能的链条：

```
日志分配
  ↓
长空闲链表搜索 / 分配器锁
  ↓
调度受阻或关键资源等待
  ↓
实时任务响应延迟
```

也可能是：

```
日志大量复制
  ↓
CPU 与 DMA 总线竞争
  ↓
控制路径访存延迟增加
```

必须用测量区分，不能仅凭“使用了 malloc”下结论。

#### 架构调整

- 控制路径无动态分配。
- 日志改为固定大小记录池。
- 日志任务负责格式化和输出。
- 池满按策略丢弃低优先级日志。
- 故障日志保留独立静态槽位。

核心接口：

```
bool log_submit(const log_record_t *record)
{
    log_record_t *slot = log_pool_try_acquire();

    if (slot == NULL) {
        log_drop_counter_increment();
        return false;
    }

    *slot = *record;

    if (!log_queue_try_send(slot)) {
        log_pool_release(slot);
        return false;
    }

    /* 队列成功后由日志任务负责归还。 */
    return true;
}
```

设计要点：

- `record` 应是值类型，不能带有指向调用者临时对象的未管理指针。
- ISR 版本必须使用明确支持 ISR 的池与队列接口。
- 丢弃日志是容量策略，不能静默泄漏记录。
- 验证指标包括控制环最坏观测延迟、池峰值和丢弃率。

## 12. 高频问题深度答疑

### 12.1 `malloc()` 是不是每次都向操作系统申请内存？

不是。

在 MCU 上，通常没有通用操作系统虚拟内存接口。分配器管理预留的 SRAM，或经 `_sbrk()` 等机制扩展其管理范围。

在 Linux 上，用户态分配器通常从已有 arena 中满足请求，必要时通过系统接口获得更多虚拟地址空间。

因此：

**API 名称相同，底层资源获取机制可能完全不同。**

### 12.2 为什么崩溃发生在 `free()`，却不能认定 `free()` 有问题？

因为块头可能早已损坏。

典型时间线：

```
t0：分配 A、B
t1：A 越界，覆盖 B 的块头
t2：系统继续运行
t3：free(B) 读取损坏的尺寸或链表指针
t4：异常
```

定位策略：

- 在边界添加检测区；
- 使用 AddressSanitizer 复现；
- 对被破坏块头设置硬件写观察点；
- 记录分配来源与尺寸；
- 缩小首次损坏的时间窗口。

故障发生点通常是**发现损坏的位置**。

### 12.3 释放后立刻置空，能防止所有 use-after-free 吗？

不能。

```
free(owner);
owner = NULL;
```

只能减少通过 `owner` 再次使用的风险。

其他别名、队列中的指针、DMA 保存的地址都不会自动失效。

完整解决依赖：

- 唯一所有权；
- 明确借用；
- 异步完成；
- 对象句柄和代数；
- 必要的引用计数或宽限期。

引用计数本身也有成本，并且需要解决循环引用与并发正确性。

### 12.4 有互斥锁的分配器是不是实时安全？

不一定。

互斥锁解决的是并发访问正确性。实时性还包括：

- 等锁上界；
- 持锁任务是否会被抢占；
- 是否支持优先级继承；
- 搜索空闲块的最坏长度；
- 是否触发扩堆；
- `realloc()` 复制量；
- 缓存和总线干扰。

**线程安全是正确性属性，实时确定性是时间属性。**

### 12.5 只在启动阶段使用 `malloc()`，是否就没有风险？

风险明显减少，但不会自动消失。

仍需保证：

- 启动失败可回收或进入安全状态；
- 总容量足够；
- 创建顺序不会造成不必要浪费；
- 第三方库不会在运行期偷偷分配；
- 后续不会释放并重新创建长期对象；
- 所有分配完成后才开启依赖它们的功能。

可以在进入运行状态后启用分配审计，检测违规调用。

如果采用分配冻结，必须确认 C 库格式化、TLS、网络重连等路径是否会延迟分配。

### 12.6 怎样证明失败路径没有泄漏？

最有效的方法之一是**逐分配点故障注入**。

假设成功路径一共分配 KK 次：

1. 第 1 次分配失败；
2. 第 2 次分配失败；
3. ……
4. 第 KK 次分配失败；
5. 全部成功。

每次执行后检查：

live_blocksafter=live_blocksbeforelive_blocksafter​=live_blocksbefore​

以及：

- 原对象仍有效；
- 输出参数满足失败契约；
- 没有重复释放；
- 共享状态未部分提交；
- 能再次执行操作并成功。

注意：路径可能因输入和失败位置改变，所以不能只测试一组输入。

## 13. 课程核心总结

### 13.1 核心要点

1. **动态内存首先是所有权和生命周期设计问题。**
2. `malloc()` 不初始化内容，成功分配不代表对象已经可用。
3. `free()` 只能接收匹配分配器的有效原始指针，或空指针。
4. 非零尺寸 `realloc()` 失败时旧对象保持有效。
5. `realloc()` 成功后应依据新返回值重建所有内部引用。
6. 总空闲量不能替代最大连续空闲块。
7. 合并机制不能消除由活对象隔离产生的碎片。
8. 分配器线程安全不能证明 ISR 可用或满足硬实时要求。
9. 扩容既有复制成本，也有瞬时双份容量成本。
10. 失败路径必须具有明确、可测试的资源回收语义。

### 13.2 性能排序

就常见的存储管理成本而言：

```
静态预留 / 简单栈管理
    ↓
无竞争的固定池 / arena
    ↓
有界索引的通用分配器
    ↓
依赖空闲链表遍历的通用分配器
```

该排序只表达常见趋势。

实际结果还取决于：

- 同步；
- 缓存；
- 元数据位置；
- 是否清零；
- 是否复制；
- 任务唤醒；
- 内存总线争用。

**对象来自堆，不意味着对它进行一次普通 SRAM 读取天然比栈对象更慢。**

### 13.3 通用选型结论

- 数量和尺寸固定：静态对象。
- 高频固定对象：固定池。
- 阶段性临时对象：arena。
- 非实时可变长对象：带上限的受控堆。
- 硬实时对象：预分配，或提供完整的时空上界证明。
- 大型异步缓冲区：专用区域与明确所有权。
- 长期运行系统：分离生命周期，并持续监测碎片与容量。

- 主机分配器和 MCU 分配器不同；
- 主机通过不代表板端碎片与实时性合格；
- 自定义池若只表现为一整块大数组，工具未必能识别内部逻辑对象边界。

板端继续验证：

- DMA 可达性；
- 缓存一致性；
- 分配器同步；
- 实际周期分布；
- 内存峰值；
- 长时间运行与断连重连轨迹。

本课最终的工程交付物应包括：**内存所有权说明、分配域与容量表、失败语义、峰值预算、分配轨迹测试、板端时延报告，以及运行期诊断指标。**
