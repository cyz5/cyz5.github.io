## 3. 技术概述

## 3.1 数组的定义

数组是由**多个相同类型元素组成的连续对象**：

```
uint32_t samples[8];
```

其含义是：

- `samples` 是一个对象。
- 该对象包含 8 个 `uint32_t` 元素。
- 元素在内存中连续排列。
- 数组对象本身不能整体赋值、整体比较或整体传参复制。
- 数组对象的大小在其类型中体现，即 `sizeof(samples)` 为整个数组的字节数。

如果 `sizeof(uint32_t) == 4`，则：

```
sizeof(samples) == 8 * 4 == 32
```

数组对象的地址范围为：

```
[&samples[0], &samples[0] + 8)
```

`&samples[0] + 8` 是尾后指针，可以构造和比较，但不能解引用。

## 3.2 指针的定义

指针是一个**独立对象**，其值表示：

- 某个对象的地址；
- 某个函数的地址；
- 空指针值；
- 某些平台扩展定义的地址表示。

```
uint32_t *p;
```

这里的 `p` 不是数组，也不包含任何 `uint32_t` 元素。它只是一个保存地址的指针对象。

```
uint32_t value = 10U;
uint32_t *p = &value;
```

内存关系：

```
p  ─────保存────>  value
```

如果 `p` 位于 32 位 MCU 上，通常：

```
sizeof(p) == 4
```

但这只表示指针对象本身占 4 字节，不代表它指向的对象大小是 4 字节。

## 3.3 数组与指针的本质差异

|维度|数组|指针|
|---|---|---|
|本质|连续元素集合|保存地址的独立对象|
|是否拥有元素存储空间|是|否，仅保存地址|
|是否可重新指向|否|是，除非是指针常量|
|`sizeof`|整个数组大小|指针对象大小|
|是否可整体赋值|不可以|可以|
|是否可整体传参|函数参数中会退化为指针|直接复制地址|
|地址步进|按元素大小步进|按所指向类型大小步进|
|是否有固定容量|类型中包含|指针本身不包含容量|
|生命周期|与数组对象存储期相关|指针和目标对象生命周期独立|
|所有权|数组对象拥有自身元素存储|指针可能借用、拥有或指向外设|
|典型用途|固定容量、连续数据|间接访问、动态对象、外部缓冲区|

**核心结论：数组和指针不是同一种类型，也不是同一种对象。**

## 4. 核心特性横向对比

### 4.1 一维数组与指针

```
int array[4] = { 1, 2, 3, 4 };
int *pointer = array;
```

|表达式|类型|含义|
|---|---|---|
|`array`|`int[4]`，在多数表达式中转为 `int *`|数组对象或首元素地址|
|`&array`|`int (*)[4]`|整个数组对象的地址|
|`&array[0]`|`int *`|第一个元素地址|
|`pointer`|`int *`|指针对象，保存首元素地址|
|`&pointer`|`int **`|指针对象自身的地址|
|`array + 1`|`int *`|指向第 2 个元素|
|`&array + 1`|`int (*)[4]`|越过整个数组|

### 4.2 `sizeof` 对比

```
int array[10];
int *pointer = array;
```

假设 `int` 为 4 字节、指针为 4 字节：

```
sizeof(array)   == 40
sizeof(pointer) == 4
```

这是判断数组和指针本质差异的最直接方式。

### 4.3 是否可以修改

```
int array[4];
int *p = array;

p = &array[1]; /* 正确：p 可以改变指向 */

array = p;     /* 错误：数组不可赋值 */
```

数组名不是一个可修改的指针变量。它在特定表达式中会转换为首元素地址，但不能被重新赋值。

### 4.4 指针常量和指向常量

```
int data[4] = { 0 };

/* 指向 const int：不能通过 p1 修改元素 */
const int *p1 = data;

/* const 指针：不能让 p2 指向其他位置 */
int * const p2 = data;

/* 指针本身和目标对象都受限 */
const int * const p3 = data;
```

|声明|能修改指向|能通过指针修改目标|
|---|---|---|
|`int *p`|是|是|
|`const int *p`|是|否|
|`int * const p`|否|是|
|`const int * const p`|否|否|

数组本身不能重新指向，但数组元素是否可修改取决于元素类型：

```
int a[4];
const int b[4] = { 1, 2, 3, 4 };

a[0] = 10; /* 正确 */
b[0] = 10; /* 错误 */
```

## 5. 底层原理与功能特性深度解析

## 5.1 数组在内存中的连续布局

```
#include <stdint.h>

static uint16_t samples[4] = {
    100U, 200U, 300U, 400U
};
```

假设：

```
sizeof(uint16_t) == 2
```

则布局近似为：

```
地址        对象
0x20000000  samples[0]
0x20000002  samples[1]
0x20000004  samples[2]
0x20000006  samples[3]
```

数组元素地址公式：

```
&samples[i] = (地址)samples + i * sizeof(uint16_t)
```

C 语言不要求开发者手工计算字节地址，而是通过指针运算表达：

```
uint16_t *p = samples;

uint16_t first = p[0];
uint16_t second = *(p + 1);
```

以下两种形式等价：

```
samples[i]
i[samples]
```

因为：

```
samples[i] == *(samples + i)
i[samples] == *(i + samples)
```

但工程代码中应始终使用 `samples[i]`，避免可读性问题。

## 5.2 数组名的隐式转换

在大多数表达式中，数组表达式会转换为指向首元素的指针：

```
int array[4];

int *p = array;
```

这里发生了：

```
int[4]  →  int *
```

转换后的指针指向：

```
&array[0]
```

但有三个重要例外：

### 例外一：`sizeof`

```
int array[4];

sizeof(array); /* 得到整个数组大小 */
```

此时不会退化为指针。

### 例外二：取地址 `&`

```
int array[4];

&array; /* 类型是 int (*)[4]，不是 int * */
```

此时取的是整个数组对象的地址，不发生数组到指针转换。

### 例外三：字符串字面量初始化数组

```
char text[] = "abc";
```

字符串字面量用于初始化数组时，数组获得独立存储：

```
text[0] = 'a'
text[1] = 'b'
text[2] = 'c'
text[3] = '\0'
```

这里不是先创建指针再复制，而是直接初始化数组对象。

另外，在函数参数中，数组声明会被调整为指针声明，这是参数类型调整，不完全等同于普通表达式中的数组退化：

```
void process(uint8_t data[16]);
```

编译器实际按以下类型处理：

```
void process(uint8_t *data);
```

`16` 不会自动成为运行时边界约束。

## 5.3 `array`、`&array[0]` 和 `&array` 的区别

```
int array[4];
```

### `array`

在普通表达式中转换为：

```
int *
```

指向第一个元素。

### `&array[0]`

类型明确为：

```
int *
```

也指向第一个元素。

因此：

```
array == &array[0]
```

在地址值意义上通常成立。

### `&array`

类型是：

```
int (*)[4]
```

表示指向整个数组的指针。

```
int (*pa)[4] = &array;
```

指针步进差异：

```
pa + 1
```

会跳过整个 `array[4]`，即跳过 4 个 `int`。

```
int *p = array;
p + 1
```

只跳过一个 `int`。

示例：

```
#include <stdio.h>

static void demonstrate_address(void)
{
    int array[4] = { 0 };

    int *element_ptr = array;
    int (*array_ptr)[4] = &array;

    printf("%p\n", (void *)element_ptr);
    printf("%p\n", (void *)array_ptr);

    printf("%td\n", (char *)(element_ptr + 1) -
                     (char *)element_ptr);

    printf("%td\n", (char *)(array_ptr + 1) -
                     (char *)array_ptr);
}
```

如果 `sizeof(int) == 4`，则两个差值分别为：

```
4
16
```

## 5.4 数组不能整体赋值

错误代码：

```
int a[4] = { 1, 2, 3, 4 };
int b[4];

b = a; /* 编译错误 */
```

原因：数组不是可赋值的标量对象。

正确实现一：逐元素复制：

```
#include <stddef.h>

static int array_copy(int *destination,
                      size_t destination_capacity,
                      const int *source,
                      size_t source_length)
{
    size_t i;

    if ((destination == NULL) ||
        (source == NULL && source_length != 0U)) {
        return -1;
    }

    if (source_length > destination_capacity) {
        return -2;
    }

    for (i = 0U; i < source_length; ++i) {
        destination[i] = source[i];
    }

    return 0;
}
```

正确实现二：`memcpy`，前提是对象可按字节复制：

```
#include <stddef.h>
#include <string.h>

static int int_array_copy(int destination[],
                          size_t destination_count,
                          const int source[],
                          size_t source_count)
{
    if ((destination == NULL) ||
        (source == NULL && source_count != 0U)) {
        return -1;
    }

    if (source_count > destination_count) {
        return -2;
    }

    memcpy(destination,
           source,
           source_count * sizeof(source[0]));

    return 0;
}
```

如果源和目标可能重叠，必须使用 `memmove` 而不是 `memcpy`。

## 5.5 指针可以整体赋值

```
int a[4] = { 1, 2, 3, 4 };
int b[4] = { 5, 6, 7, 8 };

int *p = a;
int *q = b;

q = p;
```

执行 `q = p` 后：

```
q 指向 a[0]
```

但 `b` 的内容不会被复制：

```
b 仍然是 { 5, 6, 7, 8 }
```

此时 `p` 和 `q` 是两个指针对象，但保存同一个目标地址：

```
p ─┐
   ├──> a[0]
q ─┘
```

修改：

```
*q = 100;
```

实际修改的是：

```
a[0]
```

这体现了数组与指针的关键差异：

- 数组承载数据。
- 指针只建立访问路径。

## 5.6 函数参数中的数组本质

以下声明：

```
void packet_process(uint8_t data[128]);
```

等价于：

```
void packet_process(uint8_t *data);
```

函数内部：

```
void packet_process(uint8_t data[128])
{
    /* sizeof(data) 得到的是指针大小，不是 128 */
}
```

`sizeof(data)` 通常为 4 或 8，而不是 128。

生产级接口必须显式传递长度或容量：

```
#include <stddef.h>
#include <stdint.h>

int packet_process(uint8_t *data,
                   size_t capacity,
                   size_t *used_length)
{
    if ((data == NULL) || (used_length == NULL)) {
        return -1;
    }

    if (capacity < 2U) {
        return -2;
    }

    data[0] = 0xAAU;
    data[1] = 0x55U;
    *used_length = 2U;

    return 0;
}
```

### `static` 数组参数限定符

C 允许在数组参数中写：

```
void process(size_t length, uint8_t data[static 1]);
```

其含义是：调用者应保证 `data` 至少指向一个有效元素。它仍然不是运行时自动边界检查。

二维数组参数：

```
void matrix_process(size_t rows,
                    uint32_t data[][4]);
```

等价于：

```
void matrix_process(size_t rows,
                    uint32_t (*data)[4]);
```

列数 `4` 是类型的一部分，因为编译器需要计算：

```
data + row
```

每次跨越多少字节。

## 5.7 二维数组与二级指针

### 真正的二维数组

```
int matrix[3][4];
```

内存连续：

```
matrix[0][0] matrix[0][1] matrix[0][2] matrix[0][3]
matrix[1][0] matrix[1][1] matrix[1][2] matrix[1][3]
matrix[2][0] matrix[2][1] matrix[2][2] matrix[2][3]
```

类型：

```
matrix       → int (*)[4]  /* 在表达式中 */
&matrix      → int (*)[3][4]
```

### 指针数组形成的“行表”

```
int row0[4];
int row1[4];
int row2[4];

int *rows[3] = { row0, row1, row2 };
```

这里：

- `rows` 是数组。
- `rows[i]` 是 `int *`。
- `rows[i][j]` 通过两次间接访问获得元素。
- 各行可以不连续，长度也可以不同。

### `int **` 的动态行结构

```
int **dynamic_rows;
```

要正确使用，必须先分配指针表，再分别分配每一行：

```
#include <stddef.h>
#include <stdlib.h>

static int **matrix_alloc(size_t rows, size_t columns)
{
    int **matrix;
    size_t i;

    if ((rows == 0U) || (columns == 0U)) {
        return NULL;
    }

    matrix = calloc(rows, sizeof(*matrix));
    if (matrix == NULL) {
        return NULL;
    }

    for (i = 0U; i < rows; ++i) {
        matrix[i] = calloc(columns, sizeof(matrix[i][0]));
        if (matrix[i] == NULL) {
            while (i > 0U) {
                --i;
                free(matrix[i]);
            }

            free(matrix);
            return NULL;
        }
    }

    return matrix;
}

static void matrix_free(int **matrix, size_t rows)
{
    size_t i;

    if (matrix == NULL) {
        return;
    }

    for (i = 0U; i < rows; ++i) {
        free(matrix[i]);
    }

    free(matrix);
}
```

这种结构和 `int matrix[rows][columns]` 的本质不同：

|特性|`int matrix[R][C]`|`int **matrix`|
|---|---|---|
|行是否连续|是|不一定|
|分配次数|1 次或静态分配|1 次指针表 + R 次行分配|
|`sizeof`|能得到完整数组大小|只能得到指针大小|
|行长|固定|可不同|
|局部性|好|可能较差|
|释放复杂度|自动或一次释放|必须逐行释放|
|DMA 友好性|好|通常不适合|
|内存碎片风险|低|动态分配时较高|

## 5.8 字符数组、字符指针和字符串字面量

### 字符数组

```
char a[] = "abc";
```

内存中包含：

```
'a' 'b' 'c' '\0'
```

`sizeof(a) == 4`。

### 指向字符串字面量的指针

```
const char *p = "abc";
```

`p` 是指针，保存字符串字面量首字符地址。

```
sizeof(p)
```

得到的是指针大小，而不是字符串长度。

字符串字面量的存储通常位于只读区域，不能修改：

```
char *bad = "abc";
bad[0] = 'A'; /* 未定义行为 */
```

正确实现：

```
const char *safe = "abc";
```

如果需要修改：

```
char writable[] = "abc";
writable[0] = 'A';
```

### 字符数组与字符指针的内存差异

```
char a[] = "sensor";
const char *p = "sensor";
```

典型布局：

```
a:  [s][e][n][s][o][r][\0]   /* 数组自己的存储 */
p:  [地址]                    /* 指针对象 */
                             ↓
                        "sensor" /* 字符串字面量存储 */
```

`a` 的内容可以被修改，`p` 指向的字面量不能通过 `p` 修改。

## 6. 性能量化分析

## 6.1 内存开销

假设目标平台：

- Cortex-M4
- 32 位地址
- `sizeof(int) == 4`
- `sizeof(void *) == 4`

### 静态数组

```
int data[1024];
```

内存：

```
1024 * 4 = 4096 字节
```

### 指针数组

```
int *data[1024];
```

内存：

```
1024 * 4 = 4096 字节
```

但这只是 1024 个指针槽，不包含它们指向的整数对象。

如果每个整数单独分配：

```
int *data[1024];

for (size_t i = 0U; i < 1024U; ++i) {
    data[i] = malloc(sizeof(int));
}
```

实际内存至少包含：

```
指针表：1024 * 4 = 4096 字节
整数对象：1024 * 4 = 4096 字节
堆管理元数据和对齐损耗：由分配器决定
```

因此，单独分配会产生明显额外开销和时间不确定性。

## 6.2 访问成本

对于连续数组：

```
sum += data[i];
```

典型地址计算：

```
base + i * sizeof(element)
```

对于指针数组：

```
sum += rows[i][j];
```

典型访问过程：

```
1. 读取 rows[i]
2. 得到第 i 行地址
3. 计算第 j 个元素地址
4. 读取元素
```

连续二维数组：

```
sum += matrix[i][j];
```

通常只需根据固定列宽计算偏移：

```
base + (i * columns + j) * sizeof(element)
```

如果数据位于紧耦合内存或零等待 SRAM，额外一次指针加载可能只有几个周期；如果每行分散在 Cache line、外部 SDRAM 或不同总线区域，则性能和抖动可能显著变差。

## 6.3 访问性能示例

以下测试用于比较连续数组与指针数组：

```
#include <stddef.h>
#include <stdint.h>

static uint32_t sum_contiguous(const uint32_t *data, size_t count)
{
    uint32_t sum = 0U;
    size_t i;

    if ((data == NULL) && (count != 0U)) {
        return 0U;
    }

    for (i = 0U; i < count; ++i) {
        sum += data[i];
    }

    return sum;
}

static uint32_t sum_pointer_rows(const uint32_t * const *rows,
                                size_t row_count,
                                size_t column_count)
{
    uint32_t sum = 0U;
    size_t row;
    size_t column;

    if ((rows == NULL) && (row_count != 0U)) {
        return 0U;
    }

    for (row = 0U; row < row_count; ++row) {
        if ((rows[row] == NULL) && (column_count != 0U)) {
            continue;
        }

        for (column = 0U; column < column_count; ++column) {
            sum += rows[row][column];
        }
    }

    return sum;
}
```

实际测量时应记录：

- 总周期数；
- 每个元素平均周期；
- Cache 命中和未命中情况；
- 中断干扰；
- 编译器优化等级；
- 数据所在存储区域；
- 是否发生向量化或循环展开。

不能直接用主频除以执行时间推断所有指针访问成本，因为等待状态、总线竞争和中断都会影响结果。

## 6.4 优化手段与收益

|问题|优化方式|典型收益|
|---|---|---|
|多次间接访问|改为连续对象数组|减少指针加载，提高局部性|
|每行独立堆分配|一次性分配连续矩阵|降低碎片和分配次数|
|API 反复计算长度|结构体保存 `data/length/capacity`|降低重复计算和接口错误|
|热路径使用回调|热点采用直接调用或静态分派|保留内联机会|
|数组被误当作指针|使用 `ARRAY_SIZE` 宏或显式长度|避免容量丢失|
|DMA 访问非连续行|改用连续缓冲区|简化 DMA 描述符和缓存维护|

安全的数组长度宏：

```
#define ARRAY_SIZE(array) (sizeof(array) / sizeof((array)[0]))
```

但它只能用于真正的数组对象，不能用于函数参数中的指针：

```
int array[10];

size_t a = ARRAY_SIZE(array); /* 正确 */

void function(int *array)
{
    size_t b = ARRAY_SIZE(array); /* 错误语义：得到指针大小除以元素大小 */
}
```

推荐将宏限制在本地数组使用场景，不要把它作为通用指针长度工具。

## 7. 应用场景选型指南

```
需要保存一组同类型数据？
|
+-- 编译期容量固定、数据连续、访问频繁
|   +-- 使用 T data[N]
|
+-- 需要调用方提供存储
|   +-- 使用 T *data + length/capacity
|
+-- 数据行列固定且要求连续
|   +-- 使用 T matrix[R][C] 或 T (*matrix)[C]
|
+-- 每一行长度不同或对象分散
|   +-- 使用 T *rows[R] 或 T **
|
+-- 需要动态扩容
|   +-- 设计拥有容量的容器结构
|       +-- T *data + length + capacity
|
+-- 数据由 DMA 访问
    +-- 优先使用满足对齐和连续性要求的数组或内存池
```

### 典型场景

|场景|推荐方案|理由|
|---|---|---|
|ADC 连续采样|`sample_t buffer[N]`|连续布局，适合 DMA 和缓存|
|外部调用者提供输出缓冲区|`uint8_t *buffer, size_t capacity`|明确容量和写入范围|
|图像固定宽度帧缓冲|`pixel_t frame[H][W]`|行步进明确，适合连续处理|
|不同长度字符串表|`const char *names[N]`|各字符串长度可不同|
|动态二维不规则数据|`T **rows`|每行独立长度和生命周期|
|固定协议命令表|`const command_t table[N]`|连续、可放 Flash|
|可扩展容器|`T *data + length + capacity`|指针指向存储，元数据记录范围|

## 8. 工程最佳实践

## 8.1 设计原则

### 原则一：数组接口必须携带长度或容量

错误：

```
int packet_encode(uint8_t *buffer);
```

正确：

```
int packet_encode(uint8_t *buffer,
                  size_t capacity,
                  size_t *encoded_length);
```

### 原则二：区分长度和容量

- `length`：已有有效数据长度。
- `capacity`：缓冲区可以容纳的最大元素数。

```
typedef struct {
    uint8_t *data;
    size_t length;
    size_t capacity;
} byte_buffer_t;
```

### 原则三：明确指针的所有权

接口文档必须说明：

- 输入指针是否只读；
- 输出指针是否由调用者分配；
- 函数是否保存该指针；
- 函数返回后调用者是否可以释放或复用内存；
- 是否允许空指针；
- 是否支持零长度数据。

### 原则四：优先连续布局

对于：

- DMA；
- 大规模遍历；
- Cache 友好访问；
- 固定实时周期；
- 传输协议帧；

优先使用连续数组，而不是大量离散对象和指针数组。

### 原则五：避免隐式数组退化带来的信息丢失

数组退化后，以下信息会丢失：

- 元素数量；
- 总容量；
- 数组类型本身；
- `sizeof` 得到整个数组的能力。

如果需要保留这些信息，应使用结构体封装：

```
typedef struct {
    uint16_t *data;
    size_t length;
    size_t capacity;
} sample_buffer_t;
```

## 8.2 选型决策矩阵

|需求|首选|不推荐|
|---|---|---|
|编译期固定数据集合|`T array[N]`|`T *` 加不明确的硬编码长度|
|函数输入缓冲区|`const T *data, size_t length`|仅传指针|
|函数输出缓冲区|`T *data, size_t capacity, size_t *used`|无容量的字符串操作|
|连续二维矩阵|`T matrix[R][C]`|强转为 `T **`|
|不规则二维数据|指针数组或 `T **`|假设所有行连续|
|动态容器|`T *data + length + capacity`|只有 `T *data`|
|DMA 缓冲区|对齐、连续、静态或内存池数组|随意使用栈数组或碎片堆内存|
|只读常量表|`static const T table[N]`|可写全局指针|

## 8.3 工业级编码规范

- 使用 `sizeof(*pointer)`，避免重复写类型：

```
object = malloc(sizeof(*object));
```

- 使用元素表达式获取大小：

```
memcpy(destination, source, count * sizeof(destination[0]));
```

- 指针参数必须伴随长度、容量或明确终止条件。
- 不要在 API 内部使用 `sizeof(pointer)` 推断外部数组大小。
- 不要把数组参数写成看似带容量但实际不会检查的形式：

```
void process(uint8_t data[1024]); /* 1024 不构成运行时保护 */
```

- 对只读输入使用 `const`。
- 对寄存器或异步硬件状态使用正确的 `volatile`，但不要将其当作同步机制。
- 对 DMA 缓冲区明确对齐、缓存、所有权和访问阶段。
- 禁止通过强制类型转换掩盖数组类型不兼容。
- 使用静态分析检查数组边界、指针生命周期和整数乘法溢出。

## 9. 常见错误与避坑指南

## 错误一：在函数参数中使用 `sizeof` 获取数组长度

错误代码：

```
#include <stddef.h>

static void process(int data[10])
{
    size_t count = sizeof(data) / sizeof(data[0]);
    /* count 通常等于 1 或 2，而不是 10 */
}
```

根因：函数参数中的数组声明调整为指针。

正确实现：

```
static void process(const int *data, size_t count)
{
    size_t i;

    if ((data == NULL) && (count != 0U)) {
        return;
    }

    for (i = 0U; i < count; ++i) {
        /* 处理 data[i] */
    }
}
```

风险影响：只处理部分数据、越界访问或产生平台相关错误。

## 错误二：认为数组可以赋值

错误代码：

```
int source[4] = { 1, 2, 3, 4 };
int destination[4];

destination = source;
```

根因：数组对象不是可赋值对象。

正确实现：

```
#include <string.h>

memcpy(destination,
       source,
       sizeof(destination));
```

前提：

- 两个数组大小一致；
- 对象允许按字节复制；
- 两个区域不重叠。

如果可能重叠，使用：

```
memmove(destination, source, sizeof(destination));
```

风险影响：编译错误；若改用错误指针逻辑，可能只复制地址而没有复制数据。

## 错误三：把数组指针当成元素指针

错误代码：

```
int matrix[4][8];
int *p = matrix; /* 类型不匹配 */
```

根因：`matrix` 转换后是：

```
int (*)[8]
```

而不是：

```
int *
```

正确实现：

```
int (*row_pointer)[8] = matrix;
int *element_pointer = &matrix[0][0];
```

使用方式：

```
row_pointer[2][3] = 10;
element_pointer[2 * 8 + 3] = 10;
```

风险影响：地址步进错误，访问错误元素或触发未定义行为。

## 错误四：将二维数组强转成二级指针

错误代码：

```
void process(int **data);

int matrix[4][8];

process((int **)matrix);
```

根因：

- `matrix` 的内存保存的是 `int` 元素；
- `int **` 要求首层内容是 `int *` 指针；
- 两种布局完全不同。

正确实现：

```
void process(size_t rows, int data[][8]);

process(4U, matrix);
```

或者：

```
void process_flat(int *data,
                  size_t rows,
                  size_t columns);

process_flat(&matrix[0][0], 4U, 8U);
```

风险影响：读取整数内容作为地址，导致非法访问、HardFault 或内存破坏。

## 错误五：误以为指针包含数组长度

错误代码：

```
static void clear_buffer(uint8_t *buffer)
{
    size_t capacity = sizeof(buffer);
    memset(buffer, 0, capacity);
}
```

根因：`buffer` 是指针，`sizeof(buffer)` 是指针大小。

正确实现：

```
static void clear_buffer(uint8_t *buffer, size_t capacity)
{
    if ((buffer == NULL) && (capacity != 0U)) {
        return;
    }

    if (capacity != 0U) {
        memset(buffer, 0, capacity);
    }
}
```

风险影响：只清除前 4 或 8 字节，导致数据残留；或者错误设计下出现越界写。

## 错误六：返回局部数组地址

错误代码：

```
static char *build_name(void)
{
    char name[16] = "sensor";
    return name;
}
```

根因：`name` 是自动存储期数组，函数返回后生命周期结束。

正确实现一：由调用者提供存储：

```
static int build_name(char *output, size_t capacity)
{
    static const char name[] = "sensor";
    size_t length = sizeof(name);

    if ((output == NULL) || (capacity < length)) {
        return -1;
    }

    memcpy(output, name, length);
    return 0;
}
```

正确实现二：返回静态只读数据：

```
static const char *get_name(void)
{
    return "sensor";
}
```

风险影响：悬空指针、栈复用后内容改变、异步任务读取非法数据。

## 错误七：误修改字符串字面量

错误代码：

```
char *message = "ERROR";
message[0] = 'e';
```

根因：字符串字面量通常存储在只读区域，修改属于未定义行为。

正确实现：

```
char message[] = "ERROR";
message[0] = 'e';
```

或者：

```
const char *message = "ERROR";
```

风险影响：嵌入式系统可能触发总线错误、内存保护异常或直接复位。

## 10. 多机制组合使用方案

## 10.1 设计一个生产级数组缓冲区

单独传递 `T *` 不足以表达一个可用缓冲区。推荐将：

- 数据指针；
- 当前长度；
- 总容量；
- 所有权；
- 读写状态；

封装为结构体。

```
#include <stddef.h>
#include <stdint.h>
#include <string.h>

typedef struct {
    uint8_t *data;
    size_t length;
    size_t capacity;
} byte_buffer_t;

static int byte_buffer_init(byte_buffer_t *buffer,
                            uint8_t *storage,
                            size_t capacity)
{
    if ((buffer == NULL) ||
        (storage == NULL && capacity != 0U)) {
        return -1;
    }

    buffer->data = storage;
    buffer->length = 0U;
    buffer->capacity = capacity;

    return 0;
}

static int byte_buffer_append(byte_buffer_t *buffer,
                              const uint8_t *data,
                              size_t length)
{
    if ((buffer == NULL) ||
        (data == NULL && length != 0U)) {
        return -1;
    }

    if (length > (buffer->capacity - buffer->length)) {
        return -2;
    }

    if (length != 0U) {
        memcpy(&buffer->data[buffer->length], data, length);
        buffer->length += length;
    }

    return 0;
}

static void byte_buffer_clear(byte_buffer_t *buffer)
{
    if (buffer != NULL) {
        buffer->length = 0U;
    }
}
```

调用：

```
static uint8_t storage[128];
static byte_buffer_t buffer;

static void example(void)
{
    static const uint8_t frame[] = { 0xAAU, 0x55U, 0x01U };

    if (byte_buffer_init(&buffer,
                         storage,
                         sizeof(storage)) != 0) {
        return;
    }

    (void)byte_buffer_append(&buffer,
                             frame,
                             sizeof(frame));
}
```

这里的设计优势：

- 不依赖堆；
- 容量显式；
- 通过 `buffer->length` 表达有效数据；
- 通过 `buffer->capacity` 防止越界；
- 调用者可以提供静态数组、内存池或 DMA 缓冲区。

## 10.2 编译期数组封装

对于必须保留数组长度信息的场景，可以使用宏生成结构体，但要限制宏使用范围：

```
#define ARRAY_VIEW(type, name, count) \
    struct {                           \
        type data[count];              \
        size_t length;                 \
    } name
```

示例：

```
ARRAY_VIEW(uint16_t, samples, 32U);

static void samples_init(void)
{
    samples.length = 0U;
}
```

更安全、更清晰的工程方式通常是直接定义类型：

```
enum {
    SAMPLE_CAPACITY = 32U
};

typedef struct {
    uint16_t data[SAMPLE_CAPACITY];
    size_t length;
} sample_array_t;
```

## 11. 工业级实际案例分析

## 案例一：ADC DMA 连续采样缓冲区

### 需求

- ADC 每次采集 256 个样本。
- DMA 直接写入缓冲区。
- 采集完成后由任务处理。
- 不允许任务在 DMA 写入期间修改缓冲区。
- 需要明确缓冲区长度和所有权。

### 架构

```
DMA 写入数组
    |
    v
DMA 完成中断
    |
    v
发布 buffer_index
    |
    v
处理任务读取数组
    |
    v
处理完成后归还 DMA
```

### 核心代码

```
#include <stddef.h>
#include <stdint.h>

enum {
    ADC_BLOCK_SIZE = 256U,
    ADC_BLOCK_COUNT = 2U
};

typedef struct {
    uint16_t data[ADC_BLOCK_SIZE];
    volatile uint8_t owned_by_dma;
} adc_block_t;

static adc_block_t adc_blocks[ADC_BLOCK_COUNT];

static int adc_block_acquire_for_dma(size_t index)
{
    if (index >= ADC_BLOCK_COUNT) {
        return -1;
    }

    if (adc_blocks[index].owned_by_dma != 0U) {
        return -2;
    }

    adc_blocks[index].owned_by_dma = 1U;
    return 0;
}

static int adc_block_release_from_dma(size_t index)
{
    if (index >= ADC_BLOCK_COUNT) {
        return -1;
    }

    adc_blocks[index].owned_by_dma = 0U;
    return 0;
}
```

### 设计要点

- 数组必须满足 DMA 的对齐和可访问内存区域要求。
- `volatile` 只表达硬件或异步修改可见性，不能独立解决任务和 ISR 的同步。
- 在有数据 Cache 的 MCU 上，需要执行 DMA 前后的 Cache 维护。
- 任务只处理已完成的块，不能处理 DMA 当前正在写入的块。
- `ADC_BLOCK_SIZE` 是容量，DMA 实际完成长度应单独记录。

## 案例二：协议接收缓冲区

### 需求

- UART 接收帧长度不固定。
- 接收缓冲区由驱动提供。
- 协议解析器不能越界。
- 解析失败时不修改原始数据。
- 支持零长度和截断错误检测。

### 核心代码

```
#include <stddef.h>
#include <stdint.h>

typedef enum {
    PARSE_OK = 0,
    PARSE_INVALID_ARGUMENT = -1,
    PARSE_TOO_SHORT = -2,
    PARSE_LENGTH_ERROR = -3
} parse_result_t;

typedef struct {
    uint8_t command;
    const uint8_t *payload;
    size_t payload_length;
} packet_view_t;

static parse_result_t packet_parse(const uint8_t *frame,
                                   size_t frame_length,
                                   packet_view_t *output)
{
    size_t payload_length;

    if ((frame == NULL) || (output == NULL)) {
        return PARSE_INVALID_ARGUMENT;
    }

    if (frame_length < 3U) {
        return PARSE_TOO_SHORT;
    }

    payload_length = frame[1];

    if (payload_length > (frame_length - 3U)) {
        return PARSE_LENGTH_ERROR;
    }

    if (frame[2U + payload_length] != 0x0DU) {
        return PARSE_LENGTH_ERROR;
    }

    output->command = frame[0];
    output->payload = &frame[2];
    output->payload_length = payload_length;

    return PARSE_OK;
}
```

### 设计要点

- `packet_view_t` 保存的是借用指针，不拥有 `frame`。
- `frame` 在 `packet_view_t` 使用期间必须保持有效。
- `frame[2U + payload_length]` 前必须先验证长度，避免整数和数组越界。
- 如果需要异步保存 payload，应复制数据，而不是保存临时指针。
- 解析器不应通过 `sizeof(frame)` 获取帧长度，因为函数参数是指针。

## 案例三：固定二维传感器数据矩阵

### 需求

- 8 个通道，每个通道保存 16 个采样点。
- 需要连续存储，便于 DMA 和批量计算。
- 计算模块以固定列数接收数据。
- 不允许将矩阵误传成 `int **`。

### 核心代码

```
#include <stddef.h>
#include <stdint.h>

enum {
    CHANNEL_COUNT = 8U,
    SAMPLE_COUNT = 16U
};

typedef uint16_t sample_t;

static uint32_t channel_sum(const sample_t data[][SAMPLE_COUNT],
                            size_t channel)
{
    uint32_t sum = 0U;
    size_t sample;

    if ((data == NULL) || (channel >= CHANNEL_COUNT)) {
        return 0U;
    }

    for (sample = 0U; sample < SAMPLE_COUNT; ++sample) {
        sum += data[channel][sample];
    }

    return sum;
}

static sample_t samples[CHANNEL_COUNT][SAMPLE_COUNT];
```

调用：

```
uint32_t sum = channel_sum(samples, 3U);
```

类型关系：

```
samples
```

在参数传递时转换为：

```
sample_t (*)[SAMPLE_COUNT]
```

而不是：

```
sample_t **
```

### 设计要点

- 固定列数属于类型信息，不能从接口中删除。
- 若列数运行时变化，可使用一维数组加显式行列：

```
uint16_t *data;
size_t rows;
size_t columns;
```

- 运行时计算 `row * columns + column` 时，必须考虑尺寸乘法溢出。
- 连续矩阵更适合 DMA、Cache 和批量 SIMD 处理。

## 12. 高频问题深度答疑

### 1. 为什么说“数组名不是指针”？

因为它们是不同类型和不同对象：

```
int array[4];
int *pointer;
```

`array` 是数组对象，包含 4 个 `int`。`pointer` 是指针对象，只保存一个地址。在多数表达式中 `array` 会自动转换为 `int *`，造成“数组就是指针”的错觉，但 `sizeof(array)`、`&array` 和赋值行为会直接暴露它们的差异。

### 2. 数组名在什么情况下不退化？

主要包括：

```
sizeof(array)
&array
```

以及字符串字面量用于初始化数组时：

```
char text[] = "abc";
```

此外，函数参数声明中的数组会进行参数类型调整，不能简单理解为普通表达式中的退化。

### 3. 为什么函数参数写 `int a[10]` 没有容量保护？

因为在函数参数列表中：

```
int a[10]
```

被调整为：

```
int *a
```

`10` 不会生成运行时检查，也不会影响 `sizeof(a)`。容量必须通过单独参数、结构体或约定传递。

### 4. `array + 1` 和 `&array + 1` 为什么不同？

如果：

```
int array[4];
```

则：

```
array + 1
```

先将数组转为 `int *`，向后移动一个 `int`。

而：

```
&array + 1
```

是 `int (*)[4]` 类型，向后移动一个完整的 `int[4]` 数组。

因此步长分别为：

```
sizeof(int)
sizeof(int[4])
```

### 5. 什么时候应该使用指针数组而不是连续数组？

当每个元素：

- 长度不同；
- 生命周期不同；
- 类型相同但存储位置不同；
- 需要快速替换对象地址；
- 需要保存字符串或对象引用；

可以使用指针数组。但必须额外管理每个目标对象的生命周期、可空性和所有权。

### 6. 为什么嵌入式系统通常偏好连续数组？

连续数组具有：

- 更好的地址局部性；
- 更低的管理开销；
- 更容易进行 DMA；
- 更少的堆碎片；
- 更容易进行静态内存评估；
- 更稳定的访问时延。

但连续数组容量固定，若实际数据不规则，强行使用可能造成空间浪费。

### 7. 数组变量能否作为函数返回值？

C 函数不能直接返回数组类型：

```
int[4] get_array(void); /* 非法 */
```

常见替代方式：

- 调用者提供输出数组；
- 返回指向静态数组的指针；
- 返回结构体，结构体内部包含数组；
- 使用动态分配并返回指针，但必须明确释放责任。

### 8. `memcpy` 复制数组是否总是安全？

不总是。

适合：

- 两个数组对象不重叠；
- 数据类型允许按字节复制；
- 长度计算正确；
- 地址有效且满足访问要求。

如果区域重叠，使用 `memmove`。如果对象包含需要特殊生命周期管理的内容，不能简单把字节复制作为逻辑复制。

## 13. 课程核心总结

### 核心要点

1. **数组是连续元素集合，指针是保存地址的独立对象。**
2. 数组名在多数表达式中转换为首元素指针，但不是指针变量。
3. `sizeof(array)` 得到整个数组大小；`sizeof(pointer)` 得到指针对象大小。
4. `&array` 的类型是指向整个数组的指针，与 `array` 转换后的元素指针不同。
5. 数组不可整体赋值；指针可以改变指向。
6. 函数参数中的数组声明会调整为指针，容量不会自动保留。
7. 二维数组通常是连续矩阵，其类型是 `T (*)[columns]`，不能当作 `T **`。
8. 字符数组拥有自己的字符存储；字符指针通常只是指向字符串字面量或外部字符区。
9. 指针不携带长度、容量和所有权信息，生产级接口必须显式补充这些信息。
10. DMA、Cache、实时性和内存碎片场景通常更偏好连续数组或固定内存池。

### 性能与工程排序

在固定容量、连续遍历和 DMA 场景中，通常优先级为：

```
静态连续数组
    >
连续内存池
    >
单次动态连续分配
    >
指针数组
    >
大量独立动态分配
```

这不是绝对速度排序，而是综合考虑：

- 访问局部性；
- 分配开销；
- 内存碎片；
- 实时性；
- 所有权复杂度；
- DMA 适配难度。

### 通用选型结论

- **固定容量且数据连续：使用数组。**
- **调用者提供存储：使用指针加长度/容量。**
- **固定二维布局：使用真正的二维数组或数组指针。**
- **不规则行结构：使用指针数组或二级指针。**
- **需要动态扩容：使用带 `data/length/capacity` 的容器。**
- **需要硬件传输：优先连续、对齐、生命周期明确的数组缓冲区。**

## 14. 快速参考速查表

### 14.1 声明对照

|声明|含义|
|---|---|
|`int a[10]`|包含 10 个 `int` 的数组|
|`int *p`|指向 `int` 的指针|
|`int *a[10]`|包含 10 个 `int *` 的指针数组|
|`int (*p)[10]`|指向含 10 个 `int` 的数组的指针|
|`int **p`|指向 `int *` 的指针|
|`const int *p`|指向只读 `int` 的指针|
|`int * const p`|不可改变指向的指针|
|`int a[][10]`|函数参数中等价于 `int (*a)[10]`|

### 14.2 表达式对照

假设：

```
int a[4];
int *p = a;
```

|表达式|类型|说明|
|---|---|---|
|`a`|`int *`，在普通表达式中|指向 `a[0]`|
|`&a[0]`|`int *`|首元素地址|
|`&a`|`int (*)[4]`|整个数组地址|
|`p`|`int *`|指针对象的值|
|`&p`|`int **`|指针对象地址|
|`a + 1`|`int *`|后移一个元素|
|`&a + 1`|`int (*)[4]`|后移整个数组|
|`sizeof(a)`|`4 * sizeof(int)`|数组总大小|
|`sizeof(p)`|`sizeof(int *)`|指针大小|
|`a[2]`|`int`|第 3 个元素|
|`p[2]`|`int`|通过指针访问第 3 个元素|

### 14.3 API 选型表

|需求|推荐接口|
|---|---|
|只读输入数组|`const T *data, size_t length`|
|可写输出数组|`T *data, size_t capacity`|
|输出实际长度|`size_t *used_length`|
|固定列宽矩阵|`T data[][C]`|
|不规则二维数据|`T *rows[R]` 或 `T **rows`|
|动态容器|`struct { T *data; size_t length; size_t capacity; }`|
|DMA 缓冲区|对齐的连续数组 + 所有权状态|
|字符串常量|`const char *`|
|可修改字符串|`char []` 或调用者提供的 `char * + capacity`|

## 16. 实践与进阶路径

### 16.1 梯度实战任务

#### 任务一：地址与类型验证

编写程序验证：

```
int a[4];

sizeof(a);
sizeof(&a);
sizeof(a + 0);
sizeof(&a + 0);
```

使用编译器告警、`_Generic` 或调试器检查每个表达式的类型和大小。

#### 任务二：数组复制与指针赋值

实现并对比：

- 数组逐元素复制；
- `memcpy` 复制；
- 指针赋值；
- 指针指向后修改目标对象。

要求说明每种操作对原数组的影响。

#### 任务三：二维矩阵接口

分别实现：

```
void process_matrix_a(int data[][8]);
void process_matrix_b(int *data, size_t rows, size_t columns);
```

禁止使用：

```
int **data
```

并验证二者的访问结果和内存布局。

#### 任务四：安全缓冲区

实现：

```
typedef struct {
    uint8_t *data;
    size_t length;
    size_t capacity;
} buffer_t;
```

要求支持：

- 初始化；
- 添加数据；
- 删除数据；
- 清空；
- 容量不足错误；
- 空指针和零长度处理；
- 溢出检查。

#### 任务五：DMA 缓冲池

实现双缓冲或三缓冲：

- DMA 拥有状态；
- CPU 拥有状态；
- 完成队列；
- 重复归还检测；
- 缓冲区索引边界检查。

### 16.2 性能测试方法

在目标 MCU 上测量：

1. 连续数组线性遍历；
2. 指针数组遍历；
3. 连续二维数组访问；
4. 分散二维数据访问；
5. 静态数组与堆分配对象访问；
6. 不同存储区域的访问延迟。

测量时固定：

- 编译器版本；
- 优化等级；
- LTO 设置；
- Cache 配置；
- 中断状态；
- 数据地址；
- 访问次数。

结果至少报告：

```
总周期数
每元素平均周期
最小值
最大值
均值
访问抖动
代码大小
静态 RAM
动态 RAM 或堆峰值
```

### 16.3 进阶学习方向

- C 标准中的数组类型、复合类型和类型兼容规则。
- 变长数组和动态二维矩阵接口。

- MISRA C 中数组边界、指针运算和指针转换规则。
