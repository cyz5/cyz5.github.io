## 为什么要有练习库

课是「读」的，能力是「写」出来的。每节课末尾第 16 节都有 4 个梯度实战任务（基础 → 组合 → 性能 → 方案对比），练习库就是把这些任务变成可以 `git clone`、可以跑 CI、可以验收的代码。

## 仓库结构：一个 monorepo + 少量旗舰仓库

不建议「每节课一个 GitHub 仓库」。144 节课就是 144 个仓库，光是建仓、配 CI、维护 README 就会吃掉每周本就有限的 10–12 小时。推荐的结构：

```text
embedded-labs/
├── README.md                 # 总索引：技能点编号 -> 练习目录
├── cmake/                    # 公共工具链
├── labs/
│   ├── 01-c/
│   │   ├── 1.1.1-pointer-array/
│   │   │   ├── README.md     # 任务 / 验收标准 / 提示
│   │   │   ├── src/
│   │   │   ├── tests/
│   │   │   ├── CMakeLists.txt
│   │   │   └── lab.json      # 技能点、难度、硬件依赖
│   │   └── 1.2.3-memory-pool/
│   ├── 03-mcu/
│   │   └── 3.1.2-nvic/
│   └── 04-rtos/
│       └── 4.5.1-priority-inversion/
└── .github/workflows/ci.yml  # 矩阵构建，只跑改动的 lab
```

目录名用「技能点编号 + 英文短名」，和站内课程一一对应；GitHub 上每个目录的 README 都会单独渲染，看起来就像一个小仓库，但只需要维护一个 CI。

旗舰项目另开仓库（3–5 个即可），它们是你的简历项目，不是课后作业：

| 仓库 | 对应能力 | 产出 |
| --- | --- | --- |
| `foc-drive` | 9.1.3–9.1.6、3.1.9/3.1.10 | 有感/无感 FOC、电流环波形、调参记录 |
| `ecat-servo` | 8.1.3、8.1.9、4.1–4.3 | EtherCAT 从站 + CiA402 + DC 抖动数据 |
| `secure-boot-u5` | 10.2、3.1.8 | 双分区、签名校验、回滚、启动耗时 |
| `bsp-board` | 3.8、3.10 | 分层 BSP、传感器抽象、跨平台移植 |

```markdown

（照抄课程 16.1 的任务，拆成可运行的 main）

（不超过三条，避免变成抄答案）
```

## CI 怎么跑：没有板子也能测

| 类型 | 做法 | 适合 |
| --- | --- | --- |
| 主机测试 | gcc + CMake + CTest，纯算法/数据结构/协议解析 | C 语言、协议、内存池 |
| 指令级仿真 | QEMU（`qemu-system-arm -M netduinoplus2`）跑裸机固件 | NVIC、启动代码、异常 |
| 外设仿真 | Renode（STM32F4/H7 模型）跑 GPIO/UART/定时器 | 驱动逻辑、中断链路 |
| 硬件在环 | 自托管 runner + 开发板 + 逻辑分析仪 | 时序、功耗、EMC |

前两类进 GitHub Actions 的矩阵；第三类本地跑；第四类不进 CI，只留测量脚本和数据。

## 课程与练习怎么对应

站内每节课的 URL 是 `/p/3-1-2/`，练习目录是 `labs/03-mcu/3.1.2-nvic/`，编号一致即可双向跳转。等练习库建好后，课程页底部会出现「对应练习」入口。
